# 契约 04：恢复、资源保护与完成提交

状态：Proposed。前置：[状态与执行权](02-state-and-execution.md)、[验证与审批](03-verification-and-approval.md)。

## 1. 持久化边界

业务数据库是 Task、Run、审批、动作身份和审计的权威存储。文件内容位于产物存储/工作目录，外部服务具有自己的状态；它们不能被宣称随业务数据库一起原子回滚。

数据库事务保持短小。模型请求、CLI、网络调用、等待人类都在事务之外。通知不是唯一事实来源，客户端断线后通过数据库读取恢复视图。

V1 不要求事件溯源、消息中间件或分布式调度。关键审计记录与对应业务写入同事务保存；可丢的 UI 唤醒通知在提交后发送。需要保证外部通知送达时另行使用持久化待发送记录，不能以内存事件承诺送达。

## 2. 逻辑动作与尝试

- logical_operation_id：一个确定意图的稳定身份，关联 Run、Step、目标、参数和内容。
- invocation/attempt：该动作的一次实际调用记录。
- 相同动作因进程恢复继续核对时身份不变；不能新建 ID 规避 UNKNOWN 或重复消费批准。
- 有证据证明未执行，或 Adapter 明确支持可核验幂等性时，才可对同一逻辑动作发起后续尝试。
- 修正了内容、目标或参数就成为新动作，需要重新判定权限及审批；旧动作未知时不能用“新动作”绕过未决影响。

最小动作状态：PREPARED / DISPATCHING / SUCCEEDED / FAILED / UNKNOWN / DENIED。等待审批发生在调用准备之前的 Review 流程；不把“尚未批准”伪装成外部执行失败。

## 3. 调用协议

1. 规范化实际目标和参数，解析真实资源，核对 Task ownership_epoch、Worker claim、资源占有和控制请求。
2. 判定当前 Permission。ASK 创建绑定动作的 Review；DENY 记录拒绝且不调用。
3. 短事务写 PREPARED 意图，并关联适用批准；重复 command/operation 返回既有记录。
4. 调用前重新校验控制请求与授权，在短事务中将 PREPARED 条件更新为 DISPATCHING。
5. 事务外调用 Adapter；记录内容/执行证据，不把凭据写进日志。
6. 短事务记录 SUCCEEDED、确定未执行的 FAILED 或 UNKNOWN。只有明确成功结果才推进 Step。

PREPARED 保证未到本系统的实际调用点；DISPATCHING 不能证明外部动作已发生，也不能证明未发生。权限撤销在最终执行准入检查前生效则拒绝；动作已获准并进入调用后，只能尽力停止/核对，不能承诺撤回已经产生的副作用。

Adapter 不提供可核对结果的写动作，UNKNOWN 时转人工处理并保持相关资源禁止新写。用户“知道了”不是成功证据；需记录可证明的结果或明确的恢复处置。仍不能判定时继续保留 UNKNOWN。

## 4. 崩溃恢复矩阵

| 崩溃位置 | 重启后的判断 | 允许动作 |
|---|---|---|
| 意图尚未保存 | 没有执行记录，也未进入调用 | 同命令重新准备 |
| PREPARED 已保存 | 尚未发起调用 | 重查当前授权/控制请求后继续或取消 |
| DISPATCHING 已保存、无确定结果 | 可能执行 | UNKNOWN，先核对；不能默认重发 |
| 外部已成功、结果未保存 | 同上 | 用动作身份/目标状态核对，再保存证据 |
| SUCCEEDED 已保存、Step 未推进 | 已有确定结果 | 幂等推进 Step，不再次调用 |
| PASS 已保存、业务未提交 | 检查验证仍适用 | 仅重试完成事务 |
| 业务已提交、响应丢失 | 查 command_id/完成记录 | 返回原结果，不重复追加 delta |

纯模型生成可按预算重新尝试，但可能增加成本并产生不同内容；结果仍需新产物版本和验证，不能声称模型执行 exactly-once。

## 5. 工作目录排他与过期执行者

V1 对同一规范化真实工作根目录采用单写执行。重叠根目录、路径别名与链接不能绕过排他；注册 Project 根目录时拒绝未明确处理的重叠绑定。读取历史产物可并行，实时工作文件读取要记录版本，不能把读取中的混合状态当一致快照。

资源占有在活动执行期间持久化。PAUSED/等待人类时可仅在无在途动作、无未知结果且有安全检查点时释放资源；Resume 必须重新获得资源并校验期间变化。释放资源不自动释放 Task 的 AI 执行权。

租约过期只说明旧 Worker 不再被信任，不说明旧子进程已经停止。先隔离旧 claim 的业务写入，再核对在途进程/外部动作，安全后才发放新的冲突写权限。ownership_epoch、claim epoch 与资源占有都必须在提交处核对。

数据库 fencing 不能阻止已经运行的外部程序写磁盘；因此不得仅凭租约到期自动并发启动新的冲突命令。

## 6. 文件和产物协议

不可变产物：写入独立暂存内容 → 完整保存并计算摘要 → 发布到不可变存储位置 → 数据库登记版本。数据库记录只能引用已完整持久保存的内容。崩溃留下的未引用暂存内容可以后续清理，不能作为成功产物。

工作文件修改：读取基线摘要/版本 → 生成 change set → 提交前重读检查 → 在资源排他下应用。检测到用户外部编辑时拒绝静默覆盖，保留候选更改并提示冲突。

注意：没有跨编辑器的操作系统锁时，重读比较与写入之间仍可能发生外部编辑。V1 对受管文件可通过应用独占写入保证；对用户自由编辑的仓库，优先在隔离副本生成变更并显式合入，不能声称普通 hash 检查彻底消除竞态。

多文件修改不承诺跨文件系统与数据库的全原子性。保存逐文件基线、目标摘要和执行结果；中断后核对实际内容，部分应用不能报告整体成功。第一实现路径只向受管存储发布新 Markdown 版本，避免提前构建通用多文件事务系统。

## 7. 幂等业务完成事务

应用用例负责协调，同一事务调用各领域写入口：

```text
按 command_id 查询既有结果
→ 若存在且请求一致，返回原结果
→ 锁定/条件更新 Task、Run 及必要 State revision
→ 核对 Task owner、claim/epoch、无待处理控制请求
→ 核对确切产物已保存、验证仍适用、必要 Review 已解决
→ 核对不存在影响完成的 UNKNOWN / 在途必要动作
→ 写 Task DONE 与 completion_basis
→ 应用必要的确定性 Project State delta（可能为空）
→ 写 Run COMPLETED、释放占有
→ 写完成记录、command 结果与关键审计
→ 提交
```

提交失败整个数据库事务回滚。引用的已发布产物仍保留，不能假装事务回滚也删除外部事实。重试完成只重做短事务，不重新生成或调用工具。

若 State revision 因无关变化产生冲突，重新读取并由确定性规则重新计算 delta；涉及需用户决定的冲突则暂停处理，不让 LLM 随意覆盖。只做有界重试，避免无限争抢。

完成凭据绑定 Task 当前执行周期/acceptance_revision 与 Run。Task 重开后旧 command 重放只能返回历史结果，不能重新把当前 Task 标为 DONE。

非阻塞阶段建议独立于必要完成条件。若该次完成产生建议，可与完成记录一同持久保存或用持久待处理任务生成；建议生成失败不撤销已完成的必需事实，也不能依赖一次内存事件保证它必定出现。

## 8. 本地执行安全准入

第一实现路径允许受管内容读写与显式公共资料获取，不启用任意 shell。公共 Web 获取限制协议、目的地址、重定向及响应大小；遇到私网/本机/敏感目标转拒绝，不允许凭网页内容扩权。

真实 Git / CLI 开放前必须定义执行配置：固定/可信程序、结构化参数、真实根目录、最小环境变量、可用凭据、网络边界、资源/时间上限、取消与结果核对方式。脚本、构建配置、可执行插件发生相关变更时重新检查信任依据；不能仅因命令字符串相同就保留自动许可。

若使用宿主受信项目模式，产品明确其不提供恶意代码隔离；用户明确建立的执行配置才可应用 AUTO，未知代码或扩大能力的变化走 ASK/DENY。需要处理不可信代码时先采用实际隔离环境。即使使用隔离环境，挂载、凭据与网络权限也要明确，不能把“容器”当作无限制安全保证。

文件工具校验真实路径、链接及受保护文件；Gateway 不能把程序工作目录当完整权限边界。外部文本和工具输出不具有授权地位。此处延续评审已核验的 [ProcessBuilder 属性边界](https://docs.oracle.com/en/java/javase/26/docs/api/java.base/java/lang/ProcessBuilder.html) 与 [OWASP 程序及参数约束原则](https://cheatsheetseries.owasp.org/cheatsheets/OS_Command_Injection_Defense_Cheat_Sheet.html)，不指定未验证的具体隔离产品。

## 9. 恢复与故障验收

| 编号 | 故障/输入 | 预期 |
|---|---|---|
| D01 | PREPARED 后崩溃 | 重查授权后可继续，不丢动作与批准关联 |
| D02 | DISPATCHING 后失联 | UNKNOWN，先核对，不盲目 fallback |
| D03 | 动作成功后、Step 推进前崩溃 | 复用成功证据，不再次调用 |
| D04 | PASS 后、完成事务前崩溃 | 仅重试有效性检查与完成事务 |
| D05 | 完成事务任一步失败 | 数据库事实整体回滚，产物历史仍可追溯 |
| D06 | 提交后响应丢失/旧完成命令重放 | 原结果可查询，不重复 delta，不完成已重开的 Task |
| D07 | 旧进程未停止、另一 Task 请求写目录 | 不发放冲突写权 |
| D08 | Agent 改测试脚本后请求原命令 | 重新校验实际执行配置，不能因命令白名单直接 AUTO |
| D09 | 路径别名/链接/重叠根目录、环境凭据 | 不绕过声明边界，不泄露不必要凭据 |
| D10 | 用户外部编辑/多文件部分应用 | 检测可检测冲突并展示实际状态，不承诺不存在的原子性 |
| D11 | Web 重定向进入受限网络 | 拒绝，不能只校验初始 URL |

上述应优先用 Fake Adapter、确定性检查器和可控故障点实现自动化测试。真实模型成功示例不能替代恢复测试。
