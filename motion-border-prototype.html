Agent 状态视觉反馈系统 · 输入区动效三候选

独立原型，未接入项目。页面内状态与文案均为演示数据，不代表任何真实 Run / Task 事实。 颜色、间距、圆角取自 docs/frontend/design-tokens.json（v0.4.0 Proposed）； design-system.md §7.1 与 workbench-design.md §6.1 是规则依据。 本轮把动效从「整圈流光 + 弥散光晕」收缩为 低干扰状态表达：全部时长与缓动只来自 --motion-* token，运行期动效降为 Level 1–2，Level 3 只做一次性强调且不循环。 三个候选共用同一套 StateVisualConfig，差异只在输入框边框层的表达方式。

关闭动效只改展示，不发送暂停或取消命令，不隐藏状态文字与操作入口；输入框在任何状态下都可编辑。

二、输入区动效三候选

A 静默基线 零循环

边框只换 1px 静态色；运行期完全不动，靠指示器图标 + 文字 + 边框色三通道表达。Level 0–3 全部静态，唯一动作是进入 need / success / error 时的一次性描边强调。

代价：长时间执行时「仍在工作」的感知最弱，需要用户看指示器文字。

B 局部光点 Level 2 · 单点

上边一条 18% 宽的 2px 光点。不做整圈流光，不加 blur 光晕，只用 transform。

上下文 8%

代价：光点经过输入文字上方 2px，需要确认不干扰首行阅读。

C 底部细基线 Level 2 · 往复

内缩基线上 26% 宽的低对比段。基线不接触边框，四角不可见，避免「进度条被误读为可拖动进度」。

上下文 8%

代价：与输入区底部分隔线重合，需要确认在 Windows 缩放下不显脏。

三、快捷操作图标状态

运行中 = 图标自身缓慢旋转（无额外文字）；终态 = 图标变色 + 静态角标；需要人工 = 问号角标。图标区域高度固定，角标不推动布局。

五、验收自查（本页可直接验证的项）

  • 执行中三个输入框均可点击、输入、选择、复制；无 disabled，无遮罩层。
  • 不看文字时，A 靠指示器图标形状 + 边框色，B 靠上边光点，C 靠底部基线段，可区分 running / paused / need / success / error。
  • 同一时刻只有一个候选的运行期循环动效处于 Level 2；快捷操作区仅运行中那一个旋转。
  • 进入 success / error / need 后，所有循环动效立即停止（emphasis 为 forwards 一次性，不循环）。
  • waiting_user 三候选同时出现琥珀边框 + 指示器问号图标 + placeholder 变更，三通道同时变化。
  • 切换状态时输入框高度不变（见上方位移检测读数）。
  • 勾选「减少动态效果」后循环动效消失，但图标、文字、边框色、角标仍能区分全部状态。

六、待验证项（本页无法证明）

  • 长时间 running 下 4.5s / 7s 周期是否仍产生视觉疲劳，需真实桌面窗口连续使用 30 分钟以上判断。
  • Windows WebView 在 125%–150% DPI 下 2px 光点与基线的实际观感。
  • 键盘 focus-visible 描边与运行期光点/基线并存的对比度是否达标。
  • 光点经过输入首行文字上方时，Windows 透明合成层是否产生文字边缘抖动。
  • 真实接入后：Task A 的迟到事件不得点亮 Task B 的输入区；后台 SSE 断流时状态不得停在 running。
  • 屏幕阅读器只播报状态文字，不读出装饰动效；装饰层必须保持 aria-hidden。
