Agent 状态视觉反馈系统

输入区动效六候选 · A 边框呼吸 / B 上边光点 / C 三点序列 / D 左边光点 / E 角弧光点 / F 环绕全框光点。独立原型，未接入项目；页面内状态与文案均为演示数据，不代表任何真实 Run / Task 事实。

颜色、间距、圆角取自 docs/frontend/design-tokens.json（v0.4.0 Proposed）； design-system.md §7.1 与 workbench-design.md §6.1 是规则依据。 本轮把动效从「整圈流光 + 弥散光晕」收缩为 低干扰状态表达：全部时长与缓动只来自 --motion-* token，运行期动效降为 Level 1–2，Level 3 只做一次性强调且不循环。 六个候选共用同一套 StateVisualConfig，差异只在输入框边框层的表达方式： B / D / E / F 属「局部光点」家族，靠载体位置与路径区分；A / C 走非光点机制。

关闭动效只改展示，不发送暂停或取消命令，不隐藏状态文字与操作入口；输入框在任何状态下都可编辑。

02输入区动效六候选

A

边框呼吸

零位移 · 非光点

整条 1px 边框在两个色阶之间往复，零位移、零方向。不横穿、不抖动——语义是「边界本身在注意」。

上下文 8%

代价　长时间执行时「仍在工作」的感知最弱，需要用户看指示器文字。

B

局部光点

Level 2 · 单点

上边一条 18% 宽的 2px 光点。不做整圈流光，不加 blur 光晕，只用 transform。

上下文 8%

代价　光点经过输入文字上方 2px，需要确认不干扰首行阅读。

C

三点序列

Level 2 · 离散

底部三点依次点亮，总长度恒定、只换明暗相位。读作信号或步骤推进，不会被误认为可拖动进度条。

上下文 8%

代价　三点位于输入区底缘，与底部分隔线距离近，需要确认在 Windows 缩放下不显脏。

D

左边光点

Level 2 · 光点族

B 的 90° 旋转：左边框一条 20% 高的 2px 光点竖向穿行。同一条光点语汇，换到纵向轴上。

上下文 8%

代价　纵向光点与光标上下方向一致，可能被误读为「正在打字」。

E

角弧光点

Level 2 · 光点族

光点只走左上角一段 90° 弧，不进入其余三边。角是视觉上最「有动作感」的位置，也是最容易看出运动的角落。

上下文 8%

代价　可用面积最小，只覆盖一个角，长时间 running 时感知弱于整边光点。

F

环绕全框

Level 2 · 光点族

光点沿圆角矩形真实周长跑满一整圈。段长固定为周长 22%，靠 stroke-dashoffset 行进，不是整圈流光。

上下文 8%

代价　整圈环绕的「正在推进」暗示最强，也最容易被读成可拖动进度条，需在真实窗口确认误读风险。

05验收自查（本页可直接验证的项）

  • 执行中六个输入框均可点击、输入、选择、复制；无 disabled，无遮罩层。
  • 不看文字时，六候选各自可区分：A 靠边框色阶往复（无位移），B 靠上边光点，C 靠底部三点顺序，D 靠左边光点，E 靠角弧，F 靠整圈环绕光点。
  • 四个光点族候选（B / D / E / F）盲看是否可区分，需在真实窗口确认——同族同质感，只靠位置与路径区分，是本轮最需要人工判断的取舍。
  • 同一时刻只有一个候选的运行期循环动效处于 Level 2；快捷操作区仅运行中那一个旋转。
  • 进入 success / error / need 后，所有循环动效立即停止（emphasis 为 forwards 一次性，不循环）。
  • waiting_user 六候选同时出现琥珀边框 + 指示器问号图标 + placeholder 变更，三通道同时变化。
  • 切换状态时输入框高度不变（见上方位移检测读数，六项均须为 0px）。
  • 勾选「减少动态效果」后循环动效消失，但图标、文字、边框色、角标仍能区分全部状态。

06待验证项（本页无法证明）

  • 长时间 running 下 4.5s / 7s 周期是否仍产生视觉疲劳，需真实桌面窗口连续使用 30 分钟以上判断。
  • Windows WebView 在 125%–150% DPI 下 2px 光点、三点与环形的实际观感。
  • 键盘 focus-visible 描边与运行期光点/三点/环形并存的对比度是否达标。
  • 光点经过输入首行文字上方时，Windows 透明合成层是否产生文字边缘抖动。
  • 四个光点族候选同屏并列时，D（纵向）与 E（角弧）的暗示强度是否够，是否需要牺牲其中一个。
  • 真实接入后：Task A 的迟到事件不得点亮 Task B 的输入区；后台 SSE 断流时状态不得停在 running。
  • 屏幕阅读器只播报状态文字，不读出装饰动效；装饰层必须保持 aria-hidden。
