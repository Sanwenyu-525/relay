## 1. 目标与边界

目标是让用户从明确的日常启动入口进入真实工作空间，使用已有核心功能完成实际读写，获得与现有参考图一致、可读、流畅且状态可信的界面。

- 保留当前 React + TypeScript + Vite、Tauri、Fastify、Kysely/PostgreSQL 组合，复用已有业务入口、客户端、组件和路由，不重建项目。
- 覆盖现有已实现或已确认本期范围的页面与交互，不只美化首页。不把所有概念图中的远期能力一并实现。
- 允许为联通现有功能补齐必要的前后端代码、错误处理、查询刷新、启动配置与测试；涉及新增业务语义、权限扩大或重要架构变化时，先明确差异和待决项，继续不依赖该决定的工作。
- 不删除 fixture 测试设施，也不让正常使用链路依赖 fixture。示例入口应明确、主动选择；真实服务出错时不得自动展示示例内容冒充业务数据。
- “真实 API + PostgreSQL”“Mock 模型/工具”“真实模型 Provider”“真实外部工具效果”是不同维度。按当前门槛保留 Mock 模型/工具，不为证明前后端联通擅自启用真实 Provider 或扩大工具权限。
- 本轮交付可运行的本机使用路径和 UI；不把目录包宣称为已完成安装、升级或发布验收。

## 3. 分批实施

### 第一批：启动与数据来源可信

打通标准日常入口到真实工作空间的完整路径。优先修复现有桌面引导、构建或配置问题，不另造连接系统。

- 正常桌面进入 live；首次缺配置、API 不可用、数据库未就绪分别给出可理解、可操作的反馈，不泄漏敏感连接信息。
- 浏览器开发入口清楚区分未连接、连接中、真实数据、显式示例。刷新后的行为必须明确；不得为自动重连把 Bearer 写入 URL、localStorage、构建产物或日志。
- 空数据库展示真正空态及创建入口，不能填充样例项目来掩盖未连接。
- 切换工作空间/项目或连接后清理过期视图，迟到响应不得污染新上下文。连接失效应阻止无依据的写操作并保留用户草稿。
- 确认当前可执行文件确实包含本轮前端与 API 产物。与其他任务共用构建目录时使用既有隔离机制，避免覆盖正在验收的包。

### 第二批：逐页真实业务闭环

先完成“创建项目 → 创建任务 → 开始人工处理 → 保存产物版本 → 核验并选择接受版本 → 满足完成条件后完成 → 重开”的闭环，再检查其他已有页面。

逐项核查今日、项目列表/详情、全局与项目任务、任务详情、产物编辑/版本/追溯、Run/待审、知识/资料、动态、连接/设置，以及已实现的通用/论文/开发工作台、Assist/蓝图等入口。

- 每个列表、详情、计数、状态、搜索、筛选和主要按钮明确数据来源；已在本期范围且有后端能力的必须实际接通。
- 写操作成功必须来自后端回执；写后重新读取权威事实并刷新受影响列表、详情和统计。刷新页面、关闭重开后仍能读到数据。
- 表单默认值、UI 临时状态、测试 fixture 和业务事实分开；禁止将硬编码名称、数量、日期、进度或 `setTimeout` 成功提示用作真实结果。
- 缺接口时先检查已有契约和应用用例；本期必要缺口按现有边界补齐，未确认或后置能力明确不可用及原因，不伪造成功。
- 遵守 `command_id`、`expected_revision`、`allowed_actions`、版本绑定与幂等约束；超时结果不明先查同一命令回执，不换 ID 盲重试。
- 处理 401/403、409、422、网络中断与服务故障；冲突保留草稿并提供核对路径。已有 SSE/轮询复用当前机制，避免重复订阅与响应竞态。
- Task、Run、Review、Handoff、Verification 的状态不混用。UNKNOWN 保持待核对；取消已提交不等于已停止；模型输出不等于任务完成。

### 第三批：按现有视觉方向精修完整界面

直接查看参考图，再查看当前运行截图，按页面记录偏差。延续暖纸色浅底、墨绿主操作、宋体标题、细线和留白，数值消费现有 tokens；不擅自另选视觉风格、生成新设计体系或全页推倒重做。

- 先调整共用页壳、标题栏、导航、内容宽度、排版层级和基础组件，再逐页修复布局与阅读问题。
- 对齐表单、表格、按钮、页签、状态标签、弹窗与抽屉的尺寸和状态；明确主操作，降低无关边框和卡片堆叠，避免大面积空白或信息挤压。
- 长正文、Markdown、版本比较和知识阅读应有合适行宽、真实滚动和稳定工具区；工程 ID/hash 不应挤占用户判断所需的标题、内容、来源与操作，但追溯详情仍应可达。
- 右侧上下文区遵守现有单一区域规则，小窗转抽屉；不靠全局缩小页面解决拥挤。
- 复用最新共享标题栏；核对后退/前进、搜索、新建任务、拖动区和窗口控制，避免重复窗口栏。保留草稿离开保护。
- 完整处理 loading、empty、error、disabled、提交中、冲突、恢复和完成态。已有内容刷新时尽量保持布局稳定，避免闪屏；长 Run 不锁死全页。
- 检查键盘焦点、标签、对比度、中文输入法、长中文、窄窗以及 Windows 100%/125%/150% 缩放。未具备实测条件的尺寸或缩放明确列为未验证。
- 不因精修丢失近期新增的原文锁定、手动影响检查、人工待处理与通知相关入口及状态。

### 4.3 目标信息结构

保持既有导航与路由。下图仅定义内容顺序和层级，不要求添加新的右栏、统计卡或导航：

```text
共享桌面标题栏：后退 / 前进 / 搜索 / 新建任务 / 拖动区 / 窗口控制
共享应用顶栏：面包屑                                      连接状态

今日 / 当前查询日期                         内容区主要行动（按状态）
把今天留给重要的事
一句简短说明

查询工具条：日期选择 · 当前时区/调整入口 · 刷新
必要的错误、提交结果待核对提示（按状态出现）

今日焦点：紧凑空态，或已选任务的名称、归属、当前状态、主要操作

有数据：可开始或继续 → 已置顶但受阻 → 其他等待
全空：单一空态说明 + 创建任务 / 查看已有任务
```

标题栏保留用户已选定的操作布局，不更名品牌。内容区主行动用于降低空态中的寻找成本，不再堆叠第三套操作工具条。不添加没有真实依据的“完成率”“效率分”“今日进度”或示例任务。

### 4.4 字体、尺寸与间距：先复用，再有依据调整

下面是**待运行截图验证的角色选择建议**，不是从截图测出的真值。CSS px、rem、DIP、物理像素分开记录；禁止用 `zoom`、`transform: scale` 或手工乘 DPI 来整体缩小界面。

| 元素 | 优先使用的现有 token | 本轮要求 |
|---|---|---|
| 今日标题 | `font.size.compactPage`（2rem）优先试验，宽窗按实际效果评估 `font.size.page`（3rem） | 不再无条件使用 display 的 3.5rem；保留同一句标题；允许自然换行，不定高裁切 |
| 分组标题 | `font.size.rowTitle`（1.25rem）或 `font.size.section`（1.5rem） | 空分组不以大标题占位；数量使用较轻的 UI 字体，不与主标题竞争 |
| 导航、按钮、字段、一般正文 | `font.family.ui` + `font.size.body`（1rem） | 核对 YaHei UI 等实际命中，输入/select 也应正确继承；不得全部套用宋体 |
| 日期、来源、说明 | `font.size.meta`（0.875rem） | 保持可读对比度，不用小字或低透明度藏重要错误 |
| 输入和按钮 | `control.height`（2.5rem） | 同行基线、内边距、边界一致；不只改外框而裁切中文输入内容 |
| 内容边距 | `layout.main.padding` / `compactPadding` / `smallPadding` | 页壳和页面不重复叠加 padding；共用左边线 |
| 组内/组间间距 | `space.2/3/4` 与 `space.6/8` | 同类关系统一；空态不沿用长任务列表的大间隔 |
| 内容最大宽度 | `layout.content.maxWidth` | 先检查现有约束生效，正文不横跨整屏形成超长句；不为填满屏幕造卡片 |

这些建议可能改变当前设计系统的“今日标题用 display”规则。执行者若采用，应同步修改该角色规则和对应消费者，说明原因；不要私自降低全局 display token 影响其他页面，也不要把本提示词变成第二份 token 表。这里只引用已有值；确需新增语义 token 时先检查现有可复用项，并在唯一 JSON 中维护。

### 4.5 日期与时区工具条

- 日期仍是实际查询条件。保留日期输入的键盘/原生选择能力，可以改善外观，不为了漂亮替换成复杂日历库。
- 常态显示当前查询时区；将时区编辑放在“调整时区”展开区域或小浮层，保留可发现的入口、标签、确认和取消。错误贴近字段，取消不能改变已生效时区。
- 继续区分已生效时区和编辑中的时区；验证通过后才查询，非法值不覆盖上一次有效查询。切换日期/时区时不显示另一查询范围的任务为当前结果。
- 日期与星期来自同一查询语义；非今天应清楚显示正在查看的日期，不让顶栏系统日期冒充筛选日期。
- 刷新有明确反馈、避免重复发送；已有内容后台刷新可保留但必须标识刷新/失效状态，不能把过期数据当新结果。首次 loading 不显示“0 个任务”。

### 4.6 文案具体替换方向

保持 API 字段、命令和状态枚举不变，只调整展示语言。下表是推荐用语，按现有业务事实微调，保留危险状态必要解释。

| 现有表达 | 推荐展示 | 细节归属 |
|---|---|---|
| Pin / 取消 Pin | 置顶 / 取消置顶 | 代码仍用 pin |
| Later / 清除 Later | 延后 / 取消延后 | 展示实际日期，保留时区语义 |
| Focus / 设为本日 Focus | 今日焦点 / 设为今日焦点 | 不解释为获得执行权限 |
| Pin 但仍受阻 | 已置顶，待处理 | 具体等待原因在任务行中可见；后端没给原因不能编造 |
| 本日尚未选择 Focus | 还未选择今日焦点 | 有候选才引导从任务中选择；无候选引导创建/查看任务 |
| 服务端判定可开始/继续 | 可开始 / 可继续，按真实状态区分 | 判定依据放详情；无法细分时保持“可开始或继续” |
| 任务能否开始、如何排序由服务端…… | 置顶和焦点帮助安排今天；受阻任务需先处理阻碍 | 完整规则放“安排说明”，人工待处理作为独立链接 |
| 选择版本、revision、command_id、allowed_actions | 默认显示状态、结果和可用操作 | 核对详情保留原技术信息与复制入口；待核对告警和核对操作不能隐藏 |

不把“已连接”改成“已保存”，不把“已提交取消”改成“已停止”。不得通过删除关键警告营造简洁。

### 4.7 空态与有数据状态必须分别设计

1. **未连接/不可用：** 连接说明或错误及恢复入口，不渲染成没有任务。
2. **首次加载：** 简洁骨架或状态提示，给后续区域稳定占位，不先闪全空状态。
3. **查询成功、全部为空：** 一个空态，“当前日期下没有可安排的任务”，主行动“新建任务”，次行动“查看全部任务”。只有额外真实查询证明整个空间无任务时，才写“还没有任务”。不能把筛选为空等同于从未创建。
4. **没有焦点、有候选：** 紧凑提示从候选中选择。复用既有设焦点动作；若加“选择焦点”按钮，必须打开真实候选列表或聚焦相应区域，不能是无效装饰按钮。
5. **有焦点：** 名称是视觉中心；显示可核实的项目、状态和主要行动，清除为次要操作。找不到目标时显示不可用及可执行处置，不能默认仅展示 UUID 当作正常标题，也不编造名称。
6. **焦点受阻或不在查询范围生效：** 保留事实，清楚说明，不默默移除或自动换成别的任务，不给可执行绿勾。
7. **部分分组为空：** 零数量组收为简短提示或可展开标题；有数据组仍完整可见。全空时不重复三份空说明。用户仍能理解分组范围，没有把不支持误装成空数据。
8. **有任务：** 每行先展示任务名和实际归属，再展示状态/截止等必要信息；置顶、设焦点等为就近操作；延后、计划和诊断信息渐进展开。真实项目标题不可用时不造名称。
9. **受阻任务：** 状态原因和能做的下一步可达；不得只置灰或把操作藏到不可达区域。没有接口提供明确原因时显示“查看任务了解处理要求”等诚实提示。
10. **写入 pending/失败/冲突：** 行内保留反馈与草稿，结果不明保留核对入口和命令身份；分组重排后保持可理解的焦点位置。

### 4.8 滚动、窗口与可访问性

- 核实当前使用文档滚动还是主内容滚动，在已有方案内修正；不为截图另造一套复杂滚动管理。
- 一个主滚动区域足以覆盖今日页，侧栏在短窗口可有必要的独立滚动；不出现内外两根主滚动条或正文与页壳抢滚轮。
- 顶部/底部不会遮住标题、表单错误、任务行和最后一个按钮。普通文字区域无横向滚动；不得用全局 `overflow: hidden` 掩盖溢出。
- 正文 focus、跳转、展开、路由返回均可见；滚动中标题自然离开视口不算裁切 Bug，不要错误地把所有标题固定。
- 键盘能完成日期调整、刷新、选择焦点和打开任务；时区浮层关闭后焦点回到触发按钮。loading/回执通过状态区域通知，不因每次轮询重复打断。
- 保留 hover/focus/active/disabled 的差异，禁用操作提供原因。图标按钮有可访问名称，标题栏按钮不落入拖动区。
