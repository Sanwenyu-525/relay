---

你在 `D:/Develop/Relay-Agent` 工作。目标是把当前“人工基础闭环能运行，但模型使用链和 UI 尚未完成”的系统收敛到可实际试用的 Windows 应用。先读 AGENTS.md、CODEX_NEXT_STEP.md、docs/README.md、docs/testing/overall-acceptance-2026-09-28.md，再按需读契约、ADR-010、M01–M07、V1 范围、UI 交互/设计系统/token 与全部逐页提示词。所有解释用中文。

以当前代码和现场证据为准。仓库有未提交修改，先记录基准与差异，不覆盖、不回退他人工作，不复制重做已有功能。先复现问题再改最小范围；本提示词列出的是问题与验收出口，不是要求重写架构。

## 第一包：修正回归与启动/模型状态事实

1. 复现 A03：CLI 集成测试预期停在 32 条，migration 测试清单停在 39 条，当前有 42 条迁移。核实账本及迁移文件，保留完整性、SHA 和幂等断言，修正基线并跑定向/全量真实 PG 回归。
   同时处理 A09：控制优先级用例全量失败、定向通过。固定旧 START/批准/控制请求的提交顺序，检查 LOST 后先停机核对再 requeue 的流程；不得简单增加重试次数或删除断言掩盖问题。区分测试编排与生产逻辑缺陷。
   同时处理 A10：Skill 蓝图三项全量失败、文件独立 5/5 通过，检查共享数据库残留任务、Assist 领取身份、清理和连带失败；修复后必须全量复验，不能只交定向成绩。
   A11 网页导入全量统计多出一项 failed、定向 1/1 通过，调查全局 tick 与遗留任务。当前全量基准为 461 项：449 通过、9 失败、3 跳过；不能将修复后的定向成绩拼成全量通过。
2. 核实当前浏览器 API、桌面 API、Worker 各自的配置来源和版本；只报告 provider/model/脱敏来源/指纹，不输出密钥。现场浏览器已显示真实 Provider，不能继续默认“没有配置”。
3. 修复 test-desktop Start 覆盖 desktop.env 的路径。明确用户模型配置与运行时生成字段的 Owner，保证重启/重打包不丢配置。不能仅编辑 apps/api/.env 就声称桌面已配置。
4. 设置页明确区分“本机服务已连接”“模型已配置”“模型验证成功”“Worker 可执行”，不得用配置格式通过冒充网络成功。先完成本地可测部分。

出口：回归无未解释失败；重启保留配置、API/Worker 一致性有证据；现场信息与文档不再冲突。

## 第二包：完成真实模型使用闭环

先核对 M03 既定门槛与当前授权。若尚缺可靠性证据，完成本地 Mock/恢复检查；已有明确放行记录则按该范围执行，不重复请求许可。没有放行或缺少端点凭据时，只把真实外呼列为阻塞，继续第三包等独立工作，不绕过门槛。

已有 OpenAI 兼容适配器，不新建第二套 Runtime。先设计最小配置与验证入口，保持密钥只在受控服务端/宿主保存，不能放 localStorage 或回传明文。API/Worker 配置切换对在途 Run 的影响必须明确；批准不能隐式扩大工具权限。

获准真实调用后，用无项目资料的固定短文本先验证认证、端点、模型和流式协议；然后在专用测试项目中验证 Assist、Delegate、Review、产物、完成和重开。每个结论必须有可关联的 Run/调用/产物/版本记录。只有收到模型回复不算业务完成。

验证正常输出、401/403、429、超时、流中断、取消、结构化输出错误、缺少 usage，以及现有 SDK 参数/JSON 模式的兼容性。失败不能回退 Mock；UNKNOWN 保留原调用身份先核对；取消中不能提前显示已取消。设置页提供最近验证结果和可执行的错误指引，不能只显示开发变量名。

出口：真实端点端到端证据绑定实际配置与构建；未验证的第二 Provider、安装或异常组合单独保留，禁止扩大结论。

## 第三包：逐页完成 UI，而非继续补工程说明

沿用已有效果图、33 页面/状态映射与 token。先修共享问题，再逐页验收；不缩减为三张示例，不擅自改变整体视觉风格。业务契约不能直接充当用户文案。

优先处理：

- 新建项目/设置：Pack 当前组合以简明摘要呈现，历史版本、hash、协议详情可展开；去掉默认铺开造成的约 4039px 长页面。
- 项目列表/详情：下一步显示可读 Task 标题与入口；UUID/CAS/revision 留在详情，保留真实查询与失效处理。
- 任务页：合并紧凑筛选，避免 960×640 首屏几乎没有任务；消除搜索双边框，主要动作清晰。
- 知识页：修复“新建”按钮换行，统一中文标签、标题尺寸、空态和列表/阅读区比例。
- 今日、待审、运行、成果、Assist、连接：检查空态、loading、错误重试、来源、权限、暂停中/已暂停、接手、UNKNOWN 的真实状态，不能只做颜色和圆角。
- 核对阶段设置、确认事实、连接检测与筛选等入口的实际能力。只补 V1 已确认缺口，不顺带造深色主题、多语言、通用设置平台。

每个页面留下：对应 UI 编号/路由、数据模式、主要操作、空/错/处理中、截图、实际命令或查询、验证结论和剩余限制。检查 1280×800、960×640，以及真实 Windows 125%/150% 缩放、键盘焦点和长内容。fixture 美观不代表 live 页面完成。

## 第四包：性能、桌面与最终复验

测量冷启动、列表首反馈、委托到 Worker 领取、首段输出及取消反馈；记录环境、样本和分位数。当前约 1.09MB 主 JS 是检查线索，不是重写语言/引入 Redis 的理由；按测量结果决定页面懒加载或查询优化。

使用包含本轮修改的确切 EXE 和资源清单，验证启动→连接→真实业务→停止→重启恢复，补相关 UNKNOWN/权限撤销/重复提交/停止竞争证据。M07 安装升级、数据保留和回退单独验收。不可拿开发浏览器、旧截图或旧包 SHA 代替当前 Windows 结果。

每个大包完成后自检并复核，失败就修复复验，再进入依赖包；独立工作可继续。除非当前任务明确授权，不派发其他聊天或外部消息。不要因缺真实凭据停止全部本地整改，也不要把未跑项标为通过。

同步现有文档：阶段只在 CODEX_NEXT_STEP；UI 交互/视觉/token 分别归原事实源；API 改动写 Breaking Change，重要配置/持久化取舍才新增必要 ADR；更新验收记录和运行证据。运行 node scripts/check-docs.mjs。最终交付问题关闭表、文件范围、实际测试、确切桌面包、试用步骤与剩余阻塞，不用“全部完成”掩盖未验项。
