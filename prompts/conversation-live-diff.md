## 1. 交付目标与权威输入

实现真实后端数据到前端的闭环：聊天文件编辑记录旁的实时局部增删行数，以及输入框上方居中的会话总 diff。不是只做 UI、方案、模拟动画或验收报告。

产品唯一方案为[工作台 §34](../docs/frontend/workbench-design.md#34-会话局部与总-diff)，视觉为[设计系统 §9.15](../docs/frontend/design-system.md#915-会话-diff-的展示建议)，验收为[CD-01–20](../docs/testing/verification-plan.md#34-会话局部与总-diff-验收规格)。用户已明确选择 **B「本轮对话开始以来的净变化」**，禁止替换成 HEAD 到工作区、每次工具行数累加或每条消息重置。其他细则的「推荐默认」与「已确认」区分以方案为准，不谎称用户逐条确认。

开工按顺序读取：

1. `AGENTS.md`、`CODEX_NEXT_STEP.md`、`docs/README.md` 与统一功能验收表当前相关行。
2. 上述三份方案/视觉/验收主文档，以及后续路线 §12。
3. 契约包 01–04 中与事实 Owner、动作准入、执行恢复有关的部分，领域模型、运行架构、工具适配器相关段落；复用策略与 ADR-005。
4. 代码、当前未提交差异与既有测试。`git status` 和定向 `git diff` 核对共享工作树，不能把现在的文件行号或迁移号当固定事实。

本任务书规定执行顺序和检查入口，不复制产品规格。开发中发现冲突，先列「方案要求 → 源码事实 → 差异/影响 → 推荐处理」，修正需要修正的一侧并保留依据；不能为快速交付擅自降低已选语义，也不能静默改文档掩盖偏离。

## 3. 开发前核定最小工程契约

按对象与 Owner → 用例/短事务 → 版本/幂等/资源 → 持久化/恢复 → API/UI 的顺序核定，并将结论写入对应主文档后实施。

- 应用层是会话基线的唯一协调入口，存储职责留在既有 Repository/Integration 分层。模型参数流只提供可丢弃的显示预览；实际写仍走原 Gateway，前端不得直读磁盘或私自执行 Git。
- 先查现有不可变内容存储是否能容纳会话证据，以及权限、生命周期和清理是否适配；不合适则做有当前消费者的最小持久化，不滥用业务 Artifact/Task，也不创建通用快照平台。会话开始内容必须可恢复，不能仅存 hash 或事后首次触碰版本。
- 基线身份至少能核对会话、Workspace、受管资源及其 epoch、统计段和基线 revision；短事务发布唯一有效起点，目录扫描/模型等待不能进入长事务。失败/重启/重复请求不发布两个起点，不越过原实际目录资源排他。
- 冻结扫描范围及文件清单，定义单文件、文件数、总字节、时间/CPU、预览大小、轮询和正文返回上限；按实际项目测试给值，不随意整仓无界复制。二进制/超限/缺失和外部变化的完整性状态要可投影，不能只给一个貌似完整总数。
- 会话开始前失败就如实无基线，并沿方案维持既有聊天和执行能力；不因为统计故障丢掉用户消息，不事后补造原起点。只读统计失败不自动发起工具重试。
- 读取保留原可见性和能力边界；后台/重连刷新不能借自动轮询绕开 Gateway，或每次生成大量用户动作/审计。明确最小只读用例如何复用现有准入与授权、怎样限频，不能直接绕过 adapter 的过滤/路径校验。
- 接口需表达身份、比较基线、实际采样时间、单调 revision、各文件与总数、完整性/未知原因、临时预览与已落盘的区别；同一 revision 的总数、列表和正文一致。核定缓存/快照读取方式，防止点击展开时用新磁盘内容配旧统计。
- 预览临时持久化/传递优先沿已有跨 API/Worker 的预览机制，按原模型调用和工具身份隔离、限频及清理；不依赖同进程内存才能实时，也不要求重启恢复半截预览。切轮次、失权、取消、终态立即失效，迟到片段不得复活。
- 非破坏性扩展也要记录 HTTP `Breaking Change: No` 与旧客户端兼容；实际有破坏性变更则列明迁移/兼容策略。数据库有变更就重新检查 migration 空位，关联唯一性/约束、升级与回滚风险；不能改已应用迁移。
- 涉及新的持久化责任与恢复边界时，在现有架构专题中记录取舍，达到项目重要决策标准再补 ADR；本任务书不预先指定表名、端点、迁移号和依赖版本。

## 4. 实施工作包与出口

### W1：基线和净 diff 服务闭环

先写 CD-02/03/04/08 的业务红例，确认失败是缺少目标行为，不能用导入失败冒充红灯。建立真实会话起点，允许初始脏目录和未跟踪文件；计算原基线到当前允许范围的净差异，统一换行、空文本、无末尾换行及重命名规则。不要直接执行 `git diff HEAD --numstat` 后改名叫「本次对话」。

通过真实临时 Git 仓库与真实 PG 测试恢复、唯一发布、资源 epoch、目录切换与旧会话不可用，再接真实 HTTP/client。先完成服务与 client，再做 UI；不能只实现计数算法后宣布交付。后台扫描要有上限，不改用户 Git 状态，不在整个实际项目里做破坏性实验。

### W2：工具参数生成预览与实际结算

先用可控 Provider/模型端口分块输出工具调用，验证片段能在完整模型输出之前达到消费方。借鉴现有 SDK 的工具流合并机制；必要的上游定向研究按研究清单读本地缓存并记录确切路径/提交，不克隆第二套工程或搬入整套 runtime。

实现安全的增量提取/行差异预览，处理原始 JSON 字符串转义、Unicode 片段、路径晚到、多文件及交错工具调用，优先复用成熟解析能力；若引入依赖先核对必要性、维护和许可，不能为此写通用 JSON/编辑 DSL。没有可验证基线时不估数字，完整目标前不将剩余文件尾巴当删除。

预览和工具派发严格隔离；既有批准、baseline hash 校验、结果落库、UNKNOWN 核对均保留。已修改标记来自实际逐文件结果。总数只反映落盘；拒绝和取消清预览不加数，部分应用不把全 changeset 标成功。W2 出口为 CD-09–13 的真实流时序与结果状态反例通过。

### W3：两个 UI 位置、展开与刷新

局部行按原消息与模型/工具/动作/文件身份挂载；多次编辑同文件各有自己的局部历史。总入口在输入卡外上方居中，展示会话净数与文件数，可打开同一修订的文件列表与正文；基线时点和同期外部编辑说明可见。路径长、数字宽度变化不挤掉计数或发送/停止按钮。

复用事件提示后重读、单调 revision 与会话隔离；写入后立即刷新，当前活动会话低频有界补读人工/CLI 改动，重连/回前台补偿。不按 token 刷新整仓，不给两个位置各建独立会话基线；旧响应不能覆盖新数。

生成/待应用/已修改/失败/部分应用/待核对、加载/空/失权/缺基线/部分统计/刷新失败都按方案展示，首条/已有会话与无目录路径都有明确表现。新增数字直接切换并保持等宽数位，沿现有动效/颜色 token；不改 composer 的发送、附件、分点/润色、斜杠菜单、未保存保护或在途控制。

### W4：独立视角复查与真实环境

当前 Agent 换审查视角，对照产品规则逐项走 CD-01–20，不只检查实现自己生成的断言。至少实际跑过：

1. 相关纯算法/片段解析与状态单测、模型端口受控流用例。
2. 真实临时 Git 仓库，真实 PG/HTTP，包含服务重启与原会话继续执行；使用现有集成脚本并避免与共享工作树其他测试进程争抢数据库或 dist。
3. DTO/parse/client、聊天局部行/总入口、迟到响应与取消/失权/目录切换组件回归。
4. API 与前端类型检查、受影响构建；既有相关测试入口有 `git-adapter`、`file-write-frozen-diff`、`run-tool-call-projection`、`tool-loop`、`git-user-action`、`executionTrajectorySummary`、`runToolTrajectory`、`gitReadClient`，按改动选运行范围，不机械重跑无关全仓。
5. 浏览器主路径：初始脏目录→开始会话→分块生成预览→写入→总数更新→再次改同文件→恢复内容归零→刷新/断线重连→切会话；宽/窄视口确认总入口位置、展开、焦点与输入卡几何。
6. 可用且获准时做真实 Provider 工具流以及真实 Windows/WebView2 窗口，核对多 DPI/中文组词/数字更新。缺环境时完成可做部分并清楚保留未验收，不能用 Fake、headless 浏览器或截图代替真实 Provider/Windows 证据。

编制时包脚本为 API/workbench `pnpm typecheck`、workbench `pnpm build`、Vitest/Playwright 与 API 集成脚本；开工先核实实际命令与依赖环境，避免写出未执行的成绩。除专项对真实工具流的必要验证外，不增加模型、压力、成本或安装验收范围。

## 5. 防偏离规则、停止条件与文档

- 每个工作包的结果都要能映射工作台 §34 和 CD 场景；把差异列为「已满足／部分满足／无来源／外部阻塞」，不能把最终结果数字当实时预览通过。
- 推荐默认里的周期、上限等例行工程选择可在既有授权内合理确定并记录；不能把「整仓 HEAD 统计」「逐次相加」「只统计当前 Run」「延迟首次触碰基线」当简化实现擅自替代 B。
- 如必须把时间范围统计改为「只归因 Agent 修改」、取消预览或扩大读取范围，先说明需求差异、数据来源和影响，保留待决；不要静默实现再改方案追认。用户同期新指令优先，并将决定同步到唯一主文档。
- 发现共享热文件有不可安全合并的改动、原权限链无法支撑合法读取、旧历史无法重建或环境不能真实操作时，只暂停受阻部分，继续独立可做工作，不覆盖他人、不伪造起点/成功/验收。
- 同步受影响的工作台、设计系统、测试计划、必要架构/ADR/API/数据库；当前阶段仅更新 CODEX_NEXT_STEP，成绩只在统一功能验收表。README/路线图/变更记录/已知问题按实际影响检查，不为清单齐全新增重复文档。
- 执行 `node scripts/check-docs.mjs` 与本次受影响 diff 的空白检查，人工核对事实源、推荐/确认/实现边界、链接语义和方案偏离。开发记录只保留必要设计或重大故障根因，不追加全量逐轮日志。

最终用中文说明实际改动和可用路径、方案差异、CD 场景对应真实检查与结果、文档同步、未通过/未运行项。自动化、可控模型、真实 PG/HTTP/Git、浏览器、真实 Provider、Windows 分层报告；不把方案已写、模型返回、工具成功、Task 完成和用户验收混为一件事。
