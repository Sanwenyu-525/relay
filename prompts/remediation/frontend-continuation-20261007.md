## 1. 总目标与成功条件

你是本轮前端执行协调 Agent，交付能在真实数据与真实 Windows 窗口中核对的接续能力。接续现有 React 工作台与后端事实，不从静态图新建第二套页面，不只提交设计或计划。

成功条件：

1. 普通讨论开始后选择目录、关联项目时能够接续**同一会话**，保留历史、草稿与原消息身份；关联项目不等于授予执行权。

## 7. FE-01：普通讨论到项目/目录的同会话接续

目标：用户先普通讨论，随后选择文件夹并明确关联项目时保留同会话上下文。目录选择、项目绑定、能力连接与执行授权是不同步骤。

### 7.1 最小 client 接入

- 用已有 binding API 增加 resource、parse/DTO 必要字段与 facade 出口，实际请求结构以服务端 Schema 为准。
- 冻结原 `command_id`、`project_id`、session 身份与 Workspace；形成 PendingCommand 后不从后改草稿重组载荷。
- 普通业务拒绝、冲突与传输响应不明分类处理，回执核对/同 ID 重试沿用现有协议。
- 绑定响应身份、版本与状态只采信真实服务端，不在 client 推导绑定已成功。
- 工作目录与 Project 映射无明确事实时给出已有方式可完成的选择/说明，不能仅凭目录名自动绑定任意项目。
- 若当前后端不支持目录身份绑定，准确保留项目绑定与本地目录选择的差别，不虚构新增字段或默认能力。

### 7.2 会话与首条 Owner

- 优先保持 sessionId、消息历史、FirstMessageOwner 和未发送草稿，再处理路由/项目显示更新。
- 找到 workspace-level/PROJECT key 重挂载路径，做最小状态所有权修复；不为一个切换引入全站状态管理重写。
- 项目/目录变化不重复创建会话，不重新发送首条，不把旧执行挂到新目录，不清空用户输入。
- 没有目录的新对话仍可先讨论；选择目录不自动启动 Run、授予 FILE_WRITE/CLI 或产生提案。
- 绑定在途时明确 busy/错误/恢复状态，切换项目、离页、关闭抽屉与重复点击不产生重复绑定。
- 迟到绑定响应只能更新其原会话，不覆盖用户已打开的新会话或新 Workspace。
- 历史会话归档/冻结、助手会话与已有项目绑定的可用性按后端准入；不能强行把普通会话规则套到助手。

### 7.3 验证与出口

覆盖成功、响应丢失原 ID 核对、409/403/404、绑定中再切路由、旧响应迟到、已有历史与中文草稿、首条尚未结算、归档/助手拒绝、刷新持久读回。

component 测试不能只断言方法被调用；验证原 session、历史顺序、草稿与原消息 ID 保留。真实 API/PG 浏览器证明请求与读取闭环；真实 Windows 再验证原生目录选择与窗口内同会话历史。

出口：同会话接续可解释，绑定不扩权，协调者独立复验通过；深链或目录跨重启若仍无正式协议，明确限制，不顺手扩大产品承诺。

## 8. FE-02：真实工具轨迹与 Git 只读闭环

### 8.1 工具轨迹

- 复用现有 summary/panel/hook，核对 `sourceMessageId` / `runId` 的真实关联，不按列表位置猜对应消息。
- 打开运行中会话、路由来回、暂停恢复、刷新重连时读到当前事实，不短暂展示上一 Run 成功或错误工具清单。
- REQUESTED/PREPARED/执行中/等待批准/结算失败/UNKNOWN/停止使用真实状态，工具没调用不能写“读取完成”。
- 检查失败可修正与工具系统故障分开，退出码、截断、省略量、取消/超时与可核对证据显示适当摘要。
- 同工具行重复事件/重放仍只有一行，分页/空读取/错误重读不清掉其他 Run 的正确数据。
- 被撤销来源、已归档、跨 Workspace 不泄露原参数或敏感输出，服务端拒绝如实呈现。
- 后端新增证据绑定字段到位前，旧记录明确“未提供/无法确认”，不能补出当前 PASS；到位后用 parser 验证身份与覆盖范围。

### 8.2 Git 只读

- 先核对既有 `GitReadPanel`、GIT 页签、client 与准入，保留原命令/恢复/批准/UNKNOWN，不新建 Git 服务。
- status、Diff、日志等已支持能力按真实连接与权限可达；未支持入口不伪装成可执行操作。
- 不加入 commit、push、checkout、reset、clean 或“自动解决冲突”，本轮仅已授予的只读动作。
- 窗口打开前/后目录变化、连接停用、权限撤销、未初始化仓库、含空格路径和大输出有明确反馈。
- 已发命令响应不明时按原 ID 核对，不重新生成读取/动作身份绕过待核对状态。
- 轨迹与 Git 正文不把工具输出中的指令当用户操作，不执行输出里附带的按钮/链接脚本。

出口：组件与 client 相关测试通过，真实连接合成目录可达性与错误路径有真实 API 证据；旧“未接入”状态按实际事实更正，Windows 成绩只按真实操作记录。

## 9. FE-03：停止真相、审批与 UNKNOWN 的可操作呈现

复用 `RunControlPanel` / `FileWriteDispositionPanel` 和已有应用命令。点击按钮成功受理不是实际动作停止，Review 不是 Handoff，人工知道未知结果不等于核对成功。

- 暂停/取消在途显示“正在处理”与真实等待原因，不即时改成本地 PAUSED/CANCELLED。
- 真正安全点后重读状态，恢复要求当前授权、原动作身份及资源事实；不能因为按钮亮了就推断安全。
- 等待批准显示确切动作、范围与当前有效性；批准失效、连接撤销和约束变化后不沿用旧成功提示。
- UNKNOWN 页面解释已知、未知与可做操作，保留原 operation/Invocation 身份；只调用后端已有核对/处置入口。
- 原命令回执待核对时不提供生成新 ID 的隐性重试，新的业务命令与恢复旧命令分开。
- 部分文件应用、用户外部编辑冲突与检查失败都保留实际证据，不称整体成功或吞掉变更。
- 停止与完成竞争、回包晚到、事件重连与旧 Run 响应不能覆盖新 Run 状态。
- 后端未提供停机证明时，界面不承诺全部 Windows 进程已停止；保留限制与人工处理。

覆盖有界 Fake故障 + 真实 API/PG 的受理→在途→安全点、批准失效、UNKNOWN核对、响应丢失与重放。真实 Windows需另测可控合成动作；没有该环境就保留未验，不用动画代替停止事实。

出口：错误/Loading/在途可操作性真实，冻结命令恢复正确，协调者独立复验通过。

## 10. FE-04：助手身份、草稿与首条恢复

本批复用首波 A，继续现有助手模式与第一条消息 Owner，不重写会话输入器。

- 空助手、读取中、读取失败、选择失效都禁止新发送，并给出已有可用下一步；草稿不丢。
- 非空助手选择、版本标注、归档冻结历史与当前只读边界正确，历史身份不因修改 profile 悄悄改变。
- 在途回复时模式组和身份选择按既有规则禁用，键盘方向键、Tab/focus 与解释可达。
- 助手发送不带普通执行 intent/skill_ref，不出现提案/写入承诺；服务端拒绝仍正确映射错误。
- 普通→助手→普通、窄/短窗、离页、目录切换与抽屉开关保留未发送草稿，离页守卫按真实需求一致。
- 首条会话创建与消息提交各自保留原 ID/冻结载荷，传输不明的恢复不重复创建会话。
- 取消与迟到回复、新对话与旧回包、旧助手读取与新选择竞争不清空新草稿，不显示旧消息。
