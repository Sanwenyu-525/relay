# 长期项目协作差异化体验：分包开发与验收提示词

日期：2026-10-24。角色：总纲 §0.17 七个方向的统一开发入口，接续本轮已确认的成果守护、接手演练及试用验收细节。**本轮仅编制任务书，未启动代码、migration、模型调用或验收。用户实际下发后才执行指定包。** 不因本文存在改变在途任务或 N01→N02→N03 顺序。

产品事实归[总纲 §0.17](../Personal_Workflow_OS_Master_Spec.md#017-长期项目协作的差异化体验)，范围与依赖归[路线 §14](../docs/requirements/post-v1-roadmap.md#14-差异化体验的范围与推荐顺序)，交互归[工作台 §45](../docs/frontend/workbench-design.md#45-长期项目协作的差异化体验)及[§45.1](../docs/frontend/workbench-design.md#451-软件功能的试用反馈与返工)，目标检查归[测试计划 §42](../docs/testing/verification-plan.md#42-长期项目协作差异化体验的目标验收)。本文组织实施，不另维护产品事实或通过结论。

## 1. 可直接下发的总指令

在 D:/Develop/Relay-Agent 实施用户选定的本文件工作包；未指定包时先开展包 A 的事实核对，明确本次范围后再写代码，不默认一次开发七项。先读 AGENTS.md、CODEX_NEXT_STEP.md、统一功能验收表的相关行、上述所属主文档和目标文件 diff。受保护的并行改动保留，不自动 commit/push、不新建聊天、不默认派子代理。

目标是完成选定包的调查、必要代码修复与开发、真实数据/API 接线、相关测试、失败修复及文档同步，不只交方案或模拟卡片。先输出简短差距表：已有实现、可复用入口、真实缺口、未验证出口、产品待定项。已有能力不重做；工程选择在授权范围内自行完成；改变产品语义或需要额外权限的选择准备具体方案后澄清，仅暂停受影响部分。

建议分包 A→B→C，D1–D3 按用户范围接续；这是依赖建议，不是新增排期授权。单包实施不默认进入下一包。用户明确下发整组时，按依赖闭合后继续获准部分。

## 2. 复用入口与文件责任

下表是本次编制时核对到的候选入口，不表示相关完整能力已实现。执行时以当前代码和验收记录为准。

| 范围 | 已有候选入口 | 本包责任 |
|---|---|---|
| 变化影响、候选 | `apps/api/src/application/artifact-impact-checks.ts`、`artifact-impact-groups.ts`、`impact-group-selections.ts` | 延续已有关系与原写入 Owner，补确切基线、缺口、去重和恢复；不把模型推断变确定影响 |
| 验收与完成 | `completion-evidence-queries.ts`、`task-acceptance-materials.ts`、`task-acceptance-trials.ts`、`completion-commands.ts`、`review-decisions.ts`，均位于上述 application 目录 | 证据、认可、验证和业务完成分别沿原入口，不另造 Task/Run 状态机 |
| 决定复审 | `apps/api/src/application/decision-reviews.ts` | 先核对 register/prepare/resolve/list 现有链，缺失的呈现和接续增量才新增 |
| 会话与上下文 | `apps/api/src/application/assist-commands.ts`、`assist-runner.ts`，`apps/api/src/workflow/prompts/` | 沿已有请求、权限和运行时路由；接手演练不得继承原会话隐含答案 |
| 真实工作台 | `apps/workbench/src/views/`、`components/`、既有 API client | 先定位现有入口再定点修改，消费同一投影；不用 fixture 成果冒充实际产物或稳定预览 |

后端负责用例、事务、持久恢复及 API；前端负责真实入口、版本呈现和操作反馈。数据库 migration 编号实施前读取目录确定，不能复用历史编号。接口、表名、事件名和阈值在查完代码后设计，不把本文当作已有契约。

## 3. 公共工程出口

1. 按「对象与 Owner → 用例/事务 → 版本/幂等/执行权 → 持久化/恢复 → API/UI」冻结必要协议；需要新增 API 时记录 Breaking Change 与兼容，存储变化记录 migration、已有数据兼容及回滚风险。
2. 候选、提醒、演练、反馈及补齐请求须有稳定身份，明确项目/Workspace、来源、确切版本及实际覆盖范围；同一请求重放不重复建任务、计修复轮次或产生业务副作用。
3. 长耗时模型、工具、预览、人工等待不放入数据库长事务。启动、结果保存和应用之间重查权限、基线及原请求身份；迟到结果只保留其适用基准，不覆盖新事实。
4. 停止意图持久化，UNKNOWN 沿原动作核对，重启不绕过执行权与授权。生成中、读取不全、失败、取消、过期、冲突和回执未明分别显示；失败检查不改成通过。
5. 所有材料仅来自用户获准来源，模型外发服从现有授权；不从设计文本推导全仓扫描、自动截屏、录屏、外部窗口读取或新后台监控权限。

## 4. 包 A：成果有效性守护

实现总纲 §0.17.1 本轮确认的完整链，复用 N02 影响检查和已有验收证据入口，先核对实际覆盖范围，再补缺口：

- 连续修改归并来源，在准备验收、确认完成和重新接手时集中提醒；直接影响正在进行的验收则立即提示。仅消费已有获准变化来源，不另起全局轮询模型引擎。
- 展示确定受影响、可能受影响、尚未核对以及原结论的适用基线。没有关系记录不等于无影响；旧 PASS 保留历史，新版本不得继承批准。
- 在既有读取权限内核对并准备补验方案；明确“开始补验”才执行验证，不由此推导修复权限。需重开 Task 时沿原 ReopenTask 用例及相应明确决定。
- 补验失败汇总失败项、原因/未知和修复范围；用户明确授权修复后实现该范围内修复—复验。最多自动修复 3 轮，初次补验不计修复轮次；重复失败、无法验证、范围/需求或权限变化提前停止。计数持久化，重试/重启/换会话不重置，不以换模型或任务绕过。
- 对应当前基线的必要检查全部通过，原提醒标“已复验”并收起，变化与证据可追溯；人工待验、缺环境、未运行及未核对项不能跟随其他 PASS 一并关闭。结果与基线竞争时原结果只对原版本成立。

验收：DX-01、DX-07。构造“密码登录改为验证码登录”、连续多次变更、在途验收受影响、结果迟到、重启后第 3 轮上限、部分通过仍有人工检查等反例；证明没有自动撤销历史完成、静默修复或误关新提醒。

## 5. 包 B：项目接手演练与资料补齐

实现总纲 §0.17.2 已确认链：当前工作主线 → 无原会话上下文的只读推演 → 缺口/草案 → 明确补齐授权 → 自动新上下文复查一次。

- 默认读取当前任务及关联决定、成果、验证和恢复资料。主线不明确时澄清，不默认为整个项目扫描；报告实际读取范围和未读取部分。
- 新逻辑会话只接收授权项目资料及演练问题，不接收原聊天隐含答案。输出每项下一步、原因、验证方法和恢复位置的引用，区分未找到、无权、冲突、读取失败；不执行启动命令、测试，不接管任务。
- 按“阻碍当前接手／可稍后补充”排序，有事实依据才准备补齐草案；未知事实不猜填，冲突需明确判断。用户说“补齐这些资料”后复核版本/权限，只修改所属主文档，不创建另一份项目事实或顺带修代码。
- 写入效果与回执分别核对；部分写入或保存失败如实显示，不将写入成功等同演练通过。
- 补齐后自动复查一次，冻结更新后的资料基线。复查 Agent 不携带上次答案或补齐者的自报结果；回答完成后再对照两轮，给出已消除、遗留和新增缺口。复查不循环补写、不自动接管；失败、取消、额度不足及基线漂移保留未核对范围。

验收：DX-02、DX-07。预置缺启动说明、有效决定冲突、权限受限、资料存在但搜索未命中等样本；检查输入隔离、引用真实性、补齐前零项目写入、失权/基线变化不写、重复补齐不重复应用、重启不重复复查。Fake 只能证明协议；真实模型的接手质量另行验证。

## 6. 包 C：成果试用、反馈返工与用户验收

本包合并 §0.17.5 与 §0.17.7 的软件首场景，详细行为以工作台 §45.1 为准。接续[原证据任务书](evidence-and-investment.md)，不重做已存在的证据投影、计时及材料关联，也不把旧首片“只提供建议”当作本次新增执行链的完成出口。

- 从同一功能/需求进入确切成果版本与可体验入口，默认自由试用并提示必要检查。支持完整流程集中体验及单项入口，功能结果与整体流程结果分别记录。
- 自然语言反馈绑定实际体验版本；已有现场事实不反复要求填写。连续补充归原反馈，归属不明留在流程下调查，不强迫用户先找技术模块。
- 明确缺陷在原授权内修复，主观反馈先调查、给具体推荐改法，确认后执行；明确修改指令不普遍二次确认。新增需求/范围歧义沿原决定边界。
- 用户继续体验稳定旧版本，开发在独立工作副本产生新版本，用户主动切换。先证明环境与数据隔离能力，不能仅靠分支名承诺稳定运行。
- 兼容数据安全沿用，保留干净环境入口。结构变化/冲突先解释影响，保存含未提交输入的现场，再由用户选择转换或重新开始；无法保存暂停切换，转换不可用明确说明，不清空、不伪报成功。协议应覆盖切换失败、部分转换、重开和重复操作。
- 用户说“这版可以”时，记录确切版本和已体验范围的明确认可；列剩余必要检查、原因及入口，满足原完成条件后才正式完成。实质歧义就近澄清，新版本不继承认可；回执未明不显示已登记。
- 新提交展示逐项修复/未解决及真实证据，保留原反馈；迟到修复不能覆盖新要求。试用切换与文件回退分别处理，沿工作台 §27.3.6 的共享资源规则，不把查看旧版本当成恢复文件。

验收：DX-05、DX-07–10。真实浏览器/Windows 跑创建项目→任务→执行→成果→反馈→修复版→切换→部分认可→剩余检查路径，覆盖未提交表单、数据不兼容、保存/转换失败、当前版本变化及跨功能局部通过。真实预览条件不具备时如实列阻塞，不能交付仅模拟的“边试边修”。

## 7. 包 D：决定驱动与变更前调查

这些方向已纳入产品规划，细节未全部访谈确认；只在本包获准且范围核定后实施，工程常规选择自行完成，不能擅自冻结产品待定项。

| 子包 | 执行要求 | 验收 |
|---|---|---|
| D1 决策重审提醒 | 复用 `decision-reviews.ts` 与证据任务书第 2 批；只对已登记前提/假设变化准备候选，显示原决定、来源、变化和待判断事项。幂等归并，基线变化复核，不废止决定、不自动取消或执行 | DX-03、DX-07，及既有 EVI 相关项 |
| D2 修改前影响预演 | 对明确变更草案展示登记关系、推测和未核对范围，含在途工作。复用已有影响/需求 Owner，候选绑定确切基线；接受草案不修改活动执行契约、不授予执行权，应用按原入口再核对 | DX-04、DX-07，结合测试计划 §22 相关 FSC 项 |
| D3 围绕待决定事项组织工作 | 在现有统一待处理/项目摘要上展示决定、阻塞及可继续条件。排序只能依据真实依赖、截止时间和阻塞，未知不伪造紧迫性；同一决定合并引用，不合并不同批准。关闭/延后提醒不等于作出决定，不自动恢复执行 | DX-06、DX-07 |

D1/D2/D3 可独立下发，不以建立完整依赖图、通用 DAG、自动优先级系统或新的后台引擎为前提。通用软件协作 §0.10 未细化部分先形成差距与范围建议，不把本包扩大为全部未来研发平台。

## 8. 验证、独立复核与停止条件

先针对真实缺口建立可复现失败，再修改并复跑；已有实现先证明当前行为，避免为指标新增镜像实现的测试。按实际影响选择：规则单测，事务/revision/唯一性/幂等用真实 PG/HTTP，结果保存/回执丢失/停止与完成竞争用故障点，UI 用组件与真实浏览器，最终路径用 Windows 实窗。

已核对的检查入口：`pnpm --filter @relay-agent/api run typecheck`、API 的 `test:integration`（先读现有 PowerShell runner 参数再选套件）、`pnpm --dir apps/workbench run typecheck`、工作台 `test`/`test:browser`。不凭空写不存在的测试文件或 fixture 参数。选择包相关检查，失败修复后再复验，不默认全仓压力测试或批量真实模型调用。

每个大包需未参与实现者独立验收：核对同一版本、复跑核心成功与失败路径，不能把执行者自检重命名为独立验收。获准派发时显式使用 `gpt-6.1-sol`，交代文件责任、共享工作区与不得回退他人改动；不能派发时如实标“独立验收未做”，不伪造。每包实际证据只写统一功能验收表，不能直接给本文件目标标通过。

缺真实权限/Provider/Windows 条件时完成可独立的实现和测试，列出未验出口；仅依赖未知身份、未知外部效果或产品范围决定的动作停止。先核对 UNKNOWN，不换请求 ID 重试；保留可恢复现场。

同步受影响的需求、架构、API、数据库、交互与测试主文档，当前阶段只归 CODEX_NEXT_STEP。运行 `node scripts/check-docs.mjs`；文档检查不能代替运行验收。编制当日全仓存在 25 项缺失历史文件链接，执行时重新核对，不抄成永久例外。

交付：用户能完成的路径、复用和新增文件、当前代码基准、实际命令与证据、独立验收结论、文档同步、未验边界和下一包前置。后端完成且按用户要求交付前端任务书时，引用真实接口/错误/状态和现有组件范围，不把提示词交付算前端实现。
