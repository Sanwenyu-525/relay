## 4. 必须闭合的交互

1. 工作详情标题、关闭、进展/成果/记录三页签 active/hover/focus 清楚。实现 tablist、tab、tabpanel 关联及 roving tabindex，方向键和 Home/End 可操作。
2. 进展只显示实际任务、Run、步骤和原因。已结束步骤 N/M 是合法统计，明确它是步骤统计，不把它当成业务完成或有效验证比例。
3. 成果清单只列已有产物。验收条件不是成果文件；无产物明确空态，读取失败明确错误和重读，不能误报空态。
4. 点真实成果时携带 task/artifact/version 确切身份，读取既有版本正文接口。列表、正文分别有 Loading/Error/Empty；正文失败不转换成“示例内容”或“请去别处查看”的假正文。
5. 深预览显示文件名、版本、来源、确切版本 ID、必要元数据和 Markdown。版本来自服务端；当前最新版本不自动继承历史版本的接受状态。无验证数据则如实未提供。
6. 返回恢复成果页和合理焦点；关闭回到打开入口。任务 A 切 B 时立即隐藏 A 的正文，异步晚到响应不能污染 B；同任务普通刷新不应随意关闭预览。
7. 记录展示真实步骤、原因和来源，不编造工具活动、Token、费用、检查回执、权限或完成凭据。
8. 聊天与任务切换保留原能力。聊天＋工作详情不再挤成聊天/成果/详情三块窄内容列；通过现有布局入口按需打开成果和判断。保留组件挂载和未保存草稿，不因视觉切换丢输入。
9. Run=RUNNING 且无暂停回执时，待判断提示不能声称“Agent 已暂停”。判断入口依然可达；等待判断、请求暂停与已暂停分开。

业务红线：模型回复结束、Run COMPLETED、检查通过、人工接受、Task 正式完成分别成立；UNKNOWN 按原动作核对，不制造重试身份；控制请求受理不等于停止/接手；完成凭据只能读取原用例结果。没有真实 diff 数据源，不造“变更”页的假差异。

## 5. 验收矩阵

| 场景 | 通过条件 |
|---|---|
| 1440×900、1280×800 聊天＋详情 | 消息与输入可读，无四栏挤压、主要操作不截断 |
| 1100、900、768、767、390 宽 | 无整页横向溢出，详情/抽屉可关闭，输入与发送可访问 |
| 长标题、长路径 | 换行或省略合理，完整值有适当入口，不推走关闭键 |
| 键盘页签 | 方向键/Home/End、选中状态、panel 关联及焦点正确 |
| 成果非空 | 真正产物可点击，版本正文和来源一致 |
| 最新未接受＋历史已接受 | 只在确切被接受的版本上展示接受事实 |
| 无成果 | 显示空态，不把 criteria 当文件 |
| 清单失败、正文失败 | 明确失败、能重读，无假正文与假空态 |
| A→B/旧请求晚到 | A 的文件不串入 B，旧异步结果被忽略 |
| 待判断但 Run 运行中 | 不声称已暂停，原判断入口可达 |
| 原有编辑、草稿、控制、判断 | 沿原入口与 Owner 操作，视觉收纳不丢状态 |
| 代表页面回归 | projects/tasks/knowledge 无本轮共享样式退化 |

主 Agent 用内置 Browser 对照相同视口与状态的原型和实现，打开实际截图逐项判断字体、间距、色彩、资产、文案。P0/P1/P2 修复后复验；P3 可作为后续说明。原型演示文案替换为真实事实、对比度修正、既有壳导航和双视图属于应注明的产品差异，不强行复制演示数据。
