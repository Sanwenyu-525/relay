## 1. 直接执行指令

在 D:/Develop/Relay-Agent 负责用户选定包的调查、必要协议、实际代码开发/修复、持久化与真实入口、测试和文档。先读 AGENTS.md、CODEX_NEXT_STEP、相关验收行、上述主文档与 git status/目标 diff；默认当前 Agent 单独执行，不新建聊天、不自动 commit/push，保护并行工作。

核对现有助手、人设、主子会话、Context/记忆、模型配置、Task/Run、PG Worker、调度、控制与桌面生命周期，列出复用、缺口及未验边界。`apps/api/src/application/assistant-profile-commands.ts`、`assistant-readonly-round.ts`、`assist-session-controls.ts`、`assist-goals.ts`、`scheduled-tasks.ts`、`apps/api/src/worker/` 和 `apps/desktop/` 只是候选入口，不表示长期成员、消息和唤醒已经实现。不重做已有链，也不把只读助手升级为可写成员。

单包授权只执行本包；整组授权按 A→B→C→D→E 依赖接续。缺外部共享领取时可先完成不依赖它的内置成员部分，外部端保持未验，不伪造。常规可逆工程设计自行完成，真正改变产品承诺的未决点给方案并定向澄清。

## 2. 固定边界

- 项目级稳定成员、角色模板、会话与实际运行分开；按需添加，不自动建齐团队或自行增员，不跨项目路由。
- 项目协调成员在明确授权范围内调查、拆分、分派、处理依赖与汇总；新增需求、扩大范围/权限、放宽验收和未解决争议转人工，不凭私聊或投票变更有效事实。
- 内置与外部身份可持续，外部只走本机 API/MCP 主动领取，离线等待；不直接启动外部工具，不声称可强停其进程。
- 不新增项目、成员或团队累计费用、时长、轮数、调用次数配额。实际消耗持续记录，未知不补零；现有服务商限额、单请求技术约束、暂停/撤权、默认三轮返工转人工、原临时子委派槽位与故障重试仍有效，不能换身份绕过。
- 事件唤醒加定期巡检，没工作等待，不持续调用模型制造工作。关闭窗口本机继续，明确退出或关机停止；重启先核对原授权、执行权、目录及 UNKNOWN。不新增系统服务、云端或关机运行承诺。
- 保持 React/Tauri、TypeScript/PostgreSQL/Kysely 与原 LangGraph/PG 边界；成员协调不是第二 Workflow、数据库或完成 Owner。

## 3. 包 A：稳定身份、职责、授权与模型配置

先核定成员归属、协调者指定/更换、模板与实例、内置/外部运行方式、停用/归档/恢复及原会话兼容。定义成员配置修订及其对在途执行的效力，任务与资源的原排他关系不因换成员或模型重置。

按成员配置模型，默认继承项目设置；模型、角色与权限分别保存/校验。模型不可用如实报告，只用用户配置的备用项，不静默降级。外部真实执行者身份和成员映射要可信，不能仅凭自报名称。

在所属主文档冻结 API/数据最小协议后继续实现服务端、迁移与客户端接线。migration 编号现场分配，记录 Breaking Change、已有助手/会话兼容与回滚风险，不提前建立无调用方的通用组织系统。

验收 PT-01、PT-07–08：重开身份不变、模板复用但记录隔离、跨项目/撤权拒绝、停用后迟到执行、配置漂移和运行方式更换不重叠取得执行权。

## 4. 包 B：私聊、群聊、共享事实与交接

冻结成员与单聊/群聊的关联、消息身份、接收者、投递/消费/失败重试、留存与可读范围。指定成员接收，未指定由协调者接住并按需邀请；不默认激活全员。按原请求身份去重，保存消息来源及实际处理结果。

共享需求、决定、任务、产物和证据等原事实，个人记忆和推测不自动升格为项目结论。交接携带目标、确切基线、当前结果、依据、未决和下一动作；跨会话读取需授权，不把所有成员聊天拼进每轮 Context。记忆的召回、纠正与失效沿原模块核定，不建第二记忆库。

冻结讨论结束与无进展处理：同一事实、互相回应或重复事件不得形成无限唤醒链。私聊改变范围或承诺时关联原来源，转原有效决定入口，不能隐藏在某成员摘要里。

验收 PT-02–04、PT-11：重复/乱序投递、失败恢复、读取失权、私聊隔离、无新证据的讨论终止及未指定接收者。真实 Provider 的语义质量另测，Fake 只证明输入/消息协议。

## 5. 包 C：范围内工作推进与外部成员

协调者复用事项/Task/Run 应用用例完成范围内拆分、领取/分派、依赖处理与交接。每次准入重查授权、当前任务/条件版本、实际目录与原执行权；群聊消息不能直接写 DONE/PASS 或绕过权限。

外部部分复用共享任务包的身份/领取代次、worktree/确切提交、独立验收、三轮返工、人工批准及集成回归；包 A/B 成员身份本身不证明该协议已完成。新成员和新运行端不能抢占仍可能写入的旧进程。

保留实际调用、消耗来源和未知值；移除或避开误套入团队的额外累计配额，但不删除旧 N06 的固定任务链预算契约，也不削弱单次安全边界。服务商限额/恢复识别依据实施前核定，不把未知当无限或已耗尽。

验收 PT-03、PT-07、PT-09–10 与相关 ES：多人重复领取、同根跨 Task、条件变化、暂停和完成竞争、三轮上限、外部断联与额度未知，不以模型生成了计划就算工作启动。

## 6. 包 D：事件、巡检与真实生命周期恢复

复用原 PG/Worker 与现有调度入口，先冻结事件/巡检合并、持久消费身份、并发准入、巡检间隔、控制代次、额度等待与恢复条件，不新增通用调度引擎或靠前端循环推进。

完成、退回、依赖解除等获准事件触发必要工作；重复事件、并发巡检及重启不得重复创建 Task/Run 或多次领取。无可推进工作只等待；取消、撤权、暂停后不发起新工作，PAUSING 与 PAUSED 不混淆。

明确退出的在途处理与桌面子进程停止协议，网络/CLI/模型等待不放入业务长事务。真实验证关闭窗口仍推进、明确退出不再发起新工作，以及重启先核对原外部效果再接续。外部进程不受宿主退出自动证明停止。

验收 PT-05–06、PT-09–10：双事件/巡检竞争、崩溃落库前后、回执丢失、外部效果未知、权限撤销、额度耗尽/恢复。单元模拟退出不能替代真实 Windows 进程证据。

## 7. 包 E：私聊、群聊、概览与完整小功能

工作台连接相同项目、成员、任务与证据投影，展示真正的在线/离线/等待、阻塞、决定、已请求停止/已停止及消耗未知；服务端当前动作决定按钮准入，聊天和概览不维护第二份状态。

关键决定、风险、阻塞及成果需批准时通知，同一事实合并、不重复打扰，普通交流可展开追溯。已读、关闭提醒不修改 Review、Task 或执行权。

按 PT-11–12 跑一个真实小功能跨需求、设计、开发、独立验收、人工批准与集成回归，覆盖不同会话、关闭窗口与重启。内置、外部、真实 Provider、浏览器、Windows/安装各自报告，成员数量和一次演示不证明长期收益。

## 8. 验证与交付出口

按实际影响建立失败反例再开发/修复。规则用单测，消息/领取/revision/唯一性/幂等用真实 PG/HTTP，唤醒/结果保存/控制竞争用可控故障点，UI/生命周期用真实浏览器与 Windows。先读项目 scripts 再选定向套件，修复后复验，不删除失败检查，不把静态类型绿色当完整交付。

大包需未参与实现者独立验收；获准派发时显式 `gpt-6.1-sol`、明确文件责任与验收条件、共享工作区保护要求，不降级模型。未做独立验收就明确未做，不能把自检改名。缺 Provider/外部环境/Windows 时完成独立部分，保留未验出口。

同步需求、架构、必要 ADR、API/数据库兼容与迁移、交互及测试，阶段只归 CODEX_NEXT_STEP，运行结果只归统一功能验收表。运行 `node scripts/check-docs.mjs`。交付实际路径、代码范围、必要命令和证据、独立验收、文档及剩余限制；不为普通过程新增逐轮报告。
