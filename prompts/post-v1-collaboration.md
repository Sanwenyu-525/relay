## 公共执行契约

每段提示词均须连同本节阅读；后续分派只选一个包及一个明确切片，不一次实现全部远期目录。

1. 先读 AGENTS、CODEX_NEXT_STEP、docs/README、prompts/README、后续路线对应条目、domain-model 第 11 节、ADR-013、verification-plan 第 14 节和涉及的原主文档。核对当前用户范围、依赖证据和未提交改动，不重做已交付部分、不覆盖其他工作。
2. 对照实际代码列出复用入口、缺口、本次文件/模块所有权、待定策略和成功标准。仓库路径仅作定位线索，须核对实际文件；纯规划不冒充代码审查或执行验证。
3. 实现前按“对象与 Owner → 用例/事务 → 版本/幂等/执行权 → 持久化/恢复 → API/UI”冻结本片设计。不可推断的权限、预算、恢复、通知和保留决策先定向讨论；只阻塞依赖它的工作。
4. 研究相关本地上游机制，遵循复用策略。新增依赖前核验正式发布、许可与兼容；没有需求/测量证据不增加服务、队列或通用框架，不编造已读研究结果。
5. 复用既有命令、回执、Task/Run 状态和 Gateway。提案、调度、Skill 或模型不能直接写业务表；UNKNOWN 保留原动作身份核对。UI 消费原 token，新增页面设计先做方向评审，不由提示词擅自重做视觉。
6. API/数据库变化先写所属契约与 Breaking Change、兼容/迁移/回滚风险；迁移只追加。核心持久化/竞争用真实 PG；恢复用可控失败点；用户路径用真实 API 和 Windows。Mock、浏览器、开发自检不能替代独立或安装验收。
7. 交付“条目 → 实际变更 → 确切基准/证据 → 未覆盖项”，并给出 READY_FOR_ACCEPTANCE 或具体阻塞。协调侧独立复验后才可进入依赖包，已获明确调整的顺序以用户为准；不得自行声称独立验收通过。
8. 同步受影响主文档与 CODEX_NEXT_STEP，不复制第二套进度；运行 node scripts/check-docs.mjs。保持当前模型设置，不依据旧提示词固定模型；未获明确委派不启动子代理，不自动 push/发布/外发资料。
