# 项目事项与外部 Agent 共享任务：开发与验收提示词

## 1. 直接执行指令与事实核对

在 D:/Develop/Relay-Agent 工作，读取 AGENTS.md、CODEX_NEXT_STEP、统一功能验收表相关行、上述主文档与当前目标文件 diff。按用户指定的包完成调查、协议设计、代码开发/修复、测试、真实入口与文档；不只生成报告。不自动 commit/push、不新建聊天，默认当前 Agent 完成；保护所有并行改动。

先核对已有 Task/Run、Delegate、权限、资源、成果/证据、Review、完成及 Git 接入能力。候选入口包括 `apps/api/src/application/delegate-task.ts`、`task-commands.ts`、`review-decisions.ts`、`completion-commands.ts` 和 `apps/workbench/src/views/`；实际接线必须继续沿调用链查证。事项 Owner、外部执行映射及领取协议不可只凭名字假设已存在。列明可复用、缺失和未验收部分，不重建原状态机。

首版在 Relay 自身新事项试运行；在可用且用户明确启用之前，当前登记处仍以禅道接入文档为准。旧事项继续在禅道，本文不授权建单、自动导入、同步关闭或迁移。

## 2. 包 A：冻结必要协议并实现事项与领取

工程设计是获准实施的一部分，设计完继续实现，不把所有常规字段选择推回给用户；仅真正改变产品承诺/权限的选择定向澄清。

| 协议面 | 必须冻结并落实的条件 |
|---|---|
| 事项事实 | 明确需求/Bug 正文、来源、条件版本与 Task 关系的唯一 Owner，优先扩展真实已有对象；多 Task 事项有必需集合与组合完成条件，不因一个 Task 完成就关闭 |
| 身份与权限 | 本机身份发放/撤销、项目/角色资格、实际执行者关联及审计；不能信客户端自报角色，开发者不能仅换身份领取自己的独立验收 |
| 原子领取 | 确认范围后才准入；资格、任务排他、领取代次和实际目录资源排他在同一必要短事务核对。重复领取与回执查回有稳定身份，不重复授执行权 |
| 运行兼容 | 外部执行绑定原 Task/Workflow 与领取代次；明确现有 Run 机制如何适配，不绕过生命周期建第二个外部完成状态机 |
| 失联与接手 | 心跳超时只记失联待核对；核实旧进程停止、现有改动和外部效果后才接手。租约过期不释放目录，迟到旧结果不得推进新代次 |
| 版本与恢复 | 需求/条件变化保留历史，受影响执行待核对；沿用或切换范围要有明确决定。重开不自动执行，原 PASS/批准不能继承 |

新增 API 明确 Breaking Change/旧客户端兼容；migration 实际编号现场分配，记录升级、已有数据和回滚风险。逻辑边界不强制拆服务或引入新数据库。

交付服务端事项登记/范围确认、可领取投影、指定任务或下一条符合资格任务的同一领取入口，最小真实客户端接线。拒绝原因可读，排队/无在线执行者显示等待而非运行。

验收 ES-02–04、ES-07、ES-09–10：真实 PG/HTTP 并发仅一人领取、跨 Task 同根冲突、撤权竞争、失联重启、旧领取迟到和重复命令。检查成功和提交回执丢失等窗口，不用内存锁替代持久约束。

## 3. 包 B：提交、独立验收与返工

开发结果必须绑定确切提交/不可变变更快照、执行基准、条件与证据。分支名、可变目录或模型一句“完成”都不能替代冻结版本。worktree 的创建、所有权、保留与清理先检查现有机制并冻结协议，未经核对的工作副本不能删除。

外部工具通过同一应用入口提交；结果保存、校验、独立验收及接受/退回分别可恢复。Verification 记录验证事实，Review 记录判断；开发者自检不冒充独立验收。实际独立性未知时显示未知，不以不同账户名自证。

退回带失败项、证据、被验版本和下一步，原开发者再次连接并领取后返工；Relay 不直接唤起离线外部工具。默认最多 3 轮、项目可调整，重复提交/重放不重复计数；调整对在途执行的效力先冻结。业务失败与基础设施故障分别记录，不能为绕过上限重建身份或任务。

验收 ES-05–07、ES-09：验收中目录变化、旧条件、缺证据、工具故障、重复退回、争议转人工及到达上限。服务端必须拒绝越权和过期版本，不能只禁用前端按钮。

## 4. 包 C：人工批准、集成回归与完成

独立验收通过后，用户批准确切变更及目标基准，再按授权执行集成。集成前重查目标分支/工作区基线、原批准和当前权限；目标漂移、冲突、集成失败和回归失败均保持真实待处理，不提前完成事项。

Git 与业务数据库不假装原子：持久化动作身份、准入与完成回执，网络/CLI 不进入数据库长事务。Git 成功但结果落库失败时记 UNKNOWN，先核对原提交/效果再接续；不得换动作 ID 或再次合并碰运气。所有必要回归及事实满足后沿原应用完成用例提交审计与当前状态，事项汇总完整关联条件。

验收 ES-01、ES-08：真实一次性 Git 仓库覆盖批准后漂移、冲突、Git 成功落库失败、回执丢失、回归失败、重复完成和多 Task 部分完成。不得在用户主工作树中测试破坏性故障。

## 5. 包 D：API/MCP 与项目事项用户闭环

本机 API 和 MCP 只是包 A–C 同一应用用例的两种入口，先冻结并复用身份/请求/回执契约；不另建 MCP 数据库或直接 SQL 写入。选择传输方式前查现有接入与成熟机制，新增依赖确有必要再引入。

项目内事项详情、自然语言登记/分派/查询/处理连接同一投影；表单是详细编辑入口。显示角色、执行者、worktree、结果版本、返工原因、失联、人工决定、集成和回归真实状态，操作来源以服务端当前准入为准。

无在线领取者保持等待；应用接口权限不等于外部进程文件/费用隔离，取消不宣称已有修改被撤销。凭据只通过获准的安全配置来源，不能写入正文、交接、日志或代码。

按 ES-11–12，用不同外部执行者实际完成一项需求和一项 Bug，从范围确认到独立验收、批准、集成与业务完成。外部环境不可用时保留未验出口，不以 curl/Mock 或内部子代理替代真实外部协作证据；API、MCP 客户端、不同外部 Agent、浏览器、Windows 分别报告。

## 6. 完成出口与停止条件

每包先写核心失败反例再实现/修复，必要单测、真实 PG/HTTP、进程/恢复与真实 Git 检查按影响运行，修复后针对问题复验。大包需要未参与实现者独立验收，实际派发显式 `gpt-6.1-sol` 并告知文件责任、共享工作区及不得回退他人修改；未做就标未做，不把自检改称独立验收。

现有检查入口先读包内 scripts：API `typecheck`、`test:integration` 的 PowerShell runner，工作台 `typecheck`、`test`、`test:browser`；不要假设 runner 参数或编造通过记录。缺真实 Provider/外部 Agent/Windows 权限时完成不依赖部分并列未验，UNKNOWN/失权/争议不盲重试。

默认只做选定包，明确整组授权时才按依赖接续。远程、标准 A2A、直接启动外部工具、通用多 Agent Router、完整禅道后台和双向同步不属于本首版。

更新受影响的主文档、API、数据库、测试与交互；进度只在 CODEX_NEXT_STEP，实际成绩只在统一功能验收表。运行 `node scripts/check-docs.mjs`，交付实际路径、文件、命令/证据、独立验收、兼容风险及剩余限制，不为普通测试另写重复报告。
