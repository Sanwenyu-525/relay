## 3. 固定产品边界

下列选择已确认，不重新组织访谈：

1. 首片针对单个 Agent 交付 Task，解决证据分散；默认核对已登记验收条件。AI 查漏只在明确请求时开展，其建议不自动改验收条件。
2. 主动选择外部纯文本日志、测试输出、Markdown；首片不扫描全仓或其他 Agent，不扩展 PDF、Word、截图/OCR、Connector 或任意 Shell。
3. 关联不完整的材料允许留存并标待核实；收录、关联、正式验证、人工接受和业务完成分别表达。
4. Task、验收修订、条件、被测版本与确切材料版本须可核对。用户声明的被测身份不自动成为可信执行证明，导入不产生 CheckResult/PASS。
5. 未运行、失败、工具故障、缺失、过期、待核实分别显示；历史 Trace 匹配不等于当前适用，单项 PASS 不等于组合通过。
6. 交付消息下摘要加展开，Task 详情同一投影；失败、UNKNOWN、材料不可读、冲突和必要决定不能隐藏。
7. 首片只有证据汇总、补救建议与原入口，不新建完整执行检查闭环；已有补救执行仍服从原权限、冻结配置、预算、动作身份和完成路径。
8. 主指标为找证据耗时，辅助为收到交付至接受或拒绝的总耗时。准备/关联成本单独记录并计入总耗时，未采集不补零。
9. 计时只测找证据，支持开始、结束、手动暂停和继续，保留有效计时、暂停记录与总经过时间；其他时间可一句话补录，不做多阶段自动计时。
10. 相近任务与材料规模交替使用原流程和新视图，保留失败及熟悉效应。基线后、正式对比前冻结相对降幅、样本和比较口径，当前没有已确认百分比。
11. 漏验或把旧证据当当前结果不能算成功。准备增加但查找节省更多可能有净收益，整体省时须按计入准备成本后的总耗时判断。
12. 正式假设管理不成为首片试用前置；其余能力遵循后续批次，不能为了先做计时而创建通用假设、事件或计划平台。

| 试用与计时 | 区分原流程/新视图及样本身份；开始/暂停/继续/结束的合法转换、权威时间来源、有效/暂停/总经过时间、重复提交、刷新和中断恢复；不引入第二套执行控制 |

| 一致性与恢复 | revision/CAS、命令身份、同 ID 异载荷、权限复核、短事务及审计；重复导入/关联/计时不得重复计数，结果未知先核对原请求，不换 ID 重发 |
| API/数据库与兼容 | 实际需要的请求/响应、错误/回执和查询范围，Breaking Change、migration、升级与回滚；不预造通用端点、字段或空表 |
