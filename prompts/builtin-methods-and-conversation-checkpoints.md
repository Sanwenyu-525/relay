2. 对已结束的旧讨论/工具结果，在完成节点或增长预算到达时生成接续摘要。

十、阶段 D：消息发送前可恢复文件基线

先解决基线真实性，后写撤回按钮。明确受管工作资源和合法读取范围，在用户消息发送前建立与该消息可信关联的可恢复基线，任何相关执行开始前具备可核对来源。模型生成前、首次准备写动作或点击撤回时的磁盘状态不能冒充该时点。

选择可验证的最小文件快照方案，证明一致性和并发行为，不要求数据库/磁盘假原子。需要真实旧字节或不可变字节引用、文件存在性、路径和资源身份、内容摘要及必要来源版本。只存 hash、git HEAD、有限文本 diff 或可变硬链接不够；不要求目录必须是 Git 仓库，也不操作用户 index/分支来制造回退点。

不全盘快照，不越出合法受管范围；对基线捕获期间已有 Writer/人工变化定义可检测的边界和失败语义，不能采集混合时点然后报告一致快照。未知后续修改的恢复不能凭模型判断安全。

实际支持范围内覆盖 CREATE/MODIFY/DELETE、文本/二进制、已核定大文件和路径边界。目录成员变化、未跟踪文件、编码/换行、Windows 大小写/别名/重解析点及资源根变化按已有文件规则核对。快照存放受保护区域，恢复不把应用数据库、凭据或不可变 Artifact 历史一起覆盖。

保留预算、清理/失权/删除和引用完整性必须可检查：被历史/在途恢复引用的基线不能随意清理，已经不可用的旧消息诚实标不可恢复；不要从当前内容补造旧文件，也不以所有旧消息都可撤回宣称上线能力。

明确本会话消息到 Task/Run/Operation/Invocation/ChangeSet 的持续来源链。检查程序或脚本产生的文件副作用若在承诺恢复范围内，必须有真实归因和基线支持；不能只逆转 FILE_WRITE 记录、遗漏 run_check 产生的文件，再说“全部恢复”。不能归因的后续变化按冲突/支持边界处理。

阶段出口：发送前/首写时不同的反例通过；真实字节/存在性恢复证据完整，资源身份/权限/存储预算/旧消息缺失基线可正确处理。有限文本差异账本不能冒充此阶段完成。

十一、阶段 E：安全停写、文件恢复和 Task 重开

点击用户消息下按钮，持久保存恢复请求和原目标身份，冻结该条及后续本会话的关联范围。重复点击/刷新/响应丢失复用原请求；不能每次点出一套新恢复动作。

先阻止相关排队和后续写入，持久化控制并安全停止；按 Task 排他和同实际目录资源排他分别核对。不能只中止最新模型调用，遗漏旧 Run、已准备动作或迟到进程。租约过期不证明进程结束；保持原 Operation/Invocation 处理 UNKNOWN。

恢复之前整体预检目标、权限、基线、当前文件和可得来源版本；动作准入/每个恢复安全点再次核对。人工、其他 Task/会话或来源不明的后续修改不覆盖，不用 Git reset --hard/clean/checkout 一口气回退目录。

正常路径一次点击完成原意图，不再让用户输入 /undo 文件或每个文件重复确认。若冲突需要改变范围，展示确切新范围和影响并取得具体决定；不能把原整组意图当成自动缩水方案的批准。

恢复是新的受控文件动作，经原 Gateway/Adapter 和当前权限，具有独立身份、冻结参数和逐项回执；历史成功写入保持原证据，不改成未发生。顺序、资源锁和窗口需防止旧 Writer 再改刚恢复文件。

真实保存“停止中/核对中/恢复中/已恢复/冲突/失败/部分结果”的合法事实，具体枚举由协议确定。恢复某文件之后回执保存前崩溃，重启核对原动作与当前真实字节，不盲目再次写。FS 与 DB 不原子，部分结果在折叠摘要里可见。

若确实撤销当前完成成果，通过原 ReopenTask 版本核对、新验收周期和审计重开受影响 DONE；保留历史 Completion/Acceptance/Verification/ArtifactVersion。仅历史 Artifact 仍存在不证明当前目录满足新周期条件，旧 PASS 不继承，不自动执行下一 Run。

文件恢复和 Task 重开分别结算：文件恢复成功而重开 revision 冲突时，显示实际恢复+待处理任务，保留原重开命令核对，不把它们伪装为同一原子事务。阶段/计划等无关业务变化不随按钮一起撤回。

阶段出口：消息 A/B 例、CREATE/MODIFY/DELETE、后续人工/其他任务冲突、在途停止、旧 Writer 迟到、UNKNOWN、重复点击、断线/崩溃和重开失败反例均有真实文件/数据库证据。按钮变灰或 UI 显示已恢复不算通过。

- 隔离桌面：powershell -NoProfile -ExecutionPolicy Bypass -File apps/desktop/scripts/start-acceptance-session.ps1 -InstallGraph -ReleaseRoot "D:/Develop/Relay-Agent/test-release"

以上是已存在回归入口，不是本专项新增覆盖；写新测试后按真实文件补入定向命令。根 workspace 目前只有 API，不编造 @relay-agent/workbench 或 test:unit 脚本。

run-integration.ps1 的 -TestFile 是逗号分隔 basename，不带 .integration.test.ts；默认构建。仅确认对应源码包新鲜后用 -SkipBuild，需要时按脚本真实参数使用 -TestNamePattern/-UseCLocale。它自建 portable PG，角色/数据库来自实际输出，勿默认 postgres 或连接用户业务库。

桌面 -TestPackage 输出独立 test-release，不覆盖默认用户 release。构建期间输入变化或清单不匹配时停止该验收包，协调文件基准后重建，不伪造包身份。启动后记录实际 session_root、包指纹和 session.json；不猜 API 端口、Workspace、数据库角色或凭据。

仅关闭本次隔离窗口后，用 powershell -NoProfile -ExecutionPolicy Bypass -File apps/desktop/scripts/stop-acceptance-session.ps1 -SessionRoot "<本次实际 session_root>" 清理。对应窗口仍运行时脚本会拒绝；不得改成按进程名杀所有 Node/PostgreSQL/Relay。开发 dev-stack 默认不开 Worker，按实际参数核对，开发预览不等于桌面验收。

真实模型套件如 real-model-tool-loop、real-model-skills 在 RELAY_MODEL_* 未配置时会跳过；SKIP 不是真实 Provider 通过，也不代替本专项新增压缩/恢复长任务验证。不要在报告中把配置缺失造成的跳过写成全绿。

十四、DeepSeek 对照与参数冻结

在有效连接、权限和既定范围预算内，选择确切 Provider/模型/模式和固定长任务样本。测试数据最小化，不把用户整个仓库或不必要历史外发，不输出密钥。

对照现有截取或未压缩的可执行基线与新策略，保持相同目标/工具/关键约束及可比输入规模。基线不能完成长样本时诚实记录失败，不为了比较强塞超窗口请求。

至少采集：
- 目标/约束遗漏、未决项保持、有效接续成功和协议错误。
- 每次实际调用身份、已知输入/输出/cache token、摘要/重试/恢复调用。
- 总调用数、可得总成本、压缩耗时、续接延迟及实际窗口变化。
- 同一原动作是否重复外呼，UNKNOWN 是否被错误清除。

Provider 未上报的 token/cache/成本保持未知；无法精确计费就报告可得计数，不假填价格。收益比较包含摘要成本，短回复不等于总成本更低，稳定前缀也不保证 100% 缓存。

样本、通过阈值、失败判定和候选策略在运行前冻结；通过测量选择最小有效参数，记录不满足项和适用模型。没有真实 DeepSeek 证据，不能宣称“已经利好 DeepSeek”“最佳窗口/阈值”或真实兼容通过。

十五、停止条件与继续边界

下列情况先停止依赖的动作，保留原身份和真实状态，但继续不依赖它的已授权工作：
- 未决外部效果/UNKNOWN、旧 Writer 未停止、真实资源归属不明。
- 基线不完整或来源不能证明，准备恢复会覆盖人工/其他任务修改。
- 旧 Run 缺模型/协议快照且继续策略未核定，不能伪造历史绑定。
- 必需上下文/协议无法放入实际预算，或摘要预算/原范围预算已耗尽。
- 当前 Provider/桌面/隔离数据库出口未获放行或工具不可用。
- 共享文件存在会被覆盖的他人修改，或新需求实质扩大权限/插件/原生压缩范围。

报告确切阻塞对象、原请求/动作、已完成内容、不能继续的依赖和最小需要的决定/外部条件。不要把这些情况改成成功，也不要因一个真实窗口限制停止所有编码与可执行回归。

普通实现错误、失败测试、类型不匹配、接口遗漏、文档断链由你继续修复并复验，不把可自行解决的问题交回用户。不能为了赶进度跳过高风险恢复/权限测试。
