## 4. 按优先级实施

### CT-01 / P1：详情与文件预览下的容器布局

复现：已有任务会话 → 工作详情 → 成果 → 打开成果。截图 `01-artifact-provenance.jpg` 左上可见新建会话与任务视图重叠；普通工作详情则覆盖消息右侧，两个阶段使用不同空间策略。

推荐统一有效主区宽度规则：空间足够时详情与主区明确分栏；空间不足时收成有完整关闭路径的覆盖抽屉，避免保留一个无法使用的窄聊天列。使用容器宽度判断，不能只看整个窗口宽度。长会话标题省略且可查看全名；按钮可缩为有可访问名称的图标或合理换行；不能用隐藏任务视图/发送键来通过测试。

保留：关闭回原会话、切换页签的状态、成果预览返回工作详情、确切版本选择、用户草稿和阅读位置。覆盖抽屉明确遮罩/焦点规则；非模态分栏不伪装成模态。避免正文被悄悄覆盖却仍声称“不影响协作”。

### CT-02 / P1：资料与发送选项的职责和高度

复现：输入器点“资料 0”或“普通讨论”，出现同一大片面板，包含大标题、资料检索、生成方式、意图及长说明。

将资料选择与发送选项在现有组件中明确分组：资料入口优先显示检索、已选数量、已选项和引用范围；生成方式/意图进入相应设置区，使用现有能力，不改命令语义。推荐资料面板限制高度并在内容区滚动，保留输入器和关闭入口；标题采用面板字号，不能像整页 hero。

保留空态、查无结果、读取失败和可重试，不能用空列表掩盖错误。已选版本冻结、资料不等于权限等约束，用简短提示与展开依据表达。选择资料不能自行创建执行或发模型消息；未接入本地文件继续如实禁用，不顺带建设上传后端。

### CT-03 / P2：二级页面空间与首屏密度

项目列表已隐藏近期会话栏，但项目总览/蓝图/继续项目以及新建任务又显示该栏。沿现有产品约定统一非聊天页面的会话栏收纳，保留可返回工作台入口，不清除会话状态。

新建任务压缩介绍和“所属项目”卡片的装饰留白，保留名称、预期结果、验收标准的清楚层级，长表单合理滚动；主要操作应易找到。完成标准说明避免标题重复。项目创建保持必要输入简洁，详细命令说明移到已有创建说明中。

项目概览减少重复元信息与等价“继续/打开工作台”入口；下一步未明确时给出真实可用的完善入口，不能虚构下一步。若仅能跳现有设置页，就如实跳转并预定位，不新增无调用方的编辑框架。

### CT-04 / P2：实现词汇和来源证据分层

常用区域使用用户语言，例如“暂无需要你判断的事项”“目标尚未关联”“尚未指定下一步”“人工创建”。内部 ID、SHA、Skill 定义版本和原始枚举保留到“依据/技术详情/版本与来源”中，可复制或展开；不要删除这些证据。

新建项目、蓝图和接续页不要把 API 命令、数据库对象、协议解释当主要使用步骤。保留“创建项目不自动调用模型”“候选确认后才应用”等影响决定的信息，简洁说明结果和作用范围。版本来源页本来就是证据入口，允许保留技术内容，优先补中文标签与长值断行，不为美化隐去确切版本绑定。

### CT-05 / P2：小菜单只承载操作，详情进入详情面板

任务 … 菜单内目前同时包含禁用委托、视图切换、执行详情、文件工具和连接说明。保持一个清楚的操作列表，较长的状态依据复用已有工作详情/运行检查入口，不把全文塞进小浮层。已完成任务的禁用委托要有正确 disabled 表现和简短原因，不能是最突出的实心主按钮；不得因此放开委托条件。

会话重命名框在窄栏内需有最小可用宽度、边缘避让和清晰保存/取消；保持当前已验证的取消路径。统一 Esc、外部点击、焦点返回及子菜单关闭规则，例外应有明确理由。不能为了统一样式把所有面板都改成全局模态。

### CT-06 / P2：全局搜索聚焦搜索与可用动作

复现截图 `02-global-search.jpg`：入口叫搜索资料，打开标题为命令面板，首屏长说明混有 Knowledge/Memory/Decision/Rule/READY/START。

明确搜索和快捷导航的分组，保留 Ctrl+K、搜索框焦点、键盘选择和 Esc 返回。主说明压成必要的一句，详细匹配范围放帮助区。中文显示类型；不可用动作给简短原因、降低视觉强度。保留真实匹配范围，不能把字面匹配包装成语义搜索，也不能在选中结果前自动提交业务命令。
