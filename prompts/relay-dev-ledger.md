# 独立小型开发台账：完整实施提示词

状态：2026-10-20 用户选择独立自建，要求交付提示词；本轮未启动编码。将本任务书交给开发 Agent 并要求执行后，才开始以下工作。产品选择记录归 [后续路线 §7.1](../docs/requirements/post-v1-roadmap.md#71-bug功能与多-agent-工单流转2026-10-20)。

## 1. 任务与工作区

你负责实现一个能实际使用的中文小型开发台账，用于当前 Relay 开发中的 Bug、功能和多个 Agent 之间的工作交接。请完成代码、启动入口、测试、真实浏览器检查与必要文档，不要只交方案、原型或 Mock 页面。

这是独立工具，默认目标目录为 `D:/Develop/relay-dev-ledger`。本任务明确覆盖提示词目录中默认使用 Relay 根目录的通用约定：`D:/Develop/Relay-Agent` 只作为本任务书及产品背景的只读来源，不能把新工具放进它的 apps、数据库或启动链。独立工具故障不能妨碍 Relay 继续开发。

开始前核对目标目录、可用 Node/包管理器及已有文件。如果目录已有相关工程，先查其 AGENTS、README、Git 状态和目标文件 diff，复用已有实现；存在无关工程或无法安全合并的冲突才停下说明。不要清空、移动或覆盖已有文件。你不是工作区唯一参与者，不回退其他人的修改。

默认当前 Agent 独立完成，不派子代理，不 commit/push，不创建远端仓库，不调用真实模型或向外部协作系统发送项目材料。不要修改 Relay 业务代码，不复制整套 Relay 架构，也不要批量扫描/导入 Relay 文档或把其中待办自动建单。

先用中文说明目标、必要假设、成功条件和简短实施顺序；普通技术选择按下文推荐完成，不为每个细节反复确认。涉及目标目录冲突、数据丢失、外发或明显扩大范围时才澄清。

## 2. 最终使用方式

用户打开本机页面，一句话登记 Bug 或功能，查看谁在处理、处理到哪里、还缺什么。不同开发 Agent 通过统一 API 或 CLI 读取最新工单、领取工作、登记进展、提交证据和发起交接。验收者读取同一工单，确认通过或退回。

台账记录工作，不自动启动 Agent、不执行 Shell、不代改 Relay 文件、不轮询其他聊天、不把负责人变更当作执行授权。所谓 Agent 接入，首版必须真实实现 API＋CLI；尚未实现 MCP 时明确说明，不能用文档中的示例冒充已接入某个 Agent 平台。

自然语言入口在首版是「保存一句话原文为工单」：用户选择 Bug/功能后，标题必填，其余可选，直接保存。模型理解、自动分类、自动补验收条件不做；外部编码 Agent 可以整理后调用建单接口。保存不自动派发、不调用模型，也不要求用户配置 Provider。

## 3. 技术与交付约束

推荐 TypeScript、React＋Vite、单个 Node HTTP 服务和 SQLite。已有工程有合适技术则优先复用。新工程采用成熟小型 HTTP 框架与一个适配当前 Node/Windows 的 SQLite 驱动，落实前核对官方兼容性；不要同时引入多个 ORM、运行时或状态库。前后端及 CLI 共用必要的请求/响应类型，不为分层搭建多工程平台。

- 同机单用户可信协作，默认只监听 `127.0.0.1`，单 SQLite 文件；不依赖 Docker、PostgreSQL、Redis、云账号或外部网络服务运行。
- 开发命令和一个 Windows PowerShell 启动入口；正常使用只需启动一个服务，同源提供构建后的页面和 API。端口占用、依赖缺失、数据库不可写时说明真实原因，不能杀掉别人的进程。
- 数据目录固定且在 README 写明，重启不丢数据；首次运行允许空库，演示数据只能显式生成，不能与真实数据混淆。
- CLI 默认访问运行中的 HTTP 服务，不自行写数据库；网页与 CLI 都经过同一业务入口，避免两份状态逻辑。
- 只做本机访问的最小保护：CLI 写入使用本机生成的访问令牌，网页使用同源会话；校验写请求的来源、JSON 类型及输入，关闭宽松跨域。令牌不提交、不放 URL、不输出到日志。无需账号注册、角色平台或企业权限系统；actor 是可信本地参与者的署名，不能声称它具备强身份认证或可防恶意参与者伪造。
- README 提供正常停止后备份数据库及恢复步骤，并实际验证一次；不能在 WAL 活跃时只复制主文件后宣称备份完整。不建设在线备份平台。

## 4. 只实现以下范围

### 4.1 工单与页面

首版仅服务 Relay 一个开发项目，不做项目管理模块。工单包含：

- 稳定内部身份、易读编号（如 `DEV-0001`）、Bug/功能类型、标题和描述。
- 可选优先级、验收条件、复现步骤、实际/预期、环境说明、阻塞原因与解除条件、下一步。
- 当前状态、当前执行负责人、待接收的交接、版本号及服务端创建/更新时间。
- 评论、处理记录、提交/文件/日志/测试结果引用，记录提交者与时间。不存令牌或全量会话。

未知字段留空并可补充，不能生成虚假的复现与证据。编号由服务端在事务中分配，删除/取消不能重新使用；首版不提供物理删除，取消及重复关联保留历史。关联其他工单仅保存明确关系，不实现依赖调度器。

页面最少两个：

1. 工单列表：标题/编号搜索、按类型/状态/负责人筛选、简易列表/看板切换、快速新建。看板按钮改变状态即可，不要求拖拽。
2. 工单详情：问题与验收、负责人及下一步、阻塞、证据、按时间排列的历史，以及当前可执行动作。高级字段收起，不把内部 UUID/revision/command_id 放到日常表单。

中文、清楚、紧凑，普通笔记本窗口可用。首次打开就能登记；空态、读取失败、保存中、成功、版本冲突及重试有明确反馈，不制造统计大屏。证据中的路径/链接只是引用，不自动读取文件或执行命令；外部文字安全渲染，不直接注入 HTML。

### 4.2 状态与验收

推荐状态：待澄清、待处理、处理中、待验收、已完成、已取消。阻塞是独立原因及标记，不用新增完整状态机；有阻塞时不能提交验收或关闭，清除阻塞要留记录。

- 新建可以直接待处理，信息不足时选择待澄清；领取时进入处理中，未领取不能冒充已开工。
- 当前负责人提交结果及证据摘要后进入待验收。待验收保留交付负责人供追溯，不允许其他 Agent 直接领取绕过验收。
- 验收必须记录结论、理由和所验交付版本；通过后完成，不通过则回处理中并保留原负责人及返工要求。存在尚未处理的交接时不得提交或关闭。
- 验收条件、问题范围或交付证据变化会推进相应基线，使旧验收不能用于关闭新基线；普通评论不必使交付失效。区分工单并发版本与交付基线，采用能清楚表达此规则的最小实现。
- 完成后需要修改范围/条件/交付证据时先重开；重开理由必填，回待处理并清除当前执行领取，保留历史负责人、证据和旧验收，不能沿用旧通过自动完成。
- 首版不让开发 Agent 用普通状态更新直接标完成，完成必须经验收命令。允许用户本人验收；若选择独立 Agent 验收，校验署名不同，并明确这只是流程检查，不能证明模型或判断独立。
- 取消要求理由，不把取消算通过；标记重复必须关联一个存在的不同工单并保留原记录。

页面、API、CLI 遵守相同转换规则，不能从通用 PATCH 绕过领取、交接、验收和重开。非法转换给出稳定错误码和可读原因。

### 4.3 多 Agent 领取与交接

先支持人工及用户指定的 Agent 署名，不预建 Agent 平台注册中心。

- 同一工单最多一个有效执行领取。并发领取必须在数据库原子判定，只有一个成功；失败者读回当前负责人，不能覆盖。
- 领取返回不可复用的领取身份；当前负责人相关写操作须携带有效领取身份及期望版本，不能只比较姓名。释放再领取，即使姓名相同也必须换领取身份，旧回执不能继续写。
- 发起交接指定接手者，登记进展、证据、未完成项和下一步；接受之前原负责人仍是负责人，页面显示待接收。接手者接受后在一个事务中切换负责人并使原领取失效。拒绝或撤回保留原负责人。
- 接手前必须读取最新版本；交接发起后交付范围/结果变化要使旧交接不可接受，不能让对方确认一个已变化的交接包。
- Agent 掉线或超时不自动换负责人、不自动认为外部进程已停止。提供人工「释放/重新分配」入口，必须填写理由并确认原执行已停下或已人工核对；保存该人工声明，不声称台账已技术验证进程停止。台账的领取也不等于实际文件系统锁。
- 待处理/待验收/阻塞均能查询。CLI 可导出有界 Markdown 交接包，含工单身份、导出时间、当前版本、范围、进展、证据引用、未决项、下一步和负责人。包是时点快照，接手仍需重读；不自动向别的聊天发送。

### 4.4 并发、幂等与历史

- 业务变更、历史事件、命令回执在同一个短 SQLite 事务提交。网络调用和人工等待不进入事务。
- 每个写命令使用调用方生成的 `command_id`。同一身份和载荷重试返回原结果，不重复建单、评论、转交或验收；相同身份换载荷返回冲突。先查命令回执再判断当前 revision，已成功请求不能因版本推进而失去重放能力。
- 载荷比较覆盖动作、目标、操作者、期望版本及业务内容，采用稳定序列化或等价可靠比较；不要只比标题。刷新/超时后保留原命令与原载荷核对，真正新操作才生成新 ID。
- 修改使用期望版本 CAS；旧版本返回 409 及可安全展示的当前版本，页面保留用户草稿并提供重新读取/比较入口，不能静默覆盖或自动重试旧意图。只读和重放不能写第二条历史。
- 历史至少包含动作、操作者、时间、前后状态/负责人、理由、命令关联与交付基线；只读展示，不提供篡改历史入口。不把 API 来访者声称的测试通过升级为系统已验证，通过来源要可辨认。
- 同一工单的内容修改、交接、领取、验收和强制重分配都受相同并发规则保护；不可用通用更新绕过。

## 5. Agent 使用入口

实现最小 HTTP API 及一个 CLI，语义至少覆盖：新建、列表/详情、修改、评论、领取、提交验收、验收/退回、交接发起/接受/拒绝/撤回、释放/人工重分配、取消/重复关联、重开与交接包导出。允许复用明确的命令接口，不要求每个动作一个控制器。

CLI 同时支持可读中文摘要与 `--json` 机器输出；失败退出码非零，409 明确提示冲突、负责人及重新读取方式，不泄露密钥。支持从文件/stdin 传多行描述和证据，不靠复杂 Shell 转义；重试可显式复用 command_id。令牌通过受忽略的本机配置或环境读取。

提供一份简短 `AGENT_GUIDE.md`，写明读取最新状态、使用自己的署名、领取后处理、提交证据、验收返工、交接接收及发生冲突/超时的处理。提供可复制的 PowerShell 示例；示例中的命令必须实际跑过，不能凭空设计一套没有实现的 CLI。

不做内置聊天、模型调用、MCP Server、GitHub/禅道同步、桌面壳、远程访问、多用户账号、复杂权限、排期绩效或自动调度。将来确有需要再加，不提前为它们搭插件框架。

## 6. 实施顺序与成功条件

1. 检查环境及目录，说明必要假设；建最小工程和 SQLite schema/migration。先跑通持久化与命令事务。
2. 先写会失败的关键测试：双 Agent 抢领、旧版本覆盖、重复命令及旧交接接收，再实现 API/CLI 直到转绿。不用把 HTTP/SQLite 全 Mock 的测试证明持久并发。
3. 接真实 API 的中文页面，走新建、领取、交接、提交验收、退回、再次提交、验收通过及重开。不是用前端数组/localStorage 模拟状态。
4. 提供 Windows 启动入口，用两个独立 CLI 进程模拟两个 Agent，真实浏览器完成核心路径；验证停服重启及备份恢复。
5. 更新独立项目 README、AGENT_GUIDE 及必要 API/数据说明，报告实现、自检、实际运行和未验边界。创建新工具自己的简短验收记录，不把成绩写成 Relay 产品已通过验收。

至少完成以下有业务意义的验证，优先复用同一套夹具，避免建泛化测试平台：

| 编号 | 必须验证的结果 |
|---|---|
| L01 | Bug/功能快速登记后重启仍在；可查唯一编号，非 Mock 数据 |
| L02 | 两个独立客户端同一时刻抢领，只有一个成功，无双负责人 |
| L03 | 同命令重试不重复建单或事件；同命令换载荷拒绝；成功后跨重启仍可重放 |
| L04 | 旧 revision 更新被拒绝，页面草稿保留，已保存内容不丢 |
| L05 | 提出交接不改变负责人，接受后原领取失效，原 Agent 迟到写入拒绝 |
| L06 | 拒绝/撤回交接保留原负责人；交接基线变化后旧接受拒绝 |
| L07 | 人工重分配后，同名 Agent 的旧领取仍不能写；保留核对声明及理由 |
| L08 | 当前负责人提交结果，验收退回后返工；旧交付的通过不能关闭新交付 |
| L09 | 已完成必须重开后才能修改范围/结果；重开不继承旧验收或旧领取 |
| L10 | 状态绕过、未领取提交、阻塞未解除关闭、待交接提交均拒绝；非法请求不留下半条业务变更 |
| L11 | 真实 HTTP/CLI 与真实浏览器看到相同事实；端口占用、服务不可用、冲突有真实错误提示 |
| L12 | 正常停服备份并恢复到临时数据目录后，工单、历史、领取和命令回执一致 |

不要为拿绿删除失败用例、放宽规则、伪造测试结果或改种子掩盖实际读写错误。程序自己完成的检查只能叫自检；没有另一位执行者实际验收就写未做独立验收。CLI 模拟 Agent 不等于已经连接各平台 Agent，也不证明实际编码进程安全停止。

## 7. 完成交付与停止条件

交付必须包含：绝对项目路径、Windows 启动方式和页面地址、已实现范围、实际测试/浏览器/CLI/恢复证据、未实现项，以及用户如何登记第一条 Bug、让第一个 Agent 领取和交接的最短步骤。

本次新建工具可维护短 README 与一份简短开发/验收说明，不创建重复的架构文档、空路线图或大量逐轮日志。数据库升级和破坏性变更说明兼容风险；真实数据、令牌及本机配置不进入 Git。

若遇到环境阻塞，保留代码和失败证据，完成不依赖阻塞项的工作，再明确缺少什么；不自动换成另一个平台、不扩大为 Relay 重构。若需要清空数据库、覆盖已有目录、外发材料或删除失败测试，停止该动作并说明，不能用“完成任务”作为越权理由。

请持续实施到上述小范围工具可运行并完成必要验证，不要在方案、脚手架、页面截图或第一条绿色测试后停下。也不要为了追求完整度扩展成本轮未要求的平台能力。
