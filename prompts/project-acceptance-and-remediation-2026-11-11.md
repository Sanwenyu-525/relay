可将本文直接发给接手开发的 Agent。工作区为 D:/Develop/Relay-Agent。全程中文。目的是让一个做长期项目的人能开始工作、判断执行进度、审阅真实成果，隔天回来还能接着做。交付包括已复现问题的修复、核心旅程复跑、必要性审查和带证据的剩余项。

## 开工与证据

1. 阅读根 AGENTS.md、CODEX_NEXT_STEP.md、docs/requirements/v1-scope.md 和统一验收表相关行。先查 git status、当前 HEAD、目标文件 diff。11 月 11 日抽查基准是 beaaa9f1 加当时的未提交改动。允许并行开发已经修好问题，先重现再决定是否需要补丁。
2. 查 D 盘、运行实例、现有测试端口和构建归属。此次观察到 D 盘 27.56 GiB 可用、4173 已被占用，并行编译和浏览器曾耗尽系统内存。用空闲端口、单 worker、串行启动重任务。API 按 manifest 使用 Node 24。避免复用无法确认来源的 dist，保留他人的安装包、工作目录和数据库。
3. 本轮交付物优先级依次为用户可见的错误反馈、键盘阻碍、验收基线漂移，再到产品减负。若核心旅程实测发现数据错误或无法完成，应提前处理。生产数据禁止作测试种子。UI 依据 workbench-design、design-system、tokens 以及适用的 UI 技能。

## 工作包 A · 显示偏好的回执必须和持久化结果一致

- 从“设置 → 通用设置 → 显示与界面”开始。使用全新浏览器上下文，记录原时区、动效、导航位置。让 Storage.prototype.setItem 仅在 key 为 relay.motion 时抛出 QuotaExceededError，其余写入正常。切换动效为“关闭”，点“保存显示偏好”，记下即时效果、回执、刷新后的实际值。
- 已观察到页面显示“显示偏好已保存，仅在本设备生效。”，刷新回到“跟随系统”。检查 apps/workbench/src/lib/motionPreference.ts 的 storeMotionPreference、SettingsView.tsx 的提交处理以及其余调用方。时区与动效各自写入，第一项可能已经成功。
- 推荐保留当次可用的动效选择，准确告知哪些偏好已保存、哪一项只在当前窗口生效。保存失败后可重试，成功后旧错误消失。保留既有本地存储键、旧值兼容、默认工作台和导航位置即时保存语义。
- 回归至少覆盖全部成功、只拒绝动效写入、首项写入失败、失败后成功、刷新读回。用新的页面实例读存储，避免仅断言 React state。输出实际回执、刷新前后值及改动位置。

## 工作包 B · 近期会话摘要支持键盘收起

- 以有至少一条历史会话的协作页为起点，1280×900，键盘聚焦会话行，摘要出现。保持焦点按 Esc，检查 tooltip、触发行焦点、aria-describedby、路由和选中会话。本轮实测焦点仍在行上，等待一秒摘要仍有一个可见实例。
- 定位 RecentWorkRow.tsx 的 RowSummary、行按钮 focus/blur、pointer enter/leave，以及 ⋯ 菜单的打开状态。把 Esc 交给当前可见浮层；检查键盘聚焦及鼠标悬停两种打开方式。摘要关闭后无需移焦，不应提交命令、打开会话或误关外层窗口。下一次真正重新进入仍可打开。
- 验证停留、Esc、移出后重新进入、Tab 到下一行、打开操作菜单、滚动收起。重点观察指针停在按钮上时是否立即重新打开、摘要消失后是否遗留描述引用。在窄窗打开侧栏后用长中文标题量测摘要左右边界；记下实际坐标再判断是否有第二个缺陷。
- 只改变收起语义，保留高密度单行、长标题、时间和目录来源。截图显示位置，键盘断言显示行为，两者都留。

- Playwright 配置从 RELAY_E2E_PORT 取端口，recentWorkRailDensity.spec.ts 的跨域桩从 RELAY_RAIL_TEST_PORT 取值。仅设前者时出现连接等待超时。先同时指向同一空闲端口作对照，再整理默认推导；检查是否有专用脚本依赖后者及其优先级。验证只设公共端口也能连接，并保留显式专用配置的有效用途。
- 在正确端口上该套件 12/15。失败用例入口为原文件第 242、286、818 行。768px 宽度时行高 24px，测试期待至少 31.5px；目录加号和会话菜单断言也沿用 32px。styles.css 留有按用户反馈从 32 收至 24 的说明。对照现行交互文档、token、决策日期和三个触发器的实际命中框，先写出哪个控件采用哪个规格。
- 若确认 24px 是现行要求，使用对应 token 验证实际控件，保留搜索框可读宽度、行距、焦点可见、悬停前后布局稳定和操作目标不重叠的断言。不要跳过文件、删除失败检查或整体改回 32px 来刷绿。复跑 768、1000、1280、1920 像素及手调最窄栏宽。贴出失败前后实测数字。
- 检查截图输出隔离。contextUsagePanel.spec.ts 把截图写入固定 D 盘绝对目录；settingsUx.spec.ts 也复用固定的历史截图目录。Playwright 的 --output 单独设置并不能隔离这些截图。优先采用每次运行的输出路径，显式需要对照图时才导出。用两个不同输出目录顺序运行，确认前一轮证据未被覆盖。

## 工作包 D · 以一个真实项目验收业务闭环

建立隔离项目“整理实验记录”，创建任务“输出本周实验摘要”，唯一可审阅产物为摘要文件，验收条件包含“给出结果”和“列出尚待核实的实验”。记下 workspace、project、task、run、artifact version、review、completion 的引用。以下每一步都从用户入口开始，读回业务事实；真实模型只发合成内容。按现有 prompts/task-run-execution-chain-2026-11-09.md 和 execution-recovery-control-2026-11-09.md 复用受控环境、命令与断言。

| 用户旅程 | 操作与干扰 | 通过条件 |
|---|---|---|
| 首次进入 | 空工作区开始，无模型时先做人工任务，再配置测试连接 | 用户能创建首个项目与任务；模型配置缺失能定位；人工路径可独立完成 |
| 从对话到任务 | 先讨论，再显式转入正式执行；连点、刷新、往返会话 | 正式 Task/Run 数量正确；目录、模型与任务对象可核对；普通聊天不会误报业务完成 |
| 审阅与返工 | 提交 v1，只接受第一项，退回另一项；生成 v2，重载审批页 | 同意对象和版本明确；旧成果及判断可读；两项均满足才生成唯一完成凭据 |
| 中断接续 | 执行中暂停，等待安全点；审批等待时暂停再继续；分别试取消和交接 | 控制请求先有回执；到安全点再切状态；接手人和可用下一步正确；检查外部动作次数 |
| 历史与当前 | 完成后重开，打开旧 Run 与旧成果，从原会话回到当前任务 | 历史链接到确切版本，能分清当前与历史；缺引用或权限撤销后入口诚实收回 |
| 故障与恢复 | 用受控适配器模拟断网、写后回执丢失、验证器故障、审批过期 | 不确定时可查询原动作；同一命令重试无重复效果；验证器故障保持未通过 |
| 次日返回 | 关闭再打开隔离实例，从最近工作、项目、今日或收件箱接续 | 用户能辨认上次成果、当前执行者、等待谁及下一步；三处显示指向相同事实 |

每条记环境、执行时间、输入对象、操作顺序、用户所见、权威读回、耗时和结论。首跑与重试分别记录。API 返回成功、文本“已完成”、能点开页面都不足以代替回执和版本读回。若测试只能到达一半，写最后一个已验证步骤及阻断点。

## 工作包 E · 功能必要性与 UI/UX

把同一项目交给首次用户和隔天返回的用户各走一遍。记录首次找到入口所需时间、点击次数、主动返回找入口次数、下一步误判、需解释的术语。没有真实参与者就标为专家走查，不给虚构满意度或成功率。

从实拍首屏做两个小实验。1280×900 的协作页在同一输入框上方列出 11 个提示动作，其中“讨论一个想法”和“梳理需求”面对尚未明确的想法都说得通。请首次使用者完成“我想整理上周实验，还没决定交付什么”，记录是否花时间猜按钮差异，以及直接输入后能否顺利开始。再给返回用户“接续上次工作”，比较点击侧栏已有会话和点击同名提示动作实际落到哪个对象。只有出现稳定误选，才建议收敛首屏入口；保留用户常用动作的可达性。

同一截图里，目标读取与执行过程读取各报一次响应格式错误，两处都直接显示内部英文对象名。该图来自为左栏测试构造的响应，不能证明正常连接会报错。请分别构造有效响应和格式错误响应：有效时首屏没有错误条；错误时首先说明哪部分资料暂时不可用、其他操作是否可继续、怎样重读，详细字段路径保留给诊断。确认同一次重试只重读对应资源。

| 功能组 | 审查问题 | 本轮建议与决策依据 |
|---|---|---|
| 项目、任务、成果版本、人工判断 | 隐去该信息后还能否确认谁做、做了什么、接受哪版？ | 保留主链。任何减少步骤的方案都应能回溯对象、版本与接手人 |
| 最近工作、今日、收件箱 | 给出“接续昨天讨论”“找今日安排”“处理等我决定的事”，观察首选入口 | 分别评估接续、安排、待判断三种意图。发生重复跳转时先改名称与返回路径 |
| 模型用量与上下文 | 用户能否说明 4% 的分母、上次冻结窗口和当前档位的关系？无真实用量时如何理解？ | 保留费用和容量诊断入口与已确认的当前档位口径。首层优先用量与下一步，明细按需看 |
| 显示与界面 | 请用户修改时区、导航位置和动效，并预测哪些需保存 | 导航即时生效，其他项经按钮提交。观察把即时设置移出提交组或明确标记后是否减少误判。浅色为唯一可用外观时，开发中主题名称可作为减负候选 |
| 知识、记忆、决定、规则 | 同一条实验结论从哪里录入、谁确认、改了后哪些上下文会引用？ | 按来源、生命周期与写入权限区分；名称相似不足以合并。验证失效筛选、空态、撤销和来源链接 |
| 自动化、工具与权限 | 常规打开目录要经过几次配置？撤权后能否再执行？无人值守动作失败后从哪里恢复？ | 对照已有 product-complexity-reduction.md。保留权限与恢复底座；低频配置仅在需要处出现。删除能力须有调用方和历史数据影响分析 |

复核 1440×900、1162×782、760px 窄窗、560px 浮层和 430px 高短窗。覆盖真实鼠标、仅键盘、长中文、空值、加载慢、失败重试、滚动后返回、减少动效、缩放与焦点恢复。记录被遮住的实际按钮或文字。Windows 上另验 WebView2、系统 DPI、冷启动和重启恢复；对照应用打包版本。浏览器扩展单列启用、断连和重新连接场景；记录与桌面宿主的真实通信边界。
