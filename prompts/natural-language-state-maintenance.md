二、保留本轮已确认的交互选择

1. 明确的修改/收录指令，在对象、内容和范围足够明确时，本身表达该项用户确认。沿原创建/修改/接受入口生效，复用已知信息，不普遍再要求填表或点接受。普通讨论、模型归纳、自动提炼和发现的仓库修改仍为候选。
2. 直接要求的调整生效；另一既定承诺需要改变时，先显示具体影响，再问一句。例如「导出下周再做」不能自行推迟本周发布或删除发布要求。无法确定精确日期等实质信息时聚焦澄清，不能编造期限。
3. 用户报告其他工具已完成工作后，在已有权限内主动核对对应成果、确切版本和原完成条件。足够时沿原用例推进；缺证据、FAIL/ERROR、过期或仍需人工体验时保留待核对/待验收事实。
4. 返回项目时自动核对并更新顶部接续卡；日常比较相对上次实际查看摘要时的状态。首次或无可用基线只展示当前事实。手动命名接续点保留，不被日常查看重设；未解决事项持续显示。
5. 默认先读取相关差异/证据，运行已授权、可信配置和预算内的相关轻量检查。无变化且证据仍适用时复用。全量/耗时检查另行提出，未覆盖范围保持可见。返回不自动恢复旧 Run、修复代码、执行新任务或持续后台监控。
6. 默认「摘要＋展开」：摘要说明改了什么、当前结果和下一步；展开显示变化前后、依据、来源和影响。失败、冲突、重要影响、必要决定和结果不明直接可见。用户指令的变化回执留在原对话，返回结果更新顶部卡。
7. 支持自然语言纠正及「撤回本次调整」。默认针对原指令实际生效的整组可撤回状态变化，不先要求逐项勾选。存在后续修改、依赖、在途工作或不可撤回效果时，先展示修正范围与影响；不能自行缩成部分撤回。
8. 各页面继续读取同一业务事实，保留详细编辑及无模型人工路径。助手档继续只读。接受计划不是 Delegate；一般修改/收录不能暗示完成确认。明确完成/人工接受指令仍绑定确切成果与条件，满足原完成规则后提交。

四、分片闭合产品路径，每片独立复验

A. 明确指令 → 真实状态变更 → 同源 UI → 纠正/整组撤回。
从一个真实项目的计划/任务调整形成纵向闭环，再覆盖其余确认对象。补齐必要写入口；验证明确命令无需重复表单/接受点击，讨论不写、候选不自动接受、连带承诺先决定、错误/部分成功如实呈现。原命令回执、冲突与撤回恢复同片闭合。对应 NLS-01/02/03/11/12/13/14。

B. 外部进展 → 确切成果/证据核对 → 原验收/完成入口。
用隔离目录实际改变成果，再从产品对话发出同步请求。分别验证缺失分支/成果、证据过期、检查失败、人工验收未决，以及具备原条件后的合法完成。真实检查的批准/撤权/拒绝/UNKNOWN 生命周期必须闭合；不以新 Task 或假检查结果代替原对象接续。对应 NLS-04/05/08/09/13/14。

C. 返回项目 → 上次查看基线比较 → 获授权轻量核对 → 顶部接续卡。
实现实际查看确认、返回触发、证据复用与检查去重、原身份恢复，覆盖首次/无基线、局部失败、权限变化、切换项目/目录、迟到结果和持续未决事项。命名点原行为及历史不变。对应 NLS-05/06/07/08/09/10/13/14。

D. 组合回归、确切构建与真实 Windows 验收。
串联「返回项目 → 一句话调整 → 连带决定 → 外部成果核对 → 纠正/撤回 → 重启再次接续」。检查窄/短窗、键盘与草稿、摘要展开、必要判断可见性、原对话与各详情页的一致事实；真实中文 IME/DPI 等按实际条件验证并保留未验限制。用匹配最终源码的完整包，不借旧包/Mock/浏览器成绩代替真实窗口和业务。

依赖片等自己的前置出口通过；独立调查、UI 准备或其他不依赖阻塞的工作可继续。每片自检 → 协调者独立复现关键反例并检查实际回执/业务事实 → 必要修复 → 同一场景复验，通过后再进入依赖片。不能把实现者总结或预填 fixture 当独立验收。
