# 功能地图

功能地图是开发者使用的本地只读导航工具：按模块展开功能，查找关联代码、文档、开发/整改/运行时提示词、测试和验收依据。它不修改产品业务状态，不连接用户数据库，不调用模型或外部服务。没有新增依赖、产品路由、HTTP 业务契约或 migration；Breaking Change：No。

## 使用与更新

在仓库根目录运行：

```sh
npm run feature-map:live
```

一键入口：根目录双击 `dev-views.bat`（等价 `powershell -File scripts/open-dev-views.ps1`）会启动功能地图服务并打开三个本机只读视图——功能地图页面、根目录 `preview.html` 与 `motion-border-prototype.html`。端口已被占用时复用现有服务，不会再起一个；日志写 `output/feature-map/server.log`。

浏览器打开 [实时功能地图](http://127.0.0.1:4318)。服务仅监听本机 `127.0.0.1`；页面右上角「检查间隔」选择 2 秒 / 5 秒 / 15 秒 / 1 分钟 / 5 分钟 / 30 分钟 / 1 小时 / 2 小时 / 5 小时 / 手动，选「手动」时只点「刷新」才检查，选择记在浏览器本地。默认约 2 秒，功能开发节奏不快时长间隔足够；检查只读工作区文件与 Git 状态，不写业务数据。检查间隔只影响页面发起的读取频率：没有页面访问时服务端不做任何扫描，也没有后台定时器。关闭终端或按 Ctrl+C 停止服务。端口已占用时用 `node scripts/feature-map.mjs --serve --port=4319` 指定空闲端口。服务存活期间页面才会自动更新；不是常驻系统服务，也不需要提醒自动化。

```sh
npm run feature-map
npm run feature-map:check
npm run test:feature-map
```

第一条生成 `output/feature-map/index.html` 与 `data.json`。HTML 内嵌完整数据，可直接双击离线查看；**离线快照不会自动更新**，再次生成即可刷新。生成物和本机日志不进入 Git。第二条核对目录路径、ID、阶段和验收关联，失效关联以非零退出提示。第三条验证源表解析、范围区分、新增/删除资料、失败恢复及只读 HTTP 边界。工具使用 Node 内置模块；按项目统一环境使用 Node 24，实际验证结果只见[功能验收表](../testing/overall-acceptance-2026-09-28.md#当前功能验收表)。

## 事实源和状态边界

| 信息 | 唯一维护入口 | 地图行为 |
|---|---|---|
| 模块、功能与资料关联 | [catalog.json](catalog.json) | 保存名称、范围、阶段 ID 及关联路径；不复制通过结论 |
| 阶段与下一步 | [CODEX_NEXT_STEP](../../CODEX_NEXT_STEP.md) | 动态读取 M/N 阶段表的原状态与范围 |
| 功能验收 | [统一功能验收表](../testing/overall-acceptance-2026-09-28.md#当前功能验收表) | 读取当前 H2 区域的全部行，保留结论、依据、剩余项与源行号；不读取历史表推导当前成绩 |
| 代码、文档与提示词 | 仓库实际文件 | 显示存在/缺失、最近修改时间与 Git 未提交变化；链接只读原文 |
| 视觉值 | [design-tokens.json](../frontend/design-tokens.json) | 生成时解析同一 token 源；没有另存色值表 |

地图按关联记录的原结论分类用于筛选，**不是对细粒度功能重新验收**。同一行可能只验证一个入口或一个冻结包，关联功能不能自动继承完整通过。复合结论含未验收、待验或未接入时保留这些限制。当前源表存在异常列时，合并展示后续列并标记提醒；源表保留失败时点且后文有整改接续时，通过原文核对，地图不自行裁决冲突。

读取错误时实时服务保留上一快照并在页面标明错误；文件缺失、关联失效不隐藏。Git 状态读取失败时统计显示“Git 状态不可用”，HEAD 读取失败时单独显示“不可用”，不将缺失 Git 信息解释为工作树干净。刷新保留搜索、筛选、当前功能弹窗及已展开的验收记录。文件时间只说明资料变化，不证明功能完成或验收仍有效。

## 维护关系目录

新增或调整功能时，编辑 `catalog.json` 的对应模块。ID 保持稳定，路径相对仓库根目录；`code/docs/prompts/tests` 使用真实文件路径，不使用通配符。`acceptance` 填统一当前表第一列的确切名称；没有对应记录时留空，不借用无关通过记录。`intent` 为 `current`、`planned` 或 `research`，用来区分当前、规划与研究范围，不表示开发授权。

自动扫描源码、迁移、测试、脚本、文档、契约和 `prompts` 中的文本资料，新文件出现在“未关联”筛选中。**新功能的语义与 Owner 仍需人工归类**；自动发现文件不会创建功能或推断实现完成。图像、研究缓存、构建输出、原始验收 evidence、archive、mockups 和环境文件不在资料扫描范围。运行时提示词正文与注册表可在目录的 `prompts` 数组关联到源码；开发输入与运行时来源分别筛选，历史角色以原文为准。

地图服务仅提供 GET 读取，资料入口按快照索引白名单读取并核对真实路径，不开放任意文件、工作区外路径或业务写入。每次读取 `/api/map` 才重新扫描目录、Git 变化、进度表与验收表；扫描失败保留上一快照并在页面标明错误。实时和离线模式均可导出 JSON 用于交接，导出保留生成时间、HEAD、文件变化和源记录范围。已有进度、验收结果仍只维护各自事实源，不再手工更新一份地图状态。
