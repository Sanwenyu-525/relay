# ADR-019：内置工作方法、命令与会话检查点

## 状态

Accepted（产品范围与控制边界）。用户在 2026-10-10 至 2026-10-11 的逐项讨论后明确要求直接制作文档；此处原「新增能力未实施、未验收」描述该日期的文档交付时点。2026-10-20 会话长短期记忆的工程接续归 [ADR-028](ADR-028-memory-layers.md)、[HTTP §10.99](../api/http-command-contract.md#1099-长短期记忆接口2026-10-19)；当前阶段与运行成绩各归原主文档。Provider 协议完整持久恢复、文件快照及其他 Provider 原生压缩仍未因本次记忆模块而实现，不将目标与技术推荐一并写成 Accepted 实现。

## 日期

2026-10-11。

## 背景

当前四项第一方 Skill 主要生成项目协作的结构化建议，聊天尚无 `/命令` 解析和方法执行绑定。用户需要可实际开展工作的内置方法、自然语言选择和可定制定义，同时需要长任务更早压缩、优先适配 DeepSeek，以及从用户消息直接撤回相关文件成果。

原执行、权限和恢复机制必须继续承担准入及业务事实责任。当前有限文件差异不是消息发送前的可恢复快照，普通工具消息重建也不足以证明 DeepSeek 思考模式协议完整。

## 候选方案

| 决策面 | 候选 | 取舍 |
|---|---|---|
| 方法执行 | 仅给建议 / 独立 Skill Runtime / 组合既有执行链 | 仅建议不能完成工作；独立 Runtime 重复权限和恢复；选择组合既有入口 |
| 命令交互 | 选择即执行 / 插入输入后发送 | 选择即执行使浏览菜单产生效果；选择发送后执行，可补充目标与参数 |
| 定制 | 只应用内保存 / 可读 `SKILL.md` 目录 | 文件形式便于复用和外部编辑，代价是草稿与已启用版本必须分开；选择文件形式 |
| 压缩 | 接近硬上限才压缩 / 提前按增长与工作节点分层整理 | 选择提前整理，优先 DeepSeek 接续与缓存；阈值和真实成本收益不能靠经验宣称 |
| 摘要模型 | 独立便宜模型 / 当前工作模型 | 选择当前模型，减少跨模型丢失约束的风险；摘要额外成本仍纳入原预算 |
| 文件撤回 | 混入 `/undo` / 消息下按钮 | 选择消息按钮到发送前，`/undo` 保留业务状态补偿语义 |
| 运行中撤回及完成 | 禁用按钮 / 先安全停止再恢复；保留当前 DONE / 重开受影响任务 | 选择一次点击、先停后恢复；确实撤销完成成果时重开进入新验收周期，保留历史证据 |

## 最终决策

首批方法保留四项项目 Skill，新增代码审查、故障诊断和文档维护。方法、个人/项目定制和系统命令复用原注册、会话、Task/Run/Gateway 及领域写入口，不建立第二套执行或业务事实系统。英文名和中文别名同义，菜单选中插入输入、发送才运行；自然语言可采用方法但不扩大本次行动范围。

长会话使用手动和自动压缩，模型窗口偏好 256K–512K 与工作预算及触发阈值分开。DeepSeek 优先，默认当前模型摘要，保持必要协议字段与可追溯检查点；摘要不获得业务或授权效力。首版通用摘要仍是技术推荐，其他 Provider 原生压缩不在本 ADR 中自动承诺同步交付。

文件按钮恢复到消息发送前，包含后续本会话关联修改。先持久化意图、安全停止与核对，再按受管范围恢复；后续人工或其他任务修改按冲突处理。文件恢复和 Task 重开分别报告实际结果，不假装 FS 与 DB 原子。确实撤销已完成成果时复用 ReopenTask，新周期不继承旧 PASS、不自动执行。

## 决策原因

这些入口让工作方法、会话控制和文件撤回可直接从对话使用，同时维持唯一写入 Owner、冻结契约和可恢复动作身份。提前整理与稳定前缀适合评价 DeepSeek 的长任务接续及缓存，实际收益仍依 Provider 对照。消息级文件基线才能表达用户要求的时点；仅逆转数据库状态或动作 hash 无法兑现该语义。

## 代价

需要方法绑定、不可变定制快照及命令作用范围协议；压缩有额外模型成本和来源/协议保留成本；文件恢复需要真实字节基线、来源关系、资源隔离、持久回执及冲突处理。旧消息没有基线时不能追认已可恢复。安全停止或重开失败可能产生可核对的部分结果，界面必须真实显示。

## 影响范围与关系

影响 Assist/Application、Skill 注册、Context/模型端口、Workflow 控制、Gateway/Files、Task 完成、Workbench、未来 API/数据库和测试。详细事实各归[产品总纲 §0.13](../../Personal_Workflow_OS_Master_Spec.md#013-内置工作方法与会话控制)、[Skill 专题第 9 节](../architecture/relay-skills.md#9-内置工作方法与可定制-skill)、[运行架构第 8 节](../architecture/runtime-context.md#8-会话压缩与消息文件恢复)与[工作台第 27 节](../frontend/workbench-design.md#27-内置-skill-与聊天命令)。

接续 [ADR-008](ADR-008-declarative-skills.md) 的声明式组合边界，新增方法和可定制入口，不把该 ADR 整体改为 Accepted。沿用 [ADR-016](ADR-016-folder-first-conversation.md) 的目录/对话执行及原权限，保留 [ADR-018](ADR-018-assistant-conversations.md) 的只读助手身份；本 ADR 不替代它们，不原地升权，不放开任意代码插件。

## 后续

### 2026-10-24 文件回退产品细节补全（Proposed）

用户授权补齐产品文档。原 Accepted 的文件范围、一次点击先停后恢复、冲突保护及任务重开保持不变；本补充是推荐设计，不把未逐项选择的新默认升为 Accepted，也不代表实现或验收。

| 问题与候选 | 推荐及理由 | 代价与边界 |
|---|---|---|
| 回退后截断对话，或保留历史并更新当前事实 | 保留原对话、合法工具配对及来源，用实际恢复回执校正 Context/摘要，避免误删需求或把旧效果当当前状态 | 需恢复与摘要的版本核对，以及自动推进栅栏；不能只在 UI 加“已撤回”标签 |
| 无误操作出口、任意分支时间旅行，或单层反向恢复 | 推荐撤销最近一次完整文件回退，降低一次点击误操作的损失，限定为实际触及文件 | 需回退前保护副本、当前来源/权限预检与新动作回执；不能复活旧批准或 DONE，冲突/UNKNOWN 不强行反向 |
| 永久保存所有快照，或有界本机保留 | 推荐可见的时间/容量/单文件限制，保护未决引用，已清理消息如实不可恢复 | 可能早于保留目标耗尽容量；建议数值归工作台且须实测，不承诺全文件永久可回退 |
| 查看旧版即改工作目录，或区分试用与文件恢复 | 区分历史查看、试用切换、消息文件恢复和业务撤回，使实际作用对象清楚 | 需要识别共享可变目录与试用依赖；无法隔离时先处理运行冲突 |

交互、支持范围与推荐数值归[工作台 §27.3](../frontend/workbench-design.md#273-用户消息下的文件撤回按钮)，Owner 仍归运行架构 §8.5；测试计划 BC-18–BC-25 增加未运行反例。本轮 API/数据库变更：无，Breaking Change：No。工程协议、真实存储成本与 Windows 验证另行核定，不新增 Runtime、快照数据库或通用历史分支引擎。
