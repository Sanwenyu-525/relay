# ADR-005：成熟实现优先复用，业务契约驱动适配

## 状态与日期

Accepted（实施原则），2026-09-19。依据：用户要求参考借鉴成熟项目，并进一步明确不必复制代码、语言只是实现方式。具体库、版本、进程布局与组合仍为待选，不属于本次 Accepted 范围。

## 背景

已有设计定义了所需行为，但编码提示词默认自行实现有界执行器、恢复扫描和模型适配。职责归属不等于必须自行开发基础设施，直接照此编码可能重复建设已有能力。

## 候选方案

| 方案 | 优点 | 代价 |
|---|---|---|
| 全部自研，只把上游当阅读资料 | 可完全控制技术栈 | 重复实现、恢复测试和长期维护成本高 |
| fork 完整平台 | 起步功能丰富 | 产品/语言/数据模型耦合，上游升级成本高 |
| 按职责复用库或协议，借鉴机制，补必要业务与适配 | 保留业务目标并减少通用代码 | 需要源码研究、边界验证和兼容维护 |

## 最终决策

采用第三种作为实施原则。先做定向源码研究与最小机制验证，再搭建生产工程。机制借鉴后按本项目需求实现也是有效方式，不以采用上游库作为开工条件；源码改编和 fork 需有明确必要性，不要求同时引入候选。

用户后续澄清：技术栈性能优先，延迟、吞吐和内存都纳入评估，Rust 可作为主要候选。该澄清修正本 ADR 最初偏重“直接复用优先”的表述，保留研究成熟经验和避免照搬的原则。具体编码使用 GPT-5.6 Luna xhigh；方案分析与验证职责分开，不把模型设置写入产品运行架构。

## 原因、代价与影响

将开发重点放到长期项目状态、验收证据、人机交接及工作台。代价是增加一次前置验证，并可能增加同机执行进程；具体拓扑只有验证后才决定。

影响技术选型、Runtime、部署候选、P00/P05/P08/P09/P12 与后续物理设计复核。保留 ADR-001 的业务事务原则和既有 ADR 历史；本决策不宣称接受所有旧 Proposed 方案，也不撤销权限和恢复约束。
