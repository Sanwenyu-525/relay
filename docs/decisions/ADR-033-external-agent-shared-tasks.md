# ADR-033：外部 Agent 通过共享任务参与项目协作

## 状态

Accepted（2026-10-23 用户逐项确认的产品范围与应用边界）。工程协议待核定；本增量待实现、未验收。授权仅为文档，不启动代码开发。

## 背景

用户提出将禅道能力变成项目内置 A2A，讨论后明确目标为需求、Bug 与任务协作，并选择外部 Agent 主动领取共享任务。单纯增加内置 Agent 数量不足以覆盖不同编码工具之间的交接。产品规则唯一归[总纲 §0.10 的本专题](../../Personal_Workflow_OS_Master_Spec.md#项目事项与外部-agent-共享任务协作)。

## 候选方案

| 方案 | 收益 | 代价 |
|---|---|---|
| 仅内置多 Agent | 可复用主子委派入口 | 不覆盖外部工具共享任务的目标 |
| 外部 Agent 主动领取与提交 | 用统一事项、版本、执行权和证据连接不同工具，符合当前选择 | 需要身份、原子领取、失联核对与交接；没有在线领取者就等待 |
| Relay 直接启动或连接并调度外部 Agent | 可进一步减少人工唤起 | 需要工具专用生命周期、停止与副作用核对，超出第一版 |
| 禅道长期双向同步 | 保留原管理工具 | 增加双写、冲突与当前事实归属问题，用户未选择 |

## 最终决策

采用第二项。本机 API 与 MCP 只是同一应用用例的入口，不另立业务 Owner。先以 Relay 自身新事项试运行，保留禅道旧事项的当前归属；后续迁移单独决定。

本 ADR 不替代 [ADR-017](ADR-017-bounded-multi-agent-conversations.md)：其主实施、子只读的一层委派边界继续在原场景成立。本方案允许外部开发者领取各自 Task，在独立 worktree 中产生结果，不把可写执行塞入只读子委派，也不由此授权通用多 Agent Router。标准 A2A 协议、远程接入与直接调度均不在本次决定内。

## 决策原因

2026-10-23 接续：[ADR-034](ADR-034-persistent-project-agent-team.md) 确认外部执行者也可表达为项目长期成员，成员身份与会话、运行方式分离；本 ADR 的主动领取、权限、失联核对、确切版本验收与人工批准集成保持有效。不增加直接启动外部工具或远程接入，不把离线成员当成正在运行。

将需求与缺陷管理连接到现有 Task、Run、Artifact、Verification 和人工判断，直接服务跨工具交接；主动领取可以先验证闭环，避免第一版同时承担多个外部工具的启动和停止。默认独立 worktree 与确切结果版本有利于固定验收对象；人工批准后再集成保留最终控制。

## 代价

外部工具仍可能在失联时运行，不能自动释放资源；独立身份不等于独立验收证明，接口权限也不是本机进程隔离。需承担领取、版本、权限、迟到结果、返工计数、集成冲突与回归的协议成本；通过实际试运行评估协调收益，不预先宣称效率提升。

## 影响范围

需求/Bug 所属领域入口、Task/Workflow、Application、权限与资源控制、Artifact/Verification/Review、项目事项及聊天投影、本机 API/MCP。责任映射归[领域模型 §22](../architecture/domain-model.md#22-外部-agent-共享任务的应用边界)。

本轮没有新增或修改运行 API、数据库及依赖；Breaking Change：No。后续须在实施前冻结实际请求、响应、迁移、兼容与回滚风险，不能从本 ADR 推定端点或表已存在。
