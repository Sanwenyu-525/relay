# ADR-028：长期事实与短期会话记忆分层

## 状态

Accepted（产品边界与工程方向；实现和验收进度只归 CODEX_NEXT_STEP 与统一验收表）。

## 日期

2026-10-19。

## 背景

用户要求完整推进长期、短期等记忆模块，完成大模块后再统一交付前端任务书；随后确认「自动召回已确认记忆，并可关闭」。既有 Memory 有明确确认、不可变版本、停用/恢复与有效期，但普通 Assist 主要使用显式来源，历史只取最近 20 条。它们不构成完整的记忆与接续能力。

## 候选方案

1. 只保留显式来源：边界简单，但不能满足用户确认的自动召回。
2. 从聊天自动提取并确认事实：减少操作，但会把模型推断变成长期事实，违背原人工确认边界，未获本次授权。
3. 已确认长期事实有界召回＋独立短期工作窗口：保留各自 Owner 与失效语义，支持关闭、来源追溯和持久接续；代价是额外配置、检查点与模型调用管理。

## 决策

采用方案 3。Information 继续拥有长期 Memory；从会话保存必须用户明确确认、显式选定 Workspace/Project 范围并冻结原消息身份/hash，不把摘要自动升级为事实。自动召回仅限普通 AGENT 的同 Workspace 全局记忆和当前 Project，排除已停用、过期与不可用来源，并可通过持久设置关闭。采用有界字面匹配及近期回退，不引入向量库。

Assist/Application 拥有短期会话窗口、检查点和压缩请求；原历史保留，检查点提交后才更换工作窗口。手动和自动压缩沿 ADR-019：当前工作模型、完整轮次安全边界、稳定前缀、原预算和计量；摘要作为带来源的数据，不能替代项目状态、权限、验收或执行恢复。LangGraph Run checkpoints 仍归原 Workflow，不与会话摘要混用。

## 代价与限制

召回不等于事实正确，也不保证每次必定选中。关闭召回或来源失效时，旧自动来源不能从历史答复/摘要匿名回流。摘要存在语义损失与额外模型成本，必须保留原文和确切覆盖边界；失败或旧 Worker 结果不能覆盖新窗口。真实 Provider、质量与缓存收益需另有实际证据，不由 Fake 工程测试证明。

## 影响与后续

涉及 Information、Assist、API、数据库、模型调用计量、Worker 调度、Context/来源读取与后续前端；不新增执行权限、自动画像或自动长期保存。具体工程边界与完整完成审计见[记忆模块](../development/memory-module.md)。本 ADR 接续 ADR-019，不替代其文件恢复等其他能力，也不宣称这些能力因记忆模块开发而完成。

2026-10-20 接续：[ADR-029](ADR-029-auto-memory-candidates.md) 在**不改变本文确认与召回不变量**的前提下，把「发现有价值内容」自动化（模型只产候选，人工确认后才成为 Memory）。本文候选方案 2 的排除理由仍然成立——它排除的是「自动确认」，不是「自动提取」。

## 分批接续实施细化（2026-10-30）

背景：用户要求修复累计历史10000条限制、压缩请求本身过大及资料/工具增长未进入容量判断的问题。继续每次读取并摘要整个前缀，会保留累计限制；直接丢弃前缀或活动工具结果会破坏恢复与来源语义。

决定：沿用本 ADR 的检查点与原文增量模型，每批选择能容纳的完整轮次前缀，并冻结父检查点身份、起始序号与本批确切消息/hash。每批独立 CAS 发布，成功后再准备下一批，失败保留最后一个已提交窗口。复用现有请求冻结 JSON 保存批次游标，不新增表或独立工作流；旧无游标请求保留原消费路径。对外来源投影沿父链合并，保持既有累计来源含义。

代价：大历史需要多次模型调用，单个模型仍装不下的完整轮次只能明确拒绝，不能静默拆断工具协议；手动请求完成表示这一批完成，自动链在后续 tick 持续推进到压力回落。检查点原文与父链保留，读取完整来源列表仍有随历史增长的成本。模型调用保持在数据库事务外，批次提交前继续复核来源、取消、租约与权限基线。活动工具循环只做容量预检和提前收尾，不在途中重建或重放工具。
