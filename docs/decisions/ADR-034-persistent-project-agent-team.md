# ADR-034：项目级长期 Agent 成员与跨会话协作

## 状态与日期

Accepted，2026-10-23。依据为本次用户逐项选择项目全过程、项目级成员、自主推进、内外运行统一身份、私聊/群聊及模型配置，并明确“额度不上限”，最后授权“落成文档”。仅确认产品及逻辑边界；具体协议待核定，长期团队增量待实现、未验收，不启动开发。

## 背景

临时会话内委派与外部共享任务解决局部执行和交接，无法单独表达长期职责、跨会话接续及项目团队。用户以 Grok Bot 的长期队友体验为参照，希望产品、设计、开发、测试等成员持续负责项目，而非每次重建角色和转述上下文。产品规则唯一归[总纲 §0.18](../../Personal_Workflow_OS_Master_Spec.md#018-项目级长期-agent-团队与跨会话协作)。

## 候选方案

| 方案 | 收益 | 代价 |
|---|---|---|
| 仅在单次会话内派子代理 | 复用有界委派，生命周期简单 | 不表达跨会话长期职责 |
| 项目级长期成员，身份与会话、运行分离 | 职责和记录可持续，内置/外部成员共享任务事实 | 需成员、上下文、消息、唤醒、授权及恢复契约 |
| 工作空间级自治团队、平等投票及持续模型循环 | 更广泛自主工作 | 跨项目权限和上下文、决定权及无进展循环更复杂，本次未选择 |

## 最终决策与原因

采用第二项，按需创建成员并提供角色模板，由项目协调者统筹，成员可直接交流；授权明确范围，采用事件唤醒与定期巡检，而非无变化时持续调用模型。项目不额外设累计消耗上限，计量与既有技术、权限、返工及人工决定边界仍保留。这样同时支持长期职责和可追溯执行，不用聊天内容代替业务事实。

成员身份独立于模型和运行方式；内置和外部均可作为成员，外部沿本机主动领取协议参与，离线不假装运行。关闭窗口继续本机运行，明确退出或关机后停止，重启核对再恢复；第一版不增加系统服务或云端运行承诺。

## 与旧决策的关系

- [ADR-017](ADR-017-bounded-multi-agent-conversations.md) 保留为会话内临时只读子委派机制，其两子一层及有界故障重试不作为长期团队总成员或累计预算限制。旧候选中不做长期角色的范围取舍，在本新增项目团队范围由本 ADR 接续；不把原子代理改成可写长期成员。
- [ADR-033](ADR-033-external-agent-shared-tasks.md) 的事项、外部主动领取、确切产物、独立验收、返工与人工批准集成保持有效；本 ADR 新增外部执行者作为长期成员的身份表达，未增加直接启动外部工具、远程或标准 A2A 协议支持。
- [ADR-018](ADR-018-assistant-conversations.md) 的只读人设助手继续保持只读；长期成员的工作记忆与权限须走所属入口，不通过换称呼或群聊赋予写入权。

## 代价

需处理跨会话上下文来源与隔离、消息去重、并发激活、授权撤销、配置变化和恢复；协调成员不能成为第二个业务写入 Owner。无项目额外额度上限会增加持续运行消耗，仍需真实计量、无工作等待和循环终止。外部执行者的独立性、成本及停止效果不能仅凭成员身份保证，存在未知时如实呈现。

## 影响范围

项目成员与配置、Assist 会话、Application 协调、Task/Workflow、权限与资源、Context/记忆、后台唤醒、通知、私聊/群聊/概览及本机外部接入。继续单用户同机模块化单体、单一业务事务库与既有 LangGraph/PG 边界，不引入第二个通用编排器。

本轮仅文档；运行 API/数据库变更：无；Breaking Change：No。后续新增契约、迁移、现有会话/助手兼容及回滚风险须在实施前核定，不凭本文预建表或端点。
