# ADR-021：有限任务链复用原准入与完成 Owner

## 状态

Accepted，2026-10-14；当前基础任务链、只读来源与受控修改/检查协议，不升级 ADR-013 的完整后续方案或 M/N 总出口。

## 背景与候选

用户授权继续基础前后端开发，UI 后置。N06 已确认串行、明确授权、累计任务/调用上限、到期安全暂停和重开人工继续；现有 Delegate、Run/LangGraph、账本、Review/Complete 与 Control 已拥有业务事实。

候选 A：新建通用链图与第二套执行状态。代价是重复 Run/验收/恢复责任，不符合唯一通用图边界。候选 B：在应用层保存有限队列/授权，原 Owner 再查准入与短事务效果；复用现有图、审批与完成，需给原 ready/Delegate/resume 和模型 STARTED 事务增加专用链绑定检查。

## 决策、理由与代价

采用 B。TaskChain 只拥有固定选择、授权/预算、原 Task/Run/Completion 引用及队列接续；ACTIVE 是允许协调，不是模型正在运行。ready/Delegate 与链绑定/任务预留同原命令事务提交；调用预留与原 model_calls STARTED 同事务，失败回滚不扣未发调用，未知记录不释放或按零继续。

下一项依确切原 Run 完成与 Task 当前完成凭据，人工判断仍走原入口。停止与到期复用持久 PAUSE，实际安全应用前保持 PAUSING；API 重开只核对/转等待确认，保留身份和消耗。运行实例标识是内部准入元数据，不进入业务命令摘要、不生成 Task/Run 身份或代替执行权证明。

首片只接内部 Markdown 成果，无外部工具动作。每链至多 16 项、确认调用上限至多 100、有效期至多 24 小时；重新授权保留累计消耗，仅在非活动/停止中状态进行，不做活动中无缝续期。新依赖、通用 Workflow Builder、自动规划、价格/金额硬上限、UI 与并发/故障全矩阵不进入本片。

## 影响与后续

受控修改/检查接续：复用原注册工具、RunScopeGrant、ACTION_APPROVAL、文件基线/变化集和配置检查，沿 0085 规格增加有限范围授权与原 MODIFY 方法，不引入新的执行器。创建不签发有效授权；原 Delegate 按每项、每 Run 创建范围，期限不超过本链授权、不跨 Run 终态。检查材料在创建与准入时核对，沿原冻结函数共享依据；保留只读方法不改文件、DENY 不覆盖、检查失败可修正后重查、原人工完成后才接下项。代价是旧检查材料变化需重新圈定，链续期不更新既有 Run 授权；没有活动无缝续期或全自动人工验收。协议归 HTTP §10.79，实际成绩仍只归统一表。

2026-10-14 只读规格接续：在原队列项追加 0085 execution_spec，允许原固定文件读取或只读工具循环、确切资料版本和原会话 INSPECT 方法；仍复用原 Owner，不添加权限、Workflow 或模型端口。原首片“无外部工具”范围由此扩到只读文件，写入/命令仍未进入。首轮检查误以 resource_epoch 变化判配置失效，第二项在正常读取后被挡；该字段实际是原 Gateway 每次资源领取的栅栏，改核对配置 revision/identity_key/canonical_root，保留原隔离/占有检查。原数据记录和失败检查保留，复验结果只归统一表。

影响应用协调、原 ready/Delegate/resume 专用内部参数、模型调用预留、API/客户端、0084 两表与 0085 规格列；公共旧命令摘要和默认行为保持。协议归 HTTP §10.77–10.79、数据库 §85–86、领域模型 §21；实际成绩只归统一验收表。后续自定义来源/方法须沿原权限、资源隔离、UNKNOWN 与运行入口另接，不能从当前授权扩张能力。
