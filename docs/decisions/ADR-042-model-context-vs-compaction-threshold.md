# ADR-042：模型窗口是能力，压缩阈值是偏好，安全预算由系统收敛

## 状态

Accepted（用户 2026-11-15 明确要求「模型决定上下文容量，用户决定压缩时机，系统负责安全保护」）。
实现与验证结果归统一验收表「上下文窗口与压缩阈值解耦」行、HTTP §10.137 与
[实施报告](../development/context-window-compaction-0165.md)；本文件只记取舍。
实施者自检，未独立验收。

## 日期

2026-11-15。

## 背景

0143/0162 的会话档位（256K / 512K / 1024K）同时被当成单次调用预算、压缩阈值来源、
上下文窗口和普通用户的设置入口。它带来三个结构性错误：

1. 用户选 1M 会被读成「模型支持 1M」，而模型真实窗口可能更小或未知；
2. 模型切换后，预算与阈值可能继续沿用切换前的档位；
3. 用户被迫同时配置「上下文窗口」和「压缩阈值」，两个数实际上只应有一个是偏好。

0145 的旧连接默认 `65,536` 还会把默认 350K 阈值压到约 59K，使默认功能失效。

## 决策

采用三层分离，且不引入第二套上下文管理系统：

- **模型容量层** `modelWindowTokens`：只从模型目录 `context_window`、高级能力声明
  `model_capability_declarations.context_window_tokens`、部署配置
  `RELAY_MODEL_CONTEXT_WINDOW` 读取；都没有时按 `262,144` 安全回退，标
  `UNKNOWN_FALLBACK`，不假定 1M。模型目录/声明读取失败只 `warn`。
- **用户偏好层** `compactionThresholdTokens`：默认 `350,000`，保存范围
  `16,384–1,000,000`，推荐 `256,000–400,000` 只提示。模型窗口变大不得自动放大用户值。
- **系统安全层**：有效窗口 = `min(1,000,000, 模型窗口/回退, 服务商单次上限)`；安全输入扣
  输出预留、协议/工具 `8,192` 与 `ceil(有效窗口 × 5%)`；生效阈值 =
  `min(用户值, floor(安全输入 × 0.9))`；压缩后目标 =
  `min(100,000, floor(生效阈值 / 2))`。

普通用户设置页只保留自动压缩开关与阈值数字输入；上下文浮层只读显示模型窗口来源、
用户设置、实际生效值及收敛原因；手动压缩、自动压缩开关、会话与任务恢复保留。
旧 `context_budget_tokens`、旧工作区默认档位与旧 `/context-budget` 仅作兼容保留，执行、
压缩、审计不再读取。迁移 0165 只加能力声明列、提升仍为旧双默认的连接预算并给旧档位列
加 LEGACY 注释，不删数据、不把旧档位无条件转成阈值。

## 候选与取舍

| 候选 | 结论 | 理由 |
|---|---|---|
| 保留会话档位作窗口，只改 UI 文案 | 否决 | 仍让用户配置虚构模型能力，模型切换/未知窗口问题不解决 |
| 用户设置 1M 就直接按 1M | 否决 | 覆盖模型真实能力，会产生无保护的溢出 |
| 模型窗口变大时把阈值同比放大 | 否决 | 违反「用户决定时机」，且大窗口下更晚压缩会增加失败半径 |
| 未知窗口假定 1M | 否决 | 无法确认能力时最危险；262,144 回退可计算、可解释 |
| 立即删除旧档位列/端点 | 否决 | 破坏在途会话、旧客户端与并行迁移；先兼容保留、停止读取 |
| 新增独立「上下文管理器」模块 | 否决 | 与既有预算/压缩/投影重复，违反复用优先 |

## 后果

- 正面：普通用户只有一个主参数；模型切换每次都按当前选择重新解析容量；未知窗口不伪装
  1M；旧默认连接提升后默认 350K 阈值可用（1M 窗口中生效 350K）。
- 代价：窗口未知时默认 350K 会被收敛到约 209K，界面必须说明；迁移只回填完全等于旧双
  默认的连接，显式小预算保持原值，可能仍低于 1M；旧 `/context-budget` 仍可写但不生效，
  需后续标 Deprecated。
- 验证缺口：真实 Provider 窗口声明/分词器、真实 Windows/WebView2/安装态未验；本轮为
  实施者自检，未独立验收、未 commit。
