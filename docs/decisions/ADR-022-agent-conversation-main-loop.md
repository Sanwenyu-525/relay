# ADR-022：普通 Agent 采用连续工具主流程

## 状态

Accepted（2026-10-15，用户确认产品与编排方向）。阶段 A/B/C 已有对应实现；2026-10-16 接续阶段 D：普通消息不再由前端另发执行/状态解释，首条先持久绑定目录，按原消息读取主流程结果，旧请求/决定/撤回仍沿原 Owner。会话↔Run 的完整结果投影等剩余范围仍见[功能验收表](../testing/overall-acceptance-2026-09-28.md#当前功能验收表)，本决策不等于整体交付。

本决策接续 [ADR-016](ADR-016-folder-first-conversation.md) 的明确请求直接执行原则；其目录、授权和业务 Owner 边界继续有效。现有固定分类与二次开始按钮不是新的默认交互要求，历史实现和验收证据保留。

## 日期

2026-10-15。

## 背景

用户在绑定目录的普通 Agent 会话请求“看一下这个目录下面的文件”，截图同时出现项目状态维护澄清和没有文件读取能力的聊天回复。源码核对发现：普通 Assist 未提供文件工具，前端发送后分别触发执行解释和状态维护解释，执行解释的模型输入来自原消息且未附绑定目录上下文。已有 `selectRuntimePrompt()` 是确定性模板选择器，与额外的模型意图分类不是同一职责。

以上说明当前链路存在上下文和回复分裂的结构风险；原截图消息的数据库当时不可连接，尚未核实其具体执行请求/Run/工具记录，不能把结构诊断当作该消息的完整运行根因或权限拒绝证据。

## 候选方案

| 方案 | 优点 | 代价 |
|---|---|---|
| 保留三路模型处理，仅补目录与措辞 | 局部改动小 | 仍要协调重复解释、冲突回复、重复调用和状态恢复，基础读取仍依赖额外分类 |
| 保留三路处理，加集中分类器选择分支 | 可减少部分并行冲突 | 分类成为每条消息的前置关卡，继续增加模型判断与独立恢复边界 |
| 一条连续主流程，按必要工具衔接原应用用例 | 同轮取得真实结果并回复，普通查看不需要业务表单或重复分类 | 须补齐会话只读适配、业务工具、Run 接续、幂等和旧请求兼容 |

## 最终决策

选择第三项。普通 AGENT 消息以原用户消息和当前作用域为输入，在一条逻辑轮次中回答、澄清或请求工具；应用负责实际准入与执行，结果回到原轮次和原会话。主流程可以调用模型多次，不再固定启动三个各自判断同一句话的分支。

纯讨论和会话读取不创建占位 Task/Run，复用已有会话只读账本与 Gateway；修改文件或运行检查沿原 Task/Run，业务状态维护沿各对象原 Owner。模型不能直接写业务数据库或把工具调用当批准。原验证、人工接受、业务完成、控制和 UNKNOWN 边界不变。

保留确定性的模板选择器、模式隔离、冻结 Skill/方法和专用验证协议。重构不引入新 Runtime、多 Agent Router、通用意图 DSL 或任意 Shell。

## 决策原因

目录已绑定且用户明确要求查看时，重复追问目录或业务状态目标没有提供必要信息。让实际工具结果进入同一轮回复，可以把文件能力、当前阶段和结果证据保持一致；业务正确性由确定性用例与原权限边界保证，无需每条普通消息先完成两次模型分类。

## 代价

普通 AGENT 须合法复用会话读取机制，不能冒充人设来源；会话轮次接续 Run 须持久保存责任和结果关联，避免双 Worker 推进同一动作。旧请求、审批、撤回及部分成功需保留原身份恢复，不能删除分类端点后丢失在途工作。模型调用成本和识别质量需实际评价，不由流程图保证。

## 影响范围

产品规则、会话上下文、Application 编排、会话只读工具、Task/Run 接续、状态维护适配、原会话展示和测试规格。API/数据库的具体变化、Breaking Change 与兼容方案在实施前核定；本次不修改运行协议、数据库或模型模板源码。
