# ADR-040 会话标题的来源、所有权与后台系统命名

- 状态：Accepted（2026-11-01 实施，实施者自检；独立验收未做）
- 日期：2026-11-01
- 相关：ADR-018（Assist 会话）、ADR-030（自动记忆）、ADR-039（后台 tick 常驻宿主）、HTTP §10.132

## 背景

会话标题在旧实现里只有一个字符串：界面把首条消息截 30 字，关联目标时写 `关于<目标>`，之后只能人工改名。三个问题：

1. **没有来源事实。** 无法回答「这个标题是用户写的、系统占位的，还是语义生成的」，因此自动命名无论怎么做都可能覆盖用户刚输入的名字。
2. **临时标题不是任务描述。** 首条消息前 30 字通常只是半句话；它既不像任务，也不随对话演进。
3. **模型结果没有可核对的请求身份。** 一次外呼迟到、并发或服务重启之后，没有依据判断「这份输出还能不能写」。

标题仍是 Assist 模块的导航事实，不是 Task/Run 的业务状态；它不应引入新的执行权，也不应让 UI 拥有「能否覆盖」的判定权。

## 决定

1. **会话行记录标题来源。** `assist_sessions.title_source ∈ LEGACY | PROVISIONAL | AI_GENERATED | USER_DEFINED`。迁移只给旧行打 `LEGACY`，**不批量改名**；用户手动改名在同一个 CAS 里写 `USER_DEFINED`。
2. **调用方可声明占位标题。** `CreateAssistSession` 新增可选 `title_source`：不传按 `USER_DEFINED`（既有调用方显式给的名字受保护）；工作台传 `PROVISIONAL`，由服务端把未关联目标的占位文本规范化为 `分类-任务名`，关联项目/任务的讨论保留 `关于<目标>` 直到首次语义生成。
3. **分类与格式只由后端定义。** 固定枚举 UI／功能／修复／架构／测试／调研／文档／其他；模型只返回 `{"category","subject"}`，由服务端校验（长度、中文、无 Markdown／Emoji／执行状态／模糊话术）并拼接标题。界面不复制词表，也不拼标题。
4. **一次生成 = 一条持久请求。** `assist_title_generations` 保存 `request_kind`、领取租约、尝试次数、冻结的 `base_title`/`base_title_source`、输入摘要与终态。AUTO 请求只入队、不在主生成循环里调用模型；常驻后台 tick（ADR-039 的宿主）领取并推进。
5. **落标题必须 CAS。** 只有请求仍由本次领取持有、会话仍 ACTIVE、**标题与来源仍等于请求时冻结的那一份**，才写标题并推进 `revision`；否则请求停在 `SKIPPED`。迟到的模型输出不能覆盖用户之后的手动改名。
6. **显式重新生成是唯一的越权入口。** `POST /assist-sessions/{id}/title/generate` 只受理、返回 `request_id`，仍走 `command_id` 幂等与 `expected_revision` CAS。它允许替换 `USER_DEFINED`/`LEGACY`，因为这是用户本人当前的选择；自动请求永远不越过这条边界，UI 对 `USER_DEFINED` 先确认再发。
7. **模型失败有确定性降级。** 没有真实模型配置、超时或输出不合规时，AUTO 用规则标题（`generator='RULES'`，来源仍 `PROVISIONAL`）；显式重新生成如实 `FAILED` 并保留原标题。模型错误不变成主 Agent 错误，也不改消息终态。
8. **频率保守。** 同一会话 10 分钟内最多一次 AUTO 请求；已有正式标题后，只有用户消息出现明确换任务标记才再次入队。无法可靠判断目标变化时保持原标题，不为了「看起来智能」而频繁跳动。
9. **辅助外呼单独记账。** `model_calls.purpose` 增 `TITLE`：进账本与预算闸门，但不抢「最近一次调用」读数，也不计入本轮 PRIMARY 用量。输入只含首条有效用户消息、最近用户消息、关联任务/项目标题与刚结算的回复摘要，整体包在 `<untrusted_data>`；不读工具日志、文件正文、附件或凭据。
10. **短首发输入不自动命名（2026-11-10 补充）。** 首轮用户消息去空白后不足 10 个字符时不写 `assist_title_generations` 请求：这类输入本身就是可读的临时标题（例如「其他-你好」），继续命名只会多一次真实外呼，并把它稳定覆盖成泛化分类。口径与上游 ZCode 相同（`MIN_GENERATED_TITLE_INPUT_CHARS = 10`）；显式重新生成不受这条限制。为此，纯寒暄的 `PROVISIONAL` 标题保留首条消息原文，不再退化成 `其他-新会话`。

## 候选与取舍

- **只靠规则、不调模型。** 分类与临时标题可以确定性生成，但无法从「聊了几句界面布局」提炼出「聊天消息宽度与布局优化」；规则只作降级，不冒充语义分析。
- **客户端调模型并直接写标题。** 会让 UI 成为覆盖规则的执行者，也无法持久化并发与恢复状态；否决。
- **在主回复生成循环里同步再调一次模型。** 会推迟下一条排队消息，且标题失败可能连累回复；改为结算后只入队。
- **为标题另建一套调度器。** ADR-039 已把「谁周期性调用」收口到常驻宿主；复用同一 tick 加一个阶段，不新建进程、队列或状态机。
- **每次回复都重新命名。** 标题会不断跳动，且成本不可控；改为首次 + 明确换任务标记 + 人工显式重新生成。
- **把规则标题标成 `AI_GENERATED`。** 会虚假宣称经过语义分析；规则降级保持 `PROVISIONAL`，模型可用时可再升级。

## 后果与代价

- 新增一张会话自有子表与两列；删除会话按既有 ADR-027 路径需要 DELETE 授权，0157 已补。
- 标题变化会推进会话 `revision`（与改名同一口径），因此打开中的旧修订会在下一次改名/置顶时撞 409；界面按既有「重读后由人决定」处理，不自动重发。
- 没有真实模型配置时，自动标题只有规则级质量；用户可显式重新生成，模型恢复后再试。
- `title_generation` 是每行一个 lateral 读取，列表查询仍是一条语句；代价在左栏行数上，可接受。
- 旧会话不会被自动改名；这满足「不因迁移批量改名」，但旧会话也不会从新能力中自动获益，除非用户显式重新生成。

## 未取证的边界

- 真实 Provider 的标题语义质量（分类准确率、中文提炼质量）只用受控 Fake 端口验证；不声称已达到产品级命名质量。
- 真实 Windows/WebView2、多 DPI、安装态未验；产品当前只有亮色主题。
- 标题生成 tick 在真实 Supervisor 拓扑下的长期节奏只由 API 常驻调度与受控触发证明，未在实机窗口里长时间观察。
- 并发两个 tick、进程崩溃后的租约接管与重复投递只在仓储/集成层验证；没有在多机或真实双进程下压测。
- 换任务标记是保守闭集，真实用户可能用没有命中的表达；此时标题保持原样，而不是猜测。
