# ADR-014：维护排空采用数据库级持久准入门

## 状态与日期

Accepted，2026-09-30。仅决定 P20/M07 首片的新工作准入边界；实现、自检与独立验收范围见[功能验收表](../testing/overall-acceptance-2026-09-28.md#当前功能验收表)。不代表完整备份、恢复或 M07 已通过。

## 背景

用户已授权继续 M 阶段，并允许提前开发不依赖前序的 M07 内容。完整备份需要先停止新工作进入，同时保留在途执行按原身份安全结算的能力。现有 HTTP 命令、Run、Assist 和 Web 领取来自不同进程；关闭 UI 或单进程开关不能形成持久准入边界。备份目标包含同一业务库内全部 Workspace 和图 schema。

## 候选方案

| 方案 | 优点 | 代价 |
|---|---|---|
| HTTP 或进程内维护标志 | 改动小 | 重启丢失，后台领取可绕过，不能裁决并发提交 |
| Workspace 独立开关 | 可单独维护一个工作区 | 不能覆盖整库备份，易遗漏同库其他 Workspace |
| 数据库单行准入门 | 跨进程持久，与短事务竞争具有明确提交顺序 | 所有首次命令和新领取必须参与；不能直接证明在途写入已停止 |

## 决策与原因

采用数据库单行 `NORMAL/DRAINING` 状态及 revision，由维护应用用例协调，Repository 为唯一运行期 SQL 写入 Owner，受信本机 CLI 为调用入口。首次业务命令和新领取在业务锁前持行级 `FOR SHARE`；维护变更使用专用事务先持同一行 `FOR UPDATE`，CAS 状态与原命令回执一起提交，避免共享锁升级。使用有界锁等待，失败整笔回滚。`FOR SHARE` 能与修改非键字段的 UPDATE 冲突，`FOR KEY SHARE` 不具备此保证，依据 [PostgreSQL 18 行锁语义](https://www.postgresql.org/docs/18/explicit-locking.html#LOCKING-ROWS)；实际竞争仍须真实 PG 验证。

业务命令先查旧回执，等待门锁后再次查回执；既有同内容回执可重放，不同内容仍报命令 ID 冲突。行锁不承诺排队 FIFO，竞争测试依据实际取锁与提交顺序，不能用请求先后推断获准顺序。门锁成功后恢复调用方原 lock_timeout，较短原期限保留，不把维护等待期限施加到后续业务锁。DRAINING 下只有固定的停止、取消和具有原停机证据的部分文件写入安全终结可首次提交，不接受客户端提供的绕过参数。缺行、权限失败或状态损坏拒绝新准入，不推断 NORMAL。状态变更的时间与原命令结果沿已有持久回执追溯，不额外复制运行日志。

## 代价与影响

影响新 migration、应用命令、两类自定义提案接受、新 Run/Assist/Web 领取、没有原 delivery 的 Gateway 领取及独立模型连接验证的 STARTED 预约；HTTP 增加 typed 维护错误，中文界面解释维护拒绝。验证协调归 Application，配置/transport 保留 Workflow，探针外呼在预约短事务之外；DRAINING 中拒绝新探针但允许原调用结算。查询、原回执、停止控制、既有领取的心跳/恢复/派发/内容发布/图 Saver/结算保持原规则，Task/Run/UNKNOWN 状态不因维护而改写。`resume-admission` 只开放准入，不恢复 Run 或解除隔离。

此前已领取工作仍可能写入；DRAINING 不能用于直接宣布快照静止或发布备份成功标志。旧二进制没有参与新门，升级启用前须停止旧版本。数据库字段、迁移兼容和回滚风险归[物理设计](../database/physical-design-postgresql.md)，运行说明归[部署设计](../deployment/本机部署.md#4-备份恢复)，不新增 HTTP 状态页或自动备份。

## 后续

下一片须证明在途副作用、内容发布、短事务、Saver 与旧进程已到安全边界，再实现备份和恢复隔离；未决 UNKNOWN 保留原身份。首片不定义无调用方的 FROZEN/RESTORE 枚举，也不把租约过期、超时或 pg_dump 单独当作静止证明。

## 2026-10-01 接续决定：复用原宿主的可信停机 Owner

Accepted。采用同一桌面 EXE 的严格无窗口私有入口，复用原命名 Job/ARMED 不变量，并持续持有旧单实例 guard。相较按 PID/租约等待，它具有原进程组身份及 OS 停机查询；相较启动普通宿主，它不会读取配置、开新 Worker 或将维护中旧工作重新派发。Node 必须校验新包能力及 EXE 摘要，握手后仍持续核对会话健康，不能把输出 JSON 导入为永久停机授权。

代价是依赖新的 Windows 包、仅涵盖当前登录会话，原 ARMED 超界或损坏必须人工核对；其他进程与文件/数据库安全点不能由这个 guard 代替。不变更 Task/Run/UNKNOWN，不新增业务 schema/HTTP 接口。具体失败根因归[M07 开发记录](../development/m07-backup-recovery.md)，实际出口仍由功能验收表限定。

## 2026-10-01 接续决定：独立数据库连接维护会话

Accepted。以原数据库Owner的独立migrator Client持原业务/Graph会话锁，在权限变更前保存不可变有效ACL凭据，短事务提交本库PUBLIC/app CONNECT撤销，再拒绝残余连接、启动连接和prepared transaction。相较仅REVOKE或关闭业务池，它覆盖旧Saver池和授权后尚在启动的连接；相较ALLOW_CONNECTIONS=false，它保留受信dump与恢复连接。相较新增全局监控/强杀权限，它依原catalog可见身份与目标库启动对象锁保守拒绝未知写者，不扩大运行账号权限。

失败恢复只补偿本操作可能已提交的权限变更；未尝试COMMIT的前置失败不恢复外部变更。原凭据不重写，按当前完整有效ACL裁决幂等恢复与漂移拒绝。代价为受信运维角色/本地凭据、目标身份绑定、不可分类连接的保守拒绝及异常后的显式恢复；Owner/管理员与外部文件写者仍是独立边界。该会话不是FROZEN或完整备份协调器，不改业务状态、数据库表、HTTP契约及恢复Owner。操作说明归[部署设计](../deployment/本机部署.md#数据库连接维护与权限恢复)，故障依据归开发记录。

## 2026-10-01 接续决定：恢复目标在普通启动前隔离

Accepted。DRAINING仍允许原控制、恢复及结算，不能阻止复制来的历史执行被普通入口消费；数据库也可能处于尚未还原的状态。因此采用data_root根目录项 `restore-isolation.json`，在宿主创建目录、恢复旧Job/ARMED、建立新Job和启动子进程前检查，监督器重启亦参与；API、Worker与Node监督器在创建数据库池、监听、旧launch核销和派发前检查。任何标记目录项都拒绝，正文不构成放行权限；链接、目录或损坏正文不绕过，无法可靠确认缺失也拒绝。无标记的正常目录别名与首次安装保持既有行为。

相较仅靠数据库DRAINING，它无需已恢复schema且覆盖Job恢复；相较把标记正文解析成状态机，它不允许“恢复完成”自动授予执行权限。代价是所有目标运行入口必须升级。构建产物前检通过才声明 `relay-restore-isolation-v1`，目标运行包须另核验此能力、EXE及全部Node入口摘要；原包仍用于核对备份历史，不因hash完整就拥有新能力。此声明与诊断不是发布者签名或对抗管理员的隔离。

此决定的首片实现普通启动检查与包能力诊断，当时未实现恢复目标创建/还原或显式放行。后续恢复协调器须使用新空库与新data_root，先持久隔离再还原；目标CONNECT隔离在成功、失败和取消后均保留，只读核对不触发普通恢复Owner。源库备份会话结束会恢复ACL，不能直接复用为目标生命周期。不得仅删除标记、解除DRAINING或凭旧停止证明开放执行；原ARMED只放evidence，外部资源和UNKNOWN保留原身份。在线运行实例不会因为后来添加文件就自动停止，标记不是停机协议。影响范围是宿主/Node启动、构建清单及后续恢复准入；本片无数据库模型或HTTP接口变更。实际验收仍只归功能验收表。

## 2026-10-01 接续实现：隔离还原不自动激活

Accepted。恢复目标生命周期使用专用版本凭据及保持隔离的close，复用角色/ACL/DDL锁检查，不复用源fence的release或权限补偿。数据根先在同父新目录写入并刷盘标记，再发布；相较先建立无标记根，它避免普通启动观察到未隔离恢复目录。归档使用受信预建空库和完整单事务还原，相较create/clean或迁移补修，它保留原Owner/ACL/历史schema，并明确拒绝覆盖既有库。原物理身份与新物理身份分别记录，业务和历史依赖按原事实核对。

新根还须与源数据根分离。复用备份已有content_root_id及目标包助手的只读原生File ID协议，匹配现存祖先即拒；相较新增原绝对路径字段/CLI参数，它兼容既有备份且可识别同卷搬迁。代价是删除重建或跨卷复制后的历史ID不能证明原路径关系，运维仍需核对选址；历史ID只用于保守拒绝，不赋予执行权。助手使用完整包核验得到的固定路径与最小环境，检查发生在创建目标目录和修改目标CONNECT前。

代价是Windows/PG18/标准角色、严格普通路径和原/目标迁移正文完全一致；暂不支持含 `=` 的数据库名（libpq连接参数歧义），本机loopback同端口/OID碰撞保守拒绝，不新增集群管理员探针权限。成功及权限COMMIT后的故障都留CONNECT撤销与根标记；COMMIT前预检失败保留目标原ACL。核对凭据不执行配置切换、旧Job恢复或动作重放。影响新增运维CLI、文件还原、目标隔离会话及只读核对，无业务migration/HTTP变化；明确激活与确切发布包/安装出口仍需后续实现和验收。

## 2026-10-01 接续决定：维护核对与激活分开

Accepted。对已隔离非空目标增加业务只读的维护核对入口，重持既有目标journal所绑定的目标/ACL/准入和合作DDL锁，核对存储材料、当前选定事实投影、清单文件与确切目标包；不再次还原、不写ACL/准入或启动业务。相较一次命令同时核对和开放执行，这一出口可独立验证，但不能证明所有历史执行兼容、外部live身份、配置选择和唯一Owner，因此报告固定 `NOT_GRANTED` 并列出待核对范围。

代价是重持/释放会话，现有native内容锁首次可能创建sentinel；它是业务只读，不是整个FS零写。原备份/原包仅由已存材料绑定，不宣称重新读取或认证历史真实性。报告仅对应持锁观察区间，未来激活须重新核对或持续保持同一有效维护会话，不能凭旧报告、resume-admission或删标记放行。目标evidence/restore材料后续维护生命周期另行闭合，不能复制为活动ARMED。影响新增运维CLI与状态读取连接参数收敛，无HTTP、数据库模型或migration变化；操作归部署说明，实际成绩仅归功能验收表。
