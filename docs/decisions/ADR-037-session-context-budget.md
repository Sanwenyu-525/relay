# ADR-037：上下文档位归属会话，用量分项按真实请求采集

## 状态

Accepted（用户 2026-10-30 明确要求「每个会话独立持久化，新会话继承跳转前所在会话；浮层展示真实可追溯的上下文构成」）。
实现与验证结果只归统一验收表与 HTTP §10.120；本文件只记取舍。

## 日期

2026-10-30。

## 背景

0135 把三档（256K / 512K / 1024K）做成**工作区**默认：一行配置、一个修订号，全工作区共用。
用户这一轮的要求与它直接冲突：会话 A 选 512K、会话 B 选 256K 必须互不影响，刷新、切会话、
重启后各自仍读自己的值；新会话从来源会话继承一次，此后独立。

同时用户要求浮层显示「这些 token 是哪来的」。现状只有 Provider 回的 `input_tokens` 总量，
它说明这一轮共送进去多少，但说不了构成；把总量平均分摊到几个分类只是换个说法，不是构成。

## 候选方案

1. **沿用工作区档位，前端按会话记 localStorage**（否决）：业务事实有两个来源，多窗口、重启、
   换设备都会漂，且与「不能只依赖 React State 或 localStorage 作为业务事实源」直接冲突。
2. **给 `assist_sessions.revision` 复用一份档位**（否决）：那份修订号被改名、置顶、归档、
   切模式共用，一次无关的重命名会把用户的保存打成 409。
3. **会话行上新增 `context_budget_tokens` + 自己的 `context_budget_revision`**（采纳）：
   档位成为会话的自己的一行事实，CAS 只被档位写入推进；工作区默认继续服务 Run、委派、
   连接验证等没有会话的消费者。
4. **按请求装配时采集分项并随调用落库**（采纳）：`model_calls.context_usage` 与 STARTED 行
   一起提交，绑定确切调用身份。事后无法还原提示词与工具结果，因此不能等到结算再算。
5. **按总量比例反推分项**（否决）：会让面板永远「相加等于总量」，也就是永远在编数字。

## 决策

采用方案 3 + 4。要点：

- 列不可空：新会话在建立事务里就写下确定档位（继承来源或 262144），「没选过」不再是一种状态，
  因此浮层里也没有「跟随应用默认」。
- 继承只发生一次，来源进命令体参与载荷 hash；来源读不到（跨工作区、已删除、响应迟到）按
  「没有来源」处理，绝不修改来源会话。
- **建会话时档位的优先级**：用户首条消息前明确选的档位 > 来源会话的档位 > 262144。
  明确选择必须进**创建事务**（而不是建完再补写），否则第一个模型调用会按错误预算冻结；
  响应丢失后按原命令重试也写同一档。
- **浮层里「选档 → 保存」**（2026-10-30 复审更正）：保留「保存档位 / 重新读取」两枚按钮。此前「不设保存按钮、选中即变」的写法**没有得到用户明确授权**（用户原话只要求每会话独立持久化、新会话继承来源、浮层展示真实构成），按任务书「无明确授权就恢复原定交互」改回。只有服务端回执才能让界面宣称「已生效」；保存中禁改档、禁重发；409 与传输失败一律保留原 command_id 并重读最新值。档位是低风险、可逆的单值设置，
  多一步确认只是仪式；写成功用回执确认、409 重读并说明、传输失败保留原 `command_id` 待核对。
  代价是「点一下就生效」需要更明确的反馈——回执、冲突、待核对三种状态因此都以行内状态行呈现。
- 分项口径是「请求里实际存在的文本」：UTF-8 字节 ÷ 3（与端口容量检查同一换算），
  分类互斥（文件类只读工具的结果记「文件读取」，其余工具内容记「工具调用」），
  注入段由装配方登记（不按正文前缀猜）。`precision` 恒为 `ESTIMATED`。
- 面板显示「最近一次调用的冻结预算」解释历史占比，同时单独显示当前会话档位；两者不同时
  明说，避免「16%」与「1024K」被读成矛盾。
- 旧行没有 `context_usage` 时显示「暂无分项统计」，总用量继续可读；不回填、不推断。

## 代价与影响

- **Breaking Change（语义）**：输入器圆环不再写工作区档位。设置页仍写它（对 Run/委派有效），
  因此同一个「上下文档位」在两个作用域各有事实，文档必须分别说明（HTTP §10.120、工作台 §27.4）。
- 冻结快照字段由 `workspace_context_budget_tokens` 改名 `context_budget_tokens`，
  解析侧兼容旧键——否则在途消息会因缺字段被判非法。
- 分项之和与 Provider 总量不相等是**预期**而非缺陷：两者口径不同，界面不追求相加相等。
- 迁移 0145 对既有会话回填（工作区档位优先，否则 262144）：升级后行为不随进程配置漂移。
