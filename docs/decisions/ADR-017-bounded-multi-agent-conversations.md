# ADR-017：有界多 Agent 与自动主子会话

## 状态

Accepted（用户已确认的首版产品规则及沿用既有业务 Owner 的原则）。具体 API、物理 schema、图/claim 协议和预算数值仍为待核定工程设计；尚未实现或验收。本轮授权仅为文档和实施提示词。

## 日期

## 背景

用户希望减少在不同 AI 之间转述、分派和催进度，并能看到自动创建的会话、回看结果和继续纠正。现有 Assist 可保存会话与独立历史，近期栏仍为 Task 投影，主 Run 无本增量委派/汇合协议；只改提示词或界面无法保证身份、预算和重启接续。

## 候选方案

| 方案 | 优点 | 代价 |
|---|---|---|
| 单 Agent 加进度摘要 | 改动小，继续复用现有执行链 | 不提供独立调查/审查及自动交接，人工协调问题未闭合 |
| 主 Agent 实现＋只读子 Agent，持久主子会话 | 能验证协调收益，保留单一代码实施责任，协作过程可回看 | 需补委派、消息来源、并发预算、控制与恢复 |
| 长期具名 bot、多写入 Agent 及自主路由 | 角色长期积累，更多并行实现空间 | 引入长期记忆、目录/合并冲突、执行权和更复杂调度，超过首场景所需 |

## 最终决策

选择第二项。首版产品规则唯一归[总纲 §0.9](../../Personal_Workflow_OS_Master_Spec.md#09-有界多-agent-与自动会话)，范围归[范围补充](../requirements/v1-scope.md#有界多-agent-与自动会话补充)。会话是持久工作记录，每次子执行有独立上下文；委派属于原主 Run 内部工作，Task 执行权、工具准入及正式完成沿用既有 Owner。

## 决策原因

直接服务于已选目标和软件需求场景：主 Agent 接住总需求，自动安排有明确范围的调查和独立审查，反馈回主会话，用户只在需要纠正或决定时介入。先用只读子执行检验协作收益，避免首版同时解决多方写入、长期角色记忆和跨项目调度。

明确独立需求自动建主会话、同需求保留原会话，能减少找入口又保留连续讨论；嵌套及直接补充让委派可见、可纠正。自动创建和转发仍须保存原用户来源，不能顺带产生执行授权。

## 代价

需要持久主子关联、委派与结果投递/消费身份、父子领取及共享预算预留；必须处理停止竞争、未知调用、迟到结果和读取/订阅窗口。必要审查失败仍会暂停交付，可能增加等待和模型成本；两子一层限制并行规模。效果需实际比较，不能预先承诺更快或更可靠。

## 影响范围

Assist/Workflow/Application、Context/模型计量、Gateway 只读准入、会话导航及补充反馈、API/数据库兼容和恢复测试。工程责任只维护在[运行架构 §2.5](../architecture/runtime-context.md#25-有界子-agent-的委派与会话关联)，交互归[工作台 §23](../frontend/workbench-design.md#23-主子会话与有界协作)。

本轮仅文档，Breaking Change：No；未发布 API 或 migration。后续接口/存储变化须按实际协议另标 Breaking Change、旧会话/URL/checkpoint 兼容及回滚风险。本 ADR 不替代 ADR-010 的主栈、ADR-016 的对话授权或契约 01–04；也不前移多 Agent Router、N04/N06 或关闭应用后的后台执行。
