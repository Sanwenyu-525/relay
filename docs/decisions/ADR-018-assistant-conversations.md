# ADR-018：会话模式与人设助手会话

## 状态

Accepted（产品规则由用户 2026-10-05 逐项确认；命名由用户在同日改为「助手」，不叫 bot）。
后端 Task 1–3 已实现并有真实 PostgreSQL 出口；前端单选框与真实 Windows 验收未做，因此本 ADR
记录的是**已落地的后端协议**，不含任何未运行的界面结论。Breaking Change：Yes（语义）。

## 日期

2026-10-05。产品选择来源：用户在协作页聊天框要求一个切换模式的单选框，两档为「普通 Agent」
与「像 grok bot 那种的」；随后明确 bot 只是举例，改称助手，并选定「团队角色」只作为组织方式
进入本片（不引入多角色同场协作）。

## 背景

用户在同一个聊天框里需要两种东西：一种是能把活干完的 Agent（改文件、建任务、跑检查），另一种是
一个固定人设、只读的助手（像 grok 自定义 bot 那样有名字和口吻，但不该动代码）。既有 Assist 会话
只有一种身份，`DISCUSS` 与「提出提案」是同一条消息上的 intent 选项，因此「这条消息能走多远」由
模型当轮判断，而不是用户在发消息前决定。

ADR-017 已在计划里有界多 Agent，但那条链需要先有单 Agent 的工具循环与轨迹呈现作依赖门，且其
A→B→C 的链式独立验收门禁当前不可用。因此本 ADR **不前移多 Agent**，只新增另一种会话身份。

## 候选方案

| 方案 | 优点 | 代价 |
|---|---|---|
| 每条消息一个下拉（intent） | 改动最小，沿用现有控件 | 权限随模型当轮判断；用户无法预先知道这条消息会不会改文件 |
| 会话级身份（A 档普通 / B 档助手） | 权限在会话建立时定死，可预判；两种体验各自干净 | 需要身份列、人设快照与一套只读工具词表 |
| 助手也走 Run 工具循环 | 完全复用既有执行链 | B 档不建 Task 却是「可读不可写」，挂在 Task/Run 上要么污染状态面板，要么造出空的执行外壳 |

## 最终决策

选第二项：**会话建立时冻结一种身份**。

- A 档 `conversation_mode = 'AGENT'`：既有行为逐字不变，仍由解释层决定 `DISCUSS` / `CLARIFY` /
  `PREPARE`，仍可建 Task、Delegate Run、改文件、跑检查。
- B 档 `conversation_mode = 'ASSISTANT'`：只读回答。可用只读工具读真实代码与已选资料版本；
  绝不建 Task、绝不委派、绝不写入、绝不申请任何动作审批。

模式在会话建立时冻结，之后不改写；切换模式等于换会话。这条是为了让「这条会话能做什么」在会话
开始前就是确定事实，而不是同一条会话前半段能写、后半段只读。

## 决策原因

权限等级必须是会话属性而不是消息属性。理由是既有不变量：Task 执行权、验收契约与审计事实不能
在一条会话中途漂移；同一会话前半段可写、后半段只读会让「这段讨论产生过什么」无法回答。

只读动作仍然走 Gateway（第四种来源 `ASSISTANT_READ`），而不是直调 file/git adapter——后者会造出
第二条准入路径，违反「Permission/Gateway 控制动作准入」。代价是一条迁移放宽四条 CHECK，
以及 `GatewayOrigin` 多一个分支。

## 代价

- 新增两张表（`assistant_profiles`、`session_tool_calls`）与 `assist_sessions` 五个列。
- B 档每轮都要重算只读词表（按当前连接），比 A 档多一次连接读取。
- B 档不排队（一条在途时再发被拒），这与 A 档允许排队的既有行为不同，需要界面如实说明。
- 人设快照冻结的是**文本**：连接被删后 B 档下一轮就少一个工具，不靠快照续命。这条容易被误读成
  「配置里写了就能读」，因此在迁移、仓储与提示词三处都写明。

**Breaking Change：Yes（语义）**。建会话请求体新增可选 `conversation_mode` 与
`assistant_profile_id`；既有字段与路由语义不变，不传即 `AGENT`。既有会话按 `AGENT` 读出，
不虚构助手关系。同一 `command_id` 换模式重放按异载荷拒绝。

## 与 ADR-017 的关系

**新增一种会话身份，不推翻也不前移多 Agent。** ADR-017 的 A/B/C 三片（持久主子关联、受控子执行、
主子会话 UI）至今零代码，其独立验收门禁仍受指定模型不可用影响。本 ADR 的助手会话不派发子 Agent，
也不提供多角色同场协作；「团队角色」只作为助手配置的分组维度，运行机制仍是「一次只和一个助手对话」。

多角色同场协作与 ADR-017 已否决的候选三（长期具名 bot、多写入 Agent、自主路由）实质重叠，
若要做须另开 ADR 推翻或例外化，不在本 ADR 范围。
