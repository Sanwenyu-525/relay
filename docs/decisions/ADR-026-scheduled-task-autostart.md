# ADR-026：周期定时启动任务复用原准入与执行 Owner

## 状态

Accepted，2026-10-18；仅覆盖「周期定时启动单个 AI 任务」这一能力，不升级 N05 提醒、N06 连续委托或 M/N 总出口。

## 背景与候选

用户要求增加「定时任务」：到点自动创建并启动任务，周期重复，仅应用运行期间生效，前后端完整链路。

既有两条已确认口径直接冲突：`docs/architecture/domain-model.md` §11.2 写「定时触发不调用模型……定时器不推进 LangGraph、不写 Task」；N05 写「触发不调用模型、不启动任务链、不改成果」「固定周期……留待另选」。N06 之所以能自动 Delegate，靠的是 `task-chain-admission` 的四道闸门、24 小时授权上限与 `runtime_id` 重启隔离。

候选 A：让 N05 提醒直接携带执行意图，到点调 Delegate。代价是把「提醒」与「执行权」合并成同一事实，N05 的「待处理」语义消失，且绕开 N06 全部准入。

候选 B：新建第二套定时执行器与状态机。代价是重复 Task/Run/验收/恢复责任，违反唯一通用图与唯一逻辑 Owner。

候选 C：新增「任务模板 + 重复规则 + 提前授权」的计划对象，触发时只按已持久化授权调用原 `CreateTask` / `MarkTaskReady` / `DelegateTask`，执行权仍由原 Delegate 授予。

## 决策、理由与代价

采用 C。`ScheduledTask` 只拥有模板、重复规则、下次触发时刻、授权参数与触发发生记录；它不拥有 Task 状态、Run 生命周期、验收或执行权。每次触发**新建一个 Task**（Task 跑完即 DONE，终态不可复活，因此周期只能表现为「每次新建」），再走原三步用例。

**触发不授予新权限。** 授权在创建时由用户显式确认（`confirmed: true` + `max_runs` 1–100 + `authorization_expires_at` ≤ 90 天），持久化为事实；触发只做准入，不扩大范围。`delegateTask` 新增内部 `scheduledTaskBinding`，在**原命令事务内**核对计划状态、代次、授权有效期、预算预留与上一轮 Task 终态，未通过即拒绝，效果不落库。

**对 N06 的两处有意偏离，代价必须写明：**

1. 有效期上限由 24 小时放宽到 90 天。理由：「预约未来某时刻」与「现在开始串行跑」语义不同，24 小时使预约失去意义。代价是授权窗口变长，用户可能忘记三个月前设定的任务；因此 `max_runs` 与到期时间在列表页常驻显示，且到期按 N06 同款方式安全停止（不静默）。
2. 不引入 `runtime_id` 串行隔离。理由：每次触发产生独立 Task 与独立 Run，不存在「同一队列跨重启续跑」的问题；重启只影响「是否补跑错过的轮次」。代价是多实例并发时需要 occurrence 级租约兜底，见下。

**准入必须看 Task 终态，不是 Run 是否活跃。** Run 完成后 Task 进入 `WAITING` 等人工验收，只看 Run 会堆出一串待验收任务。上一轮 Task 不在 `DONE`/`CANCELLED` 时本轮记 `SKIPPED('PREVIOUS_TASK_NOT_ACCEPTED')`，并在界面写明「上一轮未验收，本轮不启动」。

**错过不自动执行。** 应用关闭期间错过的轮次只形成一条待处理事项（与 N05「最多形成一次待处理」同口径），由用户决定是否「补跑一次」。理由：用户不在场时不应消耗模型预算；这与「仅应用运行期间生效」是同一约束的两面。

**并发。** occurrence 插入即置 `DISPATCHING`，用 `UPDATE ... RETURNING` 抢租约，兼作崩溃恢复入口；同一计划同一代次同一序号的唯一约束是第二道防线。与 `task_chains` 一致，本能力假设单 API 进程运行调度器，多实例不在本片承诺范围。

**幂等。** 三步命令的 `commandId` 在 occurrence 落库时预生成并持久化；`expected_task_revision` 只能取自前一步回执，不得读库重算——`runIdempotentCommand` 重放比对 `payload_hash`，body 变化会抛 `CommandIdReusedError`（409）而非重放。

## 影响与后续

影响应用协调、`delegate-task` 的专用内部参数、`attention-notifications` 投影、API/客户端、新迁移两表与前端新页面；公共旧命令摘要与默认行为保持。协议归 HTTP §10.92、数据库 §102、领域模型 §11.2、工作台 §37；实际成绩只归统一验收表。

本片不做：Windows 后台服务与退出后运行、cron 表达式与月/年规则、多时区混排、失败 Run 的自动重试、任务列表的「来源」标记、把定时任务并入 N05 提醒的去重键。这些若要做，须沿原 Owner 另接，不能从本授权扩张能力。
