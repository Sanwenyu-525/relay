# ADR-041：长期记忆 V2 的分层、索引化召回与确定性整理

- 状态：Accepted（2026-11-15 实施；验证证据见 `docs/testing/memory-system-v2.md`）
- 接续：ADR-028（长期/短期分层）、ADR-030（零点击自动记忆）、ADR-032（来源类别）

## 背景

已有长期 Memory 已具备根/不可变版本、人工确认、自动捕获、来源冻结、Workspace/Project 作用域、有效期与召回设置，但缺少四类语义分层、结构化冲突键、验证状态、索引化检索、Token 预算、确定性整理和真实删除。直接新建一套平行存储会破坏「Information 是长期 Memory 唯一写入 Owner」的约束，也会让来源撤销、修订和已有命令回执失效。

## 决策

1. **不建第二套存储。** 继续以 `memory_items` / `memory_versions` 为唯一长期记忆根与不可变版本；V2 只通过追加迁移增加类型、作用域、键、置信度、验证、固定、替代链、内容指纹与检索 token。
2. **有效状态只派生、不写回。** 根 `status` 仍只有 `ACTIVE` / `RETIRED`；`SUPERSEDED` 由 `superseded_by_id` 派生，`EXPIRED` 由当前版本的 `expires_at` 派生，`STALE` 由 `stale_at` 派生。被替代的旧根保持 `ACTIVE`，避免把「历史被替代」误写成「用户停用」。
3. **作用域在检索前过滤。** Workspace、Project、Task 写入必须满足形状约束；Agent 作用域只保留列，当前没有多 Agent 身份模型，UI 不创建。写入裁决只在完全相同的作用域内比较，召回才按当前会话的 Workspace/Project/Task 叠加。
4. **应用层分词 + PostgreSQL 表达式 GIN。** 中文按相邻双字、拉丁词按连续字母数字与 `./:@-` 切分，写入 `search_title_tokens` / `search_body_tokens`；GIN 索引用 `to_tsvector('simple', ...)`，查询侧使用同一表达式排序。旧空 token 行由有界回填兜底，不因迁移丢召回。
5. **写前裁决是确定性纯逻辑。** 精确内容指纹/同文判重复；同作用域同类型同 `memory_key` 的新事实替代旧事实，但低可信来源不能顶掉已验证或固定事实；无键时仅在高 Jaccard 重叠时判近似重复；敏感凭证直接拒绝。
6. **预算是硬上限。** 固定记忆先占 `core_token_budget`，普通命中再占 `retrieval_token_budget`；超出时按分数丢弃低相关候选，token 估算复用本地确定性估算，不依赖模型。
7. **整理只做确定性动作。** 去重保留来源更强者、同键合并、陈旧标记、索引回填，不调用模型生成新事实；Worker 每拍最多处理一个到期工作区，无设置行的工作区按默认开启。
8. **真实删除必须可执行。** 清理失效项按派生有效状态反选并排除固定项；硬删除在事务内摘除替代链、自动捕获、来源引用、版本和根，并补足数据库 DELETE 授权。

## 代价与影响

- 迁移为追加式：旧行 `memory_type` 为 `UNKNOWN`，旧人工确认行标 `VERIFIED`、旧自动捕获行保持 `UNVERIFIED`；不会把旧数据凭空升级为已验证经验。
- 语义检索没有强制依赖：`HYBRID` 在当前没有 Embedding 端口时降级为字面检索并记录 `EMBEDDING_UNAVAILABLE`；基础能力不因缺少 API Key 不可用。
- 近似重复只在有界最近候选窗口内比较，旧相似条目可能被当成新事实；这是用可控写入延迟换取的取舍。
- Agent 作用域、跨设备同步、知识图谱不进入本次范围。

## 未采用

- 新建独立 Memory 数据库、向量库或 Markdown 真相源：会与既有来源撤销、命令回执和版本契约冲突。
- 把 `SUPERSEDED`/`EXPIRED` 写成根状态：会产生第二套可写状态，且难以区分用户停用与事实被替代。
- 每轮对话调用模型做完整记忆提取：成本高且不可控；自动提取保持结算后、候选化、可撤销。
