## 1. 要解决的问题与完成图景

让用户隔几天回来仍能知道项目的真实进展、判断新成果、保护自己的修改、复用已有知识，并在明确授权的短任务链内让 AI 继续推进。第一目标是减少重新理解和重复交代的成本；功能数量与自动运行时长不作成功指标。

推荐黄金路径：离开前保存接续点 → 返回后比较事实变化 → 选择需要处理的成果和问题 → 修改后看到相关影响 → 审核并收录可复用知识 → 确认下一段计划 → 在有限授权下执行 → 遇到决定或停止条件回到人工待处理。

比较的方向：

| 方向 | 收益 | 代价与本次选择 |
|---|---|---|
| 长期协作优先 | 直接连接已有 Project/Artifact/Knowledge/Review，先验证日常价值 | 涉及来源、版本和人的理解，不能只做摘要页面；用户已选择该主线 |
| 开发执行器优先 | 扩展编码任务的执行深度 | 外部回执、审批穿透与故障核对成本高；保留为后续可选分支 |
| 自定义平台优先 | 允许不同项目配置自己的工作方式 | 编辑器和兼容性会先增加产品复杂度；放到真实重复需求出现之后 |

## 2. 基线与增量的分界

2026-09-28 的源码定向核对只证明存在复用入口，不代表它们已独立验收；开工时必须重新核对确切基准。

| 已有入口 | 后续增量 | 不重复建设 |
|---|---|---|
| 项目恢复 Skill、Activity/Trace、`application/state-queries.ts` | 明确保存的接续基线、跨时间比较与接续点 | 不再生成第二套 Project State |
| `application/lineage-queries.ts`、`artifact-impact-checks.ts`、`artifact-text-locks.ts` | 跨成果的有限批次提案、冲突重算与组合证据 | 不把直接引用 `complete: false` 冒充完整影响图，不重做 V1 原文锁定和手动检查 |
| `application/information-commands.ts`、知识阅读与显式收录 | 人工知识编排、带来源的整理候选、重复与过期提示 | 不把收录、验证、模型外发合成一个开关 |
| Today/Focus、Task 提案、蓝图与验收方案 Skill | 周期计划草案、可解释的重排和容量提醒 | 不重建任务列表或任务状态机 |
| `application/attention-notifications.ts`、持久 Run command/outbox | 用户启用的特定时间/事件请求、有限连续委托 | V1 必须介入提醒继续按既有规则；提醒不是调度器 |
| Skill/Pack 固定版本与 Profile、来源视图 | 用户可编辑的受限声明、差异审查、版本 Eval | 不创建第二套 Runtime 或动态代码插件 |

相对代码路径以上均位于 `apps/api/src/`。工作台继续消费现有 API；没有对应写命令的编辑入口必须先设计契约，不从 UI 直接写数据库。

|---|---|---|---|---|

| N03 项目知识整理 | V1.1 / 核心 | 把成果和经验组织成可读、可核对的项目知识 | 手动导读编排、候选收录/归类、相似候选与来源更新提醒 | N01；复用 V1 知识读写 |

### N00 使用基线与体验收口

2026-10-02 规划接续：用户确认首个真实交付与验收样板采用小型开发项目，完整路径为「打开目录 → 对话提出修改 → 真实改文件并检查 → 审阅成果 → 隔日继续」。据此先检验真实执行、成果判断与接续的使用收益；其余两种固定路径仍保留。此选择仅确定规划优先级，不扩大实施或真实模型外发授权。

该样板的有效测量依赖[文件夹入口](../../frontend/workbench-design/part-04.md#18-文件夹入口与对话直接执行)相应切片和 M06 真实工具链出口；文件夹入口不作为 N00/N01 所有切片的新硬依赖。测量准备与 N01 既有首片核对可独立推进，不重建已有实现。实际实现与验收范围继续以当前阶段入口及功能验收表为准。

- 固定三种真实路径：隔日接续项目、修改一个被引用成果、把确定成果收录并再次用于任务。记录项目规模、输入版本、模型配置、权限、运行基准和失败样本。
- 区分 UI 受理反馈、排队到领取、首个可见内容、最终产物持久化、人工审阅、总完成时间；不将 Mock 时延当真实模型时延。
- 新增观测优先复用当前 Trace/模型调用记录；只保存必要结构化时间和引用，不默认采集正文、屏幕、全局行为或上传遥测。定位确切瓶颈后才改性能。
- 出口是可重跑基线和优先问题清单。V1 必需验收缺陷仍回原模块关闭，不借 N00 放宽 V1 出口。

### N01 项目接续与检查点

- 用户显式保存名称与可选接续说明；系统捕获一致的 Project/Task/当前选用成果、Decision/Rule/Knowledge 版本引用及未决事项。精确纳入集合、大小上限、保留/删除策略在设计中冻结。
- 返回时选择该点与当前事实比较；事实差异和 AI 解读分开，摘要中的判断能跳到来源。未读、已查看、已接手、已完成不能共用一个状态。
- 隔日打开目录的默认呈现已于 2026-10-02 确认，规则只在[工作台 §15.1](../../frontend/workbench-design/part-04.md#151-隔日打开目录的事实接续卡2026-10-02已确认规划)维护；该呈现增量不扩展已冻结的接续点引用集合，也不等于已实现或验收。
- 默认不因打开项目改变接续基线；活动 Run 可以在一致性快照后继续，UI 说明这是捕获时点而非“项目已停机”。缺失或失权的来源明确不可用。
- 首片仅保存/查看/比较。根据旧点生成恢复配置建议是单独可选片，走当前 revision 的提案；不能回滚整库、文件效果、审批、PASS 或执行权。

2026-10-09 接续：日常返回的默认查看基线及获授权核对归[工作台 §18.9](../../frontend/workbench-design/part-07.md#189-自然语言状态维护与接续摘要)，上述“不改变基线/仅查看比较”继续限定命名接续点与已冻结首片。新日常增量须核定查看确认、版本集合、核对权限/预算及停止恢复协议后另行实施；不扩展现有首片成绩，不增加后台自动快照或自动 Resume。

### N02 跨成果共创

2026-10-02 用户确认首场景采用已明确关联的 Markdown 项目文档：功能/API 说明变化后，为相关使用说明、设计说明或测试计划提出修改候选。真实代码修改和检查仍由原执行链完成；从代码差异推断文件/测试依赖不纳入本首场景，须另行设计与验证识别范围和漏检。

- 用户主动从确切前后版本发起影响检查；沿已登记关系形成有界候选组，推测关系另列。图有截断、环或未知影响时显示范围和缺口。
- 逐项展示源变化、目标基线、锁定区域、拟改内容与需要重验的条件；用户可选取独立条目。对存在依赖的候选必须明确联动或拒绝不完整选择。
- 最小片采用逐项命令与逐项回执，明确部分成功；不承诺跨多个成果全有或全无。批次只是候选和处理结果的关联，不持有另一套成果正文。
- 人工编辑、锁定变化或来源更新后，受影响候选过期；不能以新正文悄悄重算后沿用旧批准。组合版本检查单列，不把多个单项 PASS 相加当整体 PASS。

### N03 项目知识整理

2026-10-02 用户确认首个交付形态为项目知识导读，按架构约定、重要决定、使用说明和参考资料组织来源入口。人工编排与来源呈现规则归[工作台 §12.4](../../frontend/workbench-design/part-03.md#124-项目知识导读n03-形态2026-10-02规划已确认前后端均已接入)；开发经验卡保留为后续候选，不纳入首轮。

- 先提供可人工编辑的导读/集合：链接目标、决定、资料与确切成果版本，不复制第二份正文或当前状态。历史固定引用和跟随当前的导航用途必须能辨认，AI 输入始终落到确切版本。
- 用户主动请求整理；AI 产生“收录哪些、归什么类、与已有内容有什么关系”的候选。已有收录命令与新笔记版本继续复用。
- 2026-10-09 的明确收录指令可承载对应确认，沿[工作台 §18.9](../../frontend/workbench-design/part-07.md#189-自然语言状态维护与接续摘要)处理；自动提炼仍只形成候选。统一对话入口不重做首片导读，也不由知识内容静默升级 Rule/Decision。
- 发现相似条目只提示，不自动合并/删除；新总结是有来源的新版本，不能凭模型意见覆盖 Rule 或 Decision。资料失效提示不自动改写历史引用。
- PDF 作为可选下一片：先根据用户真实资料样本决定正文提取、页码定位、表格和扫描件范围；OCR/Office/语义检索不一起承诺。引入解析库前再核对正式版本、许可、资源限额与可信边界。

### N04 周期计划与重排建议

2026-10-14 基础前后端片核定结构化估时、固定容量与逐项应用协议（HTTP 契约 §10.74、数据库设计 §82）：用户手动输入，保守串行建议，诊断接受独立建 Task；自然语言入口、完整重排、UI 和实用收益后置。以下保留目标规格，其中工程协议待核定的历史描述已由本片协议接续，当前阶段与成绩仍归原主文档。

2026-10-25 前端首片已实现：live `/projects/:id/planning` 可读真实项目 Task/Goal 与估时，并支持用户按分钟录入/更新总耗时及执行、等待、Review、人工投入分项；来源说明必填且标为用户声明，按 Task 与估时 revision 做 CAS，保存后重读历史并展示适用状态。计划候选、逐项处理和固定容量范围推演沿原命令执行，结果不明时保留原 ID/载荷并核对回执；全部为 `DEFERRED` 的候选也可填写理由后拒绝，其他项推进计划 revision 后按目标项状态恢复原 `RESOLVE_ITEM` 命令。接受计划不授予执行权。具体自检与未验边界见[工作台 §19](../../frontend/workbench-design/part-06.md#19-下一段工作计划n04已确认规划)及[功能验收表](../../testing/overall-acceptance-2026-09-28.md#当前功能验收表)；真实 Windows/WebView2、Provider、独立验收和完整收益仍未验证。

- 2026-10-02 用户确认首轮采用手动发起的「下一段工作」计划：用户填写本次可用时长，结合选定目标、当前任务依赖与必须介入事项，形成一段可审阅的小计划。估时为建议并可改，不根据聊天或操作习惯自动画像；一周计划保留为后续候选。
- 输出候选任务、顺序、延后原因、资料/权限缺口和需人工处理的决定。沿现有提案与 Task 写命令应用；接受计划不自动 Delegate，也不批准工具动作。
- 活动任务不被静默改写；重排涉及验收或输入契约时走原版本/停止规则。部分应用必须报告每项结果，重复提交不重复建任务。
- 第一片不接外部日历，不新增 Calendar/Work Session 完整模块；待用户实用证明容量输入不足，再选择独立日历分支。

二轮规划已确认：本次可用时长指从本段开始到用户离开的时间窗口，计划须把执行、等待和必要审阅纳入预计完成时间，人工投入另列；有重叠的时间不能重复相加，未取得依据的时间保持未知。该窗口用于计划建议，不自动成为 N06 执行授权有效期或在途动作的硬停止期限。

关键任务估时未知时，先提出有时间边界和明确输出的诊断候选，根据诊断结果再更新后续计划；后续任务继续标为估时未知，不因标题、截止日期或模型猜测承诺本段可完成。诊断也只是一项待接受的计划候选，接受计划仍不自动 Delegate。现有 Task 的优先级、截止日期和 BLOCKS/INFORMS 可复用；结构化估时、容量和整段候选协议已由 HTTP §10.74、数据库 §82 核定，不把 Today 的 Pin/Later/Focus 当时长预算。

用户确认容量不足时优先推进所选目标的主线与必要前置，再按剩余容量安排独立任务，并说明延后原因；可以只完成一次有明确输出的诊断，不以完成更多小任务掩盖主线缺口。排序依据须来自明确目标、已登记依赖、原优先级和截止日期；未设置优先级、未登记依赖及模型判断分别保留未知/建议，不自动写成新的硬事实。

用户确认诊断预算用完仍未定位时，交付已查证据、排除项、未知问题及下一步候选，由用户决定是否继续投入，不自动占用原留给后续工作的时间。原修复任务保持未完成；诊断成果只按自己的确切验收条件判断，不能降低或沿用原修复任务的完成条件来宣称报错已修复。诊断预算耗尽后的证据交付/下一步闭环仍是后续完整 N04 规格；本轮页面只建立诊断候选，不据此宣称该闭环已完成。呈现归[工作台 §19](../../frontend/workbench-design/part-06.md#19-下一段工作计划n04已确认规划)。

### N05 有限触发与提醒控制

2026-10-14 基础片核定一次性时间、独立代次/发生、应用生命周期扫描和原通知结算协议（HTTP 契约 §10.76、数据库设计 §84）：当前 API/客户端可创建、编辑、暂停/禁用/继续、读取与处理事项；只有主动改实际时刻产生新代次，原待处理保留。以下产品规则仍为完整目标；设置/待处理 UI、Windows 原生投递、确定性时钟/故障组合与收益出口不从基础数据/真实 API 重开检查推断通过。

- 2026-10-02 用户确认首场景为一次性指定时间的「继续项目」提醒。每条提醒绑定明确项目与时刻，触发只持久化提醒/待处理；用户点击进入原计划入口，填写本次可用时长并主动发起 N04 计划。模型请求另外核验来源和预算，不因设置提醒取得外发许可。

- 二轮用户确认授权到期时阻止新准入，并通过原持久控制入口请求当前任务在安全点暂停；请求尚未安全应用时显示“暂停中”，核实后才显示“已暂停”。已完成事实保留，未决外部动作/UNKNOWN 先按原身份核对，不因到期重发、释放隔离或宣称已停。续期与到期、暂停与完成竞争须重新核验原授权/任务基线，不能由旧定时请求暂停后来独立获授权的执行。呈现归[工作台 §21](../../frontend/workbench-design/part-06.md#21-有限任务链的授权与接续n06已确认规划)；N04 计划窗口结束不自动触发本规则。

### N08 周期定时启动任务

2026-10-18 用户确认新增：到点**自动创建并启动**一个 AI 任务，周期重复，仅应用运行期间生效，交付后端与前端完整链路。N05 原写「固定周期……留待另选」，本条即那次「另选」，取舍与代价见 [ADR-026](../../decisions/ADR-026-scheduled-task-autostart.md)。

- 定时任务是**任务模板 + 重复规则 + 提前授权**，不是对某个既有 Task 的重复执行。每次触发新建一个 Task，再走原 `CreateTask → MarkTaskReady → DelegateTask`；Task 跑完即 DONE，终态不可复活，因此不存在「重跑同一个 Task」。
- 授权在创建时显式确认：`max_runs` 1–100、`authorization_expires_at` 不超过 90 天。触发只按已存授权准入，不授予新权限；到期与预算耗尽按原安全方式停止，不静默。
- 准入必须看上一轮 **Task 终态**（DONE/CANCELLED）。Run 完成后 Task 停在 WAITING 等人工验收，此时本轮记 `SKIPPED` 并在界面写明「上一轮未验收，本轮不启动」；不自动代答验收。
- 应用关闭期间错过的轮次**不自动执行**，只形成一条待处理事项，由用户决定是否补跑一次；与 N05「最多形成一次待处理」同口径。
- 首片只支持按天（每 N 天，1–30）与按周（每周指定星期几）两种规则，时刻按创建时确认的时区墙钟解释；不做 cron 表达式、月/年规则、多时区混排。
- 执行范围（资料引用、固定读取、工具循环、范围授权、原会话方法）在**触发时**按当时状态冻结；依据漂移则该次不执行并形成待处理，不静默降级为无工具执行。
- 首片假设单 API 进程运行调度器（与 N06 一致），多实例并发不在承诺范围；occurrence 级租约与唯一约束是第二道防线。

2026-10-24 补齐[原工作包中的 N08 接续提示词](../../../prompts/post-v1-collaboration.md#n08-周期定时启动任务接续)。现有实现及修复证据先查当前进度与验收表，只补真实缺口，不从零重建；本轮编制提示词不创建调度、不触发运行。

#### B. Relay 产品内的事项管理

推荐增加用户可见的「Bug／功能」统一入口，支持列表/看板、详情、关联执行与交接历史；自然语言可登记、补充或请求流转，表单作为详细编辑入口。自动发现形成候选，明确指令才沿授权与版本检查提交；不因模型声称已完成就关闭事项。

| 概念 | 推荐责任与边界 |
|---|---|
| 事项（暂称 Issue） | 拥有问题/需求身份、范围、优先级、验收条件和关联关系；物理存储及是否扩展已有对象须先查代码后冻结 |
| Task | 承载具体执行；一个事项可关联多个任务，不为 Bug 重建 Task 状态机 |
| Run | 记录一次执行过程；失败不直接宣布事项阻塞，成功不直接宣布事项完成 |
| Artifact／Verification／Review／Completion | 继续拥有产物、验证、人工判断和业务完成事实；事项只能基于明确关联及当前验收基线呈现结果 |
| 交接记录 | 保存交出者、接手者、原任务/Run、范围与版本、已完成证据、未决事项、下一步及接收结果；不能替代原控制/Handoff 协议 |

首片采用「登记一项 → 关联一个具体 Task → 执行并提交证据 → 验收 → 关闭或返工」验证端到端；多 Task 事项之后增加明确的必需任务集合与组合验收，不把若干子任务通过自动算为整体完成。不同时建设迭代排期、工时绩效、通用工作流编辑器或多 Agent Router。

#### C. 多 Agent 交接与外部系统接续

- 派发传递工单编号、确切范围及本次交接摘要；接手前读取最新事实。聊天只作沟通，工单与原领域事实承载可恢复状态，避免复制长提示词产生多份当前结论。
- 一个 Task 同时只有一个有效执行 Owner。提出转交、对方确认接收、安全释放原执行权分别记录；原执行仍在途时不得显示已接手。同工单的独立任务可分别执行，仍受实际目录/资源排他约束。
- Agent 身份、会话地址、工单负责人和执行授权分别处理；将事项指派给 Agent 不授予文件、工具或外发权限。外部 Agent 首片推荐人工交接包与回执，不承诺已接通各平台聊天或能自动调度。
- 外部托管的事项：外部工单拥有问题描述、优先级与事项状态，Relay 保留外部版本快照和映射；执行、产物与验收事实仍归 Relay 原 Owner。Relay 原生事项则由 Relay 拥有。一个事项选定一种归属，不开放两边独立修改同一字段后按更新时间覆盖。
- 后续写回经明确命令和外部版本核对；外部关闭只能作为来源变化，不能反向完成 Relay Task，Relay 任务完成也不能跳过事项组合验收。原生事项转外部托管或反向迁移须单独定义归属切换，不作为首片自动行为。
- 接入时核定外部实例/仓库/工单复合身份、创建命令幂等、来源版本与同步回执；重复事件去重，旧版本拒绝覆盖新事实。请求超时先按原身份核对，无法确定是否已建单/写回则保留 UNKNOWN，不换 ID 盲重试；外部调用不进入业务长事务。
- 最小外发材料范围、认证、撤销、脱敏与失败恢复在写入接线前冻结。当前 F25 只读边界保持；本节不是自动发消息、批量外发项目材料或放开 GitHub 写动作的授权。

#### D. 推荐顺序、验收与待确认项

1. **Relay 原生首片**：先核对现有 Task/Review/协作入口，再冻结事项 Owner、关联、revision、命令幂等及关闭/重开规则，完成单事项单 Task 的真实数据库/API 闭环，之后接自然语言登记和轻量列表。不重做已有执行与验收链。
2. **用 Relay 管理自身开发并试跑交接**：以实际 Bug 和功能各一项验证一句话登记、负责人、交接、证据与返工。出口是接手 Agent 能找到当前范围、依据和下一步，用户不必操作外部工单界面；外部 Agent 先用明确交接包和回执，接入自动化后置。
3. **外部只读关联**：沿既有连接/权限读取指定工单，保留外部身份、版本和不可用状态；重复导入不重复建事项或任务，来源内容不能升级规则与授权。
4. **受控写回与多 Agent 接续**：在写动作协议与授权冻结后增加写回、交接接收及冲突恢复。验收覆盖重复派发、旧结果迟到、双方改动、超时后核对、撤权、重启后恢复、验收失败返工及重开后旧证据失效。

自动化、真实 PG/HTTP、外部认证读写、多 Agent 实际交接、Windows 与独立验收分开记录；上述是待运行出口，不新增通过成绩。此相对次序不重排当前已授权专项，也不延长 M01–M07 原出口。

**待确认**：首轮参加的 Agent 平台与手动/工具接入方式；验收关闭权限及多 Task 聚合规则。外部工具、目标仓库/项目及托管材料范围仅在选择接入时再核定。当前推荐 Relay 原生入口优先、人工交接和显式验收关闭；用户只确认两条方向及 GitHub 难上手反馈，未确认全部工程细节或授权编码。

### 9.1 免费模型分组与自动同步

2026-10-15 记录免费模型套餐与自动更新目标；2026-10-16 用户要求先验收并更新开发任务书，新增“模型额度用完自动切下一个”；2026-10-17 用户授权 Luna 实施及协调复验，正在补齐生产链。实现范围及下一步归 CODEX_NEXT_STEP，实际结果只归统一功能验收表；下述目标不能替代运行证据。

产品中的“套餐”首版呈现为模型选择中的独立「免费模型」分组，不新增订阅、计费、充值或额度售卖业务。首个目录来源采用 OpenRouter；保留原有模型连接及默认配置。其他服务商、官网抓取、赠送余额和限时试用聚合后置，不硬编码具体免费模型名称。

| 范围 | 首版行为 |
|---|---|
| 免费定义 | 服务商目录明确给出文本输入、输出的合法零价格；请求费及本次文本调用适用的其他计价项若声明，也必须合法为零。官方可选 `request` 未声明时保留缺项，不能补写零；缺少必需输入/输出价格、非法或未知收费项均不放行，仅名称带 `free` 不足以判定。按量收费模型的赠送余额、试用额度和限时优惠不混入；零单价模型的请求配额/限流单独标注。图片等额外计价能力未闭合前不承诺免费使用 |
| 自动更新 | 配置并启用目录来源后，在应用服务启动、打开模型选择时检查；上次成功同步距今满 24 小时才更新。应用持续运行时到期检查，停机后下次启动补查，不为此安装系统计划任务或独立守护程序；同时提供“立即刷新” |
| 同步结果 | 有效完整目录成功后更新可选项，新增免费模型自动出现，转收费/下架项退出可选免费集合。失败保留最近成功目录与其时间，不覆盖成空列表；合法完整空结果和错误/不完整结果须区分 |
| 能力与可用性 | 显示来源、上下文及工具调用等已知能力；未知标为未知。目录收录、连接认证、能力声明和实际调用通过分别显示。需要工具的 Agent 请求不能选择明确不支持或能力未知的模型执行 |
| 选择与生效 | 用户选择具体首选模型；刷新目录不改变当前选择，不自动选第一个或改用随机免费路由。手动会话选择仅影响后续新请求，应用默认不变；活动 Run 仅可按下述已冻结免费候选队列自动切换，不能被会话设置或目录新项改写 |
| 调用保护 | 免费选择携带“仅免费”限制，每次请求均受零价格准入。资格过期先核对；未触发额度接续时首选价格不明/转收费/下架则停止，已因单模型额度进入接续后才跳过失效的后续候选；账户/平台总额度、权限、预算不足或无可用候选明确停止，绝不转收费。缓存仅供浏览，不是长期免费保证 |
| 凭据与限额 | 使用服务端独立配置的 OpenRouter 凭据，不能把现有其他服务商密钥发给 OpenRouter。未配置可展示可核实目录，但不可声称已可调用；限流/每日额度按实际服务商证据呈现，未知不写零，不承诺永久免费或无限量 |

同步目录不发送聊天、项目内容或测试推理请求，不消耗模型生成次数；是否需要目录认证以实施时官方协议为准。官方依据（2026-10-15 核对）：[模型目录](https://openrouter.ai/docs/api/api-reference/models/list-all-models-and-their-properties)、[价格限制路由](https://openrouter.ai/docs/guides/routing/provider-selection)、[额度与限流](https://openrouter.ai/docs/api_reference/limits)。目录价格只提供发现依据，请求时仍需实际价格上限保护。

实施顺序：先核定配置引用、会话选择与 Run 冻结契约，再完成服务端目录同步/持久缓存、选择绑定与免费准入，最后接 UI 及分层验证；不得先做仅展示名单的 UI 再将选择/冻结无限后置。API/数据库契约、凭据引用、旧 Run 兼容及具体同步并发协议由实施时核定；不同时启动压缩、Skill 定制或文件恢复。责任见[运行架构 §8.6](../../architecture/runtime-context/part-03.md#86-模型目录会话选择与免费调用边界)，交互见[工作台 §27.5](../../frontend/workbench-design/part-09.md#275-免费模型分组与模型选择)，未运行场景见[测试计划 §26.3](../../testing/verification-plan/part-05.md#263-免费模型目录与选择验收规格)，执行入口为[专项提示词](../../../prompts/free-model-catalog.md)。

#### 9.1.1 免费额度耗尽自动接续

2026-10-16 新增目标，2026-10-17 实施中，替代 2026-10-15“免费模型也绝不自动切换”的限制；目录刷新与手动会话切换不改变活动 Run 的边界保留。

选择免费分组默认启用有界接续，首次选择时明确展示该规则，不要求每次跳转再确认。候选从当前可核实免费目录产生：首选在前，其余按确切模型 ID 稳定排序，排除不能满足当前请求文本/工具/结构化输出、上下文和协议要求的项；未知能力不冒充支持。新请求或 Run 准入时冻结有序候选及策略，刷新不向活动队列注入新型号。每次跳转仍须核对最新免费资格与凭据；每个候选单次逻辑请求最多尝试一次，推荐首版最多 3 次实际模型尝试（含首选，具体值实施时冻结并测试），不循环遍历或无限等待。

只在可核实的**当前模型额度或上游限流拒绝**后切到下一项。HTTP 429 单独不足以确认：OpenRouter 首版须有官方结构化上游限流证据、排除平台限流头，并经独立账户查询确认共享免费日额度仍大于零，才允许有界尝试下一候选；不声称由此知道每模型的专属剩余额度。账户额度未知/耗尽、有平台限制或缺少上游证据均停止，不能仅凭错误文本或自造 scope 字段切换。账户共享免费日额度耗尽不能靠换模型恢复，显示实际可得恢复时间；认证/权限、应用预算、网络超时、流式中断、内容拒绝均不自动触发。尊重 Retry-After，保存受限型号的冷却依据与恢复时间（未知如实），不靠换 Key/账号绕过平台限制。依据：[OpenRouter 限额与 429 说明](https://openrouter.ai/docs/api_reference/limits)（2026-10-17 核对）。

首选尚未发生确切额度拒绝就失效（转收费/下架/资格未知）时停止，不以目录变化替代额度触发；跳过后续失效候选仅限已经满足上述额度接续条件的流程。切换保留同一消息/Task/Run，冻结原契约与首选历史，新增可追溯的实际模型尝试/切换记录；后续安全调用使用已持久化的当前候选。不重跑已成功工具、不重建 Task、不继承其他候选的调用成功结果。仅在原请求已明确拒绝、没有未核对结果及半截工具链时切换；不把半截流或 UNKNOWN 当额度失败，跨模型无法安全承接的协议停下处理。全部候选不可用时停在原链并给原因，不能显示完成。

界面按实际证据显示“模型额度或上游限流，已从 A 切换到 B”、实际生效型号、尝试次数和用量来源；原首选与当前使用型号分别可见。切换仍使用独立服务商凭据与零价格限制，不改变批准、资源范围、业务完成或总调用/token 预算。工程责任归运行架构 §8.6，新增目标检查为 FM-10–FM-13。
