# 本机禅道接入说明

禅道开源版 22.6 装在本机 `D:\Develop\ZenTao`，产品 `relay`（productID=1）是本项目**当前的问题与需求登记处**。2026-10-22 从旧的自建开发台账一次性导入了 137 条，映射与导入时的原状态记录在 [zentao-import-2026-10-22.json](zentao-import-2026-10-22.json)。本文件说明人和 Agent 如何登录与写入。

## 1. 先确认服务在跑

两个服务安装后是 **Manual** 启动类型，重启机器后不会自启：

```powershell
Get-Service apachezt, mysqlzt          # 都应为 Running
Start-Service mysqlzt, apachezt        # 没在跑就启动，顺序不能反
```

Web 只监听 `127.0.0.1:80`，局域网访问不到，这是有意的收敛。内置 MySQL 走 `127.0.0.1:3307`，与用户自己的 MySQL80（3306）互不影响，**不要动 3306 那个服务**。

本文件描述的是本机第三方工具，不是 Relay 产品的部署拓扑；产品自身的桌面部署与凭据规则见 [本机部署](本机部署.md)。

## 2. 登录：密码只从环境变量读

账号固定 `admin`，密码存在**用户级环境变量 `ZENTAO_PASSWORD`** 里。

不要把密码写进仓库文件、脚本、提交信息、日志或 Context，取值时现取现用：

```powershell
# PowerShell
$pw = [Environment]::GetEnvironmentVariable("ZENTAO_PASSWORD", "User")
```

```powershell
# Git Bash（setx / PowerShell 写的用户区变量不会自动进已启动的进程，显式读 User 区最稳）
PW=$(powershell.exe -NoProfile -Command '[Environment]::GetEnvironmentVariable("ZENTAO_PASSWORD","User")' 2>/dev/null | tr -d '\000\r')
```

用 `$env:ZENTAO_PASSWORD` 只对**重启 Qoder 之后**新开的终端有效；已经开着的会话读不到，所以按上面显式读 User 区。

## 3. 换 Token 并调用

```powershell
$pw   = [Environment]::GetEnvironmentVariable("ZENTAO_PASSWORD", "User")
$body = @{account = "admin"; password = $pw} | ConvertTo-Json
$token = (Invoke-RestMethod -Method Post -Uri "http://127.0.0.1/zentao/api.php/v1/tokens" `
         -ContentType "application/json" -Body $body).token
Invoke-RestMethod -Uri "http://127.0.0.1/zentao/api.php/v2/products" -Headers @{Token = $token}
```

Token 是 32 位、跟会话绑定，用完不要把响应存盘；失效就重新申请。

## 4. 写入口（全部实测过，必填字段照抄即可）

**实际写入走 v1，不是 v2。** `apiv2.php` 只定义了 project 维度的 POST，单机试用一般没有项目。

| 动作 | 接口 | 必填 |
|---|---|---|
| 提 Bug | `POST /api.php/v1/products/1/bugs` | `title, pri, severity, type, openedBuild` |
| 提需求 | `POST /api.php/v1/products/1/stories` | `title, spec, pri, category` |
| 解决 Bug | `POST /api.php/v1/bugs/:id/resolve` | `resolution, resolvedBuild`（resolvedBuild 实测必填，缺了返回 400「解决版本不能为空」，2026-10-23 核实），可选 `duplicateBug, comment`（评论是追加动作记录，不覆盖已有） |
| 改派 Bug | `PUT /api.php/v1/bugs/:id` | 只传 `assignedTo` 即可（2026-10-23 实测 200），用于「领取」；`resolve` 会自动把 `resolvedBy` 记成当前账号 |
| 关闭 Bug | `POST /api.php/v1/bugs/:id/close` | `comment`（须先 resolve） |
| 关闭需求 | `POST /api.php/v1/stories/:id/close` | `closedReason, comment`（评审中的需求也能直接关） |
| 评审需求 | `POST /api.php/v1/stories/:id/review` | `result`（accept/reject） |
| 删除 | `DELETE /api.php/v1/bugs/:id`、`/stories/:id` | 软删，可用作回滚 |

取值范围：`pri`、`severity` 都是 1–4（1 最高/最致命）；Bug `type` 用 `codeerror / config / install / security / performance / standard / automation / designdefect / codeimprovement / others`；需求 `category` 用 `feature / interface / performance / safe / experience / improve / other`；`openedBuild` 传 `["trunk"]`。

核对总量用 `GET /api.php/v1/products/1/bugs?status=all&limit=200`。v2 列表的 `page` 参数不生效，只能读 `pager.recTotal`。

## 5. 会咬人的坑

- **密码强度会锁死整个 Web UI。** 后台默认开启强度检查，要求"6 位及以上，包含大小写字母、数字"三类字符。不达标时登录后被强制导向"修改密码"，**Bug 列表、需求列表、后台所有页面都被重定向**（REST API 不受影响）。改密码请走页面自己的表单，别直接写库——绕过表单会漏掉 `zt_userPwd` 历史并重新触发拦截。
- **需求默认强制评审。** 建需求必须带 `reviewer`，且结果一律是 `status=reviewing`。想让需求直接建成"激活"，得先在 后台 → 自定义扩展 关掉需求评审，那属于改全局设置，先征得用户同意。
- **v1 列表的 `status` 过滤不生效。** `GET /products/1/bugs?status=active` 会返回 `total: 0`，看着像「没有待修 Bug」。取激活项要用 `?status=all&limit=500` 读全量后按 `status` 字段本地筛（2026-10-22 导入的 96 条里 47 条激活）。
- **Git Bash 里中文标题会显示成乱码。** 禅道返回的是 UTF-8，是 Windows 控制台与 Python 默认按本地代码页解码造成的：把管道内容显式按 UTF-8 读（`PYTHONIOENCODING=utf-8` 配 `sys.stdin.buffer.read().decode("utf-8")`），不要据此判断数据坏了或回写错码。

## 6. 与旧台账的关系

`D:\Develop\relay-dev-ledger` 是本项目早期的一次自建开发台账。**2026-10-22 用户决定不再往台账登记新条目**，日常 Bug 与需求直接登记到禅道。台账目录只作为历史材料与 137 条导入快照的来源保留。

- 那次是**单向导入，没有双向同步**，导入器为 `relay-dev-ledger/output/migrate-to-zentao.mjs`，已随台账停用、不再维护。
- 导入条目在禅道侧可自证身份：标题带 `[DEV-xxxx]` 前缀、`keywords` 含 `台账:DEV-xxxx;分区:…`，正文末尾有"来源：relay-dev-ledger DEV-xxxx（2026-10-22 一次性导入快照）"。精确的编号→禅道 ID 与导入时的原状态见同目录 [zentao-import-2026-10-22.json](zentao-import-2026-10-22.json)。
- 现在**禅道是这些条目的当前登记处**；导入快照里的"台账原状态"只是历史，不能当作比禅道更权威的事实回写。
- 不要重跑导入器：它按映射表跳过已建条目，映射表与本目录这份副本彼此独立，误跑会重复建单。
- 截至 2026-10-22，导入的 51 条需求全部停在 `评审中`，等用户本人评审；Agent 不要代替用户点通过。
