### 9.13 会话视图顶栏密度（2026-10-16）

**当前规则（2026-10-17 第四轮接续：左翼收成两行并贴住卡片上缘、顶栏不画分隔线而由自己的底色渐变收边）**：顶栏是左右两翼的 chrome——无上缘与下缘描边、无圆角，**也没有下缘分隔线**；它与正文之间的边界由顶栏自己的底色渐变说出（`bg.surface` 从 0% 实到 40%、100% 处透明）。底色取的就是这一列自己铺的纸面（外壳卡片 `.app-content` 的 `bg.surface`，平铺纯色、不在右缘做横向渐隐——2026-10-17 校正，见下文），所以静止时渐变不改变画面，它保证的是「顶栏与正文之间没有一条线、只有一段淡出」，两翼文字都停在 40% 以上的实底段里。**真正洗淡正文的仍是转录区自己那两条遮罩**（见下），顶栏渐变只负责自己不压出一条硬边，两者不重复计数。整条高度＝上 `space.1` + 内容 + 下 `space.2`，内容取两翼较大者：右翼 `control.height.compact`（32px）／左翼两行 20 + `space.1` + 15 = 39px，实测 1487 视口 **51px**（上一版单行档 49px，两行只多 2px）。**最小高度按内容盒预留右侧控件高度**（`compact` + `space.1` + `space.2` = 44px，`box-sizing: border-box` 下把上下内边距一起算进来）：面板弹出后右侧「工作详情」键不渲染，首条输入区左侧又只剩作用域一行，只写 `compact` 会让顶栏在展开瞬间从 44px 塌到 32px（2026-10-24 用户截图），正文随之上跳 12px；这条下限让收起态（右侧键 32px）与展开态同高，两行档仍由内容决定。左翼两行读完：**第一行是会话名**，纯文字身份（`font.size.body` + `font-weight.medium` + `text.primary`，封顶 `min(20rem, 50cqi)`，超长省略、完整标题挂 `title`）；**第二行并列两件作用域事实**（关联目标文字／会话目录＝`Folder` 图标 + 目录名，间隔 `space.6`；目标标签与占位状态走 muted、真实取值走 secondary；完整路径只放在 `title` 与可访问名称「会话目录：…」里，可见面按本档省略，两件事实各封顶 50% 并各自省略），图标单独说不出「是哪一个目录」，因此名字回到可见面（2026-10-18 接续，见下）。两行同用 `font.lineHeight.heading`，块内行距 `space.1`，两行随聊天列宽收缩（交叉轴保持默认 `stretch`，不写 `align-items: flex-start`——列向 flex 的交叉尺寸取内容宽，会话名会保住 20rem 上限伸出主列轨道，实测 1000×800 与右翼交叠 231px²），左缘对齐由两行同一起点保证。顶栏纵向按自身内容居中，右翼那颗键实测停在两行的中线上。`.collab-center` 在这一列有顶栏时把顶部留白从 `space.4` 收到 `space.2`，会话名距卡片上缘实测 12px（`space.2` + 顶栏 `space.1`），任务仪表盘与「新对话」欢迎态没有顶栏、留白不动。**顶栏内不再有会话下拉**：跨作用域挑讨论的常驻入口是近期工作栏（`recent-work-<会话 id>`，与路由切换同一套离开保护）；只有本作用域读出 ≥2 条讨论时，右翼才出现一颗「切换讨论」浮层键——Task 绑定的会话不进工作栏，没有这颗键就等于回不到旧讨论，单条讨论的顶栏不多一套切换控件。右翼＝动作区，四颗纯图标键按事实出现：「切换讨论」（本作用域 ≥2 条讨论时）、「新建会话」（任务/项目归属时；工作空间级不重复左栏「新对话」）、「任务视图」（仅任务聊天）、「工作详情」固定在最后、且只在面板收起时出现（2026-10-23 起面板弹出后整颗不渲染，收起入口只剩面板头部那颗同图标键）。四颗键同一档：可见文字全部退出（「新建会话」的标签只在非顶栏会话控制带保留），命中区 `control.height.compact` 见方（32×32）、图标 1.125rem（18px）、键间距 `space.2`，可访问名称来自各自的 `title`／`aria-label`。右翼键是 **ghost**：静止透明底、透明边、`text.secondary`，悬停 `selection.hover` + `text.primary`，按下、展开与 `aria-expanded="true"` 落 `selection.bg` + `selection.text`，圆角停在 `radius.control`；禁用态降到 muted 并给 `not-allowed`——静止没有边框可失去，不补这一档就分不清「点不动」与「能点」。「工作详情」只在收起态渲染：画 `PanelRightOpen`，`title`／`aria-label` 说「展开工作详情」，`aria-expanded`／`aria-controls` 保留；面板弹出后这颗不渲染，展开态色族（`selection.bg` + `selection.text`）只留给常驻的「切换讨论」键。右翼不设「更多」或折叠菜单：任务/项目/运行的低频与全局入口已在任务视图 PageHeader 既有的「更多操作」菜单里，会话顶栏只保留上述高频键与需要常驻的详情开关；窄档让位靠收掉左翼作用域行，不把右翼键藏进溢出菜单。顶栏整条铺满聊天列、两翼贴列边，并抬到 `zIndex.sticky`：切换浮层要从顶栏探到消息流上方，而后画、自身 positioned 的转录区默认会盖住它。转录区**上下两条边各一条** `space.8`（32px）渐隐带（`bg.surface` → 透明，`pointer-events: none`），分别由 `data-top-fade`／`data-bottom-fade` 在正文真的被那一条边切走时绘制：被顶栏下缘、或被输入区上方那行目录细条硬切，读起来像坏了；停在顶端／底端还压着渐变更像坏了。两条带都画在不滚动的外壳上（`::before`／`::after`），因此不给中栏添第二个滚动 Owner（[工作台 §31.1](../workbench-design/part-10.md#311-位置与节点)）；层级停在 auto，时间线轨道（`zIndex.sticky`）与「回到最新」键（`zIndex.popover`）都浮在带之上，渐变只洗正文、不把刻度和那颗键一起糊掉。上下两条边是同一套机制，因此规则只写在本节这一处。首条空会话不显示会话身份，左翼只剩作用域，且不从历史继承目录或目标。顶栏自身的容器查询只留一档：`@container collab-toolbar (max-width: 30rem)` 收掉右翼按钮文字只留图标（可访问名仍来自各自 `title`）并整条隐去作用域那一行（目录另见输入区上方的目录细条），把宽度还给会话名；`46rem` 那一档属于非顶栏的会话控制带，量的是顶栏自身宽度而不是视口。会话 `select` 的样式规则（收窄到内容宽、封顶 `min(12rem, 40cqi)`、`base-select` 浮层）只保留在非顶栏的会话控制带（`?skill=` 独立 Assist 页）。零新增 token、零新增色值，路由、命令与会话 Owner 未动。Breaking Change：No。

**工作详情纯图标键与会话目录图标（2026-10-17 第五轮，用户指令）**：「工作详情」原先带可见文字与按钮边框，在 32px 高的顶栏右翼里比相邻键重一档；本轮按用户给的 Codex 参考把密度收到与图标键一致：删掉「工作详情」文字，按展开态换 `PanelRightOpen`／`PanelRightClose`，命中区 `control.height.compact` 见方、图标 1.125rem（18px），静止透明、悬停 `selection.hover`、展开 `selection.bg` + `selection.text` 且不补描边；`title` 与 `aria-label` 随状态说「展开工作详情／收起工作详情」，`aria-expanded`／`aria-controls`、`data-testid`、点击处理与焦点返回均未动。同一开关同时服务会话顶栏与任务视图 PageHeader，文案由一个 `inspectorToggleLabel(open)` 派生，避免两处漂移。会话目录则由「会话目录：路径末段」文字收成 `Folder` 图标（0.875rem）：可见文字清空，完整路径放进 `title` 与 `role="img"` 的 `aria-label`（「会话目录：…」），未绑定目录时图标降 muted；右侧「关联目标」仍保留文字，两类事实的可见性因此不再对称，这是本轮唯一按指令接受的取舍。实现落在 `CollaborationView.tsx`／`CollaborationView.css`、`AssistView.tsx` 与全局 `styles.css`（分隔条），零新增 token；因视图样式先于全局 `styles.css` 求值，图标键的尺寸/底色用 `.secondary-button.collab-inspector-toggle-btn` 双类抬高特异度覆盖全局按钮档。Breaking Change：No。**取证**：`tsc --noEmit` exit 0；本批 `conversationToolbarDensity`＋`recentWorkRailDensity`＋`frontendAcceptance`＋`inspectorPreviewLayout` 四套浏览器用例 **29/29**（含新增分隔条用例：静止 `::after` 透明、悬停透明度介于 0 与 1、按下并把指针移出命中区后仍有 `drag-separator--dragging` 且颜色/宽度与悬停逐值相同、松开撤类）。**未复验**：真实 WebView2 窗口与多 DPI（探针与用例均为 headless Chromium）。

**会话目录回到「图标 + 目录名」（2026-10-18，用户实机截图圈出顶栏那一格）**：用户问「怎么没有显示当前会话在哪个目录」。上一轮把目录收成纯图标的取舍（可见文字清空、完整路径进 `title`）在真实使用里不成立：`Folder` 说得出「这里有一个目录」，说不出是哪一个，而同一行另一件作用域事实（关联目标）一直是文字，两项读起来一边有值、一边没值。改为图标 + 目录名（路径末段：`canonicalRoot` 去掉尾部 `\\`、`/` 后按分隔符切段取末段），名字 `overflow: hidden` + `text-overflow: ellipsis`；容器由 `flex: none` 改 `flex: 0 1 auto` + `min-width: 0`，让它随聊天列宽收缩，图标自己 `flex: none` 不被挤掉。完整路径仍在 `title` 与 `role="img"` 的 `aria-label`（「会话目录：…」一字未改），未绑定／待核对／暂不可读取三档占位说法因此重新出现在可见面并继续走 muted（缺事实也要看得见缺什么，不靠悬停才知道这一格是什么）。零新增 token、零新增色值，`data-testid`、路由、命令与目录 Owner 未动，Breaking Change：No。**取证**：`tsc --noEmit` exit 0；`conversationToolbarDensity`＋`recentWorkRailDensity` **17/17**（两条原锁 `directoryText === ""` 的断言改锁真实末段名 `Relay-Agent`／`code`，`title` 断言不变）、`emptyConversationWelcome`＋`narrowWindowNewConversation`＋`conversationDiffLayout` **26/26**（窄窗无溢出）、jsdom `assistBinding`＋`folderFirstConversation`＋`recentWorkPagination`＋`conversationDiffSummary` **50/50**；截图 `results/rail-goals-and-directories.png`。**未复验**：真实 WebView2 窗口与多 DPI（用例均为 headless Chromium）。

**两行左翼、去分隔线、底色渐变收边（2026-10-17 第四轮，用户实机截图四条指令）**：四条分别是「不要有这个提示」（输入卡上方那行「本次对话 · 未绑定工作目录，暂不统计」）、「更换目录往左移动，贴到归入项目右边」、「你好这一行往上移，现在离卡片的上边缘太远，然后会话目录那个字样移动到你好下面，这三个的视觉效果协调一下」、「删除顶栏下面的分隔线，文字被顶栏遮盖部分就用从上到下慢慢变透明的渐变效果处理（顶栏的颜色改变）」。三条纯视觉收敛，一条改呈现归属。**未绑定目录的统计入口整块删掉**（见[工作台 §34.2](../workbench-design/part-12.md#342-两种比较与数据含义)）：同一屏的目录细条已常驻说出「未选择目录／执行前需归入项目」（2026-10-18 起这两句分别改为「选择工作目录」与「不影响讨论，执行前需先归入项目」），这一行再复述一遍是把同一件事讲两次；绑定目录的行与服务端 `NO_RESOURCE`／`NON_GIT`／权限态一字未动。**「更换目录」去掉 `margin-inline-start: auto`**：那一句把自己推到列的右缘，读起来像另一栏；行内 `gap`（`space.2`）本来就给够一档间距，动作紧跟在这行读到哪儿的后面。**作用域两行的取舍**：按字面只搬「会话目录」会让「关联目标」独留第一行、同类事实分两行说；目录值是路径末段，跟在会话名后面必然被挤短，故两件作用域一起落到会话名下面第二行、左缘对齐，第一行只剩身份。这是本轮唯一一处比指令多做一步的解释，用户若要「只挪目录」可回退。「往上移」落在两处留白上：`.collab-center` 在有顶栏时 `padding-top` 由 `space.4` 收到 `space.2`，顶栏自己上内边距由 `space.2` 收到 `space.1`——只收一处要么仍隔 20px，要么把两翼文字贴死在卡片边。两行都补 `font.lineHeight.heading`，否则 16px/12px 各自按 `normal` 撑高，行距会随字号跳。**分隔线换成顶栏自己的底色渐变**：`linear-gradient(to bottom, bg.surface 0%, bg.surface 40%, transparent 100%)`。40% 实底段是给两翼文字留的——渐变若在 0% 就开始淡，第二行（12px 的次要文字）会先糊掉。这一列的纸面本来就是 `bg.surface`（外壳卡片 `.app-content` 铺的同一档），所以静止时渐变不改变画面，它换掉的只有那条 1px 硬边。**诚实边界**：渐变在顶栏自己身上，正文并不伸到顶栏底下，用户看到的「文字被遮盖处变淡」实际仍是转录区上缘那 32px 遮罩在做（`.agent-chat-transcript-shell::before`，`data-top-fade` 门控）；把顶栏做成覆盖在正文之上的渐变层要让它进滚动容器，会连带改浮动层归属、`scrollHeight` 与单滚动 Owner（[工作台 §31.1](../workbench-design/part-10.md#311-位置与节点)），故没走那条路。零新增 token、零新增色值，`data-testid`、文案、路由、命令与会话 Owner 未动。Breaking Change：No。

**底缘同套渐隐与回底键收成整圆（2026-10-17 第三轮，用户实机截图两条指令）**：「文字被未选择目录这一行遮盖的时候也要有同样的渐变效果」——底缘带与上缘同源（`space.8` 高、`bg.surface` → 透明、`pointer-events: none`、同一条 `prefers-reduced-motion` 例外），只是方向相反，画在 `.agent-chat-transcript-shell::after`。**判定只留一个 `syncEdgeFades`**，由真实滚动、消息整批替换（换会话）与视口自身变矮（队列面板出现、窗口变高）三处共用：只挂 `onScroll` 会漏掉后两条，它们都不产生 scroll 事件——长会话切到短会话时遮罩会永久压在第一条消息上，正是上面那句「停在顶端还压着渐变更像坏了」要避免的形态。底缘阈值取 `remaining > 1` 而不是 `> 0`：高 DPI 下 `scrollTop` 是小数，停在底部时 remaining 可能是 0.4，那样最后一条消息永远糊着一层渐变。阅读意图（`followLatest`／`atLatest` 的 32px 档）仍只由真实滚动决定，尺寸变化不改读者的位置。「回到底部的箭头改成圆形背景」——文档与代码早就写着「边长 `control.height.compact`」，实际只声明了 `min-height`，于是全局 `.icon-button` 的 `height: control.height`（40px）生效，32×40 配 `radius.round` 读成竖胶囊；补上同源的 `height` 即为整圆，零新增 token、零新增色值，命中区没缩。取证：`conversationToolbarDensity.spec.ts` 第三例扩为上下两条边＋键形，1487×900 单 worker 5/5，截图 `results/conversation-toolbar-top.png` 与 `conversation-toolbar-fade.png` 分别是「滚到最顶（底缘带在、回底键是圆）」与「停在底部（两条带都不画）」；同样消费回底键与转录区滚动的 `chatTimelineNavigation` 单 worker 11/11；jsdom 全量 1067/1089，22 条失败里没有一条提到 `data-top-fade`／`data-bottom-fade`／`assist-latest`。**未复验**：真实 WebView2 与多 DPI；同批 `uiOption2FirstSession.spec.ts` 16 例红，全部停在夹具的发送流程（`assist-copy-a-0` 不出现、近期工作栏报「当前会话暂未能在近期工作中核对」），落在他人未提交的 `RecentWorkRail.tsx` 改写（+492 行）上，本轮只报不修。

**下拉比旁边按钮高 8px 的根因，与 §9.11 同源：同特异度层叠失效。** `main.tsx` 先求值 `./router`（其依赖链带进 `AssistView.css`）再 `import "./styles.css"`，所以视图样式落在全局之前；`AssistView.css` 的 `.agent-assist-session-controls select`（0,1,1）与全局 `.field select`（0,1,1）同权重，被后者按声明顺序压回 `control.height` 40px 与 `space.2/3` 内边距。修法同样是**抬高特异度**（`.agent-assist-session-controls > .field select`，0,2,1），不靠调整声明顺序。右区的「工作详情」虽然已经带 `secondary-button--compact`，但全局 compact 只回到 `control.height`（40），故在 `.collab-toolbar-right` 内按 `control.height.compact` 再压一档，只作用于本顶栏，不改任务视图 PageHeader 里的同名开关。

**浮层收编（同日接续）**：改前那条灰/蓝色带由 Chromium 用系统 Highlight 直接绘制，`option:checked { background-color }` 加 `!important` 也不生效。两条候选：自建 listbox，或 Chromium 135+ 的「可自定义 select」。取后者——`appearance: base-select` + `::picker(select)` 让浮层与选项变成真实元素，底色、圆角、描边、投影全部落回现有 token，而键盘、IME、读屏与 `setValue` / `selectOption` 语义仍留在原生控件上，既有用例一字不动（**2026-10-19 校正：这句对方向键不成立**，见下文「方向键契约」；`setValue` / `selectOption` 与读屏仍成立）；不支持该值的引擎忽略本段、退回原生外观，功能不受影响（本机 WebView2 155、Playwright Chromium 153 均支持）。选项两档照抄栏内 `.recent-work-item` 的语义与顺序：`option:hover` 取 `selection.hover`，`option:checked` 在 `selection.bg` / `selection.text` 之上再落 `font-weight.medium`，hover 在前、当前项在后，叠加时当前项胜出。实测 `::picker(select)` 背景 `surface`、描边 `border.separator`、圆角 `radius.control`、`shadow.floating`、内边距 `space.1`；当前项 `#EDF5EF` / `#205D47`、非当前项 `text.secondary`、勾选标记 `::checkmark` 取 `selection.text`。

同时补回两处随 `base-select` 丢掉的触发框行为：①按钮改为按内容收宽，短标签只剩 62px（字段自身下限是 6rem），故 `min-width: 6rem` 与 `.field` 同值、不新增 token；②按钮里的当前值改由引擎内部件渲染，长标题会换行把顶栏撑高（实测 30px → 36px），用 `white-space: nowrap` + `overflow: hidden` 在 `select` 上截断。**保留项**：Chromium 153 上仍是旧的「fallback button」渲染（实测 `::checkmark`、`::picker-icon` 存在而 `::selectedcontent` 不存在），长标题只能整字截断、没有省略号字形；换成 `::selectedcontent` 截断或自绘标签层都会牵动控件结构，留待该伪元素落地或换实现时再改。标签本体（`标题 · 更新 时间 · 当前`）是业务去重规则，未动。

**方向键契约（2026-10-19 实测，替上一段与 §9.13 验证出口里「键盘照旧」那句）**：`appearance: base-select` 之后 `<select>` 的键序不再等于原生 select。真实 Chromium A/B（同一段 DOM，只切 `appearance` 一个值）量到：`ArrowDown` / `ArrowUp` **先开浮层并把高亮停在当前项**，在浮层内才逐项移动，**`Enter` 才提交**，`Escape` 收起浮层且不改变 value；原生那套「一次方向键直接换值」没有了。`Playwright` 的 `selectOption()` 与 `focus()` + 读屏语义不受影响，所以只有依赖方向键换值的用例要改。这条不是缺陷：把当前项换成另一档 / 另一会话的控件，本就不该被一次误按换掉。同轮把输入器工具行的会话模式下拉（`.agent-chat-mode-select`）也收进同一段浮层定义，两条下拉的 `::picker(select)` 与三档 `option` 状态只在这里写一次，规则与实测归[工作台 §25.1](../workbench-design/part-08.md#251-控件层级)；首字母／数字 typeahead 本轮未复测。

**2026-10-22 DEV-0116 接续：这一段共享里少了一条下拉。** 输入器工具行的会话模式档不再是 `<select>`，改成应用自绘的 `details` 浮层（`.agent-chat-mode-select-field` + `.agent-chat-mode-chip` + `.agent-chat-mode-options`），因此本节的 `::picker(select)` / `option` 共享块**只服务顶栏会话控制带那条下拉**（`?skill=` 独立 Assist 页），`.agent-chat-mode-select` 这个类名连同它的浮层规则已从 `AssistView.css` 删除，不留第二套事实。换载体的决定性事实与几何实测归[工作台 §25.1](../workbench-design/part-08.md#251-控件层级)；自绘浮层在设计系统这一侧只继承既有语言，不新增数值：`bg.surface` + `border.separator` + `radius.panel` + `shadow.floating` + `zIndex.popover`，当前档 `selection.bg` / `selection.text` + 勾选图标，悬停 `selection.hover`，触发框 hover／展开／焦点环三档仍写在包裹的 field 上（`:has()`）。方向键语义这次由组件自己实现，键序与上一段 `base-select` 相同（方向键到目标行、`Enter` 提交、`Esc` 只收起），差别是它现在是**代码事实**而不是平台行为，因此由 `tests/assistantModeSwitch.spec.ts` 与 `tests/browser/conversationModeMenu.spec.ts` 逐条钉住。

**「新建会话」图标档（同日第三段）**：中栏在 `@container collaboration (max-width: 46rem)` 下把「新建会话」收成加号（图标 + 标签，收的只是文字），与右区「工作详情」同一档降级、同一断点，实测 860/700 视口按钮 74 → 32×32、中栏 278 → 236px，省下的宽度归左块作用域（860 视口 128 → 146px）。图标 14px 跟随当前字号（与 `.context-rail-new` 同写法），颜色随按钮；按钮的可访问名仍来自可见文字「新建会话」（实测按钮内文字 56px、未被截断），用例不需要按图标名改。宽态按钮 74 → 96px（加号 14 + 间距 8 + 内边距各 8，文字仍 56px），中栏 282 → 300px、左块作用域 210 → 198px；这是本轮唯一一处变紧，换来中栏一眼可辨的新建入口。悬停 `selection.hover`、焦点 `2px` 森林环照旧。

### 9.14 两级上下文菜单视觉补充

2026-10-16。用户下发「+ 菜单与二级能力菜单」提示词，并在同一条里明确要求**不要把这块推倒重做**：现有白底、轻边框、轻阴影、图标＋文字、从「+」向上弹出都是 Relay 的方向，本轮只做精修并补出二级。交互契约归[工作台 §32](../workbench-design/part-11.md#32-两级上下文菜单与二级能力入口)。**token 零新增**，全部沿用既有数值。

**一级（沿用既有外壳，只加状态位）**：行高 `control.height.compact`、圆角 `radius.panel`、边框 `border.separator`、阴影 `shadow.floating`、内边距 `space.2` 全部不变；条目仍是恒定单行、图标取 `font.size.body`、名称取 `font.size.meta`。**宽度收缩到内容**（`width: max-content`，只保留 `max-width` 上限）——2026-10-16 用户截图指出「菜单右侧留白太多」：此前写死 `min-width: 15rem`（Chromium 实测 235px）而最宽一行只占约 145px，短行右侧最多空出 108px 空白带；去掉下限后面板收到 **200px**。状态位分为行尾一个**尾组**：计数（`font.size.caption` + `text.muted`）、选中对勾与二级 chevron（均 `font.size.body`、`text.secondary`），尾组整体用 `margin-left: auto` 右对齐，因此短行多出来的空间落在文字与尾组之间、各行 chevron 落在同一列，行内左右内边距相等（实测各行尾组右缘距行右缘恒为 8px，与左内边距相同）。**不用彩色 Badge、不用实心色块**——状态是事实标注，不是装饰。

**不参与宽度计算的长文本**：菜单里的空态（「本机还没有最近目录」这类）是整段说明，若让它参与「收缩到适应宽度」，一条长说明就会把面板重新撑宽（Chromium 实测二级面板会从 194px 涨到 345px）。这类文本用 `width: 0; min-width: 100%`：只填充最终宽度、自行折行，不贡献固有宽度。**脚注已不在菜单里**（2026-10-19，见本节末）。

**展开中的一级行**：底色取 `selection.bg`（比 hover 的 `selection.hover` 深一档），读起来是「当前所在层级」；不做旋转、不加粗、不改字号。

**二级面板**：与一级同一套外壳语言（`radius.panel` + `border.separator` + `shadow.floating` + `space.2` 内边距），贴一级右侧、缝隙 `space.2`；宽度同样收缩到内容，但**上限比一级低一档**（2026-10-18 用户截图指认「这个菜单太宽了」）：一级 `max-width: min(22rem, 100vw - space.6)`，二级收成 `min(16rem, 100vw - space.6)`。理由是二级列的是目录名、资料标题与 Skill 名，一条长最近目录就会把面板顶到 22rem——真实 Chromium 静态量测一级 159px 对二级 352px，宽出一倍多；改 16rem 后二级 256px，长名照常省略号收尾（完整说法在 `title`）。内容不超长时两档都仍按最宽一行收缩（实测 **194px**）。高度上限 `min(60vh, 26rem)` 并在内部滚动（内容超高出现滚动条时实测无横向溢出、面板宽度不变）。面板内的小节标题用 `font.size.caption` + `text.muted`、上缘 `border.separator` 分隔；空态同款（`font.size.caption`、`text.muted`、`lineHeight.snug`）。

**本轮几何证据（临时量测页 + 真实 Chromium，用后已删）**：面板宽度一级 235px → 200px、二级 → 194px；各级每行尾组右缘距行右缘 8px＝左内边距，逐行一致；二级面板 25 行超高滚动时 `scrollWidth === clientWidth`（无横向溢出）。量测页只用于几何验证，不作为产品页面保留。

**动效**：一级入场 `opacity + translateY(space.1) + scale(0.98)`，二级入场 `opacity + translateX(±space.1)`（按展开方向取符号），时长与缓动统一 `motion.duration.fast` + `motion.easing.standard`。没有回弹、旋转、发光或渐变。`prefers-reduced-motion: reduce` 与 `html[data-motion="off"]` 两处都把动画置为 `none`，状态文字与控制入口不受影响。

**验证出口**：`tests/composerAttachMenu.spec.tsx` 十六条（两级开合、状态位、**尾组右对齐的结构前提**、引用开关与上限、空态、键盘、Esc 两段、外部点击、方向翻转、未接入项的禁用与 `title`）与 `tests/assistantModeSwitch.spec.ts` 的两条真实路由用例。jsdom 不量几何，所以「对称」由结构断言（尾组是行的最后一个子项、面板无 `min-width` 下限）＋上面的 Chromium 实测共同守住；真实 Windows 窗口与 DPI 下的观感未验收。

**菜单内不再有说明文字（2026-10-19 晚）**：用户指认「每个菜单下面都有文字……这个文字很影响体验」，对照上游同类菜单也没有这种整段脚注。移除一级弹层底部的 `.agent-chat-attach-note`（禁用原因、按项目登记说明）与二级底部的 `.agent-chat-attach-subnote`（未接入能力的接入点），**行内仍保留状态位**（计数、对勾、`暂未接入`、`需已有会话`），**原因改由行的原生 `title` 承载**。视觉后果：弹层高度只由选项行决定，不再出现「最后多一段灰字」；`aria-describedby` 一并去掉——它原本指向那些被删掉的节点，留着就是悬空引用。可用的命令也不再逐行写「可用」（`chatCommandStatus` 只在例外时返回文字）。

**hover 展开与二级单行省略（2026-10-17）**：用户对照参考菜单要求「鼠标悬停就显示子菜单、子菜单直接列出文件与 skill」。视觉上不新增任何一档：一级行在 hover 展开时复用既有「展开中」的 `selection.bg`（`data-active="true"`），未展开时仍是 `selection.hover`，因此「指针所在」与「二级开在这一行」两种状态不会混淆。二级条目名从可折行改为**恒定单行 + 省略号**（`overflow: hidden` + `text-overflow: ellipsis` + `white-space: nowrap`，`min-width: 0` 已由既有规则提供），完整说法进 `title`：资料标题与 Skill 名可能很长，折行会把 `control.height.compact` 的行撑成两三行，一列清单高低不齐；省略后各行等高，与参考菜单的文件列表同一种读法。面板宽度当时仍与一级同档（`width: max-content` + `max-width: min(22rem, 100vw - space.6)`），因此省略号只在真的触到上限时出现，不提前截断短标题；二级降到 `16rem` 是 2026-10-18 那一轮（见上）。

**二级纵向相对一级居中（2026-10-19，取代同日的「贴住当前行」）**：用户指令「二级要以一级的高度居中，如果一级太下面就底部跟一级对齐」——贴行让二级随 hover 的行上下跳，读起来像两个各自漂的浮层。现在 `top` 由 JS 写成 `(一级高 − 二级高) / 2`：二级更高时上探出一级顶边（用户截图里就是这副样子，不设 0 下限），唯一硬边是视口顶边；一级贴近视口底部时改为二级底边与一级底边对齐，再放不下交给既有 `max-height` 内部滚动；面板尺寸变化仍由 `ResizeObserver` 重算。真实 Chromium 实测（临时预览页，用后已删）：两档常规视口 offset 恰为 `(96−222)/2 = −63`；一级贴底档底边差 0；二级比视口还高的极端档被 `max-height` 夹住、未越出视口顶边。token 零新增。交互契约归[工作台 §32.4](../workbench-design/part-11.md#324-开合键盘与方向)。

### 9.15 会话 diff 的展示建议

2026-10-16，**推荐方案，未实施**。业务和状态归[工作台 §34](../workbench-design/part-12.md#34-会话局部与总-diff)。局部 diff 与文件名同一行，路径过长截断且完整路径可查看，数字不随路径一起被截断；预览／待核对使用既有次级文字，实际已修改才显示对应确认状态。总 diff 在输入卡外上方居中，以一行文字按钮作为展开入口，不增加厚卡片；窄宽度允许缩短标签，不能遮住发送、停止或草稿辅助入口，不因刷新撑高输入卡。

新增为绿、删除为红，沿既有增删语义 token 并核对文字对比度；同时保留 `+`/`−` 和可访问名称，不能只靠颜色区分。数字使用等宽数位（`font-variant-numeric: tabular-nums`），直接切换到最新值，可沿用既有 `motion.duration.fast` 的淡入，不做计数补间或强制滚轮。遵从 reduced-motion 和全局关闭动效，避免为每次更新建立读屏播报；状态变化与展开阅读可访问，键盘开合及回焦沿既有组件。复用已有字体、间距与浮层 token，本轮不新增数值 token；位置与窄窗几何待浏览器和 Windows 实测。
