### 协作页结构原语（2026-10-10）

协作页结构重塑（工作台 §28）新增四条可复用外观规则，全部引用既有 token，**未新增色值、字号、圆角或动效数值**。数值唯一源仍是 [design-tokens.json](../design-tokens.json)，此处只记引用关系，不复制数值。

- **chips**（模式切换 / 资料 / 动作下拉）：`radius.round` 胶囊 + `border.control` 边 + `bg.surface` 底；选中态（含展开中的下拉）`selection.bg` + `selection.text` + `action.primary` 边；hover `selection.hover`，过渡 `motion.duration.fast`。禁用态用 `disabled.bg` / `disabled.text`，不留「无底」的中间形态。同一排的 chips 不再插竖分隔线——那会把同类控件切成两组。**降档变体（常驻状态线上唯一的动作）**：静止可以是「无底 + `border.separator` 边 + `text.secondary` 文字」，hover 才回到完整 chip（`selection.hover` 底 + `border.control` 边 + `text.primary` 文字），按下仍走选中色族。用在信息层级已由文字说清的场合——那里的一圈深色描边会比它旁边的卡片更抢眼。降档只降静止权重：胶囊形、`control.height.compact` 命中区与三态一个都不能少，否则又退回「读成分段控件的一段而不是一个动作」。**2026-10-18 起唯一消费者退场**：目录细条的［更换目录］并进了目录名本身（见下条），该变体暂时没有消费者，规则保留供后续常驻状态线复用。
- **文件夹作用域细条**：它是输入区上方常驻的一行状态，不是卡片也不是浮层：不铺底色、不加圆角与阴影，也没有上缘分隔线（2026-10-16 按用户反馈去掉，消息区与输入区之间只留这一行常驻状态）；内容与输入卡同宽同轴（`--chat-measure` + 居中），不横贯整列。目录名 `font.size.body` + `font.weight.medium` 是这一行的事实主角，归属是 `font.size.meta` + `text.muted` 的次要事实，宽度不足时先在归属处省略。告警态**不铺警示底色**（琥珀底横贯输入列喧宾夺主，2026-10-15 去掉），状态由图标、目录名与状态短语三处的前景色 `status.warning.text` 同时承载（不靠单一颜色表达状态），次要事实保持 `text.secondary`，不跟着整条换色；状态短语只说后果、不复述归属那一句，完整原因给读障与 `title`。整行不收进胶囊（常驻状态线不是卡片）。**目录名即入口（2026-10-18 用户指令「更换目录和未选择目录合并成一个按钮」）**：行内不再有独立的动作键——目录名本身就是 `<button>`（`aria-haspopup="dialog"`，busy 禁用，点它打开更换目录浮层（§9.19））。它首先是事实：颜色对比、字重、省略与 `title` 照旧，告警态随细条换色；其次才是键：全局 `button` 只继承字体与颜色、不重置外框，这枚键自己剥掉原生边框、底与内边距，静止不描边、不铺底、不加下划线，**悬停只补一道下划线**说出「可点」，键盘 focus 走全局 focus ring，命中区就是这段文字本身（不撒到行内 gap 上）。**缺目录那一档是唯一的例外（2026-10-18 用户指认「未选择目录看不出是按钮」）**：文案本身就是动作「选择工作目录」，静止再加一道虚线下划线（`text-decoration: underline dashed`，色取 `text.muted`、线宽 `border.width`、偏移 `1px`，本档 `overflow: visible`，悬停换实线）——偏移不能沿用全站链接的 `0.2em`：3.2px 会落到 20px 行盒之外，被这颗键为省略号保留的 `overflow: hidden` 裁掉，计算样式仍报虚线、像素却画不出来（2026-10-18 用户实机截图「常驻下划线没生效」即此）；缺目录文案是固定短串、永不省略，本档放开溢出不影响省略号规则。虚线只说「这里还缺内容，点它是去补」，因此不用 `currentColor`：告警态文字是琥珀色，同色下划线会把整行读成一条警示。装饰一律走 `text-decoration` 而不是描边／铺底，上面那组「无原生控件外观」读数（`border.style: none`、`border.width: 0`、底透明、内边距 0）在两档都不变。布局依据见[工作台 §28.3](workbench-design.md#283-文件夹作用域细条folder scopebar）。
- **作用域来源标记**（2026-10-19，默认工作目录）：目录细条在目录名之后、归属之前加一段 `font.size.meta` + `text.secondary` 的「默认目录（来自设置）」，`flex: 0 1 auto` 可省略、不加图标、不加底色、不做成第二颗胶囊——它不是第二个作用域，也不是动作；目录名仍是这一行唯一的更换入口。顶栏同一句话取 `text.muted` + `white-space: nowrap`，目录名保持可省略的那一项。只有服务端 `context.working_directory.source = WORKSPACE_DEFAULT` 时才出现；`USER_PICKED` 与缺字段（历史未知）都不渲染占位，不用空字符串或问号替代。规则归[工作台 §18.1.5](../workbench-design/part-05.md#1815-未选目录时的默认工作目录2026-10-18已确认未实施)。
- **欢迎卡与引导卡**：欢迎标题 `font.size.compactPage` + `font.family.ui` + `font.weight.semibold`；引导卡 `bg.subtle` 底 + `border.separator` 边 + `radius.control`，卡内正文左对齐（外层欢迎区居中，列表居中会读成诗）。
- **「回到最新」悬浮键**：`radius.round` + `border.control` + `bg.surface` + `shadow.floating` + `zIndex.popover`，边长 `control.height.compact`，hover 用 `selection.hover`。它是真实 `button`，不是装饰；出现与消失仍是挂载/卸载，没有退场动画。宽高必须**同源声明**：只写 `min-height` 时全局 `.icon-button` 的 `height: control.height`（40px）仍然生效，32×40 配 `radius.round` 读出来是一枚竖胶囊而不是整圆（2026-10-17 用户实机截图指令校正，命中区仍是 32px，高于 `control.target.minimum`）。
- **输入器「+」弹层**（2026-10-16）：外壳沿用浮层语言（`radius.panel` + `border.separator` + `shadow.floating` + `zIndex.popover`）。选项恒定单行：图标取 `font.size.body`，名称取 `font.size.meta` + `font.weight.medium`，行高 `control.height.compact`，图标与名称一起垂直居中。**禁用原因归弹层底部脚注，不归条目正文**：同一份弹层里出现两条两行高的选项时，解释与选项名几乎同权重，四个动作读不成形；脚注用 `font.size.caption` + `font.weight.regular` + `text.muted`，顶部 `border.separator` 细线切开动作区，左缘对齐名称列。同一原因合并成一条，每条禁用项用 `aria-describedby` 指回对应那一行——Chromium 不在 disabled 控件上弹 `title`，原因必须留在可见文本里。这一条推翻此前「原因写在条目正文里」那句，旧写法保留在第 202 行 Menu 行的约束之下，不再作为呈现方式。

### 6.1 交互状态的统一表达（2026-09-29）

本节是设计约束补充，不代表所有页面已实现；[状态图](../mockups/2026-09-29/README.md)供视觉对照，业务结果以[工作台第13节](../workbench-design/part-03.md#13-交互反馈与业务状态绑定)为准。

2026-09-29 接续实现：共享按钮类的悬停（action.hover / selection.hover）、按下（primary 用 action.pressed；次级与文字按钮用 selection.bg）、键盘焦点（全局 focus-visible ring）、禁用（disabled 配色 + 就近 `disabled-reason`）与提交中（动词等宽替换为"正在保存/正在提交"并禁用拦截重复激活，不引入循环动画）已在共享 CSS 与既有页面模式中落地；字段错误态为 `field--invalid` 红边框 + `aria-invalid` + 就近图标错误文字。真实指针与键盘状态截图见[交互状态证据](../../testing/evidence/interaction-states-2026-09-29)；danger 按钮未单列按下态（其悬停已是语义色底），tooltip 键盘触发仍依赖原生 title，未自建浮层。

| 状态 | 视觉与输入规则 | 退出条件 |
|---|---|---|
| 默认 | 明确操作对象与动词；同一决策区只突出一个主操作 | 指针、焦点或业务状态改变 |
| 悬停 | 主按钮使用 `color.action.hover`；列表使用 `color.selection.hover`；无底的主操作按列表档反馈（§9.10）；不改变选中标志、执行者或版本 | 指针离开；键盘用户不依赖悬停获取信息 |
| 按下 | 使用 `color.action.pressed`，不缩放布局、不显示成功勾选 | 释放或取消按压；只在有效激活时提交一次 |
| 键盘聚焦 | 独立使用 `color.focus.ring`、`focus.width`、`focus.offset`；可与选中/错误共存 | 焦点真实移动；异步刷新不随意夺焦点 |
| 选中 | 稳定背景、文字和激活标记共同表达；与悬停有可辨差别 | 用户显式选择，或当前事实变更 |
| 不可用 | 使用 `color.disabled.*`，就近显示原因与可行下一步；原因不能仅藏在 tooltip 中 | 前置条件重新核对有效；禁用不等于隐藏原因 |
| 提交中 | 保留宽度与位置，动词改为“保存中/提交中”；拦截重复激活，保留阅读和安全导航 | 得到明确回执，或转为结果待核对 |
| 失败/冲突 | 原操作附近持续显示原因；保留用户草稿；与字段关联，不能只闪 toast；只有辅助信息的读取失败与「停留到关闭」的 Notice 可进浮层，见 §6.4 | 用户修正、重读或完成规定恢复流程 |
| 成功 | 按真实提交范围更新对象和状态，保留可查的版本/结果入口 | 不用固定延迟代替成功判定 |

任务行主链接、复选框和更多菜单各自独立；点击菜单不同时打开任务。行内辅助操作可在 hover 或 focus-within 出现，但必要操作始终可发现。来源链接悬停只提示目标，不自动读取、选入 Context 或授权。标题栏操作区不参与拖动；留白才可拖动，窗口控制与业务按钮状态分离。无后退历史时按钮不可用但名称仍可读。

Tooltip 仅补充名称/快捷键，键盘聚焦同样可触发，离开或 Esc 可关闭。菜单关闭回到触发控件；抽屉/对话框打开后聚焦其标题或首个合理控件，关闭返回原入口。未保存编辑的关闭行为沿用离开保护；Esc 不等于丢弃草稿，也不取消后台 Run。更新完成后若原控件消失，将焦点移到对应结果标题，避免落到页面起点。

动效时长只引用 `motion.duration.fast`、`motion.duration.panel`、`motion.duration.reduced` 与 `motion.easing.standard`，浮层反馈的停留时长另引用 `motion.duration.toast`、`motion.duration.snackbar`（§6.4），不建立第二套数值。减少动态效果时保留静态文字和焦点反馈；既有输入区运行流光仅遵守第7.1节的限定，不扩展为通用加载动画。

2026-09-30 整套页面呈现纠偏：普通主标题使用 page，今日仍保留用户选定的 compactPage；品牌、导航与默认侧栏宽度统一到唯一 token，已保存的侧栏宽度仍优先。任务列表标题不再被窄内容列限制；详情的状态、验收与产物事实横向并列，右侧编辑动作纵向铺满。知识阅读采用目录、白纸正文、来源三列，并按确切版本显示标题与目录；三工作台、知识管理和动态的辅助设置默认折叠，已应用的活动范围必须展开。折叠仅改变呈现，不能卸载草稿、原命令或未决结果。运行步骤用白纸与细线分组，诊断、控制和 UNKNOWN 入口保留。协作纸面为正文留出更多空间，判断元数据常驻，说明按需展开；宽而短的窗口允许判断区自身滚动。窄窗共用顶栏隐藏中间面包屑和日期、收为带可访问名称的来源按钮，保留搜索与收件箱入口。逐页证据及未测状态见[视觉 QA](../../../design-qa.md)。

效果图对照补充：页面引导与侧栏说明使用 reading 层级，列表标题使用 editorial/rowTitle，行内摘要使用 body，技术标识仍用 meta；不将业务摘要压成辅助小字。任务验收标准用白纸、序号和细分隔线，Run 步骤用真实状态节点与连接线。创建页宽窗标签和输入对齐，设置页按分组导航、内容、说明组织；窄窗保持自然阅读顺序或既有抽屉。所有字号与颜色继续引用唯一 token；这些呈现修正不代表整套参考图或 Windows 视觉已验收。

待审、产物、Task 建议和完成凭据的结构补充：主区承担列表或阅读纸面，右栏承担所选对象的判断/保存/确认或只读去向；取消外页与内页的重复边距，主区与右栏分别使用既有 main padding 与 rail width。待审列表、派生检查表、合并提案和完成依据用对齐行与细线分组，技术身份可展开核对。产物页将 Task 上下文收为可展开区，保留独立页签和错误/重读入口，阅读/编辑/预览共用一张纸面；冲突草稿与当前确切正文在宽窗并排、窄窗堆叠。含命令 Owner 的右栏在窄窗进入正常单列流，不用同时挂载桌面与抽屉副本；完成凭据仅只读链接，继续沿用原抽屉，抽屉标题不重复。上述组件继续使用唯一 token，不建立第二套数值。

阅读与恢复补充：Markdown 表格采用语义表头、细分隔线和既有 subtle 背景，长单元格可换行，超宽内容在独立表格区横滚并保留键盘焦点。恢复事实与上下文列表也用细线分组，查询范围和新接续点输入按需展开；错误与未决结果不能被默认折叠掩盖。窄窗搜索弹层使用一层纵向滚动，避免结果列表与面板同时限制高度。

### 6.2 全局控件与交互实施基线（2026-10-01）

本轮按用户要求优先保证最大化桌面窗口可用，保留已选视觉方向。体系沿用唯一 tokens、[共享样式](../../../apps/workbench/src/styles.css)及已有 React 行为组件，不新增组件库或第二套 Button/Input 数值；页面负责业务状态和命令 Owner，公共层负责控件外观、语义和键盘行为。第 6.1 节的状态区分继续有效，焦点表达以本节接续规则取代历史外扩 ring；这不是所有页面/业务状态均已验收的声明。

| 控件 | 公共入口 | 页面必须提供的状态与行为 |
|---|---|---|
| 主/次/危险/文字/图标按钮 | `primary-button`、`secondary-button`、`danger-button`、`text-button`、`icon-button` | 明确 `type`、操作名称及真实禁用原因；图标操作须有可访问名称。公共层统一 hover/pressed/focus/disabled，禁用不响应悬停；危险按下使用 danger/text-onAction，图标按下使用 selection，不改变布局。提交使用准确动词、`aria-busy` 和重复激活门禁；结果未知继续归原命令核对，不由公共控件自行重试 |
| 输入、下拉、多行框、单/复选 | 原生语义控件 + `field`/`edit-form` | 标签常驻；说明/错误以 `aria-describedby` 关联，错误用 `aria-invalid`，required 与业务条件一致。公共层统一字体、边界、placeholder、hover、readonly、disabled 与错误；单/复选使用现有 action 色。只读保留选取，禁用有原因且文字不整体淡化。任务表单只在校验失败后聚焦首个错误，继续输入不跳焦点；结果替换表单且无上层弹层时焦点转至结果标题，迟到结果不抢走弹层焦点 |
| 同页互斥页签 | [tabNavigation](../../../apps/workbench/src/lib/tabNavigation.ts) | `tablist`/`tab`/`tabpanel`、稳定关联、`aria-selected` 与单一 Tab 停靠点；方向键/Home/End共用入口并过滤 IME。资料类型与开发工具复用此入口，草稿确认/未决命令优先于切换。单面板开关用 `aria-expanded`/`aria-controls`，路由仍用链接 |
| 弹层与抽屉 | [AppDialog](../../../apps/workbench/src/components/AppDialog.tsx) + dialogStack | 只有顶层响应关闭和焦点；跳过隐藏祖先、闭合 details、负 tabindex、禁用/隐藏输入及 inert 内容；面板/外部起点的 Tab 回到有效对象，关闭取消延迟聚焦并恢复原入口。IME 组合期间 Esc 不关窗，退出行为仍由页面草稿保护决定 |
| 就地反馈与异步输入 | `field-error`、`action-error`、`warning-callout`、`receipt-message` + 页面状态 | 字段/业务失败、空态、读取中、提交中、待核对分开；错误与成功使用相应 alert/status 并保留可查结果。连接 readiness 检查期间冻结被核对的输入，失败后恢复编辑，避免屏幕值与实际激活值错配。会改写业务事实的结果继续留在就地；只说明「这条辅助信息暂时读不到」或短暂成功回执的可迁入浮层栈（§6.4），迁移判定归[工作台 §13.1](../workbench-design/part-03.md#131-反馈通道的四类划分2026-10-17) |
| 最大化页壳与滚动 | `.desktop-window .app-frame`/`.app-content`/`.app-main` | Grid 行及内容最小高度受剩余客户区约束；普通长页面由主区滚动，侧栏底部保持可达；协作内部滚动继续沿既有规则，不用外壳裁切隐藏按钮 |

用户五图反馈的接续规则：焦点线覆盖原边界并向内加粗，无边框控件仍有内侧焦点，错误字段保留 danger 色，实心主按钮以 onAction 区分焦点；复合搜索/分段/文件入口只保留容器焦点，不叠加外圈。同一控件行显式选择一个高度，会话下拉、新建与刷新统一引用 control.height，主次差异由底色与字重表达。工具右栏及执行输出抽屉与主画布同用 canvas，subtle 列表和文档内容 surface 保留各自用途。近期项目分组 summary 的 hover/pressed 使用 selection.hover/bg，反馈不改变尺寸或展开状态。紧凑连接详情占稳定剩余宽度，摘要与工具按钮顶端对齐且共用 control.height，正文只在摘要下方展开；代码入口为[ModelConnectionStrip](../../../apps/workbench/src/components/ModelConnectionStrip.css)。

本轮没有缩窗/DPI、真实输入法组词或全量业务状态验收；原生 title 的键盘 tooltip 等未实现能力不因本基线自动变成已完成。实际结果只归[功能验收表](../../testing/overall-acceptance-2026-09-28.md#当前功能验收表)，业务输入与恢复约束见[工作台第 17.5 节](../workbench-design/part-04.md#175-最大化优先的控件与交互接续2026-10-01)。

### 6.3 全局滚动条与拖拽分隔条（2026-10-17）

**滚动条只用 `::-webkit-scrollbar` 自绘。** 公共层原先在 `*` 上双写 `scrollbar-width: thin` + `scrollbar-color: border.control`，与下面那组前缀规则并存。这条双写在 WebView2/Chromium 上是有害的：只要 `scrollbar-width` 不是 `auto`，引擎就改画**原生**滚动条并忽略整组前缀规则——于是 thumb 是 `color.palette.control`（#849185，控件边界档，为「与画布 ≥3:1」而生，用作 thumb 明显过重），且轨道两端各带一枚跳转箭头，正是用户实机圈出的两处。现规则：`*` 上不再写标准属性，thumb 静止取 `color.palette.lineStrong`（#DCE5DD）、悬停取 `color.palette.control`，`::-webkit-scrollbar-button` 显式归零。需要整条隐藏的容器（近期工作栏、时间线轨道）继续用 `scrollbar-width: none`，它同样屏蔽前缀规则，语义不变。零新增 token。

**拖拽分隔条在拖拽过程中与悬停同款。** `role="separator"` 的列宽拖拽条（`.drag-separator`，三处消费者：近期工作栏手柄、对话与成果之间的分栏条、工作详情左边界手柄（2026-10-24））静止时线透明，悬停/键盘聚焦/拖拽时由 `::after` 画线；三态同色同宽，取 `color-mix(in srgb, border.control 55%, transparent)`。此前悬停用 `border.control` 实色、拖拽又被压回静止外观，抓握后指针滑出 24px 命中区时线会消失，实机读成「一拖就断」。现按用户指令把线整体调浅，并让 `--dragging` 与悬停共用同一条规则（多带一级 `:hover` 的旧覆盖已删除），指针离开命中区也保持同一外观。零新增 token、不改命中区宽度与列宽 Owner。

**验证边界**：以上两条在 headless Chromium 探针里量的是计算样式（`scrollbar-width` 回到 `auto`、`::after` 三态色值），**滚动条的实际宽度与箭头消失只能在真实 WebView2 窗口复核**——headless 走 overlay 滚动条，`offsetWidth − clientWidth` 恒为 0，量不出占位。多 DPI 与真实窗口未复验。

### 6.4 浮层反馈（Toast／Snackbar／Notice，2026-10-17）

用户指令「像这些 toast 不要影响页面布局」把三类临时反馈从正文里搬进浮层。哪条反馈走哪一档由[工作台 §13.1](../workbench-design/part-03.md#131-反馈通道的四类划分2026-10-17) 判定，本节只管呈现。公共入口：[Feedback.tsx](../../../apps/workbench/src/components/Feedback.tsx) 的 `Toast`／`Snackbar`／`Notice` 三个插槽组件与页壳里挂一次的 `FeedbackHost`；条目状态在 [lib/feedback.ts](../../../apps/workbench/src/lib/feedback.ts)，与 `dialogStack` 同为模块级 store，本项目没有 React Context，也不为这条栈新建 provider。

**几何**：整栈 `position: fixed`、水平居中，顶边取 `control.nav.height + space.2`（桌面标题带与外壳顶部桌面带之下，与三列纸面的上缘同一条线；再往上就压住标题带的拖动命中区与右缘窗口按钮），宽度 `min(layout.feedback.maxWidth, 100vw − 两侧 space.4)`，条目自上而下按出现顺序堆叠。栈本身 `pointer-events: none`，只有卡片收指针事件——空栈不渲染，不留一个透明层盖住页面。卡片 `radius.panel` + `shadow.floating` + `space.3/4` 内间距 + meta 字号，长句 `overflow-wrap: anywhere`。位置由同日第二轮用户指令「提示要在屏幕的正上方」从底部中央改为顶部中央。

**配色**：底与字沿用四档状态色（success／danger／warning／neutral），边框取同族 35% 混色而不是 `receipt-message` 那种整圈实色——就地提示要靠强边框从段落里切出来，浮层已经有投影把自己离开画布，实色边在浮层上过重。卡片内的动作与关闭按钮 `color: inherit`，跟随语义色而不是回到全局 action 蓝。

**层级与动效**：`zIndex.toast`（60）在 `zIndex.dialog`（50）之上——对话框里的保存回执与被它挡住的读取失败同样要立刻可读；这条栈的键盘焦点不进对话框的焦点陷阱（它在 body 上，不是对话框子树）。进入动画只用 `motion.duration.panel` + `motion.easing.standard` 的下移淡入（自上方 `space.2` 落入，与栈的顶边方向一致），`prefers-reduced-motion` 与 `html[data-motion="off"]` 都去掉；停留时长引用新增的 `motion.duration.toast`／`motion.duration.snackbar`，需要停留到用户处理的条目不设置计时器。

**无障碍**：非 danger 条目 `role="status"`，danger 条目 `role="alert"`；Snackbar 的动作按钮是卡片里唯一的按钮，Notice 的关闭按钮用紧凑档 `icon-button` 并带「关闭提示」可访问名称。悬停或键盘聚焦期间暂停自动消失，离开后才走完时长；Esc 不关浮层，该键继续归停止生成与对话框关闭。

**命令式入口（2026-10-18，危险操作的反悔入口）**：三个插槽组件是声明式的——挂载即入栈、卸载即出栈，这决定了它们承载不了撤销条：会话行的撤销必须活过菜单自身的关闭（面板收起时 `SessionRowMenu` 连同它的插槽一起卸载）。故同一 `Feedback.tsx` 增加三个命令式导出，`openUndoFeedback(key, { text, actionLabel, onUndo, testId })` 入栈一条 Snackbar，`escalateFeedback(key, { text, testId })` 把同一条原地改写为停留到关闭的 danger Notice，`closeUndoFeedback(key)` 撤走它。三条规则：一张 `Map<key, id>` 让同键复用旧 id，靠 `putFeedback` 按 id 原位替换实现「同键只有一条且不重排栈」；升级**不新增 variant、不新增 token、不动 CSS**，因为 `FeedbackCard` 的计时 effect 依赖 `entry.dwellMs`，换成 `null` 自然清掉旧定时器并出现关闭按钮；倒计时归宿主侧的 `FeedbackCard` 所有，`FeedbackHost` 在页壳里只挂一次，所以条目与触发它的业务行卸载与否无关。点击撤销时 `FeedbackCard` 已按 id 收走条目，入口内部先清键登记再跑调用方的反向命令，避免撤销成功后同键二次入栈。判据与文案义务归[工作台 §13.2](../workbench-design/part-03.md#132-危险操作的两条通道2026-10-18)。

**本轮范围与验证边界**：对话页输入卡外的三条（模型调用状态读取失败→Snackbar、命令回执→Toast、动作失败→停留到关闭的 Notice）之外，本切片新增第四条通道消费者＝近期工作栏会话归档的撤销条。其余页面仍按 §6.2 的就地反馈保留，逐页迁移时先过 §13.1 四问。jsdom 用例断言条目落在 body 上的栈里、不在组件容器里，另有一条读源码 CSS 的位置守卫（顶边锚在 `control.nav.height + space.2`、不再声明 `bottom`、进入动画自上方落）。命令式入口在 jsdom 取证四条：归属组件卸载后条目仍在并能关闭、同键只渲染一张卡、点撤销回调恰一次且条目同步撤走、升级后不再被计时器收走（`tests/feedback.spec.tsx` 11/11）；调用方一侧取证三条（`tests/sessionRowMenu.spec.ts` 15/15）：撤销发出**第二条**命令且 `expected_revision` 等于归档回执推进后的修订、重开撞 409 时同一条升级为 Notice 且不发第三发命令、回执不明时**没有**撤销条。**仓外 Chromium 静态探针实测**（真 `styles.css` ＋ 展平后的 token ＋ 按 `Feedback.tsx` 抄出的 DOM，不是应用运行时）：1440×900 下栈顶 56px＝标题带 48 ＋ `space.2` 8，宽 448px（28rem）、left 496＝(1440−448)/2 精确水平居中，动画落定后首张卡片顶边与三列纸面上缘同线；一条与三条卡片两态下正文盒 `top/left/width/height` 与 `.app-main` 滚动高度逐值不变（101 / 306.39 / 1121.61 / 24 与 798），栈 `pointer-events: none`、卡片 `auto`，进入动画起点在最终位置上方 8px（48 → 56）。**顶部居中的已知代价（同一探针实测）**：三条一起出现时栈高 189px，会压住正文阅读区上沿约 190px；窗口宽 900 那一档居中的卡片横过应用顶栏的面包屑并吃掉其点击（`elementFromPoint` 命中的是浮层文字），1440／1100／760 三档不碰——浮层只停留 4／8 秒或可手动关闭，本轮未再加避让。**未验**：浮层的几何仍只有上面的静态探针与 jsdom，真实 WebView2 窗口下撤销条出现/消失不改正文几何、多 DPI 观感，以及「悬停暂停计时后再点撤销」的真人操作序列，均未复核。

## 7. 可访问性与动效

按本项目验收目标，普通文字组合至少 4.5:1；关键非文本控件边界和焦点相对相邻背景至少 3:1。装饰分隔线不承担控件识别职责；选中色块仍保留文字/图标/激活线。当前 JSON 检查只验证预设纯色组合，不等于页面符合 WCAG。[文字对比度](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)、[非文本对比度](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)。

独立交互目标最低使用 control.target.minimum；需要更宽松点击区的桌面控件使用 control.height.comfort 或更大。正文内链接可以保留文本布局，其他小图标扩展实际点击区。较大的点击区是产品选择，不将 44px 误写成 WCAG 2.2 AA 的通用强制值。[目标尺寸说明](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)。

Tab 顺序遵循视觉/文档顺序，提供跳到主内容入口；图标按钮有可访问名称。只有真正的同页 Tab 使用相应键盘模式，导航仍为链接。[Tabs 模式](https://www.w3.org/WAI/ARIA/apg/patterns/tabs/)。

M04 Assist 子页复用现有表单、面板、按钮和间距 token：来源选择为明确的复选框与版本文字，消息状态为静态文本，提案正文按纯文本可滚动展示，不渲染模型输出为可执行 HTML。错误与回执就近显示；切换会话后清除未发送的来源选择。新增局部列表样式不建立第二套 token，也不引入第 7.1 节尚未实现的运行流光。

首批第一方 Skill 在相同 Assist 表单中增加“普通 Assist / Skill”原生选择框；选择后就地显示定义版本、摘要、依赖及缺能力，单字段输入保留可见标签。历史输出使用原 `assist-proposal` 面板按服务端类型展示；模型建议本身没有接受按钮，服务端提案另开确认区；失效来源用文字替换引用，不沿用可点链接。Pack 清单复用 `surface-panel` 和列表样式，当前版优先、历史版仅供查阅；成员状态用“可调用、只读/仅建议/缺能力/可确认提案”文字表达；创建引导与设置不新增授权色或配置动作。所有长摘要和 ID 按已有可换行规则处理，不新增 token。

冻结旧 Skill 定义的历史消息沿用静态辅助文字，显式写明 `HISTORICAL_ONLY` 仅可查阅；原版本与摘要和当前可调用选项分开。PENDING/NO_OUTPUT/UNAVAILABLE 状态只显示服务端消息事实，不用占位建议卡或禁用的“接受”按钮暗示可应用。

Task Definition 的只读对照在原 `assist-proposal` 面板中按“当前验收 / 模型建议”顺序列目标、结果类型、模式和条件。revision 不一致用现有 `action-error` 文字提示过期；读取失败清空旧对照，只保留就地错误和重读按钮。条件差异的标题写“未逐字重复/未完全相同”，不使用删除或新增色彩暗示未来合并效果。Verification Plan 的当前 CheckPlan 准入预览与历史 Run 验证分开显示来源、原因和未执行说明；Project Resume 的模型下一步仍非 Today 准入事实。Task Skill 服务端合并提案以原 `assist-proposal` 面板列出目标/结果、保留与新增条件、双版本及来源摘要；原生两步确认按钮只在提案可读且版本一致时出现，409、失权与回执不明使用现有文字状态和按钮，不新增 token。

项目 Knowledge 的 P17 URL 导入表单同样复用现有面板、字段、按钮、提示及错误样式；Job 状态用“已排队／处理中／导入成功／导入失败”文本与原状态码一起呈现，Gateway 等待批准时以文字和 Review 链接说明。Job ID、原 command_id 和 Knowledge 版本 ID 保持可选取文本，长 URL 与 ID 允许换行；刷新保留已知状态，不使用完成比例或流光推断后台进度。导入结果仅显示服务端版本摘录纯文本，不渲染网页 HTML。局部间距、分隔线沿用已有 token，不增加新的色彩或动效变量。

WEB_FETCH 连接选项同时显示服务端可公开的允许主机名与连接 ID；主机名为空时只显示 ID，不用 URL 反推连接配置。

hover/focus 的颜色过渡用 motion.duration.fast；抽屉/面板用 panel；不使用弹簧、循环装饰动画或大位移。唯一有界例外是第 7.1 节绑定真实运行状态的输入区辅助流光，不推广到普通输入框或其他装饰。prefers-reduced-motion 时使用 reduced，进度仍可用静态文本表达。流式输出不逐 token 触发 aria-live 播报；只播报开始、需要处理、结束等有意义节点。

### 7.1 输入区运行光点（2026-10-05 选定局部光点）

在途时用**上边一条 18% 宽、2px 高的光点沿上边单向移动**表达当前回复仍在生成。输入区域本身保持静止；光点只动 `transform`，不重绘卡内内容。不做整圈流光、不加 blur 光晕、不做呼吸缩放或持续强光。边框基础宽度复用 `border.width`，光点高度由它推导，运行周期用 `motion.loop.calm`（6s）。不再设第二套数值源。

另两个候选——静默基线（只把边框调深一档、运行期完全静止）与底部内缩基线往复段——已在真实界面比对后弃用，代码与其专属 token 一并移除。若日后要重新评估，应从本节当前形态出发，不要复活已弃用方案。

光点只承载辅助提示，不表示完成百分比，也不能替代状态文字。状态由消息行的「正在生成」标签承担（`PENDING` 不标状态词，呈现见上文）；首字到达前的消息体内另有三点占位。

两种输入器形态都承载该反馈：独立对话卡的 `.agent-chat-composer` 与嵌入式子页的 `.create-form`。后者原本不是定位上下文，光点会跑到更外层，因此给它补 `position: relative`。不推广到普通输入框或其他装饰。

**提交瞬间不得出现闪动**，这约束了实现方式：

- 在途状态不能只由已读到的消息列表推导。消息列表要等查询返回才带上新回复行，那之前输入器会短暂呈现「无在途」再跳到「在途」。实现改为在 202 回执落地时记住该回复 id，在查询真正看见那一行之前持续按在途呈现；它只记 id，不缓存状态。
- 装饰层不给 `transition`。在途切换与淡入若都带过渡，两段动画叠在一起比单纯状态切换更闪。
- 队列面板是常驻区块而非 `details`，且空态渲染等高不可见占位：队列长度在提交瞬间从 0 变 1、最后一条离开时变回 0，折叠控件的 summary 与展开箭头会跟着一起闪现，转录区高度也会被推动。
- 光点层常驻占位、在途时只切 `opacity`，不增减任何尺寸。

动效只由 `html[data-motion]` 控制，取值来自本机偏好与系统 `prefers-reduced-motion` 的组合，解析与持久化见 `src/lib/motionPreference.ts`（本机显式选择优先于系统设置）。关动效时装饰层 `display: none` 而非仅把时长压到 0——否则光点会停在起点被读成一个固定亮条。关动效只改展示：不发送暂停或取消命令，也不隐藏状态文字与停止入口。

流光不替换文本输入框的键盘焦点边框，不遮挡控件、不截获点击，也不改变输入区尺寸或导致布局跳动。焦点提示独立且持续可见，符合[焦点可见原则](https://www.w3.org/WAI/WCAG22/Understanding/focus-visible.html)。阶段说明占用稳定的一行区域，窄窗口允许换行，查看进度与停止等操作仍须可键盘触达。

状态文本使用适当的 `role="status"` 或礼貌播报区域，无需抢焦点即可获知阶段变化；装饰光带不参与辅助技术朗读。只播报开始、重要阶段变化、需要人工处理及结束，避免逐 token、逐秒或每次事件重复播报，参见[状态消息指南](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html)。

提供可保存偏好的独立“运行提示动效”开关；用户关闭或系统 `prefers-reduced-motion: reduce` 任一成立时均禁用循环流光，保留静态边框、图标、状态文字和控制入口。开关只控制展示，不发送暂停或取消命令。依据见[暂停、停止、隐藏指南](https://www.w3.org/WAI/WCAG22/Understanding/pause-stop-hide.html)及[减少动态效果设置](https://developer.mozilla.org/en-US/docs/Web/CSS/@media/prefers-reduced-motion)。

具体状态、运行绑定、断线与 UNKNOWN、停止确认和完成语义只由[工作台输入区运行反馈](../workbench-design/part-02.md#61-输入区运行反馈2026-09-25待实现)维护；本节不定义第二套业务状态机。实施时需验证实际桌面缩放、焦点对比度、键盘与屏幕阅读器、动效关闭和减少动态效果；静态图或文档检查不能替代这些验证。

### 9.1 连续工作区呈现接续（2026-10-01）

本轮按用户授权实施[连续协作规则](../workbench-design/part-04.md#176-连续协作工作区2026-10-01)，不更换配色、字体、UI 框架或业务 Owner。普通页面 `font.size.page` 复用 `font.size.compactPage`，`layout.section.gap` 收为 `space.6`；正文仍采用独立 body/reading 层级。默认对话比例由新增 `layout.collaboration.chatRatio` 定义，展示偏好读取该 token，不在 CSS 复制默认比例。

任务页头覆盖两栏，行内显示当前需要与执行步骤，操作与诊断就近放置。可调分隔条支持鼠标/指针和键盘，聚焦时有明确焦点线。专注模式只是展示选择；隐藏的子树不能被可见区键盘访问，也不能丢弃状态。窄窗先切区域，短窗允许主区自然滚动；展开长诊断后不会把阅读和操作压成不可达的小框。

聊天普通正文优先，提议摘要以状态、目标和可展开接受入口组织，不默认铺满 hash 与字段表。消息区与输入器有明确边界，返回最新不额外占一行。成果名称/版本、版本比较与编辑采用一条工具栏；版本浮层限定滚动空间。普通判断的对象、条件、影响与操作保持可见，依据与补充说明靠近按钮；多个判断通过就近选择区切换。阅读版本与判断绑定版本不一致时使用明确提示与返回入口，不靠短 ID 让用户自行推断。

动作审批、未知结果、失权和未决命令仍采用完整可读的异常区域。Trace/执行输出用可展开分组保留全部记录，不能因收紧默认密度而隐藏 UNKNOWN。业务规则、存储键、恢复和键盘行为只归工作台第 17.6 节；实际环境与验证结果只归功能验收表，不把公开产品截图当 Relay 验收。

### 9.2 共享页级原语（2026-10-01）

改造前 `grep page-header` 为 0：16 个 view 各自内联标题块，8 个页面各自重声明页面外壳，同一层级在不同页面长得不一样。本节引入三个最小原语，只收敛结构与可访问性，不新增业务状态、执行权限或写入 Owner。

| 原语 | 结构责任 | 字段可见性规则 | 验证出口 |
|---|---|---|---|
| [PageHeader](../../../apps/workbench/src/components/PageHeader.tsx) | `title` / `status` / `meta` / `lede` / `actions` / `more` / `children`，各占固定层级；`more` 渲染为「更多操作」浮层，Escape 在 IME 组词期不触发，关闭后焦点回到 summary | 名称、状态、当前需要与**首屏动作**常驻；诊断、模式切换、工具与模型端口进 `more` | 展开 `more` 前后页头高度不变；深层动作仍有可访问名称；旧路由与深链接不变 |
| [FactBar](../../../apps/workbench/src/components/FactBar.tsx) | `cells[{label, value?, note?, action?}]`，按 `layout.factbar.cellMin` 自适应分列；格数由调用方按页面语义给 | 事实条是页头的**按需细节**：协作页默认收起，其余页面按对象决定是否常驻 | 不整块套卡片；不足整条换行不压缩文字；已加载范围说明与标题同排，不另占一行 |
| [JudgmentBar](../../../apps/workbench/src/components/JudgmentBar.tsx) | `title` / `head`（标题同行）/ `description` / `actions` / `details`；剩余属性透传到根元素，调用方因此可以继续用自己的作用域类与 `data-*`。外观：`bg.surface` 底、`radius.control` 四角圆角、整圈 `separator` 边框；`--warning` 把边框整体换成 `status.warning.text` | 对象、条件、影响与动作常驻；产物版本 ID、`target_hash`、验收条件 ID 与来源深链进 `details`。作为独立圆角卡排在所读纸面之外，不贴在纸面内层——那会盖住正文最后一行 | 截断 UUID 不再出现在首屏；动作审批不使用紧凑形态；UNKNOWN、结果待核对与执行权事实不收进 `details` |

三条硬约束：

1. **折叠不是隐藏**。`more` 与 `details` 里的内容必须仍有可访问名称与可达路径；判断条、技术身份、原未决命令、权限拒绝与无法确认的执行结果不得只存在于展开区。
2. **强制展开优先于省高度**。UNKNOWN、控制请求未结清、执行失败这三类出现时，协作页的 Run 控制移到页头常驻（`CollaborationView.tsx` 的 `runNeedsAttention`），不留在浮层里。
3. **数值仍归唯一 tokens**。本轮没有新增色值、圆角、时长或动效；新增的只有 `.page-head*` / `.fact-bar*` / `.judgment-bar*` 三组类名和 `font.size.section` 在成果文档头上的复用。效果图中 1487×1058 的列宽与留白是生成图推算值，不写入数值源。

协作成果区另有两条呈现约束：阅读区保留 `layout.workspace.centerMin` 下限，判断条 `position: sticky` 贴底（短窗口 `max-height: 40rem` 下改为正常流）。判断条高度因此不再挤压确切正文，两者都不靠像素调优维持。实际取样与限制只归[功能验收表](../../testing/overall-acceptance-2026-09-28.md#当前功能验收表)。

### 9.4 新建与已有对话对齐（2026-10-05）

依据用户提供的已有对话截图，新建入口复用 `.agent-chat-composer` 的底部常驻布局与 `layout.reading.maxWidth`，不再以 `layout.workspace.sideWidth` 限制首条输入器。欢迎语占空白消息区，目录与接续已有任务按需展开；两者置于主区顶部，避免在输入器下方另占一行。主区内距与已有对话共用，短窗沿用既有自然高度规则。

首条输入器与已有会话共用两行初始输入、占位文案、圆角、底栏类名和圆发送键。左侧资料及普通档讨论入口、右侧缓存及上下文圆环保持同一顺序；助手档隐藏讨论入口，准入与恢复规则归工作台 §25.1。首次模型调用前复用 `ContextMeter` 的未知状态，不伪造占用或缓存比例。资料按钮的禁用与讨论说明由[工作台 §18.1.1](../workbench-design/part-04.md#1811-新对话直接起步2026-10-05-接续实施)定义。

2026-10-07 单行底栏修正：模式 radio chip 与资料/讨论 chip 同样以 `2 × radius.composer` 推导最小高度，与发送键对齐，避免通用控件高度撑高普通工具行；保留原生 radio、焦点与目标下限。助手选择器、说明和创建表单展开后仍按内容自然增高，不能把整个助手区固定为单行。数值只归现有 token，不更新几何断言迁就布局缺陷。

2026-10-16 发送键字形：按用户指令由纸飞机（lucide `Send`）换成**向上箭头**（lucide `ArrowUp`），首条输入器与已有会话两处同步。只换字形——键仍是 `control.height.compact` 32px 方形、`radius.control` 8px 圆角、图标 `control.icon.size` 20px、`control.icon.stroke` 描边，停止态的同位方块字形不动，可访问名称与 title 仍说明当前动作。此前文档只写过「圆发送键」的形状与几何，未固定字形，因此这条不构成对既有决定的推翻。
