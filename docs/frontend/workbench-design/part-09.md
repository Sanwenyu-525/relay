### 27.5 免费模型分组与模型选择

2026-10-15 目标交互；2026-10-17 选择器、客户端及首条发送接线已写入源码，运行接续仍在实施复验，成绩只归统一验收表。范围与免费定义归[后续路线 §9.1](../../requirements/post-v1-roadmap/part-01.md#91-免费模型分组与自动同步)，调用责任归[运行架构 §8.6](../../architecture/runtime-context/part-03.md#86-模型目录会话选择与免费调用边界)。沿用现有输入器与浮层语言（模型选择是锚定下拉，不是居中弹窗），不借此重做导航或视觉系统。

模型选择包含原已配置模型与独立「免费模型」分组；分组展示来源、最近成功更新时间、“立即刷新”、模型名称及确切 ID、已知上下文窗口/工具能力和限制说明。目录单价为零与账户额度可用分别表达；未知能力或限额不编造。当前配置继续可辨，不自动把新模型设为默认。

浏览、搜索、刷新和取消均不切换模型、不发送聊天或测试推理。`/model` 仍遵守菜单选中插入草稿、发送才执行的规则；无参数发送时打开选择器，带具体型号发送时沿原模型选择命令执行。选择器的明确应用操作就是点选清单条目（见下文 2026-10-17 指令），经服务端确认后显示“用于本会话后续请求”。保存中禁止重复提交；失败保留原选择；回执未知复用原 PendingAction 的命令身份查询/重试，不另建回执 Owner。无会话时只保存首条选择草稿：发送过程固定创建、选择和消息各自命令 ID，选择成功后把其 revision 随首请求发送；服务端在消息准入事务内核对版本并冻结快照。两命令间发生改选则拒绝消息，不先按默认发出、不静默采用其他选择；响应丢失沿原 ID 接续，不重建会话。

首次加载、刷新中、首次失败无缓存、成功但无免费模型、旧缓存且刷新失败、未配 OpenRouter 凭据、能力不足、额度耗尽、已选模型下架/转收费分别可见。旧列表显示“上次同步”，过期或无法核实的项不得继续作为可调用免费模型；已选失效项保留名称和原因，供重新选择，不悄悄改值。应用默认与会话覆盖、会话选择与活动 Run 冻结策略分别说明，活动 Run 不随选择器变化。

2026-10-16 新增目标，2026-10-17 实施中：免费分组首次选择明确告知“当前模型额度或上游限流且账户额度仍可用时，按冻结顺序有界尝试其他免费型号”；展示首选与有界候选顺序，切换无需逐次确认。实际发生时显示从 A 到 B、已核实原因、实际生效型号和尝试序号，不把首选名当本次实际调用名，不自动改应用默认。区分“当前模型受限，已接续”“账户总额度耗尽，等待恢复”“全部候选不可用”“状态待核对”；已知冷却/恢复时间按来源显示，未知不倒计时编造。用户可在下一请求前改选择，停止/取消仍作用原消息/Run；切换历史和各次真实用量可追溯，不把重试当新任务或任务完成。完整规则归[后续路线 §9.1.1](../../requirements/post-v1-roadmap/part-01.md#911-免费额度耗尽自动接续)。

仅需为必要状态复用现有组件与 tokens；键盘选择、焦点返回、Esc 保留草稿、窄窗与中文 IME 不能退化。具体控件随实施映射现有模型状态区，未运行出口归[测试计划 §26.3](../../testing/verification-plan/part-05.md#263-免费模型目录与选择验收规格)。

**2026-10-17 用户指令（已实施）**：选择器不再在行内摊开来源、上下文、工具与 ID——触发器显示**当前具体模型名**（未选择时显示「模型」），清单**每项只显示模型名**，具体信息（ID、上下文、能力、失效/过期/未配凭据等原因）悬停看条目 title、读屏看可访问名称，当前选择以行尾对勾与淡底标记。清单条目点击**即应用并关闭**（既有命令入口，失败与 UNKNOWN 沿原回执恢复）；首条消息场景改为点选即写入本地选择草稿，不再要求先选再按确认键。原生效校验（配置/凭据/过期/文本输入输出能力）与「目录变化不自动改选」不变；`/model <型号>` 直接发送路径不变。视觉归[设计系统 §9.16](../design-system/part-06.md#916-模型选择器触发器显名与清单只显名2026-10-17)。

**2026-10-17 用户第二轮指令（已实施）**：形态由居中弹窗改为**锚定在触发键上方的下拉清单**，与输入框「+」菜单同一套浮层语言（`zIndex.popover`、`radius.panel`、`border.separator`、`shadow.floating`、收缩到内容宽度），不新增 token；参考图里的「倍率」那一列不做，可见面仍然只有模型名。随之去掉「应用到后续消息」确认键——上一轮的点选即应用已经让它成为多余的第二步，`applyOnSelect` 这个区分也随之消失，首条与会话两种场景走同一条路径。收起语义：点下拉之外一次即收、Esc 收并把焦点还给触发键、刷新进行中不收（否则「目录已更新／暂未更新」的回执会在眼前消失）。键盘仍是「Tab 到条目 + Enter/Space/Esc」，不为此自建方向键 roving tabindex。触发器与清单条目都保留原生按钮语义；`aria-haspopup` 由 `dialog` 改为 `listbox`。

**2026-10-19 用户截图指令（已实施）**：「这个模型下拉框太大了」。真实窗口 473×887 实测面板高 558px、占视口 62.9%（未配 OpenRouter 调用凭据时约 600px／68%）：清单 `min(40dvh, sideWidth)`(355px) 是最大头，底部两段脚注在 meta 档还要再占约 126px。三处收型，**事实、命令与交互一条不减**：① 清单上限改 `min(24dvh, 18rem)`，用户窗约 6 行、常规桌面约 8-9 行即开滚（仍内部滚动，筛选框照旧）；② 同步脚注（最近成功同步 + 凭据/过期/失败告警）整行改 `font.size.caption` + `lineHeight.snug`，时间戳整块 `white-space: nowrap`——meta 档下「最近成功同步：<ISO 时间戳>」实测 268px，超出被「立即刷新」挤剩的 252px 列宽会溢到按钮上，caption 档约 230px 各占一行，时间戳也不再从连字符处断成两截；③ 有界接续说明同改 caption 档并压缩文案（默认启用、触发条件、最多 3 个合格型号、绝不转收费、共享额度耗尽即停均在，完整规则仍归上文与[后续路线 §9.1.1](../../requirements/post-v1-roadmap/part-01.md#911-免费额度耗尽自动接续)）。同窗复测 **386px／43.5%**。量测用 Playwright + 页面内路由夹具（不连数据库与 Provider），复跑 `modelSelectorDropdown.spec.ts` 6/6 与 `modelSelector.spec.tsx`＋`newConversationEntry.spec.ts` 21/21 通过；视觉与数值归[设计系统 §9.16](../design-system/part-06.md#916-模型选择器触发器显名与清单只显名2026-10-17)。

**2026-10-20 用户指令「记住上一次选择的模型，不要每个新会话都先显示『模型』两个字」（源码已接入）**：新对话的模型芯片不再从占位文案起步，初始就是这台机器上该工作区最后一次点选的型号。落点是本机偏好 `apps/workbench/src/lib/modelPreferences.ts`（键 `relay.workbench.lastModel:1:<workspaceId>`，与 `composerDrafts`、`recentWorkingDirectories` 同属「本机偏好」这一族；按 workspace 分区，因为不同工作区可能连着不同 API 与目录、型号未必互通），写入时机是点选那一下（首条选择器与会话内选择器两处都记），读取时机是新对话挂载与同页再点「新对话」的重置——后者只清草稿与在途状态，不再顺手把模型抹回占位，否则每点一次新建都退回「模型」两个字。

这条偏好**只是初始值，不是第二份业务事实**：① 会话自己的首选仍以服务端 model-selection 为唯一事实，会话内芯片读服务端投影，本机记忆不参与显示；② 服务端对没有选择过的会话沿用应用默认，界面不会拿本机记忆冒充当前生效模型——未建会话时它只是待绑定的首条选择草稿，发送时才随 `createAssistSession` 的 `modelSelection` 交给服务端核对（沿用上文首条消息的两命令时序，幂等与 UNKNOWN 语义不变）；③ 目录、资料、Skill 选择不在这里持久化，仍按「本次请求的候选输入、发送时服务端重新复核」的既有边界；④ 存储不可读或不可写（隐私模式、配额）时按「没有上次选择」处理，选择本身不受影响，只是不跨会话记住。验证：`tests/modelPreferences.spec.ts`（存储层：往返、跨 workspace 隔离、坏 JSON、空值即删、存储抛错）与 `tests/newConversationEntry.spec.ts` 三条视图级用例（芯片初始就是上次型号且首条发送按原命令绑定、点选即写偏好且重新挂载从它起步、同页再点「新对话」不退回占位）；实际成绩与未验范围只归[功能验收表](../../testing/overall-acceptance-2026-09-28.md#当前功能验收表)。

**2026-10-21 用户复述同一诉求（已实施，补上另一半路径）**：「要记住上一次选择的模型，不要每一个会话都先显示『模型』两个字」。10-20 那条只覆盖了**新对话**（首条输入器从本机偏好起步）；**已有会话**还有一条没走到的路径：服务端 model-selection 为空（该会话从未显式选过模型）且用户没打开过下拉时，`currentModel` 尚未读取，芯片仍然退回「模型」占位——切到任何一条没选过模型的老会话都会看到这两个字。改法是让芯片的显示值多一级服务端兜底：`ModelSelector` **挂载即读** `getModelPortStatus`（不再等打开下拉那一下），显示链改为「会话显式选择 → 打开下拉时读到的当前值 → 挂载读到的应用默认」，三级全空才退回「模型」占位（服务端没配默认、本机没选过，此刻确实没有可显示的型号）。应用默认只来自服务端 model-port 投影，不是本地推断，因此不冒充会话事实；会话有显式选择时优先级不受影响。验证：`tests/modelSelector.spec.tsx` 新增三例（无显式选择显示应用默认、服务端无默认才退回占位、显式选择优先于应用默认）**12/12**，A/B 去掉兜底链恰好第一条转红；回归 `modelPreferences`＋`modelSelectionClient`＋`writePermissionTier` 合计 **44/44**。本机偏好与服务端兜底的分界不变：偏好只做新对话的初始值，芯片显示的「当前生效型号」仍以服务端为准。


当前界面在输入卡外读取最近一条助手消息的模型运行态，首选、最近实际调用与当前候选分别显示，冻结顺序及逐次用量置于可展开详情。生成期间只读轮询，终态停止；切换原因和额度作用域来自服务端持久事实，未知不归因为模型额度。展示的是限流核对时的共享日余额，不能伪称当前余额；旧无快照消息不倒造首选。该读投影不替代消息状态、调用账本、Run 控制或业务验收。

## 28. 协作页结构重塑（2026-10-10）

依据 [协作页 UI 优化设计](../../superpowers/specs/2026-10-10-collab-page-ui-optimization-design.md)（用户 2026-10-10 逐问收敛）。本轮只动 `/agent` 的**工作区级会话态**（`task === null`）与承载它的左栏，不改业务规则、命令、状态机、权限与草稿保护；视觉数值仍只有 [design-tokens.json](../design-tokens.json) 一个源。

### 28.1 左栏（`RecentWorkRail`）

- **「＋ 新对话」置顶**：由纯图标入口升为带文字的 `primary-button`（`control.height`），仍在栏头行右侧，复用既有 `/agent?new=…` 唯一入口，不新建路由，也不新建第二套会话状态。
- **单行列表与悬停摘要卡**（2026-10-16 第五轮，用户指认；同日按用户逐条指认收尾）：行只有一行文字——可选的会话图标、标题（`font.size.meta` + `font.weight.regular`，单行省略）与置顶徽标同行；**行内不再常驻更新时间**。时间与归属改由悬停／键盘聚焦时出现的摘要卡呈现：第一行是完整标题（`meta` + `medium`）与右对齐的更新时间（`caption` + `color.text.muted`，`tabular-nums`），第二行是归属（`Folder` 图标 + 目录末段／项目名，与各自的分组依据同源）。摘要卡是纯展示层（`pointer-events: none`），指针从行移到卡片上不会闪断行的悬停态；位置由组件按行的实测位置摆放（`position: fixed`，贴行右缘外、与行竖直居中对齐，越界拉回视口内），滚动即收起。按设备本地日期：今天只显示时分、昨天显示「昨天」、更早显示月日，跨年补年份；同组同名项在日期后保留时分帮助区分。`time` 的 `dateTime` 与 `title` 保留原始与完整时间，摘要卡由 `aria-describedby` 与行关联。**行内不重复项目名**，归属由组标题与摘要卡承担，行的 `aria-label` 保留完整标题及项目。字号不再缩小，留白与缩进规则见[设计系统 §9.11](../design-system/part-04.md#911-近期工作栏窄列搜索框与行密度2026-10-16)。
- **行距与激活标记收尾**（2026-10-16 第五轮，用户逐条指认）：行高 `min-height` 由 `control.height.comfort`(44px) 收到 `control.height.compact`(32px)，行内竖直内边距 `space.2`(8px) → `space.1`(4px) → `space.0-5`(2px)，行间距 `space.1`(4px) → `space.0-5`(2px)，**行距 48px → 34px**（命中区仍是整行宽，不缩窄指针目标，行高下限仍是紧凑档）；激活标记（行内激活条）相对条目左缘右移 **3px**——token 里没有 3px 这一档，按用户给定值写，标为待真实窗口复核（[设计系统 §9.11](../design-system/part-04.md#911-近期工作栏窄列搜索框与行密度2026-10-16)）。摘要卡的时间沿用原有口径不加相对时长，用户明确「不用改」。
- **根区间距拉齐**（2026-10-16 第五轮，用户截图指认）：目标↔工作区（目录）↔任务入口原先各是 `margin-top space.3`(12px) + `padding-top space.2`(8px) = **20px**，而任务入口↔已归档只有一档 `space.3`(12px)。用户以「任务入口和已归档的间距就很合适」为准，撤掉那条分隔线删除后已属重复留白的 `padding-top`，**四个根区视觉间距统一为 12px**。用例按「上一区最后一个可见条目的底 → 下一区 summary 的顶」实测这四处间距，此前 `[20, 20, 12]`，改后 `[12, 12, 12]`。
- **会话行内操作是浮层下拉**（2026-10-16 第五轮，用户指认）：⋯ 与行按钮同属 `.recent-work-row-head`（行本体是 `<button>`，按钮里不能套按钮），因此 `inset-block-start: 50%` 的定位基准只剩行本身。展开面板从首版的「行下方就地展开」改为 `position: fixed` 的浮层下拉——就地展开会把这一行以下整列推下去，同时把 ⋯ 的 50% 拉到「行 + 面板」的中线，这正是用户指认的「点击三个点位置会改变」。面板优先开在触发器下方、放不下向上翻，右缘与触发器对齐并拉回视口内，滚动或点到别处即收起；这一列在滚动容器里，绝对定位会被裁掉，而祖先链上没有 `transform`／`filter`／`contain`，故用 `fixed` 而不引入 portal，DOM 仍留在这一行内。改名仍是面板内的一行输入；命令语义（每命令一枚 `command_id`、409 只重读不重发、结果不明不重发）未动。

- **会话行的批量选择复选框与批量删除**（2026-10-20，用户指令「给会话 item 加一个复选框，方便删除记录」）：会话行（含「已归档」段里的）在**本行悬停或键盘聚焦时**，类型图标那一格换成复选框；已勾选的那一行始终保留复选框，**其余行不常显**（同日用户指令「复选框不要常显」——勾了第一条就让整列冒出方框，这一栏会被读成一排勾选框而不是会话列表）。勾上第一段讨论后，批量操作栏出现在**左栏「工作区（目录）」段标题正下方**「已选 N 段讨论 · 删除 / 取消」（同日第五轮按用户截图指认「打断页面视觉层级、视线要横跨主工作区」从主内容区上方居中的 `fixed` 浮层挪回左栏内部：它是勾选产生的动作区，与勾选框同列才不打断层级；落点是段标题下方而非常驻固定带——后者会把一整条高度压在列表上、把左栏整体顶低，而无勾选时这一列必须逐像素回到原样；`sticky` 让它在这一段里滚动时停在列顶，底色取 `bg.subtle` + `border.separator` + `radius.control`，不用 `shadow.floating`、不做独立模态窗口；有勾选时该段不许收起，否则选了什么与能对谁操作一起消失），点「删除」在原地换成确认（「删除这 N 段讨论？」+ 一句后果 + 删除／取消，两键等宽），确认才发命令。三条边界：① **选择只是选择**——勾选不发命令、不落库、不推进任何修订，任务行没有删除命令因此不参与选择；同一段讨论同时出现在「目标」与「工作区（目录）」两段里时，两处勾选共用同一个会话 ID，删也只删一条。② **一段一条命令**：服务端只有逐条 `DeleteAssistSession`（ADR-027），客户端不假装原子，也不新增批量端点——每段各取 `command_id`、各带那一行读回来的 `expected_revision`，串行发送、逐条等回执，成功与失败分别如实报告（「已删除 2 段讨论；「×」还不能删除（被任务验收观察引用）」——同一阻断原因只写一次、标题并列，同名去重后写成「「×」等 3 段」，处置建议也只出现一次），被引用阻止的那段留在列表里并指向归档。③ **结果不明不重发**：响应丢失时勾选保留、确认键锁死，说明「本次是否已删除尚未确定」，只能退出本轮——与 ⋯ 面板里那条单条删除同一读法。④ **结果只出现一次（DEV-0098，2026-10-21）**：确认后若有阻止或部分失败，同一张卡片停在「删除结果」终态，只留「关闭」，不再退回「已选 N 段讨论 + 删除」的第三次确认；关闭清空选择，要重试需重新勾选。删除不可撤销，因此全部成功时不留提示也不给撤销条：行当场消失就是回执。选择集只在整列**读成功**时按已加载列表收敛（一次读取失败不反过来清空人的勾选），切换页面或重排不残留无效 id。视觉与实测几何归[设计系统 §9.11](../design-system/part-04.md#911-近期工作栏窄列搜索框与行密度2026-10-16)；验证出口：`tests/sessionRowMenu.spec.ts`（勾选零命令、逐段命令与修订、部分成功、回执不明锁键、同因聚合五例）、`recentWorkRailDensity.spec.ts`（新增「批量操作栏落在左栏「工作区（目录）」标题下方、sticky 停在列顶且不越出侧栏」一例：后注册 route 补足 16 段会话使左栏必须滚动，才验得出贴顶；贴顶容差取一档 space.1，并断言不盖住段标题）。
- **目标与目录分别组织会话**（2026-10-16 用户校正后实施）：
：左栏设「目标」「工作区（目录）」两个可折叠区，任务保留在「任务入口」。目标指正式 Goal，不等于 Project、Task 或文件夹；Goal 可由多个 Project 推进，也就能汇集不同目录的相关会话。当前通过已保存的 `Goal ↔ Project` 关系聚合 `task_id=null` 的会话，**未新增会话直接绑定 Goal 的能力**，不把项目关联冒充 Task 显式目标对齐。一个会话可出现在多个 Goal 入口与一个当前目录入口中，始终使用同一会话 ID 与原历史；各组计数是该组已加载入口数，不相加充当会话总数。
- **目录依据**：会话以 `GET /assist-sessions?include_context=true` 的只读 `context.working_directory` 分组，目录名只取规范路径末段、完整路径保留在提示中，不从项目名称或本地最近目录偏好猜测。`context` 缺失显示「目录待核对／目标关联暂不可读取」，真实空目录绑定显示「未绑定目录」，已绑定而路径缺失仍保留目录身份。空关联与读取失败不混用，搜索仅覆盖已加载的标题、项目、目标名及规范路径。数据库 Workspace 仍是隔离边界，UI 的「工作区（目录）」不改变它的语义。
- **目录行悬停「＋」新建会话**（2026-10-18 用户截图指令「鼠标悬停 item 的时候要显示一个新建会话的按钮，点击自动以该目录新建一个空会话」）：有真实规范路径的目录组行（`group.path !== null`）在悬停或键盘聚焦时右端显形一颗「＋」；「未绑定目录」与「目录待核对」没有可打开的路径，不长这颗键。按钮是 `<summary>` 的**兄弟节点而不是后代**——HTML 规定 summary 的后代不得是交互内容，套进去点击与折叠会互相吞；它绝对定位压在数字徽标那一格上，静止 `display: none` 不占几何，显形时徽标以 `visibility: hidden` 让位（仍占宽，标题可用宽度与行盒逐像素不动），指针从行移到「＋」上时按钮自己就是悬停目标，不闪断回徽标。点击只带一条一次性入口 `/agent?new=<commandId>&dir=<规范路径>`：左栏不建会话、不发任何命令，目录事实与首条命令仍只有协作页一个 Owner；协作页在挂载那一拍把 `?dir=` 当一次性种子，按与手动换目录**同一条 `openFolder`** 打开，落地是空白输入，会话仍在首条发送时才创建、先绑目录再发消息。**目录在途直接挂首条输入器**（2026-10-22，DEV-0104；替代 2026-10-20 三版的整页在途态）：用户复测仍点名「正在核对目标与会话」闪一下，根因是「旧会话面板 → 整页在途 → 首条输入器」至少两次整块替换。现在 `?dir=` 在途也直接挂工作区级首条输入器：发送键按 `creationPending` 禁用，细条写「正在打开目录…」，草稿可以先写；目录回执一到，项目作用域用回执里的项目事实（`project_id`／`project_title`／`project_archived`）作为首帧目标种子，`AssistView` 先画同一张输入器，再向服务端核对完整目标与会话——`targetSettled` 之前在屏上不出现「正在核对对话目标与会话」，也不显示「正在刷新目标与会话…」。任务聊天的新对话同理用已读到的任务事实作种子；恢复既有会话、默认续写与目标读回失败仍按服务端事实走，失败落到可重试错误页。**无响应时有确定出口**：`openWorkingDirectory` 仍是无超时的写命令，等待超过 4 秒在细条上方浮出「取消并回到新对话」；浮层不参与流式布局，插入与消失都不移动输入卡或空态标题（2026-10-22 真实 Chromium 复测：提示出现前后 `composerTop` 均为 584）。取消只摘掉 URL 里的 `?dir=` 种子、保留其余键（如 `?skill=`），不重发命令、不换 `command_id`（原命令结果是否落地仍由服务端决定），目录随后由细条重新打开；快路径（本机 API 通常一瞬）不显示这个出口。目录事实 Owner、命令链路与首条发送语义不变。视觉与几何归[设计系统 §9.11](../design-system/part-04.md#911-近期工作栏窄列搜索框与行密度2026-10-16)。
- **目录绑定确认后必须重读作用域**（2026-10-18 用户实机截图指认「输入卡上方说当前的工作目录是 X，顶栏与左栏还写未绑定目录」）：顶栏的「会话目录」与左栏分组都是 `context.working_directory` 的只读投影，而目录绑定命令由协作页发起——两处都不会因为一次绑定自己醒过来。协作页在回执确认后递一个变化计数（`ActiveConversation.contextEpoch` 给左栏，`sessionContextEpoch` 给会话视图），两者各自重读服务端这一条再决定显示什么；计数只是「该再问一次」的信号，不是第二份目录事实，也不改会话身份、命令身份或权限。回执已确认但重读失败时保留上一份服务端读数，不把没读到的写成「已绑定」。同一目录重复选择时不重发命令，但仍重读一次，避免早前某次读取落在绑定之前后界面永久停在旧事实。同一确认也让协作页自身那份 `boundDirectory` 投影重读——任务视图「工作详情」抽屉的「工作目录」兜底行读的是它（抽屉优先显示刚打开的 `folder`），所以换目录后抽屉不再停在切会话前那次读数。
- **恢复原会话**：目标入口以 `?session=<原ID>&goal=<GoalID>` 定位，目录入口以 `?session=<原ID>` 定位；URL 中的 Goal 只是入口线索，正文只显示服务端确认的关联。项目会话深链接先核对原会话，再按其 Project 读取，不能走自由会话分支；读取失败就地重读，不创建替代会话。正文顶部独立显示「关联目标」「会话目录」，后者是已保存的会话目录，不冒充输入区尚未核对的本地执行作用域。目标入口不自动授予全部关联目录的上下文或执行权限，目录操作不改 Goal 关联。会话行仍用 `MessageSquare` 图标，挂在任务上的会话继续由原任务入口承担。
- **分组层级**（2026-10-16 截图反馈接续，同日第二轮收淡底与折叠）：目标／工作区（目录）／任务入口统一为可折叠根区，根标题使用 meta + semibold 与右侧折叠标记，**淡底只在悬停／按下时出现，静止不铺底**——三个根区常驻淡底会在窄栏里连排成灰白条纹，读成三张卡片而不是同一列的层级；层级由字号档、字重、缩进与留白表达（同日第三轮连根区分隔线也去掉，视觉见[设计系统 §9.11](../design-system/part-04.md#911-近期工作栏窄列搜索框与行密度2026-10-16)）。内层 Goal／目录／项目名称走 caption + medium + secondary，向内缩一档，条目恢复 meta + regular，选中项提升为 medium。空态只显示辅助字号的短提示并**水平居中**（这一段没有可点对象，左对齐会读成还有一列没显示出来），完整已加载范围留提示。折叠状态仍写 `localStorage`（`relay.workbench.recentWorkCollapsedGroups`，纯展示偏好），根区键为 `goals`／`directories`／`tasks`，内层 `goal:<id>`／`directory:<id>` 及原项目任务键兼容保留。**折叠偏好是唯一依据**：定位（切换到另一条会话或任务）时展开它所在的区与组一次，之后不再常驻强制展开——原实现按「当前项在哪一组」把 `open` 钉住，活动会话必然落在「工作区（目录）」里，那一段因此永远收不起来。
- **当前项高亮**：`color.selection.bg` 底 + 行内激活标记（`focus.width` 宽、`color.action.primary`、上下内缩 `space.1`、收 `radius.round`）+ 主名 `font.weight.medium`（普通项 regular），三者共同表达同一状态，不靠颜色单独区分。标记由伪元素画在行内而不是 border：未选中行不必空出这 2px，切换选中时文字不横向跳动。条目列表在分组竖线内侧再留 `space.0.5`，让整条目与激活标记都离开竖线一档——原先二者贴着画，选中行的色带会与「这根线属于这一行」混读。键盘焦点仍走全局 `focus.ring` 内描边，与选中态分开表达。任务高亮取 URL 的 `?work=`；会话高亮取协作页发布的活动会话投影（见 §28.4）。
- **「查找更多任务 / 会话」入口删除（2026-10-16 同日第四轮，用户确认）**：原栏底就地展开面板删除，`components/TargetPicker.tsx` 随之无调用方一并删除。依据取证：该面板只读与左栏相同的两个端点（任务仅 `getWorkspaceTasksPage(null)` 第一页、无搜索无翻页；会话集与左栏一致且不含归档），能显示的左栏都能显示、翻页后左栏更多，是更弱的重复入口；左栏（搜索＋「更早的任务」）成为任务与会话的唯一导航入口。原 `aria-expanded`／`aria-controls` 与 Esc 返回焦点的约定随入口一并失效。纯前端删减，无 API、权限、命令或会话草稿 Owner 变更。
- **会话行拖拽改序（2026-10-17 用户需求）**：未归档的会话行可以按住拖动，拖动时在该列画一条横线，指出松手后这一行会落进哪道缝；横线不占网格轨道，拖拽期间整列的布局不跳，松手才重排，所以「横线承诺的位置」与「条目真正落下的位置」是同一处。**按住的那一行跟着指针走**（同日用户接续指认「鼠标要抓着这个 item」）：整行按「指针相对起手点走了多远」平移，抓握点因此始终按在行的同一处，读起来是手里拿着它，而不是它在原地等指针去够；带起来的只有起手那一列的那一份，同一会话在另一列里的副本留在原地。平移写在 `transform` 上，落点数学读的仍是布局（`offsetTop`），所以整行跟着手动不会把落点算偏。落点由该列实测几何算出，指针落在两行之间即取那道缝。只有未归档会话所在的列声明 `data-reorder-list`，任务行与归档区起手落空；⋯ 触发器与它的动作面板不参与起手，否则改名输入无法选字。位移不足 4px 仍算单击（照常打开这条会话），落回原来那道缝不写任何状态。松手后浏览器补发的那次 click 由组件内一个只活到下一个宏任务的护栏吞掉——那一击不是「进入这条讨论」，行只是被搬走了。**顺序是本机导航偏好，不是业务事实**：写在 `localStorage` 的 `relay.workbench.recentWorkSessionOrder`（`{ version: 1, sessions: [会话 ID…] }`），不发命令、不新增迁移、不改服务端 `pinned_at`／`last_message_at` 排序键，也不建立第二套全局会话事实；目标分组与目录分组读同一个全局次序，各组只是它的子序列，在一处拖、两处同步。规则：从未手动排过序的会话排在已排序项之上（新会话仍会出现在前面）；一旦排过序，该行位置不再跟随置顶——置顶仍写服务端 `pinned_at` 并照常显示徽标，只是不再把这一行推到列首。抓握必须 `setPointerCapture` 在行按钮 `.recent-work-item` 上而不是整行 `<li>`：Chromium 会把兼容的 `mouseup`／`click` 一并重定向到抓握者，抓在 `<li>` 上时补发的 click 落不到按钮，普通单击就打不开会话（真实浏览器用例实测到并据此修正）。**改序这件事必须在屏幕上看得出来**（2026-10-17 用户追加需求「增加一点动画，要不然都不知道有没有交换成功」）：松手后只有真换了位的行播一段位移，起点是松手那一拍它所在的位置（手里那一份从指间放下去，另一列的同一份从旧格子滑进同一格），所以动画指的就是那一次交换，不是整列重播；落回原格那一拖照样滑回家，不硬跳。刚落位的这一行随即留一档一次性落位强调，到点自己消失，连拖两次时前一次的强调立刻让位给后一次。这段只是装饰，不承担事实：本机关动效或系统要求减少动态效果时整段不播，行照样换位、强调照样给出（换成静态），次序与回执都不受影响。视觉、动效与数值见[设计系统 §9.17](../design-system/part-06.md#917-会话行拖拽落位横线2026-10-17)。
- **会话按最后消息时间自动上浮**（2026-10-18 用户确认口径「就按消息的最后时间算吧，不管是 ai 还是用户」）：没人手动排过序时，未归档会话列的自动序由服务端 `GET /assist-sessions` 决定——**置顶优先，其余按最后消息时间倒序，还没说过话的回落创建时间**（`pinned_at desc nulls last, coalesce(last_message_at, created_at) desc, id desc`，迁移 `0111`）。客户端 `compareSessions` 用读回的 `lastMessageAt ?? createdAt` 排同一档，不再按 `updatedAt` 自行猜一套：此前左栏按会话行的 `updated_at` 重排，而那一列只由改名／置顶／未读／归档／绑定写入，AI 回完一条消息它根本不动，「按最后回复时间排」在服务端与客户端两头都不成立。口径按用户指定取**活动序**（不分发送方，失败或取消的那一轮同样上浮），不取 OpenCode 那种只在用户发起时 touch 的「最近问序」；上游对照与为什么不复用 `updated_at`、为什么不推进 `revision` 都归[数据库 §100](../../database/physical-design-postgresql/part-05.md#100-0111-会话活动排序键2026-10-18-源码实现)与 [HTTP §10.91](../../api/http-command-contract/part-06.md#1091-会话列表的活动排序键2026-10-18-源码实现迁移-0111)。三件事本轮**没有**改：① 手动拖出来的次序仍然优先，排过位之后不再跟随活动序（上一条的规则不变）；② 悬停摘要卡显示的时间仍是会话行的 `updated_at`，未随本列改成活动时刻——它是元数据写入时间，与「刚才说过话」不是同一件事，改显示口径属另一轮界面决定；③ 未读仍不参与排序。**消息落地即收敛**（2026-10-23 用户选定「立即发生」）：发送入库与生成结算由会话视图在权威投影里观察到——末条消息换 id（新落地一条，含发送时预插的 PENDING 行）或同一条转终态（结算时刻服务端再推进一次 `last_message_at`）即递一个活动计数，左栏据此定向重读当前会话这一行并按同一档自动序就位上浮，不等整列重读，也不在本地猜时刻（判定归 `lib/sessionActivity.ts`）。计数只交给正在看的自由会话：任务聊天不参与左栏排序，已切走会话的迟到刷新不递，切换身份即清零。**剩余限制（如实）**：左栏仍无轮询——后台目标推进若在没有在途消息的间隙里落地（消息轮询只在有 PENDING/RUNNING 消息时运行），要等下一次重读才收敛；其他窗口或设备的变更同样只在下一次读取时体现。**切换会话不重排分组**（2026-10-23 用户截图指认「切换会话，会话工作区位置会交换」）：此前切换会话时的定向重读把当前会话插到列首，而「目标」「工作区（目录）」分组只是全局列序的子序列，列首一换分组整体换位——切到哪条会话，它所在的分组就跳到最前，两张截图之间只有选中项不同、分组顺序却对调。现在读回的这条按同一档自动序**原位替换**（已在列里）或**追加后入序**（深链接到未加载的更早会话，与行内命令后的 `refreshSession` 同一口径），当前选中项不参与排序；列序变化只来自置顶与最后消息时间本身。复现与回归：`tests/recentWorkPagination.spec.ts` 新增两例（切到较旧会话后分组顺序不变、当前项仍高亮；递活动计数后当前会话就地上浮、无需重挂载或整列重读），落地判定与计数守卫归 `tests/sessionActivity.spec.ts`。

### 28.2 主区（`CollaborationView` 的 `task === null` 分支）

- **「最近动态」每行以类别标签起手**（2026-10-18 用户指令「这个项目标签移动到字的前面，就不会对不齐」）：行＝圆点 + 类别 chips（完成／项目／其他…）+ 事件摘要 + 行为人与相对时间。此前 chips 跟在摘要之后，排布下每行摘要长短不一，chips 起点各不相同，读成没对齐；移到行首后 chips 由行左缘决定，天然对齐。先后关系由 `tests/collaborationWorkspace.spec.ts` 的 DOM 顺序断言锁住，不锁像素。
- **「最近动态」改紧凑单列，事件标签补满**（2026-10-20 第五轮，用户截图指认「多条内容完全相同的记录」）：① 数据侧：`activity-queries.ts` 的 `SUMMARY` 原先只覆盖 18 种事件类型，其余一律退回哨兵 `业务事件`，前端再拿自己的二级表兜一次，两边都没有的就渲染成「未识别的事件」——真实发生过的动作读成界面错误，多条同类在首屏排成一模一样的占位行。现在两端都按 `apps/api/src` 下全部 64 种 `eventType:` 补齐、措辞一致；仍然不认识时不编造动作名，降级为「其他事件（原始类型）」并保留在依据里。重复条目是真实数据，不为此去重或删除动态。② 布局侧：由两列 2×2 改紧凑单列——首页只取 4 条、每条就一两句，两列把 700px 宽切成两条 340px 窄道，摘要被省略号切碎；单列后摘要按内容铺开、不再截断，行距取一档 `space.1`。加载中（4 行骨架）／就绪（N 行 + 等格占位补到 4 行）／空态错误态（居中覆层）三种状态同高的口径不变，输入卡不移动。③ 节奏侧：与快捷入口之间的空白由 `.agent-chat-suggestions` 的一档 `space-3` 上外边距单独承担，区块自身不再叠第二档上外边距——两者叠加曾在 900px 窗口量出 65px 空档。
