## 2. Token 规则

token 文件使用本项目简单扁平结构：metadata 保存版本/状态/来源，tokens 保存命名值，contrastChecks 保存需要验证的前景/背景组合。不声明遵循某一外部 token 交换标准，也不引入主题构建工具。

- 基础值：color.palette.*、space.*、font.* 等。
- 语义值：color.bg.*、color.text.*、color.action.*、color.status.* 等，只能引用基础色或明确的语义别名。
- 可复用尺度：layout.*、control.*、radius.*、focus.*、zIndex.*、motion.*。
- 组件消费语义 token，不在页面上复制色值。文字链接用 action.text，不能因主按钮同色就把链接和按钮行为合并。
- 别名写作 {color.palette.forest}；检查器必须发现悬空、循环及类型不匹配。
- React 已通过 `src/lib/tokens.ts` 读取唯一 JSON、解析别名并安装 `--relay-color-bg-canvas` 这类 CSS 变量，token 名称中的点转为短横线；现有页壳与组件消费这些变量，没有新增 Tailwind 或另一套数值源。

本轮只定义 light。没有暗色参考，不自动创建深色主题或主题切换按钮；保留语义命名使未来可以扩展。色值变更只改 JSON；用途和组件规则改变才改本文。token 改名/删除时查所有消费者并记录迁移，不维护多个“最终版”文件。

## 3. 色彩与状态

| 用途 | token | 使用限制 |
|---|---|---|
| 应用画布 / 导航 / 文档内容 | color.bg.canvas / navigation / surface | 右区与主画布同底，不做独立深色 IDE |
| 标题 / 正文 / 辅助信息 | color.text.primary / secondary / muted | 版本、错误解释和证据不因“次要”变为不可读 |
| 主操作及 hover / pressed | color.action.primary / hover / pressed | 文本固定 onAction；避免 hover 放大或跳位 |
| 当前导航/版本/行 | color.selection.bg / text | 配合激活线、勾选或当前标记；hover 与 selected 分开 |
| 装饰分隔线 / 表单边界 | color.border.separator / control | 浅分隔线不能承担唯一控件边界；输入框使用 control |
| 成功 / 警告 / 危险 / 中性 | color.status.*.text / bg | 同时有文字和图标；警告与危险为原图未覆盖的补充 |
| 增行 / 删行 | color.diff.add.* / remove.* | 保留 + / − 和行号，正文用 primary；不单靠红绿辨认 |
| 焦点 | color.focus.ring + focus.width | 沿控件边界向内显示，不能在既有边框外再加一圈；与 selected 分开，不能仅靠背景变化 |

成功色表达“这一条检查通过”，不推导 Task 完成。待审批用中性状态配明确动作，UNKNOWN 使用警告和核对说明；失败用危险色。暂停/正在停止/待核对的文案及允许操作由工作台契约决定，视觉组件不能自行映射业务状态机。

禁用状态使用 disabled.bg / text 并提供可见原因；本规范仍对禁用说明保持可读性，不通过整块 opacity 让文字和边框一起淡掉。

## 4. 字体与排版

| 角色 | 尺寸 / 行高 token | 字体 / 字重 | 用法 |
|---|---|---|---|
| 普通页面标题 | font.size.page / heading | ui / semibold | 每页唯一主标题：项目名、验收标题、变更审查标题、待审与知识页标题 |
| 窄屏页面标题 | font.size.compactPage / heading | ui / semibold | 不把整页缩放来容纳桌面标题 |
| 区域标题 | font.size.section / heading | ui / semibold | 今日焦点、项目状态、右栏标题、等待判断；零数量的分组标题收为一行提示，不以区域标题占位 |
| 行标题 | font.size.rowTitle / ui | ui / medium | 任务/产物名称，长名换行 |
| 控件与业务正文 | font.size.body / ui | ui / regular 或 medium | 按钮、导航、状态、字段；文本输入与下拉继承 UI 字体，不落回浏览器默认字体 |
| 辅助信息 | font.size.meta / ui | ui / regular | 时间、来源、版本；不能承担长正文 |
| 背景注记 | font.size.caption / ui | ui / regular | 字段旁注、单位计数、eyebrow、状态副文案、面包屑。不承担阅读任务：这些字与正文同档时，页面会读成一片等重的字。2026-10-14 起先在协作页试点 |
| 长文阅读 | font.size.reading / reading | ui / regular | 论文/Markdown 阅读内容；编辑输入保持清晰 |
| 代码与 diff | font.size.meta / code | code / regular | 保留等宽与可复制文本；不使用图片充当代码 |

2026-10-01 字号决定：用户对 `preview.html` 中 55 张效果图逐页比对后，选择「放大字号但保留 Sans」。`font.size.page` 由 `compactPage`(1.75rem) 放开为 **2.5rem**，`font.size.section` 由 1.5rem 提到 **1.75rem**；`font.size.display`(3.5rem) 保留为历史值但页面主标题不再使用。这**推翻了 2026-09-28 「今日主标题从 display 收到 compactPage」**的单页特例：今日页与其它普通页面现在同为 `font.size.page`，窄窗一起降级。

降级只在一处发生：`styles.css` 的 `@media (max-width: 40rem)` 统一把 `.page-primary h1` 与 `.skill-page h1` 降到 `compactPage`，各视图不再各自硬编码。实测 8 个普通路由在 1280 宽一律 40px / 28px，390 宽一律 28px，无横向溢出。`2026-09-19` 逐页图里的衬线大标题**不采纳**：`font.family.editorial` 保留给历史参考，所有 UI 标题继续用 `font.family.ui`。

图中字体不可反推出精确 font-family。2026-09-30 实现使用本地自托管的 Noto Sans SC / Noto Serif SC 可变 WOFF2，分别以 `Relay Sans SC` / `Relay Serif SC` CSS 名称优先进入唯一 token 字体栈，后续保留系统回退。字体保留完整原字库，未做字符子集化；两文件合计约 18.8 MB，用离线包体积换取各机器中文排版的一致性。原始版权、来源、版本及转换前后哈希见[字体来源记录](../../apps/workbench/src/assets/fonts/provenance.json)，完整 [SIL OFL 1.1](../../apps/workbench/src/assets/fonts/OFL.txt) 随源码保存，生产分发同时携带完整许可与两份版权声明。工作主线图接续采用本地 Noto Sans SC 统一交互、所有 UI 标题与阅读正文；Serif 资源与历史参考保留，代码和 diff 继续使用 code 字体。此前生产字体身份核对不自动代表本轮最终构建；Windows WebView2 字形、IME 和 DPI 效果仍需实际窗口复验。

尺寸采用 rem，默认字号变化时同步缩放。中文正文不加夸张字间距；时间/计数可用等宽数字。主体文字禁止固定高度裁切；面包屑可截断中间层，但当前任务名必须有可见完整入口。阅读宽度受 layout.reading.maxWidth 限制，超宽显示器不拉长整行文章。

## 5. 间距、页壳与桌面窗口适配

2026-09-28 设计接续：用户要求标题栏左侧放常用操作，不显示 `Relay Agent`。[完整窗口 v2](mockups/2026-09-28/README.md)展示左侧后退、前进、搜索、新建任务，中间空白拖动区，右侧最小化/最大化或还原/关闭。该共享窗口层适用于全部页面，旧图仍仅定义页面内容。操作区已接入工作台代码；效果图本身不构成真实 Windows 验收。

标题栏与下一层应用顶栏分开；面包屑及适用工作台页签仍在应用顶栏，不重复放一组快捷操作。2026-10-05 起后退、前进、搜索、新建任务（`WorkbenchActions`，挂 `.workbench-actions`）也回到标题带最左侧、拖动区之前：用户指出这四个按钮原本就在左边，此前被移到应用顶栏反而让标题栏左侧空出一段。四枚按钮填满标题带高度、宽度复用 `control.height.comfort`、圆角归零，与右侧窗口按钮同一几何；左内边距用 `space.4`。2026-10-04 起日期与星期、收件箱、数据来源与通知入口也在标题带内，位于拖动区右侧、最小化按钮左侧（见[工作台第2节](workbench-design.md#2-信息架构与路由)）；应用顶栏因此只剩面包屑与窄屏导航按钮。标题栏与顶栏都空了的那一页（工作台页无面包屑）在宽屏按 `.app-topbar:not(:has(.breadcrumbs))` 整行收起，不留空白带；窄屏仍保留导航抽屉入口，不受该规则影响。新增 `.desktop-titlebar__cluster` 与 `.desktop-titlebar__date` 两个类名，日期沿用原 `.topbar-date` 的 `font.size.meta` 与 `color.text.muted`，未新增数值 token。高度及窗口按钮宽度复用 `control.height.comfort`，其他颜色、字体、图标、细线与留白引用现有 token；不从概念图建立第二套数值。只有中间空白参与拖动/双击，所有按钮及浮层排除拖动命中。窄窗优先隐藏快捷键提示和可替代的文字标签，保留可访问名称、焦点和窗口按钮。浏览器不显示桌面控制时，业务搜索和创建入口仍应可达。具体动作及草稿保护见[工作台第2节](workbench-design.md#2-信息架构与路由)。

现有图定义应用客户区，不包含 Windows 原生标题栏。当前 Windows 主窗口使用浅色自定义标题栏，复用 navigation 背景、UI 字体、separator 和 `control.height.comfort`；图中的应用顶栏继续承载面包屑等内容。左侧操作按钮与中间空白拖动区分离，只有空白区可拖动、双击切换最大化；右侧窗口按钮有独立命中区，关闭请求受草稿与原未决命令保护。搜索复用 Ctrl+K 命令面板，业务快捷入口集中在共享标题带，应用上下文栏不重复搜索。浏览器保留搜索、新建与应用内前后退，不渲染假最小化/最大化/关闭控件或拖动行为。连接中和服务失败页仅桌面保留真实窗口控制，业务操作按可用条件禁用。侧栏高度扣除标题带，侧栏和应用顶栏的 sticky 起点移至其下方；跳转主内容链接聚焦后显示在标题带下方，不覆盖按钮。窗口启动/关闭交互按[部署设计](../deployment/本机部署.md)，不新增托盘或多窗口。

window.content.initialWidth/initialHeight 与 minWidth/minHeight 为客户区逻辑 DIP 推荐值；不按截图像素设置窗口。首次打开和恢复窗口位置时，依据当前显示器工作区扣除系统边框/标题栏后限制尺寸和位置；工作区小于推荐最小值时允许继续收缩，避免窗口伸出屏幕。DIP 与 CSS px/rem 分开处理，不手工重复乘 Windows 缩放倍数。2026-10-15 核对：桌面壳实际以 1160×780 逻辑 px 建窗且未设 `min_inner_size`（`apps/desktop/src-tauri/src/lib.rs`），上列数值是目标约束而非当前实现值。窗口宽度落到 `width < 48rem`（150% DPI 下约少于 1152 物理像素）时外壳进窄窗档——两栏整体收起、导航与近期工作由应用顶栏的 ☰ 抽屉承担，**这是既有收纳规则，不是桌面端没接入**；48rem–64rem 保留三列，因此 150% DPI 下 960–1440 物理像素的窗口不再只剩中栏。窄窗档的抽屉入口与「新对话」可达性由 `tests/browser/narrowWindowNewConversation.spec.ts` 覆盖。

沿用图中的疏朗密度，以 space.* 形成 4px 基础、8px 主节奏。文字与图标用小间距；字段内关系、列表行和区域之间按层级增大；不为每一个偏移增加 token。

| 区域 | 尺度引用 | 规则 |
|---|---|---|
| 左导航 | layout.sidebar.width / control.nav.height | 暖灰背景、底部连接与设置；长页面可滚动，不挤压底部项；≥64rem 可拖拽调宽（10–20rem，双击复位，键盘可调），用户宽度只作用于宽断点基础列 |
| 顶栏 | layout.header.height | 面包屑、视图切换、日期按可用宽度排列；日期不阻塞主要操作。该 token 专指应用上下文顶栏 `.app-topbar` 的实际高度（`control.height.comfort` + `border.width`，2026-10-10 由 3.5rem 更正），桌面壳的固定区总高另加原生标题栏 `control.nav.height`，两者上下相邻、不重复计数 |
| 中央工作区 | layout.main.padding / layout.section.gap | 对齐统一左边线；区块用留白和细线分组 |
| 右判断区 | layout.rail.width / narrowWidth | 左侧细分隔线；有独立标题、证据、范围及操作；内容滚动可达 |
| 内容上限 | layout.content.maxWidth | 超宽屏限制工作区总宽度，避免按钮远离对象 |
| 阅读区域 | layout.reading.maxWidth | 文档内可有自己的标题节奏，不套多层卡片 |

| 桌面客户区的 CSS 视口范围 | 页壳行为 |
|---|---|
| ≥ breakpoint.wide | 完整侧栏 + 中央内容 +标准右区；接近原图比例 |
| breakpoint.rail 至 wide | 完整侧栏 + 中央内容 +窄右区 |
| breakpoint.large 至 rail | 完整侧栏；右区由明确“查看待审/上下文”按钮打开，不挤窄正文 |
| breakpoint.medium 至 large | 导航收为 compactWidth；必须可展开文字并提供可访问名称；右区按需打开 |
| < breakpoint.medium | 左导航抽屉；内容单列；右区按需全宽面板/对话框，保留目标与返回入口 |

抽屉不互相叠开；打开时按组件规则管理焦点。原图右区底部操作不得用绝对定位压住内容；采用正常流或带内容留白的 sticky 区，窗口缩小或字号放大时仍能滚到操作。正文不产生全页横向滚动，diff/宽表允许局部横向滚动并保留键盘访问。窄窗口内边距使用 layout.main.smallPadding。

断点是桌面窄窗口、文字缩放和高 DPI 下的补充适配规则，不代表手机端交付。验收覆盖推荐初始/最小客户区、最大化/还原、较小显示器工作区、100%/125%/150%/200% Windows 缩放与跨不同 DPI 显示器移动。另在 200% 内容缩放下检查重排；记录实际 DIP、CSS 视口与 DPR，不只记录截图分辨率。

- 主视觉优先给当前工作目标、可读产物、实际执行进展和必要判断。减少占据首屏的统计卡、概览大标题、重复状态块与长期空白面板；不靠机器人图标、发光装饰或聊天气泡数量表现 Agent 能力。

- 上表断点仍作为适配基线，完整右区仅在确有内容且用户需要时显示；窄窗可切换讨论/产物/判断视图，但保留当前目标、执行状态和必要操作。不以整页缩小维持多列，不让持续输入区遮挡正文或审批按钮。

本轮新增的 token 只有布局与控件尺寸：`layout.workspace.sideWidth`、`layout.workspace.centerMin`、`layout.factbar.columns`、`layout.factbar.cellMin`、`control.avatar.size`。没有新增色值、圆角、时长或动效曲线，也没有复制第二套数值；消息头像、日期分隔线、事实条三格和右栏页签全部复用既有 token。

对话消息的视觉约定：角色由头像文字（我/AI）、角色名与左右位置表达，不只靠颜色；只有用户消息保留气泡底色（`color.bg.subtle`），AI 回复保持页面底色、不加背景，避免长文被色块切割；AI 正文走 `markdown-preview`，该处必须连同 `background`、`border`、`border-radius`、`padding`、`margin` 一并拍平，否则共享 surface 底会留下白卡；时间戳取服务端既有 `created_at`，缺失时不显示时间而不是编造；正常完成态不额外标注状态词，等待生成、正在生成、生成失败和已取消必须显式表达。

在途回复的停止入口只在输入栏主按钮，不在消息体内。主按钮位置与配色不变，只在存在在途回复时把字形从发送箭头换成圆角方块；已请求取消时保留该形态但禁用并标「正在停止生成」。

`PENDING` 的显示语义按「是否存在 `RUNNING`」分两种读法，不能一律当成队列位置。`PENDING` 是消息落库时的初态，含义是「已提交、Worker 尚未领取」；服务端 `claimNextPendingMessage` 是它变成 `RUNNING` 的唯一通道。空闲时发出的一条也是 `PENDING`，此时没有任何东西排在它前面，Worker 正在领取它——若渲染成「等待中 · N 项」队列，会让空闲发送看起来像被别的任务挡住。因此：存在 `RUNNING` 时，其余 `PENDING` 才是真队列，渲染队列面板；不存在 `RUNNING` 时，那唯一一条 `PENDING` 只由消息行的「等待生成」状态标签与输入栏停止键表达，不渲染队列面板。两种情况都属在途，停止入口一致（服务端对 `PENDING` 直接收敛为 `CANCELLED`，对 `RUNNING` 记录意图由生成方结算）。队列面板在独立与嵌入式两种形态下都渲染——只在独立形态渲染会让 `?skill=assist` 上的排队回复没有取消路径。

在途且首字未到时，消息体用三点提示占位（`RUNNING` 与 `PENDING` 都算），落在正文起始位，有正文即消失，不额外撑高消息；已请求取消后不再显示，避免与「正在取消」并读。`Esc Esc` 停止快捷键绑定在会话面板根节点、不占用单次 `Esc`（资料面板关闭与焦点管理仍要用），两次按键必须仍指向同一条在途回复，避免上一条恰好完成、下一条被提上来时停掉用户没打算停的那条。参照 deepseek-harness 的 `InputBar` 与 `stop-sequence`。「202 回执不等于完成」由状态标签机制实现（完成态不标状态词，未完成与失败必须显式标注），不作为聊天文案出现在对话流里。

### EmptyState（2026-10-06）

共享空态组件 `components/EmptyState.tsx`，集中一处说明「没有什么」「为什么」和「下一步」。消费既有 token（`bg.subtle` 底 + `separator` 边框 + `radius.control` 图标框、`control.target.minimum` 图标框边长、`font.size.section`/`rowTitle` 标题、`font.size.body`/`meta` 说明），**未新增色值、圆角、时长或第二套尺寸**。

- 形态：`regular` 用于主区（真实 heading + 图标 + 说明 + 动作），`compact` 用于侧栏、右栏与次级面板（无图标、meta 字号）。两者都不套卡片、不铺满整列，按实际内容高度靠上排列，与第 5.1 节协作页空白页同源。
- 图标是装饰，含义由标题文字承担，因此 `aria-hidden`；标题保留真实 heading 以维持文档大纲，只有不承担层级的紧凑场合才用 `as="p"`。
- 一屏仍只有一个主操作：空态动作与页头常驻入口可以同屏并存，但页头入口始终可发现、不因空态出现而隐藏，也不因此产生布局跳变。

范围区分是硬要求，不能合并成同一句话：**首装为空**、**搜索无匹配**、**某个页签/归档范围为空**是三件事。搜索无匹配只能说「已加载 N 项里没有命中」，不得暗示整个工作空间为空；归档范围为空不得提供「新建项目」这类无效入口。

**待确认**：首装空态的「新建项目」与页头常驻「新建项目」目前同屏出现两个 primary。取舍理由是页头入口在「已归档」页签与列表非空时同样需要保留；是否把其中一个降为次要待定，改动可逆。

### 组件状态补充

- 空态：说明没有什么、为什么以及下一步；无模型连接仍可人工工作。已有数据时的空范围、搜索无匹配与首装为空分别表达，不用同一句话覆盖。
- 错误：就近提供原因与可行操作；权限/过期冲突不是通用“网络错误”。
- 版本冲突：保留草稿，展示当前版本和差异入口，不用 toast 后自动覆盖。
- 待核对：持续展示不确定范围，禁用可能重复副作用的动作。
- 加载：首次读取可用静态 skeleton 或文字；普通刷新可保留已知内容并标识更新，涉及新写准入的父对象重读按页面门槛隐藏旧事实并禁新写，禁止假进度。
- 浮层：使用单一层级表，focus ring 不被 overflow 裁掉；popover 不盖过 modal。

### 协作页结构原语（2026-10-10）

协作页结构重塑（工作台 §28）新增四条可复用外观规则，全部引用既有 token，**未新增色值、字号、圆角或动效数值**。数值唯一源仍是 [design-tokens.json](design-tokens.json)，此处只记引用关系，不复制数值。

- **chips**（模式切换 / 资料 / 动作下拉 / 更换目录）：`radius.round` 胶囊 + `border.control` 边 + `bg.surface` 底；选中态（含展开中的下拉）`selection.bg` + `selection.text` + `action.primary` 边；hover `selection.hover`，过渡 `motion.duration.fast`。禁用态用 `disabled.bg` / `disabled.text`，不留「无底」的中间形态。同一排的 chips 不再插竖分隔线——那会把同类控件切成两组。
- **文件夹作用域细条**：常态 `bg.canvas` 底 + `border.separator` 上缘，分隔线横贯整列、内容与输入卡同宽同轴（`layout.reading.maxWidth`）；目录名 `font.size.body` + `font.weight.medium` 是这一行的事实主角，归属是 `font.size.meta` + `text.muted` 的次要事实，宽度不足时先在归属处省略。告警态整条换 `status.warning.bg` + `status.warning.text`，由图标、目录名与状态短语三处同时承载（不靠单一颜色表达状态），次要事实保持 `text.secondary`，不跟着整条换色；状态短语只说后果、不复述归属那一句，完整原因给读屏与 `title`。它是常驻状态线，因此不加圆角、不加阴影、不套底色，也不再把整行收进胶囊；行内唯一动作按 chips 规则取 `border.control` + `bg.surface` + `radius.round` 的紧凑键。
- **欢迎卡与引导卡**：欢迎标题 `font.size.compactPage` + `font.family.ui` + `font.weight.semibold`；引导卡 `bg.subtle` 底 + `border.separator` 边 + `radius.control`，卡内正文左对齐（外层欢迎区居中，列表居中会读成诗）。
- **「回到最新」悬浮键**：`radius.round` + `border.control` + `bg.surface` + `shadow.floating` + `zIndex.popover`，边长 `control.height.compact`，hover 用 `selection.hover`。它是真实 `button`，不是装饰；出现与消失仍是挂载/卸载，没有退场动画。

### 6.1 交互状态的统一表达（2026-09-29）

本节是设计约束补充，不代表所有页面已实现；[状态图](mockups/2026-09-29/README.md)供视觉对照，业务结果以[工作台第13节](workbench-design.md#13-交互反馈与业务状态绑定)为准。

2026-09-29 接续实现：共享按钮类的悬停（action.hover / selection.hover）、按下（primary 用 action.pressed；次级与文字按钮用 selection.bg）、键盘焦点（全局 focus-visible ring）、禁用（disabled 配色 + 就近 `disabled-reason`）与提交中（动词等宽替换为"正在保存/正在提交"并禁用拦截重复激活，不引入循环动画）已在共享 CSS 与既有页面模式中落地；字段错误态为 `field--invalid` 红边框 + `aria-invalid` + 就近图标错误文字。真实指针与键盘状态截图见[交互状态证据](../testing/evidence/interaction-states-2026-09-29/)；danger 按钮未单列按下态（其悬停已是语义色底），tooltip 键盘触发仍依赖原生 title，未自建浮层。

| 状态 | 视觉与输入规则 | 退出条件 |
|---|---|---|
| 默认 | 明确操作对象与动词；同一决策区只突出一个主操作 | 指针、焦点或业务状态改变 |
| 悬停 | 主按钮使用 `color.action.hover`；列表使用 `color.selection.hover`；不改变选中标志、执行者或版本 | 指针离开；键盘用户不依赖悬停获取信息 |
| 按下 | 使用 `color.action.pressed`，不缩放布局、不显示成功勾选 | 释放或取消按压；只在有效激活时提交一次 |
| 键盘聚焦 | 独立使用 `color.focus.ring`、`focus.width`、`focus.offset`；可与选中/错误共存 | 焦点真实移动；异步刷新不随意夺焦点 |
| 选中 | 稳定背景、文字和激活标记共同表达；与悬停有可辨差别 | 用户显式选择，或当前事实变更 |
| 不可用 | 使用 `color.disabled.*`，就近显示原因与可行下一步；原因不能仅藏在 tooltip 中 | 前置条件重新核对有效；禁用不等于隐藏原因 |
| 提交中 | 保留宽度与位置，动词改为“保存中/提交中”；拦截重复激活，保留阅读和安全导航 | 得到明确回执，或转为结果待核对 |
| 失败/冲突 | 原操作附近持续显示原因；保留用户草稿；与字段关联，不能只闪 toast | 用户修正、重读或完成规定恢复流程 |
| 成功 | 按真实提交范围更新对象和状态，保留可查的版本/结果入口 | 不用固定延迟代替成功判定 |

任务行主链接、复选框和更多菜单各自独立；点击菜单不同时打开任务。行内辅助操作可在 hover 或 focus-within 出现，但必要操作始终可发现。来源链接悬停只提示目标，不自动读取、选入 Context 或授权。标题栏操作区不参与拖动；留白才可拖动，窗口控制与业务按钮状态分离。无后退历史时按钮不可用但名称仍可读。

Tooltip 仅补充名称/快捷键，键盘聚焦同样可触发，离开或 Esc 可关闭。菜单关闭回到触发控件；抽屉/对话框打开后聚焦其标题或首个合理控件，关闭返回原入口。未保存编辑的关闭行为沿用离开保护；Esc 不等于丢弃草稿，也不取消后台 Run。更新完成后若原控件消失，将焦点移到对应结果标题，避免落到页面起点。

动效时长只引用 `motion.duration.fast`、`motion.duration.panel`、`motion.duration.reduced` 与 `motion.easing.standard`，不建立第二套数值。减少动态效果时保留静态文字和焦点反馈；既有输入区运行流光仅遵守第7.1节的限定，不扩展为通用加载动画。

2026-09-30 整套页面呈现纠偏：普通主标题使用 page，今日仍保留用户选定的 compactPage；品牌、导航与默认侧栏宽度统一到唯一 token，已保存的侧栏宽度仍优先。任务列表标题不再被窄内容列限制；详情的状态、验收与产物事实横向并列，右侧编辑动作纵向铺满。知识阅读采用目录、白纸正文、来源三列，并按确切版本显示标题与目录；三工作台、知识管理和动态的辅助设置默认折叠，已应用的活动范围必须展开。折叠仅改变呈现，不能卸载草稿、原命令或未决结果。运行步骤用白纸与细线分组，诊断、控制和 UNKNOWN 入口保留。协作纸面为正文留出更多空间，判断元数据常驻，说明按需展开；宽而短的窗口允许判断区自身滚动。窄窗共用顶栏隐藏中间面包屑和日期、收为带可访问名称的来源按钮，保留搜索与收件箱入口。逐页证据及未测状态见[视觉 QA](../../design-qa.md)。

### 6.2 全局控件与交互实施基线（2026-10-01）

本轮按用户要求优先保证最大化桌面窗口可用，保留已选视觉方向。体系沿用唯一 tokens、[共享样式](../../apps/workbench/src/styles.css)及已有 React 行为组件，不新增组件库或第二套 Button/Input 数值；页面负责业务状态和命令 Owner，公共层负责控件外观、语义和键盘行为。第 6.1 节的状态区分继续有效，焦点表达以本节接续规则取代历史外扩 ring；这不是所有页面/业务状态均已验收的声明。

| 控件 | 公共入口 | 页面必须提供的状态与行为 |

## 7. 可访问性与动效

按本项目验收目标，普通文字组合至少 4.5:1；关键非文本控件边界和焦点相对相邻背景至少 3:1。装饰分隔线不承担控件识别职责；选中色块仍保留文字/图标/激活线。当前 JSON 检查只验证预设纯色组合，不等于页面符合 WCAG。[文字对比度](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)、[非文本对比度](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)。

独立交互目标最低使用 control.target.minimum；需要更宽松点击区的桌面控件使用 control.height.comfort 或更大。正文内链接可以保留文本布局，其他小图标扩展实际点击区。较大的点击区是产品选择，不将 44px 误写成 WCAG 2.2 AA 的通用强制值。[目标尺寸说明](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)。

Tab 顺序遵循视觉/文档顺序，提供跳到主内容入口；图标按钮有可访问名称。只有真正的同页 Tab 使用相应键盘模式，导航仍为链接。[Tabs 模式](https://www.w3.org/WAI/ARIA/apg/patterns/tabs/)。

M04 Assist 子页复用现有表单、面板、按钮和间距 token：来源选择为明确的复选框与版本文字，消息状态为静态文本，提案正文按纯文本可滚动展示，不渲染模型输出为可执行 HTML。错误与回执就近显示；切换会话后清除未发送的来源选择。新增局部列表样式不建立第二套 token，也不引入第 7.1 节尚未实现的运行流光。

首批第一方 Skill 在相同 Assist 表单中增加“普通 Assist / Skill”原生选择框；选择后就地显示定义版本、摘要、依赖及缺能力，单字段输入保留可见标签。历史输出使用原 `assist-proposal` 面板按服务端类型展示；模型建议本身没有接受按钮，服务端提案另开确认区；失效来源用文字替换引用，不沿用可点链接。Pack 清单复用 `surface-panel` 和列表样式，当前版优先、历史版仅供查阅；成员状态用“可调用、只读/仅建议/缺能力/可确认提案”文字表达；创建引导与设置不新增授权色或配置动作。所有长摘要和 ID 按已有可换行规则处理，不新增 token。

冻结旧 Skill 定义的历史消息沿用静态辅助文字，显式写明 `HISTORICAL_ONLY` 仅可查阅；原版本与摘要和当前可调用选项分开。PENDING/NO_OUTPUT/UNAVAILABLE 状态只显示服务端消息事实，不用占位建议卡或禁用的“接受”按钮暗示可应用。

Task Definition 的只读对照在原 `assist-proposal` 面板中按“当前验收 / 模型建议”顺序列目标、结果类型、模式和条件。revision 不一致用现有 `action-error` 文字提示过期；读取失败清空旧对照，只保留就地错误和重读按钮。条件差异的标题写“未逐字重复/未完全相同”，不使用删除或新增色彩暗示未来合并效果。Verification Plan 的当前 CheckPlan 准入预览与历史 Run 验证分开显示来源、原因和未执行说明；Project Resume 的模型下一步仍非 Today 准入事实。Task Skill 服务端合并提案以原 `assist-proposal` 面板列出目标/结果、保留与新增条件、双版本及来源摘要；原生两步确认按钮只在提案可读且版本一致时出现，409、失权与回执不明使用现有文字状态和按钮，不新增 token。

项目 Knowledge 的 P17 URL 导入表单同样复用现有面板、字段、按钮、提示及错误样式；Job 状态用“已排队／处理中／导入成功／导入失败”文本与原状态码一起呈现，Gateway 等待批准时以文字和 Review 链接说明。Job ID、原 command_id 和 Knowledge 版本 ID 保持可选取文本，长 URL 与 ID 允许换行；刷新保留已知状态，不使用完成比例或流光推断后台进度。导入结果仅显示服务端版本摘录纯文本，不渲染网页 HTML。局部间距、分隔线沿用已有 token，不增加新的色彩或动效变量。

WEB_FETCH 连接选项同时显示服务端可公开的允许主机名与连接 ID；主机名为空时只显示 ID，不用 URL 反推连接配置。

hover/focus 的颜色过渡用 motion.duration.fast；抽屉/面板用 panel；不使用弹簧、循环装饰动画或大位移。唯一有界例外是第 7.1 节绑定真实运行状态的输入区辅助流光，不推广到普通输入框或其他装饰。prefers-reduced-motion 时使用 reduced，进度仍可用静态文本表达。流式输出不逐 token 触发 aria-live 播报；只播报开始、需要处理、结束等有意义节点。

### 7.1 输入区运行光点（2026-10-05 选定局部光点）

在途时用**上边一条 18% 宽、2px 高的光点沿上边单向移动**表达当前回复仍在生成。输入区域本身保持静止；光点只动 `transform`，不重绘卡内内容。不做整圈流光、不加 blur 光晕、不做呼吸缩放或持续强光。边框基础宽度复用 `border.width`，光点高度由它推导，运行周期用 `motion.loop.calm`（6s）。不再设第二套数值源。

另两个候选——静默基线（只把边框调深一档、运行期完全静止）与底部内缩基线往复段——已在真实界面比对后弃用，代码与其专属 token 一并移除。若日后要重新评估，应从本节当前形态出发，不要复活已弃用方案。

光点只承载辅助提示，不表示完成百分比，也不能替代状态文字。状态由消息行的「等待生成 / 正在生成」标签承担；首字到达前的消息体内另有三点占位。

两种输入器形态都承载该反馈：独立对话卡的 `.agent-chat-composer` 与嵌入式子页的 `.create-form`。后者原本不是定位上下文，光点会跑到更外层，因此给它补 `position: relative`。不推广到普通输入框或其他装饰。

**提交瞬间不得出现闪动**，这约束了实现方式：

- 在途状态不能只由已读到的消息列表推导。消息列表要等查询返回才带上新回复行，那之前输入器会短暂呈现「无在途」再跳到「在途」。实现改为在 202 回执落地时记住该回复 id，在查询真正看见那一行之前持续按在途呈现；它只记 id，不缓存状态。
- 装饰层不给 `transition`。在途切换与淡入若都带过渡，两段动画叠在一起比单纯状态切换更闪。
- 队列面板是常驻区块而非 `details`，且空态渲染等高不可见占位：队列长度在提交瞬间从 0 变 1、最后一条离开时变回 0，折叠控件的 summary 与展开箭头会跟着一起闪现，转录区高度也会被推动。
- 光点层常驻占位、在途时只切 `opacity`，不增减任何尺寸。

动效只由 `html[data-motion]` 控制，取值来自本机偏好与系统 `prefers-reduced-motion` 的组合，解析与持久化见 `src/lib/motionPreference.ts`（本机显式选择优先于系统设置）。关动效时装饰层 `display: none` 而非仅把时长压到 0——否则光点会停在起点被读成一个固定亮条。关动效只改展示：不发送暂停或取消命令，也不隐藏状态文字与停止入口。

流光不替换文本输入框的键盘焦点边框，不遮挡控件、不截获点击，也不改变输入区尺寸或导致布局跳动。焦点提示独立且持续可见，符合[焦点可见原则](https://www.w3.org/WAI/WCAG22/Understanding/focus-visible.html)。阶段说明占用稳定的一行区域，窄窗口允许换行，查看进度与停止等操作仍须可键盘触达。

状态文本使用适当的 `role="status"` 或礼貌播报区域，无需抢焦点即可获知阶段变化；装饰光带不参与辅助技术朗读。只播报开始、重要阶段变化、需要人工处理及结束，避免逐 token、逐秒或每次事件重复播报，参见[状态消息指南](https://www.w3.org/WAI/WCAG22/Understanding/status-messages.html)。

提供可保存偏好的独立“运行提示动效”开关；用户关闭或系统 `prefers-reduced-motion: reduce` 任一成立时均禁用循环流光，保留静态边框、图标、状态文字和控制入口。开关只控制展示，不发送暂停或取消命令。依据见[暂停、停止、隐藏指南](https://www.w3.org/WAI/WCAG22/Understanding/pause-stop-hide.html)及[减少动态效果设置](https://developer.mozilla.org/en-US/docs/Web/CSS/@media/prefers-reduced-motion)。

具体状态、运行绑定、断线与 UNKNOWN、停止确认和完成语义只由[工作台输入区运行反馈](workbench-design.md#61-输入区运行反馈2026-09-25待实现)维护；本节不定义第二套业务状态机。实施时需验证实际桌面缩放、焦点对比度、键盘与屏幕阅读器、动效关闭和减少动态效果；静态图或文档检查不能替代这些验证。

### 9.1 连续工作区呈现接续（2026-10-01）

本轮按用户授权实施[连续协作规则](workbench-design.md#176-连续协作工作区2026-10-01)，不更换配色、字体、UI 框架或业务 Owner。普通页面 `font.size.page` 复用 `font.size.compactPage`，`layout.section.gap` 收为 `space.6`；正文仍采用独立 body/reading 层级。默认对话比例由新增 `layout.collaboration.chatRatio` 定义，展示偏好读取该 token，不在 CSS 复制默认比例。

任务页头覆盖两栏，行内显示当前需要与执行步骤，操作与诊断就近放置。可调分隔条支持鼠标/指针和键盘，聚焦时有明确焦点线。专注模式只是展示选择；隐藏的子树不能被可见区键盘访问，也不能丢弃状态。窄窗先切区域，短窗允许主区自然滚动；展开长诊断后不会把阅读和操作压成不可达的小框。

聊天普通正文优先，提议摘要以状态、目标和可展开接受入口组织，不默认铺满 hash 与字段表。消息区与输入器有明确边界，返回最新不额外占一行。成果名称/版本、版本比较与编辑采用一条工具栏；版本浮层限定滚动空间。普通判断的对象、条件、影响与操作保持可见，依据与补充说明靠近按钮；多个判断通过就近选择区切换。阅读版本与判断绑定版本不一致时使用明确提示与返回入口，不靠短 ID 让用户自行推断。

动作审批、未知结果、失权和未决命令仍采用完整可读的异常区域。Trace/执行输出用可展开分组保留全部记录，不能因收紧默认密度而隐藏 UNKNOWN。业务规则、存储键、恢复和键盘行为只归工作台第 17.6 节；实际环境与验证结果只归功能验收表，不把公开产品截图当 Relay 验收。

### 9.2 共享页级原语（2026-10-01）

改造前 `grep page-header` 为 0：16 个 view 各自内联标题块，8 个页面各自重声明页面外壳，同一层级在不同页面长得不一样。本节引入三个最小原语，只收敛结构与可访问性，不新增业务状态、执行权限或写入 Owner。

| 原语 | 结构责任 | 字段可见性规则 | 验证出口 |
|---|---|---|---|
| [PageHeader](../../apps/workbench/src/components/PageHeader.tsx) | `title` / `status` / `meta` / `lede` / `actions` / `more` / `children`，各占固定层级；`more` 渲染为「更多操作」浮层，Escape 在 IME 组词期不触发，关闭后焦点回到 summary | 名称、状态、当前需要与**首屏动作**常驻；诊断、模式切换、工具与模型端口进 `more` | 展开 `more` 前后页头高度不变；深层动作仍有可访问名称；旧路由与深链接不变 |
| [FactBar](../../apps/workbench/src/components/FactBar.tsx) | `cells[{label, value?, note?, action?}]`，按 `layout.factbar.cellMin` 自适应分列；格数由调用方按页面语义给 | 事实条是页头的**按需细节**：协作页默认收起，其余页面按对象决定是否常驻 | 不整块套卡片；不足整条换行不压缩文字；已加载范围说明与标题同排，不另占一行 |
| [JudgmentBar](../../apps/workbench/src/components/JudgmentBar.tsx) | `title` / `head`（标题同行）/ `description` / `actions` / `details`；剩余属性透传到根元素，调用方因此可以继续用自己的作用域类与 `data-*`。外观：`bg.surface` 底、`radius.control` 四角圆角、整圈 `separator` 边框；`--warning` 把边框整体换成 `status.warning.text` | 对象、条件、影响与动作常驻；产物版本 ID、`target_hash`、验收条件 ID 与来源深链进 `details`。作为独立圆角卡排在所读纸面之外，不贴在纸面内层——那会盖住正文最后一行 | 截断 UUID 不再出现在首屏；动作审批不使用紧凑形态；UNKNOWN、结果待核对与执行权事实不收进 `details` |

三条硬约束：

1. **折叠不是隐藏**。`more` 与 `details` 里的内容必须仍有可访问名称与可达路径；判断条、技术身份、原未决命令、权限拒绝与无法确认的执行结果不得只存在于展开区。
2. **强制展开优先于省高度**。UNKNOWN、控制请求未结清、执行失败这三类出现时，协作页的 Run 控制移到页头常驻（`CollaborationView.tsx` 的 `runNeedsAttention`），不留在浮层里。
3. **数值仍归唯一 tokens**。本轮没有新增色值、圆角、时长或动效；新增的只有 `.page-head*` / `.fact-bar*` / `.judgment-bar*` 三组类名和 `font.size.section` 在成果文档头上的复用。效果图中 1487×1058 的列宽与留白是生成图推算值，不写入数值源。

协作成果区另有两条呈现约束：阅读区保留 `layout.workspace.centerMin` 下限，判断条 `position: sticky` 贴底（短窗口 `max-height: 40rem` 下改为正常流）。判断条高度因此不再挤压确切正文，两者都不靠像素调优维持。实际取样与限制只归[功能验收表](../testing/overall-acceptance-2026-09-28.md#当前功能验收表)。

### 9.5 任务详情样板与全站枚举呈现（2026-10-07）

任务详情页精修样板的视觉规则，交互出口归[工作台 §17.14](workbench-design.md#1714-任务详情精修样板与全站视觉收口2026-10-07)。全部数值继续消费唯一 `design-tokens.json`，本轮未新增 token：主区为纸面阅读流（区块间 `space-6`/`space-8`、「标题+内容+分隔线」，不逐块套 surface-panel 卡片），右栏为紧凑事实列（`font.size.meta`，不为填满高度堆卡片）；区块标题 `rowTitle` + 顶部大间距、底部小间距；主区与右栏以左边框与背景区分。新增页面样式一律写页面私有 CSS（类前缀 `.task-detail-` 等），`styles.css` 只由协调者收口。


**同名行类必须按结构区分，不按子节点数量隐式推断（2026-10-08 补充）**：任务详情有两份条件列表复用 .task-detail-criteria-list / .task-detail-criterion——「验收条件」是有编号 <ol>（含 .task-detail-criterion-index），「验收依据」是无编号 <ul>（行内只有正文一个子节点）。两者结构不同，网格列数也不同：有编号的保持「编号列 + 正文列」；无编号的由修饰类显式声明单列 minmax(0, 1fr)，差异写在结构上。**不得**把两列网格无条件套在共用行类上——那会让唯一的正文子节点自动落进编号列宽度（实测 2048px 下正文仅 32px，中文被挤成每行约两字的竖条）；也**不得**为修它全局取消 grid，那会让原验收条件列表失去编号对齐。

**页头元信息按分组换行，不是一整句「·」串（2026-10-08 补充）**：长项目名会让「修订 vN」被顶到单独一行、甚至在「修订」与「v4」之间断开。页头 meta 用 flex 分组（所属项目 / 任务编号 / 修订各成一组），换行只发生在组之间；标签 + 数字 这类同一个事实的组内不允许断行。完整 36 字符任务 ID 不再直出普通 meta 长句：按上条基线降为 code 小字缩略（hash-code），完整值由同一页头内一个默认收起的 <details> 给出，可展开、可选中复制，信息不隐藏。只有 UUID / 长哈希形状才缩略，本身是可读短标识的原样显示。
**枚举与技术值的呈现基线**（全站生效，各页枚举中文化时遵循）：

- 用户可见文案不直接输出原始枚举、`JSON.stringify` 结果或完整技术 ID；中文映射 + 原枚举降级（`small`/`title`/`code`）是默认形态，映射缺失的开放扩展值回退原文且只显示一次。
- 「尚未加载（loading）」「确认没有」「字段缺失」三种状态用不同文案区分，不互相冒充；未运行、未确认、UNKNOWN、失效结果不得使用 `status-chip--success` 或勾选样式。绿色只表达服务端确认的确定事实（如 Run COMPLETED）。
- 就地辅助操作用文字按钮（下划线 + `color.action.text`），与主/次按钮三级分层；空态一行紧凑文字或共享 EmptyState，不用大标题大留白撑空间。
- 时间一律走本设备显示时区的可读格式（ISO 原串保留在 `time.dateTime`）；长 UUID/哈希保留可核对性但降为 `code` 小字或折叠 `<details>`。

本轮新增中文映射：`criterionMethodLabel` 补 `CITATION_EXISTS`/`SEMANTIC`；`acceptanceSourceLabels`（CREATE/CONTRACT_CHANGE/HUMAN）；连接页能力/决定/状态局部映射；Run 页 Gateway 动作与调用状态局部映射；各页其余映射以页面局部常量先行，后续统一收编进 `labels.ts` 由协调者执行。

### 9.6 控件基座与响应式收敛（2026-10-08）

用户要求对所有按钮、表单控件、导航元素、状态提示做控件级精修。本轮全部数值仍消费唯一 tokens（新增 `space.0.5 = 0.125rem` 微间距档；contrastChecks 补 `muted on selection.hover ≥4.5` 与 `onAction on danger ≥4.5` 两道门槛），styles.css 改造 +198/−22 行，交互出口归[工作台 §17.15](workbench-design.md#1715-控件交互基线与响应式收敛2026-10-08)。规则：

- **按钮**：`[aria-busy="true"]` 全局降饱和（opacity .7 + `cursor: progress`），五类按钮通用；`.primary-button--compact`/`.secondary-button--compact` 修饰符（min-height=control.height + meta 字号）收编页面私改的 2.5rem 主按钮，页面不得再压回全局按钮高度；danger 仅用于不可逆/终止操作，可恢复操作（暂停、取消会话）用 secondary——分级注释固化在 danger-button 规则处。复合开关控件（如委托开关：主按钮+内嵌说明文字的 flex-wrap 结构）保留自有规则，但其 hover/active/focus 必须与全局 primary 等值。
- **表单**：输入基座 `:focus-visible` 主色边框（focus 视觉 ≥ hover）；`.field` 基类排除 checkbox/radio（回归原生 + accent-color，删除历史补丁）；label 布局收敛为全局 `.field--row`（横向，label `flex:none; min-width:7rem`）与 `.field--grid`（两列 grid）两个变体，页面私有横排/两列实现应替换为变体；结构不同的页面实现允许保留但须注释收编路径。
- **状态提示**：补全局 `.success-callout`（warning 同族骨架）；receipt-message/action-error 补 3px 左色条形成同族呼应；`.loading-text` 统一裸 loading 文案（meta 字号 + muted），「还在跑」的持续信号（inflight-dots、composer 光条）不属于此类不动；`warning-callout > button` margin 全局化，页面不得手写。
- **断点收敛**：目标为三档语义——`width < 48rem`（折行/降级）、`width < 64rem`（大屏增强）、`width < 80rem`（rail 出现），写法统一 range 语法并与整数 min-width 档配对，禁止新增 `.9375rem` 补丁与 min/max 双触发。本轮处理的 700px、60rem、45rem 规则已并入对应语义档（逐处注释）；既有页面仍有遗留断点，不能描述为全站已收敛，具体剩余范围归[功能验收表](../testing/overall-acceptance-2026-09-28.md#当前功能验收表)。PageHeader 接管页面标题后，确认不再匹配的页面 `> h1`/`.page-lede` 直选规则可清理。

  2026-10-15 外壳折叠点下移（spec/计划见 `docs/superpowers/`）：外壳收纳（`.app-frame` 单列、两栏 `display: none`、图标栏退化为纯图标、`☰` 出现）由 `width < 64rem` 迁到 `width < 48rem`，因此 64rem 档回归它本来的「大屏增强」语义（拖拽手柄、页面密度），不再兼做外壳收纳；同区间新增一条 `@media (48rem <= width < 64rem)` 只覆盖 `--relay-shell-sidebar-width`，让用户拖拽宽度不泄漏到该档。页面密度（主区内边距、标题降 `compactPage`）与拖拽手柄仍留在 `< 64rem`。`.app-topbar:not(:has(.breadcrumbs))` 的整行收起区间同步改为 `min-width: 48rem`，避免该区间出现「点开只是重复屏幕上内容」的空抽屉顶栏。

  2026-10-10 收敛回写：剩余遗留断点已按四档语义值（`breakpoint.medium/large/rail/wide` = 48/64/80/90rem）收口——Reviews 的 60rem 标题档因与全局 `<64rem` 重复而删除，Knowledge/Run/TaskDetail/ArtifactPanel/LiveTaskSkillFacts/TaskCheckPlanPreview/styles 的 40rem 兜底档并入 `<48rem`，各处 `.9375rem` 与 min/max 双触发改写为 range 语法（逐处注释）。`tests/responsiveTiers.spec.ts` 把档位集合、禁补丁、禁双触发与禁旧式 max-width 写成可执行守卫；`tests/browser/responsiveFoldGeometry.spec.ts` 在真实 Chromium 复核 700/767/768/900/1023/1024px 的折行边界与无横向溢出。**未收敛**：`views/AssistView.css` 的 `max-width: 64rem` 属自然语言状态维护任务在途文件，本轮只做守卫豁免（语义档位合规、写法待其 Owner 归一），不覆盖他人未提交改动。
- **对比度**：token 组合新增两道 contrastChecks 门槛；各页新增背景/文字组合时必须能映射到 contrastChecks 已有条目或补充条目。

| 卡片 12px 圆角、6px 徽标圆角 | `radius.panel` 0.5→0.75rem，`radius.badge` 0.1875→0.375rem | 原型的卡片与状态标签比旧值更圆；`radius.composer` 保持 1rem，因为发送键按 `2 × radius` 同心推导，缩到 12px 会容不下 32px 的键 |
| 卡片投影 `0 10px 32px rgba(30,57,37,.055)` | 新增 `shadow.card` | 只给「浮在画布上的内容块」（面板、纸面）；列表、侧栏与页壳仍无阴影（§1 的既有约束不变） |

新增的其它 token：`color.palette.lineStrong`（`meter.track` 需要与纸面拉开 ≥1.2:1，`line` 只有 1.18:1）、`layout.inspector.width / wideWidth`（工作详情面板 322 / 610px）。同时**补定义**了三个早已被 `TaskInspectorPanel.css`、`TaskViewDashboard.css` 消费却从未存在的 token：`font.weight.bold`、`font.lineHeight.snug`、`font.lineHeight.relaxed`——此前浏览器按无效值回退，面板小标题与说明段落拿不到声明过的层级。

组件规则的同步变化：

- 回执与错误提示（`.receipt-message` / `.action-error`）由「左侧 3px 色条」改为「整圈 1px 边框 + 圆角」，对齐原型的 `error-box` / `attention-strip`：长句换行后，整圈边框才读得出「这是一块独立状态区」。
- 应用顶栏与近期工作栏底色由 `bg.canvas` 改为 `bg.surface`，与原型「白工具条 + 白侧栏、画布色留给主内容」的分层一致。
- 图标导航顶端新增 `.navrail-brand`（主色圆角方块，`aria-hidden`），纯装饰；短窗口（`max-height: 50rem`）隐藏，把高度让给十个常驻入口。
- 右侧面板重构为原型的「工作详情」三页签（进展 / 成果 / 记录）+ 成果深预览（预览 / 版本与来源）。**未实现原型的「变更」页签**：面板没有真实 diff 数据源，按 §2 的「不伪造」原则只呈现真实读到的字段。面板在 `<80rem` 改为覆盖在成果区之上的浮层，宽度仍取同一 token。

本轮没有改动业务规则、命令 Owner、API、路由语义与任何写入路径；色值变更只落在 JSON，验证出口与未覆盖范围归[功能验收表](../testing/overall-acceptance-2026-09-28.md#当前功能验收表)。

### 9.9 横向尺寸改为「百分比 + 上下限」（2026-10-15）

原型对齐后暴露一个问题：固定 rem 列宽会让同一界面在不同分辨率下比例不一致——侧栏固定 14rem 时，1920 宽窗里它只占 10.6%，中栏被不成比例地拉大；右栏固定 25.5rem 时同样越宽占比越小。用户据此要求「尺寸做百分比和上下限」，本轮把**所有横向列宽**改成 `clamp(下限, 百分比, 上限)`：

| 列 | token | 值 | 边界 |
|---|---|---|---|
| 图标导航 | `layout.navigation.railWidth` | 5.5rem **固定** | 有意不参与缩放：它是窗口外壳常量，竖排标签在宽窗下会被拉散 |
| 近期工作栏 | `layout.shell.sidebarWidth` | `clamp(11rem, 16%, 17rem)` | 176–272px |
| 页面右栏 | `layout.rail.width` | `clamp(20rem, 26%, 26rem)` | 320–416px |
| 窄右栏 | `layout.rail.narrowWidth` | `clamp(18rem, 24%, 24rem)` | 288–384px |
| 工作详情面板 | `layout.inspector.width` | `clamp(18rem, 20%, 22rem)` | 288–352px |
| 成果深预览 | `layout.inspector.wideWidth` | `clamp(30rem, 34%, 40rem)` | 480–640px |

百分比基准是**各自所在的容器**而不是视口：侧栏比 `.app-frame`，面板比 `.collab-columns`。这样窗口出现滚动条、或面板收成浮层时，各栏仍按同一比例分配。`layout.sidebar.width`（14rem）保留，但语义收窄为**拖拽起点默认值**——`SidebarResizeHandle` 仍按它推导 px 上下限，用户手拖后由 `--relay-sidebar-user-width` 覆写。

实测（工作详情打开；对话/成果两栏在所有宽度恒定 52/48）：

| 视口 | 侧栏 | 中栏 | 成果栏 | 面板 | 面板占比 |
|---|---|---|---|---|---|
| 1280 | 205 (16%) | 359 | 332 | 288（下限） | 29.2% |
| 1440 | 230 (16%) | 429 | 396 | 288（下限） | 25.7% |
| 1920 | 272（上限） | 645 | 595 | 312 | 20.0% |
| 2560 | 272（上限） | 957 | 883 | 352（上限） | 16.0% |

占比只在被上下限截断时才偏离百分比——这正是上下限的用途：窄窗保住可读宽度，宽窗限制上限避免侧栏吃掉中栏。

实现过程中踩到两个 CSS 陷阱，都已写进注释：

1. **clamp 的 `%` 在网格里会拿轨道宽当基准。** 面板自身 `width: clamp(18rem, 20%, 22rem)` 时，网格项的包含块是它所在的轨道，于是 20% 恒小于下限、永远取 18rem，还会在轨道与面板之间留一道空隙。修法是把宽度交给 track（`.collab-columns:has(.task-inspector) > .task-inspector { width: 100% }`），clamp 只出现在 `grid-template-columns` 里。
2. **拖拽手柄必须与列宽同源。** `.app-frame` 上解析一次 `--relay-shell-sidebar-width`（内含「用户覆写优先、否则回退 clamp」），分隔条 `left` 复用同一变量，否则列宽变了、分隔条还停在旧位置。实测手柄中心与侧栏右缘偏差 0px（含 localStorage 预设 260px 的场景）。
