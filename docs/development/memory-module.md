# 记忆模块的工程边界

2026-10-19，用户要求继续长期、短期等完整记忆模块，大模块完成后统一交付前端提示词；并确认「自动召回已确认记忆，并可关闭」。本文记录工程取舍，不维护第二份阶段或成绩；进度归 CODEX_NEXT_STEP，结果归统一验收表。

## 完整交付范围

| 要求 | 实现责任与完成证据 |
|---|---|
| 长期事实的明确保存 | 复用 Memory 根/不可变版本/确认用例；支持从确切会话消息显式保存，冻结来源 ID/hash 与用户明确选择的全局/项目范围；真实 PG/HTTP 验证确认、幂等、来源与越界拒绝 |
| 长期召回与关闭 | Workspace 持久设置；仅普通 AGENT 在同 Workspace 全局与当前 Project 内有界召回已确认、ACTIVE 且未过期记忆；显式来源优先去重，保留来源版本与召回依据；关闭后新请求不召回 |
| 短期工作窗口 | 使用原消息与既有 completed 边界，不以最近 20 条静默截断冒充完整记忆；保留近期原文，旧轮次用已持久化检查点接续；一次性模式不续读历史 |
| 手动与自动压缩 | 持久请求、当前模型冻结、独立可追溯调用计量，完整工具轮次结束后整理；摘要只作数据，失败保留原窗口，未决或不安全结果不伪装成完成 |
| 重启、并发与失效 | 请求领取/租约/发布 CAS；checkpoint 提交后才切换；重启重建 checkpoint＋增量，不重放工具；源停用/到期、目录/作用域/配置变化后旧摘要不可泄漏内容 |
| 管理与遗忘边界 | 既有长期三态/筛选/修订/停用/恢复；短期清除只改变后续工作窗口并保留原会话历史，明确安全边界，不删除项目事实或长期记忆；设置、检查点、召回使用和来源可读取核对 |
| 统一交付 | 接入真实聊天生成链并完成相关真实 PG/HTTP、Fake 模型输入证据、持久化/重启与恢复回归；文档一致后才交付整模块前端任务书，不用小切片替代大模块完成 |

## 继承与非目标

Information 是长期 Memory 的唯一写入 Owner，Assist/Application 拥有会话短期窗口与压缩请求；LangGraph Run checkpoints 继续拥有执行恢复，不重建 Workflow 或将摘要当成 Task/Project State。保留 ADR-019 的当前模型摘要、稳定前缀、安全轮次、原始历史可追溯和失败不切窗口原则。ASSISTANT/LEARNING 身份和能力边界保持，不自动升级到普通 Agent 记忆链。

不增加向量库、自动画像、模型自动确认/保存长期记忆、跨项目隐式访问、原生 Provider 压缩平台、文件恢复或任意工具权限。普通聊天的自动召回内容、历史答复和摘要均以 UNTRUSTED_DATA 输入，不写成系统规则或授权。用户确认的是长期内容可召回，不意味着每次都必须选中，也不代表内容客观正确。

2026-10-20 追加：用户确认「长期记忆应自动保存有价值内容」，并否决了「候选 + 人工确认」的确认环节（「要人手动确认感觉很麻烦」）。方向定为[零点击自动记忆](../decisions/ADR-030-zero-click-auto-memory.md)：结算后提取并**直接写入** Memory，`origin = AUTO_CAPTURE`、`confirmed_by = auto-capture`（不冒充人），参与召回但排在人工确认之后，可一键撤销且撤销后同内容不再提取，每会话每日上限 5 条。本模块原非目标「模型自动确认/保存」因此被修订：自动写入已获授权，但仍不冒充人工确认，也不新增自动画像或向量库。实现与验收边界见 `prompts/auto-memory-candidates.md`，进度归 CODEX_NEXT_STEP。

## 关键工程选择

- 复用本地 PostgreSQL 和现有命令回执/独立 revision；新增对象在新 migration 中追加，不修改已应用迁移。只维护配置、短期窗口、检查点、压缩请求和显式保存来源，不复制第二套长期正文。
- 自动召回采用有界字面相关性与近期已确认回退，明确标识选取依据，不声称语义向量检索。来源始终冻结到确切 Memory 版本，读取和每次重建时重新核对状态、有效期与作用域。
- 时间/停用不应通过旧摘要绕过来源撤销。checkpoint 保存来源足迹与覆盖边界，失效时拒用旧摘要并按可核对原文重建或明确失败，不能把源正文留在匿名摘要中继续发送。
- 清除短期窗口与一次性开关在安全边界生效；在途请求不能仅靠前端 Loading 被宣称清空完成。原会话与工具历史保留；从原消息明确保存的长期记忆保持来源，源会话物理删除须遵守跨对象引用栅栏。
- 模型调用不在数据库长事务内，使用原 model_calls 计量与作用域预算。摘要最多整理已结算文本轮次，不截断或重写在途工具协议；真实 Provider 协议/质量成绩与 Fake 工程证据分开。

## 完成审计

实现中独立审查指出的边界已纳入反例：直接召回不代表后续答复没有间接引用；来源足迹必须随实际发送的历史继续传递，分叉同样保留该足迹。从旧答复明确保存长期事实也检查传递来源。工具派生内容还需冻结权限和 project/task/目录身份，输入组装前后核对同一权限/上下文基线，不能用组装结束时的新修订给旧内容补授权。0120/0123 为此追加列，不修改已应用迁移。

运行中取消必须同时覆盖「端口抛异常」和「端口正常返回 CANCELLED」；不能把心跳因取消返回 false 一律当 Worker 丢失。原窗口保留与新请求的失败状态是分开的事实。

旧工具答复缺少可核对使用账本时，分叉用明确的「来源无法核对，正文未复制」文本占位，父会话原文保留。不能简单把新子消息正文置 null：既有 `assist_messages` CHECK 要求 COMPLETED 消息具备正文，真实PG反例已暴露该冲突；保留约束并用合法占位避免泄漏。取消历史的 STEERED 排除条件也须使用 NULL 安全比较，不能因 SQL 三值逻辑漏掉正常 CANCELLED 轮次。

逐项核对上表六类能力与统一交付出口。只存在 CRUD、派生状态、摘要表或新 API 都不足以标完成：必须检查实际模型输入、来源撤销、关闭开关、重启后窗口、失效/失败与并发路径。浏览器、真实 Windows 与安装态如未运行需如实单列，不把后端模块完成表述为整机产品交付。

## 召回与压缩接缝修正（2026-10-30）

混合语言查询原先把 `完善PostgreSQL数据库` 视为一个词，无法命中单独保存的 PostgreSQL 内容；现在按汉字与其他字母/数字边界分词，汉字继续采用相邻双字，不改变 500 字符输入、24 个词的上限，也不引入语义搜索。

自动召回原先先取最多 8 个候选，再排除显式选择的来源；当前 8 个均被显式选择时，会漏掉后面的可用记忆。现在在数据库候选限制前排除显式来源，保持原有效期、范围、来源撤销和排序规则；最终仍最多 3 条、合计 8000 字符，与显式资料合计最多 20 个来源。

短期压缩不接受工具请求；原先虽然拒绝发布摘要，却把返回 TOOL_CALLS 的外呼记为 COMPLETED。现在该调用以 FAILED / MEMORY_TOOL_CALLS_UNSUPPORTED 结算，保留 Provider 请求身份与已知用量；CONTENT 的传输完成与摘要 JSON 校验继续分开，非法摘要不切换窗口。该调整不执行任何工具、不自动重试，也不变更 HTTP 结构或数据库，Breaking Change: No。反例与实际验证结果归[记忆验收条目 093](../testing/acceptance-details/part-05.md#条目-093)。

### 上下文档位与压缩压力

用户接续要求优化压缩并可选 256K、512K、1024K。原工作区设置已保存这三个预算整数，但短期整理仍固定按32条/48KB触发，且历史、最终输入与整理输入各有128KB固定保护，导致大档位过早压缩甚至无法使用。现在三处入口共用基于冻结有效预算的工作容量策略，触发包含旧摘要大小；具体公式与兼容回退只归 [HTTP §10.99](../api/http-command-contract/part-07.md#1099-长短期记忆接口2026-10-19)。预算更小的模型仍更早触发/拒绝，不通过扩档绕过 Provider 窗口。保留8条近期原文、安全轮次、不可变检查点、取消/租约/CAS与来源失效机制；摘要失败不切换窗口，不引入静默截断或新的重试循环。
