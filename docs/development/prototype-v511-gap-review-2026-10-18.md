## 6. 追加评估：home 底部「最近执行的任务 / 最新变更」是否适合引入产品（2026-10-18 用户提问）

**原型实际内容**（`v510HomeActivity()` / `v510HomeLatest()`，均写在原型 JS 里的静态模板）：

- **最近执行的任务**：卡头（时钟图标＋「最近执行的任务」＋›）＋3 行演示数据（ripgrep 搜索 / pnpm test / 编辑 computer-adapter.ts），每行带「x 分钟前」与类型标签（工具/终端/编辑），第三行带 +66 −2；整卡点击进演示会话。
- **最新变更**：卡头（图表图标＋「最新变更」＋「查看全部 ›」）＋摘要行（已编辑 6 个文件＋文件名列表＋+503 −0）＋两颗动作（撤销 / 查看变更）。

**结论：不适合原样引入；功能方向有价值，但须以真实数据另做设计。** 理由：

1. **两块都是硬编码演示数据**，「撤销」「查看全部」也是无后端去向的假交互；原样搬入等于把假功能带进产品，违反不虚构业务事实与 fixture/live 分离原则（§17.13、AGENTS.md 第 1 节）。
2. **与产品既有入口重复**：左栏「近期工作」已是会话/任务的最近入口；会话内已有 `ExecutionTrajectorySummary`（执行轨迹，AssistView.tsx）与 `ConversationDiffSummary`（会话 diff 摘要＋真实 UndoPlan 撤销，AssistView.tsx）。原型这两卡正是这两个组件的事实来源，再在 home 放一份就是同一事实两个展示位，容易不一致。
3. **home 定位不同**：产品「新对话」是 §18.1.1 的首条输入区（欢迎块＋输入卡），不是常驻 dashboard；把执行/变更摘要塞进欢迎页会改变首屏语义，也与「首条发送才建会话」的轻定位冲突。
4. **撤销是真实命令**（UndoPlan / 撤回范围），必须走既有命令入口与确认形态，不能是 home 页上的一颗桩按钮。

**若要做（独立小需求，另行排期，不在当前 F26/免费模型链批次内）**：用真实查询做一个小型「最近动态」区——数据源为近期会话的执行轨迹与 diff 摘要（复用既有组件与 API，不建第二套读取），空态/失败态按 §17.13 规则，UI 按项目设计系统适配（不沿用原型的卡片几何与假数据）。开工前需定范围：哪些会话算「最近」、显示几条、live/fixture 数据源、是否可交互（建议只读跳转，不内嵌撤销）。

**实现（2026-10-18）**：已按上述范围落地。**范围经与用户确认**＝仅首屏 `?new=` 输入区、全局最近活动流（不分项目）、仅活动流（不带会话 diff）。落点：首屏 `assist-first-welcome` 在快捷语卡片下新增只读「最近动态」区（`components/RecentActivitySummary.tsx` + `lib/useActivities.ts`，`useActivities` 对齐 `useConversationDiff` 的 loading/error/stale/refresh 契约，失败不清零、保留上次可信值）。每行＝行为人（我/AI/系统）＋事件摘要＋相对时间（刚刚/N分钟前/…）＋引用跳转链接（复用 `activityRefTarget`），底部「查看全部动态 → /activities」。含加载中 / 空态（还没有动态。）/ 错误态（最近动态读不到。＋重试）兜底。活动标签·分类·引用文案从 `ActivityView.tsx` 下沉到 `lib/labels.ts` 共用（单一来源）。原型的硬编码「最近执行任务 / 最新变更」及假交互**未原样搬入**；未内嵌撤销（走既有命令入口）。测试：`collaborationWorkspace.spec.ts` 的 router mock 新增 `/activities` 路由，并加一条覆盖有数据/空/错误的用例（通过）。注：同文件其余 4 条「轨迹/执行摘要」用例失败为并行会话改动 `ExecutionTrajectorySummary`/`ExecutionSummary` 所致，与本改动无关。
