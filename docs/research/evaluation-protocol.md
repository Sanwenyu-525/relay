# 可选论文实验：验证策略对错误接受的影响

日期：2026-09-19。状态：推荐实验协议，待导师和任务集确认；不是已确定论文创新点，也没有实验数据。

## 研究问题

在相同任务、生成模型和执行预算下，明确的确定性检查、语义验证与人工升级，是否降低错误接受，同时带来怎样的完成率、成本和人工负担变化？系统架构是实验平台，不以模块数量证明研究贡献。

## 实验组

固定生成后直接交付；仅确定性检查；确定性检查加独立语义验证；再增加不确定项人工升级。使用同一任务集/初始输入/模型配置/修正预算，记录每次配置与 ContextManifest。每组重复多个独立运行，保留失败、超时和预算耗尽，不能只筛成功案例。

任务集先做小规模试验，包含资料摘要、结构化 Markdown、真实来源但不支持结论、缺正文、条件变化、错误产物版本等；正式样本量通过试验方差与统计计划确定，不凭空承诺固定显著性。

## 独立评价

参考答案/判定 rubric 在运行前冻结。人工标注者尽可能不知道实验组，不使用系统内部同一个 Judge 作为唯一最终裁判。分歧记录并复核。自动故障注入样本与开放语义样本分别报告，不把确定性错误当作整体语义能力。

指标：错误接受率、错误拒绝率、最终完成率、人工介入次数/时间、模型/工具成本和耗时；同时给清楚分母。未完成和缺失用量单列，不从统计中消失。报告样本不确定性，不用单次演示声称因果结论。

## 复现产物

experiment_manifests、匿名 task cases、固定规则/criteria、配置版本、原始 outcome 与评价、汇总脚本、失败记录、README。脚本必须从真实记录计算，不生成看似真实的结果；示例数据明确标为 synthetic。资料使用权/隐私由实际数据来源核验，不外发用户项目材料。

此研究任务不阻塞产品基础发布；若用户只需工程毕业设计，可交系统测试和限制说明，不能捏造研究创新或显著性。

## 与扩展版本 Eval 的边界

2026-09-20 补充：[Skill/Pack 工程 Eval](../testing/verification-plan.md#9-扩展组合与版本评测)是产品回归要求，不因本研究可选而省略。工程检查可复用这里的独立判定、固定输入和失败保留原则，但不能仅据内部 Verification PASS 推断能力提升。Context/Verification Profile、Skill 版本及 Blueprint/Workbench 操作效率可作为后续研究变量候选；选择哪个问题、对照、样本和统计协议仍需确认，不把目录数量或一次升级回归称为论文贡献。
