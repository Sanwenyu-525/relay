### 1.2 联网一手资料

下列页面均于本轮读取；产品介绍证明其公开交互描述，不等于已登录实测这些产品。

| 来源 | 可以核查的模式 | 对 Relay 的推导 |
|---|---|---|

| [Claude Cowork 官方入门](https://support.claude.com/en/articles/13345190-get-started-with-claude-cowork) | 执行过程中显示进展，用户可补充方向，并在同一会话持续查看工作 | 用户首先需要知道现在做什么、缺什么、能怎么处理；原始 Trace 和技术标识作为可展开依据。观察到的进展不是 Task 完成 |

| [W3C Tabs Pattern](https://www.w3.org/WAI/ARIA/apg/patterns/tabs/) | 真正页签关联 tablist/tab/tabpanel、选中状态及方向键操作 | 同页切换与路由导航应使用各自语义；宽窄窗口共用相同交互，不以一组普通按钮代替完整键盘行为 |

这些推导属于本项目的设计建议；没有复制上游源码、安装上游依赖或调用真实 Provider。

## 2. 当前页面取证

使用当前 React 源码，Vite 本地预览与现有 `collab-visual-server.mjs --pages`。服务只监听 loopback，拒绝业务写入，没有 PostgreSQL 或模型调用。浏览器连接面板填入的是合成 Workspace 和明确的测试字符串，未使用真实凭据。

主要检查视口为 1280×800；另检查 960×640。浏览器返回的截图可能包含整页高度，图像像素不等于 Windows DIP。原始八张截图保存在忽略目录 `output/acceptance-raw/ui-audit-20261001/`，已逐张打开核对；协作首次加载截图被拒绝并以正文加载完成的截图替换。

| 步骤 | 实际操作 | 体验判断 | 限制 |
|---|---|---|---|
| 1 | 连接只读夹具，打开设置 | 设置表单可见；大标题和静态右栏挤占高度，保存需向下查找 | 未保存设置或测全部设置分组 |
| 2 | 从导航进入项目列表 | 项目可选且可打开；阶段码、UUID 与读取说明先于实际工作信息 | 仅一个合成项目，未测大量项目性能 |
| 3 | 打开项目总览 | 下一步与 Review 有入口；首屏出现大量服务端字段缺口说明及英文状态 | 未提交蓝图、接续或归档命令 |
| 4 | 打开通用工作台 | 能定位 Task 和读取目标；正文/讨论仍需再跳入口，不能构成连续工作区 | 未截图论文/开发全部特殊状态 |
| 5 | 从近期工作进入协作 | 确切正文与判断同时可读；聊天中巨大的 Skill/检查面板出现横向滚动，挤压讨论 | 夹具含 Skill 历史，没有真实模型响应或普通提案接受结果 |
| 6 | 从文档进入产物编辑页 | 保存版、编辑、版本和完成入口存在；重复的版本选择与操作解释增加理解成本 | 当前 AI 执行权导致写按钮禁用符合夹具事实，不能据此称权限 Bug |
| 7 | 从导航进入待审 | 请求列表和判断动作可达；当前详情先露技术身份，正文/证据入口弱于判断按钮 | 未实际接受或拒绝 Review |
| 8 | 在 960×640 重进协作 | 没有页面级横向溢出；消息区域被压成很矮的滚动区，输入和判断又各自滚动 | 浏览器视口，不是 Windows 窗口、DPI 或 IME 验收 |

## 3. 高影响缺陷与交互问题

代码行号绑定本轮读取的源码快照；后续修复可能移动行号。P1/P2 为整改优先级，静态结论与实际浏览器观察分别注明。

| 优先级 | 问题、依据 | 用户影响与整改出口 |
|---|---|---|
| P1，静态确定 | [协作 CSS](../../apps/workbench/src/views/CollaborationView.css) 第 26 行把 `.agent-chat-proposals` 全部隐藏；[Assist](../../apps/workbench/src/views/AssistView.tsx) 第 548–559 行已有确认区，第 616–620 行仍允许选提案意图 | 请求提案后看不到正文/接受入口。必须恢复可见确认区或把原提案组件移到成果区，保持同一命令 Owner。需非空提案的 `/agent` 浏览器反例；本轮只读服务不证明接受成功 |
| P1，静态确定 | [近期工作](../../apps/workbench/src/components/RecentWorkRail.tsx) 第 51 行追加游标页，第 74 行固定 `slice(0, 8)`，第 106 行“更早”继续加载 | 超过八条时，后续工作始终不可见。显示已加载集合或真正切页；需至少九条和多游标反例，本轮三条夹具未动态复现 |
| P2，静态确定 | Assist 第 202 行隐藏 standalone 的会话选择，第 137–140 行默认回最近会话；近期栏只导航 Task | 创建第二会话后缺少回第一会话入口，空态指引与真实导航不符。提供同 Task 多会话选择并保留草稿/未决命令保护 |
| P2，静态确定 | Assist 第 581–583 行主按钮固定“发送讨论”，但第 590/616 行允许 Skill、文档候选或任务提案 | 最后提交处不明确真实意图。入口、按钮文字和被冻结请求意图一致；生成建议与委托执行仍分别操作 |
| P2，源码与截图 5/8 | [协作 CSS](../../apps/workbench/src/views/CollaborationView.css) 固定近等宽双栏，消息、输入、选项、判断、完成分别建立滚动区域 | 在短窗口和长 Skill 内容下阅读区被挤压、滚轮归属混乱。按内容主次分配空间，统一选项面板，必要时显式切换主视图；输入/关键判断始终可达 |
| P2，静态确定 | [右面板](../../apps/workbench/src/components/WorkspaceSidePanel.tsx) 第 75 行只有 DOCUMENT 显示判断；[协作](../../apps/workbench/src/views/CollaborationView.tsx) 第 310/324 行的待判断文本与检查入口分离 | 换到历史或检查后看到有待判断事项却缺就近入口。让待判断提示定位确切 Review；不自动提交判断或转移执行权 |
| P2，静态风险 | Assist 第 412/421 行预览失败清空正文但继续轮询，生成状态继续显示 | 预览读取失败与后台执行状态混在一起。显示独立读取状态、最近成功时间与重读入口；真实断流场景需故障测试 |
| P2，DOM与源码 | 960 视口 DOM 没有 `role=tab`；右面板第 68 行普通 nav/button，窄窗又用另一套 pressed 状态；Assist 消息区域缺明确焦点入口和回到最新操作 | 页签键盘行为及历史阅读位置缺乏统一约定。区分链接/页签/筛选，用同一语义组件；补方向键、焦点归还、中文 IME 和返回最新验证。没有进行完整辅助技术测试 |

截图 1–7 共同显示另一个结构问题：内部状态码、服务端投影说明、UUID 和操作原理常驻普通用户首屏。重做应保留可核对身份与依据入口，先显示对象名称、确切版本、当前需要的动作和影响；详细诊断按需展开。不能为了简洁隐藏待核对命令、审批目标、权限拒绝或无法确认的执行结果。

已有测试着重保护 Owner、revision、草稿、控制与恢复等业务边界，仍需保留。当前协作测试夹具主要是单 Task、单会话、空普通提案，不能证明后续页、多会话、非空提案和 CSS 可见性。业务可靠性测试通过与用户工作流可用是不同结论。

## 4. 整改取舍

1. 先闭合提案、多会话、长列表等操作断点，再统一导航与输入/成果/判断层级。
2. 先整理 AppShell 与共享交互组件，再推广七类页面；完整范围归工作台第 17 节，不把三张方向图当作全套页面交付。
3. 现有 React、Lucide、领域 Owner、API 和 tokens 足以开展这一轮设计。是否采用无样式可访问组件库需按实际缺口评估，本轮不新增依赖、不复制 DeepSeek 的插件平台。
4. 图像只用于选择结构与阅读顺序。选稿后仍需同一状态/视口的运行页面对照、真实业务回归与 Windows 人工体验；不继承旧包 UI 通过结论。

## 6. 本轮方向稿

使用内置 Image Gen 独立生成三张图，实际展示顺序为：1 [工作主线](../frontend/mockups/2026-10-01/work-first.png)、2 [成果书桌](../frontend/mockups/2026-10-01/output-first.png)、3 [项目推进](../frontend/mockups/2026-10-01/project-first.png)。顺序绑定本轮聊天中实际出现的生成结果，用户后续按数字选择时沿用此映射；不按生成请求的计划顺序猜测。

共同生成约束：中文 Windows 桌面、目标比例 1440×1024、2026-10-01 星期四、暖白/绿色起点、保留左侧常用操作和空白拖动区的自定义标题栏；以本轮页面截图作为问题参考，重组导航、讨论、成果与判断，强调清楚的版本、独立委托和完成。三张实际生成 PNG 均为 1487×1058，未拉伸或修改图片，不把生成尺寸写成桌面 DIP。第一稿以对话为主轴，第二稿以正文/比较为主轴，第三稿以项目下一步与工作目录为主轴。每张均附当前页面的实际截图，没有附登录中的外部产品界面。

图内项目、日期、任务、表格和结果均为设计示例。生成图中的文字、状态/执行者组合、主次比例和未画出的会话/错误/UNKNOWN 等状态仍需深化；不能把图里“已读取”“候选”当真实调用或保存凭据。三图是整套方向的代表画面，不是全套页面完成。以上为研究阶段边界；用户随后以附件选择工作主线图。实施规则接续到工作台第 17 节与设计系统第 9 节，实际结果归功能验收表，不反写为研究阶段已经完成。
