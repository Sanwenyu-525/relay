# motion-border-prototype.html 视觉重构设计

- 日期：2026-10-06
- 目标文件：`motion-border-prototype.html`（仓库根目录，单文件独立原型）
- 状态：设计已确认，待实施

## 1. 背景与问题

该原型用于评审「Agent 状态视觉反馈系统」的输入区动效三候选。页面当前**没有审美缺陷**：
配色（暖白 `--paper #FAF9F6` + 深绿 `--forest #285747`）干净，无渐变、无玻璃拟态、无装饰性阴影，
所有动效时长只来自 `--motion-*` token（零裸时长）。这些必须保留。

真实问题是**信息层级缺失**，导致页面无法履行其核心职责——让人比较三个候选：

| # | 问题 | 具体证据 |
|---|---|---|
| 1 | 三个候选卡视觉等同 | 除边框层外 A/B/C 完全相同，扫视无法区分，页面失去对比能力 |
| 2 | `.now` 读数被反向降权 | 「当前：光点单向横穿 4.5s」是每个候选此刻唯一的差异说明，却使用最浅的 `--sage` 底色 |
| 3 | 等宽字体泛滥 | `.desc` / `.now` / `.tag` / `.lv` / `td.k` / `.readout` / 全部 `code` 均用 `--font-code`，约 40% 可见文字为等宽 |
| 4 | 发丝线滥用 | `.toolbar` / `.card` / `.qa` / `.table-wrap` 四种语义不同的元素共用同一句 `box-shadow: inset 0 0 0 1px var(--line)` |
| 5 | h1 层级过弱 | `1.625rem / 600` + 系统默认无衬线，页面标题无排印个性 |
| 6 | 控件语言不统一 | `.chip`（药丸灰底）/ `.btn`（描边绿底）/ `.qa`（白底内阴影）三种按钮三种做法 |
| 7 | chip 换行产生孤儿 | 11 个状态 chip 换行后末行仅剩「已取消」 |
| 8 | 位移检测读数裸悬 | 灰字浮于卡片下方，无容器无归属 |

## 2. 范围

### 做

- 视觉层级重构：字阶、阴影分级、边框分级、背景分层
- 结构改造：新增桌面 app 外壳（标题栏 + 侧边导航），演示区重构为「对比模式」视图
- 候选卡差异化：A/B/C 建立第一眼可辨的视觉身份
- 控件语言统一
- 规格文档区收进可折叠面板，视觉降级但内容保留

### 不做（硬约束）

- 不改 `STATE_VISUALS`、`GLYPHS`、`ORDER`、`MARK_STATES`、`EMPHASIS_STATES`、`CANDIDATE_NOW`、`QA_ICONS`
- 不改任何 `@keyframes` 与 `--motion-*` token
- 不改 `applyState()` / `renderIndicator()` / `reportShift()` / `startSimulation()` 的行为逻辑
- 不改任何色值：`--paper` `--surface` `--sidebar` `--ink` `--secondary` `--muted` `--line` `--control` `--forest` `--sage` `--amber` `--red`
- 不删任何文档内容（映射总表、验收自查、待验证项）
- 不碰仓库内任何其他文件

## 3. 结构调整

页面变为双区结构：

```
┌─────────────────────────────────────────────────┐
│ ● ● ●   Relay-Agent · 输入区动效对比        ─ ✕ │  app 外壳（新增）
├──────────┬──────────────────────────────────────┤
│ 侧边导航  │  对比模式（演示区，视觉主角）           │
│  今日    │  ┌ A 静默 ┐ ┌ B 光点 ┐ ┌ C 基线 ┐   │
│  任务    │  │ 指示器   │ │ 指示器   │ │ 指示器   │   │
│  评审    │  │ composer │ │ composer │ │ composer │   │
│  知识    │  │ 当前：…  │ │ 当前：…  │ │ 当前：…  │   │
│          │  └─────────┘ └─────────┘ └─────────┘   │
├──────────┴──────────────────────────────────────┤
│ ▸ 设计规格（折叠面板，默认展开）                  │
│   状态映射总表 · 验收自查 · 待验证项              │
└─────────────────────────────────────────────────┘
```

### 3.1 候选卡差异化

| 维度 | A 静默基线 | B 局部光点 | C 底部细基线 |
|---|---|---|---|
| 字母 | 96px display，`--line` | 96px display，`--forest` | 96px display，`--amber` |
| 容器 | 无阴影，纯 `--surface` + 发丝线 | 底部 2px `--forest` 基底 | 内缩双层描边（呼应基线不碰边框） |
| tag | 字母右下，小号 mono | 同 | 同 |

三张卡片**第一眼可区分**，且容器处理本身暗示该候选的动效策略。

### 3.2 `.now` 提权

从最浅的 `--sage` 框改为卡片标题区下方高对比 mono 行，左侧加 `CURRENT` 微标签（`--control` 色、0.625rem、`letter-spacing: 0.08em`）。

## 4. 视觉系统改造

| 项 | 现状 | 目标 |
|---|---|---|
| 字体 | 约 40% 等宽 | 等宽仅保留给 `code`、状态键（`running`）、时长数值（`4.5s`）、`.lv`、`.tag`。描述性文字全部回 `--font-ui` |
| h1 | `1.625rem / 600` | `2.5rem`，`letter-spacing: -0.02em`，`line-height: 1.1`；新增副标题独立层级 |
| h2 | 裸文字 | 编号为 `--control` 色 mono 前置，与标题同行；标题后加延伸至容器右缘的细横线 |
| 阴影 | 1 种 inset 发丝线（4 处复用） | 3 级：外壳 `0 8px 32px rgba(24,33,31,.10)` / 卡片 `0 1px 2px rgba(24,33,31,.06)` / 浮层 `0 8px 24px rgba(24,33,31,.12)` |
| 边框 | 统一 1px | 分级：1px 弱分隔（表格行、章节横线）/ 1px 强边界（输入框、卡片）/ 无边框靠底色分层 |
| 背景 | 单层 `--paper` | 三层深度：`--sidebar`（外壳）→ `--paper`（主区）→ `--surface`（卡片） |
| 控件 | chip / btn / qa 三套做法 | 统一：同高 `1.75rem`、同圆角、同 hover 与 `focus-visible` 行为；差异靠 tone 而非造型 |
| chip 换行 | 末行孤儿「已取消」 | 容器 `overflow-x: auto` + `flex-wrap: nowrap`，或压缩文案使 11 个整齐排满 |
| 窗口控制 | 无 | 标题栏右侧三键，仅视觉，不接真实逻辑 |
| 数字对齐 | 默认 | 全站 `font-variant-numeric: tabular-nums` |

### 4.1 新增 token

仅新增结构性 token，不改既有色值：

```css
--shadow-shell: 0 8px 32px rgba(24, 33, 31, .10);
--shadow-card:  0 1px 2px rgba(24, 33, 31, .06);
--shadow-pop:   0 8px 24px rgba(24, 33, 31, .12);
--titlebar-h:   2.25rem;
--sidebar-w:    13.5rem;
--hairline:     1px solid var(--line);
```

## 5. 行为契约（重构后必须仍然成立）

1. 切换任意状态后，`布局位移检测` 读数仍为 `A 0px · B 0px · C 0px`
2. 三个 composer 在所有状态下均可点击、输入、选择、复制；无 `disabled`，无遮罩层
3. 勾选「减少动态效果」或「模拟系统减少动态效果」后循环动效消失，图标 / 文字 / 边框色 / 角标仍能区分全部 11 个状态
4. 11 个 chip 全部可见可点，`aria-pressed` 正确反映当前状态
5. 装饰动效层保持 `aria-hidden`
6. 窗口控制三键、侧边导航为纯视觉，不绑定事件，不影响演示流程
7. 规格面板可折叠/展开，折叠不影响演示区可用性

## 6. 验收方式

本轮为纯视觉重构，验收方式：

1. `python -m http.server 8791` 起本地服务，浏览器打开 `motion-border-prototype.html`
2. 逐条核对第 5 节 7 项行为契约
3. 全页截图与重构前对比，确认 `#1`（候选可辨）、`#2`（`.now` 提权）、`#3`（等宽收敛）、`#4`（阴影分级）、`#6`（控件统一）、`#7`（chip 换行）六项问题均已消除
4. `git diff --stat` 确认仅 `motion-border-prototype.html` 与本 spec 文件变更

**本轮不证明**：Windows WebView 在 125%–150% DPI 下的实际观感、长时间使用的视觉疲劳、真实接入后的跨 Task 事件隔离。这些仍属原页面第六节「待验证项」，需真实桌面窗口验证。

## 7. 风险

| 风险 | 缓解 |
|---|---|
| 结构重排破坏 `.composer` 高度稳定性，导致位移检测报错 | `.composer` 的 `min-height`、固定 `height` 的 `.indicator` / `.mark` / `.lv` 一律不改；重构后立即跑位移检测 |
| JS `closest('.card')` 与 `className.match(/cand-(\w)/)` 依赖类名 | 候选卡保留 `card cand-a/b/c` 类名不变 |
| 新增 app 外壳吃掉过多垂直空间，文档区被推到折叠线以下 | 外壳与侧栏在窄屏（`max-width: 60rem`）降级为隐藏侧栏 |
